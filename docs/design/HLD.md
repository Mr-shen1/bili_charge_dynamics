## 1. 架构概览

### 1.1 技术与运行方式

同一项目内重构前端，后端保持 Python + FastAPI + SQLite，不拆微服务，不预建多包仓库。前端目标为 Vue 3 + TypeScript + Vite + Vue Router + Element Plus；浏览器路由承载列表、详情和管理。默认使用 Composition API、composables 与必要的 provide/inject 管理状态和协调行为，主题变量配合局部 scoped CSS 或 CSS Modules。测试使用 Vitest、Vue 行为测试工具和 Playwright；优先采用 @testing-library/vue，必要时使用 Vue Test Utils，兼容版本在实施时核实。后端技术栈不列入待选技术。

运行职责如下；Vue 前端是待实现目标，其余沿用已有模块。职责表不是任何具体环境的部署或验收证明：

| 环境或进程 | 职责 |
| --- | --- |
| 开发与测试 | 保留独立 mock、可控故障及现有真实 API Adapter/采集状态测试边界；按代码修正旧断言并在 Vue 中回归 |
| 构建 | 本地或 CI 生成静态产物，不占用生产服务器执行日常构建 |
| 静态托管 | Nginx 提供前端入口、脚本和样式；无需常驻 Node.js 应用或 SSR |
| 单 API 进程 | FastAPI 提供管理和归档读取接口，不内嵌采集定时器，不启动多个 API worker 重复调度 |
| 单采集进程 | 执行固定检查时钟、目标发现、同步与媒体上传，使用持久化任务状态恢复未完成工作 |
| SQLite 与 OSS | SQLite 保存身份、配置、归档及检查同步状态；OSS 公共读图片由浏览器直接获取 |

API 和采集进程属于同一项目，共用明确的数据契约与 SQLite，不引入 Redis、Celery 或独立任务服务。下图表示优先评估的同机方案，不要求未经验证的 2 核 2GB 必须承载全部服务；不承诺 UP 数、并发量、归档容量或单个节拍内完成同步。

```text
浏览器前端
  ├─ 导航 / 会话 / 动态 / 评论 / 图片预览模块 + 管理页面（Vue 目标实现）
  ├─ 读取接口 ──真实 API Adapter──> FastAPI（单进程）
  │                                  ├─ 监控管理 ──> SQLite 配置 / UP 身份
  │                                  └─ 归档读取 ──> SQLite 已归档内容
  └─ 图片 URL ──直接获取──> 公共读 OSS

采集进程（单进程，无 API 内嵌定时器）
  ├─ 采集同步 ──> SQLite 持久化检查 / 待同步状态 / 内容
  ├─ B 站读取 ──> 上游 API / opus 页面（服务器端）
  └─ 媒体上传 ──> OSS

开发 / 测试：原 mockReader + 可控故障 Adapter 继续保留
本地或 CI ──构建产物──> Nginx ──静态文件──> 浏览器
```

页面读取与采集解耦：读归档不隐式触发上游刷新；采集异常不应使已有归档失去可读性。浏览器不持有 B 站 Cookie 或 OSS 写入密钥，应用服务器不代理浏览器图片流量。

### 1.2 关键取舍

| 决定 | 收益 | 代价或限制 |
| --- | --- | --- |
| 单工程、按职责组织模块 | 满足当前规模，减少跨包维护 | 不预先建设可独立发布的通用组件库 |
| Vue 响应式状态与 composables | 不默认增加 Pinia、请求缓存框架；按职责组织状态及依赖注入 | 请求去重、竞态与阅读快照仍需集中实现和测试，不能由 UI 库代替 |
| 异步接口 + 双 Adapter 路径 | 原模拟回归可保留，真实接口在同一边界接入 | 旧验收不覆盖真实 HTTP 与后端协议，需新增验证 |
| 单 API + 单采集进程 + SQLite | 避免重复定时器和额外中间件，适合当前小规模目标 | 写入协调、任务恢复与实际资源占用仍需验证 |
| 检查与同步分离、状态持久化 | 耗时同步不占据检查调度逻辑，异常后不丢待更新状态 | 需分开维护 observed 与成功 checkpoint，不保证同步时延 |
| 每次访问独立阅读快照 | 准确恢复同一动态的不同历史访问 | 内存及导航逻辑比按动态 ID 单份保存更复杂 |
| 自定义锚点恢复 | 更适合多图、长正文和响应式布局 | 必须处理布局就绪、图片尺寸与回退定位 |
| 单一 Element Plus 组件库与主题 | 替代通用表单、控件、提示和图片预览，降低自维护成本 | 内容布局仍需局部 CSS；预览与导航/焦点/滚动的组合行为须验证 |
| 完整重构后统一上线 | 无需生产混合框架或页面级灰度 | 实施期间分阶段验证，最终仍需完整回归及新视觉/设备签收 |

具体依赖版本在实施时核对兼容性并固定；Python 环境和依赖仅使用 uv，Node.js 使用 nvm，前端依赖与脚本仅使用 pnpm。本文不把文档选型当作已安装版本。

## 2. 模块职责与协作

模块是具有公开接口和内部实现的职责单元，不等同于一个 Vue 组件、composable 或一个文件。复杂行为应收敛在模块内部，页面通过少量公开操作使用它，而非直接改写内部状态。

| 模块 | 公开能力 | 内部负责 | 不负责 |
| --- | --- | --- | --- |
| 应用导航 | 打开详情、返回列表、打开/关闭预览、接收历史导航 | 路由匹配、访问标识、入口意图、历史有效性判断、恢复调度 | 业务排序、图片下载 |
| 会话状态 | 读取当前访问状态、提交领域操作、保存/恢复阅读快照 | 内容引用、访问快照、预览会话、请求状态的归属 | 浏览器存储持久化、HTTP 协议 |
| 动态浏览 | 展示列表/详情、追加动态、展开正文、发出导航意图 | 该页面的读取状态、文本阅读和列表展示 | 操作原始模拟文件、直接改写历史栈 |
| 评论阅读 | 选择排序、追加一级评论、回复预览/页码翻页、打开楼中楼、局部重试 | cursor 与实时页码分别协调，宽窄屏显示、回复目标、请求代次与局部状态 | 改变动态正文、独立操作历史栈 |
| 图片预览 | 打开所属组的原生预览、切换图片、请求关闭 | 库负责图片查看；连接层负责 owner/索引、错误、焦点/滚动与历史协调衔接 | 重造缩放/手势引擎、拼接 OSS 参数、独立操作历史栈 |
| 数据读取（前端） | 读取全部或单 UP 动态列表、详情、一级评论及回复 | Adapter 协议转换、展示字段规范化、读取结果语义 | 页面展开、滚动位置、路由恢复、直连上游 |
| 监控管理（后端） | 按 UID 新增 UP、修改模式与目标、停用及删除监控配置 | UP 身份与配置分离、模式互斥、指定目标归属校验、上游资料读取协作 | 手动覆盖昵称头像、删除归档、承载定时器 |
| B 站读取（后端） | 读取 UP 资料、动态候选与详情、页面时间、评论和回复 | 来源协议、安全解析、失败与受限语义、计数和时间来源说明 | 调度策略、页面交互、宣称所有受限内容可读 |
| 采集同步（后端） | 选取目标、周期检查、同步正文/评论/图片、恢复待处理任务 | 持久化检查及同步状态、去重互斥、媒体上传、分项提交成功 | 浏览器按需同步、默认每日全量校准、自动退避策略 |
| 归档读取（后端） | 从 SQLite 读取归档和公开媒体 URL | 全局或单 UP 排序分页、归档状态与来源计数映射 | 每次浏览访问上游、修改监控或执行采集 |

飞书扩展新增通知模块（待实施）：对归档写事务提供小接口登记事件/候选，内部负责基线、去重、路由、格式、领取、限流、重试、告警和心跳；不负责来源采集或修改归档成功状态。前端评论读取增加按归档身份定位入口，保留原分页、访问恢复与只读边界，详见 §1.3。

依赖约束：

- 展示模块依赖既有读取接口，由应用装配已有生产、mock 或可控 Adapter；复用实际协议映射与替换点，不因旧“下一阶段新增”表述再造读取层。
- 导航模块统一管理历史操作；图片预览和动态页面只发出意图，不分别调用底层 History API。
- 纯状态转换与副作用分离；请求、取消、DOM 测量和导航由相应 composables/协调器执行。已有纯 TypeScript 转换可复用，不为迁移框架而改写正确的业务规则。
- 日期、计数等确定性工具按实际复用需要共享；不建立只做一层转发的大量空模块。
- 模块的具体文件布局、组件拆分及函数名称由实施规格细化，不改变本文职责分配。

### 2.1 监控配置与目标选择

- UP 身份按字符串 UID 建立。管理页输入 UID，昵称和头像由服务器通过 B 站读取模块取得，不提供手动覆盖；资料缺失或读取失败不伪造成功身份信息。
- 每个 UP 的监控模式互斥：近期 N 条（默认 10，按 UP 配置）或指定动态 ID。模式仅决定目标集合，不限制内容采集范围，不增加“仅评论” scope。
- 近期模式直接复用 `script_demo` 的原识别函数判定候选，不重新评估或改写识别规则。逐页读取候选并筛选，凑足 N 条符合条件的动态；来源耗尽时允许不足 N 条，而不是只取首屏 N 条再筛选。
- 指定模式只处理与该 UP 关联的指定 ID。需校验来源作者归属；归属不符不能强行挂到该 UP 下，归属不确定不能当作校验成功。此模式不附带近期目标。
- 选中的动态采集正文、动态图片、已有一级评论及回复、一级评论图片等可实际读取的内容；不自动发现并回填全部历史动态，不等于跳过选中动态已有的历史评论。
- 删除监控配置或指定目标、停用、模式切换后不再入选或移出近期窗口，只停止后续监控，不删除 UP 身份所关联的归档、评论或图片；重新纳入后可继续同步。监控配置不是内容所有权的生命周期根，数据库关系不得以配置删除级联清除归档。
- 当前真实规模参考为 UP `550494308` 近期约 10 条，UP `3493130286402061` 指定模式目前 2 条目标；这不是容量保证，不沿用 100 条动态作为真实规模基线，也不新增目标硬上限。

### 2.2 固定检查时钟与持久化同步

采集进程采用固定节拍检查时钟（生产默认 2.7 秒，±10% 抖动）；页面信号（编辑时间/正文与图片版本/受限状态）按独立间隔采样，默认 60 秒 ±2 秒，避免每个节拍都取一次页面 HTML。同一目标上次检查尚未完成时跳过该次机会，不叠加检查；下一固定时钟再评估，不默认加入退避、自适应频率或原脚本的每日全量校准。该时钟表示检查调度节奏，不表示全量正文、评论和图片每个节拍必定更新完成。

```text
固定时钟 → 检查目标（同目标未完成则跳过）
         → 解析可信观察值 → 持久化 observed 与待同步状态
独立同步调度 → 领取持久化待处理工作 → 请求 / 解析 / 上传
             → 分项提交归档及相应成功 checkpoint
异常或进程重启 → 从未完成状态恢复，不把 observed 当作已同步成功
```

检查只取得变化信号，耗时正文、评论分页和图片上传由独立工作阶段处理；这两个阶段仍在单采集进程内，不引入另一个服务。网络请求和 OSS 上传不置于数据库长事务中。可采用进程内按目标互斥、有限并发、SQLite 短事务领取与提交、工作归属标记等设计；具体并发值、锁实现及 SQLite 参数留实施规格与测试决定，不编造吞吐或锁等待保证。

持久化状态按正文、评论、媒体分别维护：

1. 首次有效观察建立基线，并为未归档的选中目标登记首次同步工作；基线不等于同步成功。
2. 保存最近可信的 `observed`，与相应分项的上次成功 checkpoint 比较；必要时登记或更新待同步版本。检查已观察到变化但 worker 异常时，差异及未完成工作仍必须可恢复。
3. 同步绑定其开始处理的观察版本。仅当该分项成功归档时推进该版本的成功 checkpoint；期间出现更新观察值，旧任务完成不得清除较新待处理工作。
4. 同步失败只记录该分项的失败和待处理状态，不提交同步成功；后续仍按固定调度处理，不隐含额外退避算法。一个分项成功或失败均不重置其他分项状态。
5. 评论同步成功不等待图片全部上传；图片上传失败保持独立待处理状态，也不能使正文或评论的成功状态倒退。重启后的领取恢复、重复执行及成功提交需要幂等验证。

### 2.3 变化检测依据与访问边界

**正文编辑信号。** 已有样本通过一次成功的 HTML GET `https://www.bilibili.com/opus/{id}`，从 `__INITIAL_STATE__.detail.modules` 中取得页面编辑时间。这是网页初始化数据的作者字段，不是通用 feed/detail 的同名显示字段，也不依赖曾返回 412 的 `opus/detail` JSON 接口。按 `__INITIAL_STATE__` 标记安全提取初始化 JSON，再使用 JSON 解析器读取 `detail.modules`；不执行网页 JS、`eval` 或脚本，也不把任意脚本表达式当作 JSON。遍历 `modules`，按 `module_type = MODULE_TYPE_AUTHOR` 定位作者模块，再读取 `module_author.pub_time`，不能写死 `script[10]`、`modules[0]` 或统计模块下标。具体提取实现留实施规格，以脚本和模块顺序变化、非 JSON 与恶意脚本样本验证边界。页面结构不符、带编辑标记的时间无法确定或请求失败时保留原可信时间及成功 checkpoint，并记录未知/失败状态，不覆盖成空值或当前时间，也不当作确认未编辑；编辑信号不可用不阻断其他可读取部分。

同一样本的通用 feed/detail `pub_ts=1791513496` 对应显示 10:38，而页面 `pub_time` 显示“编辑于……13:01”。因此 `pub_ts` 不能单独作为编辑版本。先规范化空白、识别“编辑于”标记，再将明确日期时间按来源时区和精度规范化，与上次成功状态比较；空白差异和普通“几分钟前”等相对时间文案变化不触发正文同步，不比较正文或图片内容。初次纳入目标建立可用观察基线并登记可读取内容的首次同步，不以没有“编辑于”标记为由跳过首次同步，也不要求正文编辑信号成功后才同步评论；后续可信编辑信号变化仅触发正文及其动态图片同步，不默认重扫评论。保留 `publishedAt` 与可选 `editedAt` 的不同含义；无法可靠取得发布时间时不能以编辑时间补值。记录编辑信号的分钟精度，不伪造秒；当前阅读页不展示已裁剪的编辑信息。分钟内多次编辑可能无法区分，自然多次编辑后的持续更新及全部目标页面的时间可获取性尚未实测，不宣称可靠捕获所有编辑。

**评论变化信号。** 除首次同步和失败重试外，仅来源评论总数变化触发选中动态的一级评论和回复同步，不因正文编辑默认重扫。来源总数的语义是动态一级评论及全部楼中楼回复总数；来源字段映射仍须验证，不能由某个首屏计数推定跨接口恒等。来源总数、本地已归档一级评论数及回复数分开保存。接受新增与删除抵消、纯评论编辑等未引起总数变化的情况可能漏检，不加正文或图片比对来补足。缺失字段、接口失败、结构不确定或明确拒绝不是评论数 0；保留旧可信计数并记录对应状态。评论同步应在该轮所需根评论及回复读取、归档成功后才推进评论成功 checkpoint，不能仅因读到了新总数就宣布成功。

**独立访问结果。** 正文受限或页面显示评论暂无权，不阻断实际能够成功读取的评论接口；按各接口真实结果保存正文、评论和图片状态。这只说明样本中可独立读取，不能保证所有受限动态的评论均可读；明确拒绝须呈现为受限/失败语义，而非空评论或零计数。

证据与边界见 [后端可行性记录](../backend/evidence/backend-feasibility.md)：13 次 GET 包括 11 次成功 API、1 次 `opus/detail` 返回 412 后停止该探测、1 次页面 200（约 22483 bytes / 253.7 ms），记录含 235/501 评论样本。它们是有限样本观察，不是官方接口保证，也不是固定节拍周期、持续编辑、全量评论同步或生产容量测试。

## 3. 数据表示与读取接口

### 3.1 统一展示模型

展示实体语义遵循当前 SRS 的 DR-01，真实读取及归档扩展遵循 DR-02 至 DR-05；需求追踪见第 12 节。内部表示约定如下：

- 动态、用户、评论、回复 ID 使用字符串，不将来源大整数先转为 JavaScript 数字；身份比较使用 ID，不使用昵称。
- 有效发布时间在读取 Adapter 中统一为明确时区的 ISO 8601 时间表示；缺失或无效时间为 `null`。来源未说明时区时不能由各页面自行猜测。`publishedAt` 不被编辑时间覆盖；可选 `editedAt` 及精度信息表达独立编辑信号，分钟精度不假装成来源提供了秒。发布时间仍按原契约显示绝对北京时间到秒，不因参考截图使用相对时间而改变。
- 有效计数保留为非负整数，缺失或无效值为 `null`；显示兜底由 SRS 的 FR-12 决定，不在数据层伪造零值。
- 正文按文本表达；昵称、时间、图片及回复目标等必要字段在 Adapter 中统一检查，保留可展示的缺失状态。成功读取的空正文、访问受限和读取失败使用不同内容状态，不共用空字符串来伪装成功。
- 动态和一级评论均可拥有有序图片集合；本轮不扩展回复图片。评论的作者标识是否为 UP 主，必须比较评论作者 ID 与 `dynamic.author.id`，不能在“全部”范围用单一 `reader.creator` 判断。
- 数据检查只服务于安全展示和接口契约，不建设通用清洗系统，不提前引入复杂校验框架。
- 内容对象按不可变数据使用，可按 ID 复用；排序后的 ID 列表、已加载范围和展开状态属于具体阅读快照，不能被另一访问的操作原地改写。

排序沿用原契约：动态按发布时间降序、ID 字符串升序；一级评论在两种排序中均先置顶优先，再对同级评论按“最热”的点赞数降序、时间降序、ID 字符串升序或“最新”的时间降序、ID 字符串升序排列；回复按时间升序、ID 字符串升序。按每个比较字段逐级比较，空值排在该字段有效值之后，再进入下一比较字段；最终 ID 比较采用非语言环境相关方式，不将字符串 ID 当作数字或时间推断新旧。

### 3.2 读取接口的语义

接口提供以下异步能力；表中是契约语义，不是最终函数签名或真实 HTTP 路径。

| 读取能力 | 输入语义 | 成功结果 |
| --- | --- | --- |
| 动态列表 | scope（全部或单 UP）、首次或下一批标记、批量大小、取消信号 | 对应归档范围的动态集合与下一批标记 |
| 动态详情 | 动态 ID、取消信号 | 对应动态 |
| 一级评论 | 动态 ID、排序、首次或下一批标记、批量大小、取消信号 | 评论集合与下一批标记 |
| 楼中楼回复 | 动态 ID、根评论 ID、批量、互斥的 cursor/页码、取消信号 | cursor 返回冻结批；页码返回实时当前页、本地总数、根评论及状态，nextCursor 为 null |
| UP 导航资料 | 取消信号 | 已保存的 UP 身份及导航所需资料，包含有归档但已停止或删除配置的 UP |

当前生产 UP 资料来自服务器保存的上游身份，独立 mock 仅供回归；不允许手动覆盖昵称头像。管理写入使用单独的管理接口，不混入只读 `DynamicReader`。管理变更不意味着归档删除，也不使普通列表读取变成上游同步。

读取结果区分：

| 结果 | 含义与调用方处理 |
| --- | --- |
| 成功 | 数据可展示；空集合也是成功，不抛成异常 |
| 动态不存在 | 合法详情请求找不到对应动态，进入内容不可用状态 |
| 读取失败 | 本次操作未成功，保留已有内容并提供局部重试 |
| 已取消 | 操作不再需要，不向用户显示读取失败 |

未知路由由导航模块处理，不通过数据接口伪装成“动态不存在”。不存在的 UP 归档地址与已知 UP 的成功空列表分别表达，均可返回 `/`；上游消失或受限不表示本地归档不存在。成功读取归档可以携带正文受限、评论同步失败或媒体待上传等分项状态；HTTP 读取成功不等于采集全部成功。原始技术错误只作脱敏诊断，Cookie、OSS 密钥等不得出现在 UI、API 响应或日志中，用户提示使用可理解的错误语义。

### 3.3 cursor 与回复实时页码

分页分两种既有协议，不能因换库合并为一套：

- 动态列表每批最多 10、一级评论每批最多 20，继续传递不透明 cursor 并追加；`nextCursor = null` 表示不再追加。不解析 cursor 或从它推导页码，不以去重掩盖漏批。失败不推进标记，重试原批；失效按现有错误契约显式重新开始。
- 列表 cursor 绑定 scope，评论 cursor 绑定父动态/排序等读取上下文；生产冻结规则及不同资源的 TTL 以已交付接口为准。全部归档先全局排序再分页，不按 UP 分页后拼接；全部/单 UP 的结果和快照隔离。
- 回复的 cursor 模式仍保留首读最多 3、续读最多 10 的冻结接口，当前主要用于宽屏预览。它是兼容读取能力，不代表正常界面仍有累计“加载更多回复”按钮。
- 展开后的回复与独立楼中楼页使用现有 `page` 实时接口，每页最多 10，页内替换；每次请求在同一短读事务取得当前根评论、回复及计数。`count` 是本地已归档回复总量，`nextCursor = null`，每页都返回根评论；来源回复数另存，不用来决定本地页数。
- 页码请求携带 `cache: no-store`，翻页/同页重读不以页缓存跳过请求。每次读取实时归档，不能承诺跨页冻结、不重不漏；请求页越界返回空页和实际本地 count，前端再读取有效末页。
- 宽屏每次展开从 page 1 重新读取；收起取消在途请求并回到预览，将根评论开头滚回可见位置。详情快照保存预览、展开、当前页码和文字状态；历史恢复已展开回复时重读保存页码，而非复用冻结的整页数据。
- 窄屏（当前 ≤640px）只在来源回复数为正时显示 `up_reply` 或数量入口，未知/零不显示；有入口但没有本地回复也允许进入独立页。该页每次挂载从 page 1/顶部开始，无自身阅读快照，返回来源动态详情仍恢复详情快照。

页码与 cursor 的互斥、批量校验、错误映射及响应详见[归档 API](../backend/api/archive-api.md)与[客户端契约](../backend/api/archive-api-client.md)。这些是当前已存在协议，不是 Vue 迁移新增后端能力。

### 3.4 Adapter 装配

当前默认装配真实 API Adapter，只请求后端归档读取接口；独立 mock 和开发故障路径已存在并继续保留。开发/测试可注入可控 Adapter，按操作指定延迟、结果、失败和返回顺序，不通过随机失败制造验收样例，也不因旧 mock 测试而改变正常生产装配。

页面不导入模拟集合、故障配置或原始 API DTO。API Adapter 负责协议转换、字段检查和图片 URL 映射；调用方明确选择既有 cursor 或回复 page 读取，不自行推导另一种协议。当前 scope、身份、状态、评论图片和页码契约已经存在，早期无 scope/无图模型不再代表现状。读取、错误、取消及代次保护语义继续保留。

### 3.5 归档概念模型与状态语义

下表是概念实体，不固定 SQL 表名、库版本或最终字段签名。所有来源实体 ID、关联 ID 及前端对外 ID 均使用字符串。

| 概念 | 内容与关系 | 生命周期约束 |
| --- | --- | --- |
| UP 身份 | UID、上游昵称头像及资料读取状态；被动态作者和配置引用 | 与监控配置分开，删除配置不删除身份或归档 |
| 监控配置 | 关联 UP、启停、互斥模式、近期 N | 不以删除级联方式清除内容 |
| 监控目标 | 关联配置、UP 与动态 ID；记录近期入选或指定关联及归属校验状态 | 与动态归档分开；停用、移除或窗口外不删除已有动态 |
| 动态归档 | 来源动态 ID、作者 UID、正文与内容状态、发布时间、可选编辑时间及精度 | 保存成功可用内容，后续失败不以空值覆盖 |
| 一级评论 | 来源评论 ID、动态 ID、作者、文本、时间、点赞数及来源回复数 | 直接归属动态，不将本地条数充当来源总数 |
| 回复 | 来源回复 ID、根评论 ID、作者、回复目标、文本、时间及点赞数 | 保留根评论与回复目标关系；界面扁平展示，不扩展回复图片 |
| 媒体 | 来源地址、公开 OSS URL、可用尺寸、上传状态及错误 | 动态图和一级评论图共用上传能力；单图失败独立重试，保留旧成功归档，不使其他图或文本失效 |
| 动态媒体关联 | 动态 ID、媒体引用及来源顺序 | 与一级评论媒体关联分开，保留动态图片组归属；引用归档动态，不由监控配置删除级联清除 |
| 一级评论媒体关联 | 一级评论 ID、媒体引用及来源顺序 | 保留具体评论图片组归属，不能混入同动态的其他图片组；引用归档评论，不归属监控目标 |
| 检查同步状态 | 目标及分项、最后可信观察、待处理版本、成功 checkpoint、工作归属及错误状态 | 持久化未完成工作；正文、评论和图片独立推进，不互相重置 |

共用上传能力不等于共用一个图片组；实体关联保留各自 owner 与顺序，前端预览按归属组读取。是否复用物理 OSS 对象及其去重方式留实施规格，不在本期增加引用回收、容量清理或回复图能力。头像是身份展示资产，与上述业务归档图片分开。

`source_count` 表示来源实际返回的计数，不是本地归档评论行数；缺失/失败不能归零。`observed` 表示检查最近看到的可信值，不证明对应内容已经归档；`synced` / 成功 checkpoint 表示该分项实际成功处理到的观察版本，不因检查成功而推进。图片上传另有状态，不能借用正文或评论的 checkpoint 冒充已上传。API 应保留这三类语义及可用/受限/失败区别，具体响应形状留实施规格确定。

## 4. 异步状态与请求保护

### 4.1 状态归属

每个读取区域维护加载状态、已有结果、cursor 或页码及失败操作上下文。动态/一级评论的首次与追加读取分开；回复页码切换则替换当前页，不使用下面的累计追加图式。各根独立，加载/错误不锁住其他区域。

```text
尚未读取 ──发起──> 首次加载 ──成功──> 成功有内容 / 成功为空
                         └─失败──> 首次错误 ──重试──> 首次加载

成功有内容 ──加载更多──> 保留内容并追加加载
                           ├─成功──> 追加结果 / 已加载完毕
                           └─失败──> 保留内容并显示追加错误
```

取消不是错误态。若离开页面导致请求被取消，快照中的瞬时加载状态应转为可再次读取的状态；返回时恢复已成功内容，必要时重新发起未完成批次，不能永久停留在“加载中”。

### 4.2 双重保护

请求身份由访问 ID、资源类型、列表 scope（全部或 UP ID）、所属动态或评论 ID、排序、cursor/页码及请求代次组成。代次按读取区域维护，某条回复重试不能使无关区域的请求失效。切换“全部”与单 UP 时旧范围请求也必须失效，不能向新范围追加结果。

1. 发起前检查相同批次是否正在读取；除了禁用按钮，协调逻辑也需阻止重复启动。
2. 排序变更或页面访问被替换时，使旧代次失效，并尽量通过取消信号中止旧请求。
3. 成功与失败返回都检查归属和代次；过期结果、错误及完成回调均不得改写当前状态或提前清除新请求的加载标记。
4. 有效成功结果才可提交对应内容：cursor 追加并推进标记，回复 page 替换当前页及本地 count；有效失败仅更新所属区域。
5. 重试绑定原失败条件，不把旧排序的失败批次重试到新排序中。

取消是节省工作量的补充，不是正确性的唯一条件。模拟 Adapter 即使故意忽略取消，也必须能通过代次保护测试。

### 4.3 切换排序时序

```text
选择目标排序
  → 更新当前选择、递增评论区域代次
  → 重置目标排序的已加载范围与展开状态
  → 使旧评论及其回复请求失效，保留上方动态
  → 定位评论区并读取目标首批
  → 仅接受匹配当前访问与代次的结果
```

即使切回此前用过的排序，也按 SRS 从首批及收起状态开始，不能恢复旧排序的分页进度。缓存的数据可以复用，但可见范围不能因此越过首批。

## 5. 会话状态与阅读快照

### 5.1 生命周期

会话实例在 Vue 应用根部创建，生命周期高于路由页面，通过 provide/inject 或显式依赖交给 composables，与唯一导航协调器共同工作。不能因 route key、页面或预览变化而重建整个会话；测试应可创建隔离实例，不默认依赖跨测试共享的模块级可变单例。

响应式状态按职责分片，公开操作调用纯转换或相应副作用；避免图片切换让无关评论订阅整份状态。不默认引入 Pinia 或请求缓存库，不把旧 React hook 逐个机械改名。

不写入 `localStorage` 或 `sessionStorage`。浏览器 `history.state` 只存轻量导航元数据，不保存完整评论、展开快照或图片数据，因此它不构成持久化阅读历史。

### 5.2 状态模型

以下名称是设计概念，最终类型定义留到实施阶段。

| 状态 | 标识与内容 |
| --- | --- |
| 当前会话 | 新启动的会话标识，用于识别遗留历史元数据是否仍有对应内存 |
| 内容数据 | 按稳定 ID 引用的动态、作者、评论及回复；避免无意义的实体复制 |
| 页面访问快照 | 列表/动态详情的 `pageEntryId`、scope、来源、排序、已加载范围、cursor、文字展开、回复预览/展开/页码及位置；独立楼中楼无自身阅读快照 |
| 预览会话 | 应用生成的 `previewId`；底层 `pageEntryId`、所属动态、图片 owner 类型及 ID（动态组或一级评论组）、图片顺序、当前图片、显示模式和触发焦点标识 |
| 请求运行状态 | 每区域的请求身份、代次与加载/错误状态；取消控制器由副作用协调逻辑持有 |

每次主动进入建立独立访问记录。同一动态先后两次访问的排序、分页和位置互不覆盖；内容实体可以共享，视图快照不可共享可变引用。新访问按入口定位；独立楼中楼只用访问身份及来源关系，不因有访问 ID 就自动获得快照，重新挂载从首屏开始。

前端不新增后台自动刷新或跨标签页同步；这与采集进程后台更新归档是不同职责。已打开的阅读快照不被采集结果无条件重置。“全部”和每个 UP 的已加载范围、cursor 与快照分别归属对应 scope，不能共用一个可变列表。为满足当前会话恢复，仍可返回的访问记录不随意淘汰；长时间浏览导致的快照内存增长列为风险，不在没有测量时承诺无限历史容量。

## 6. 路由与历史协调

### 6.1 路由与元数据

| 路径 | 处理 |
| --- | --- |
| `/` | 全部已归档动态，跨 UP 全局排序后分页 |
| `/ups/:upId` | 单 UP 的已归档动态 |
| `/dynamics/:dynamicId` | 动态详情；正文和一级评论属于同一详情页 |
| `/dynamics/:dynamicId/comments/:rootId` | 指定根评论的独立楼中楼页，窄屏入口进入，支持直达/刷新 |
| `/manage` | UP 监控管理（UP 列表） |
| `/manage/ups/:upId` | 单 UP 管理（配置、目标、检查状态） |
| 其他页面路径 | 前端未找到页面状态 |

上表是按当前代码保留的六条页面路由，原五路由清单已过时。URL 表达页面、UP 范围、动态及根评论，不携带排序、页码、展开或预览参数。动态详情内的一级评论区与独立楼中楼不是同一页面，分享地址不携带阅读进度。

历史元数据区分页面记录与预览记录，包含必要的会话标识、应用访问 ID、来源和导航意图。使用应用自有命名空间中的轻量可序列化数据，不写入 Vue 响应式代理，也不覆盖 Vue Router 自有 state。业务访问 ID 不依赖路由库内部 key；`replace` 时保留需要延续的应用 ID。

### 6.2 页面导航流程

| 操作 | 设计处理 |
| --- | --- |
| 主动查看详情 | 点击卡片整体或使用其键盘入口：保存当前快照，创建新的页面访问记录，记录顶部定位意图；完全去除原“查看详情”按钮 |
| 主动查看评论 | 点击评论气泡图标及数量：进入同一动态详情，但定位意图为评论区 |
| 切换全部或 UP | 按目标 scope 新建主动访问，独立读取与保存快照；历史返回仍恢复原访问，不复用其他 scope 的 cursor |
| 历史前进/后退 | 列表/动态详情查找对应快照，不按动态 ID 取最后一次状态；楼中楼重新挂载回首屏，不恢复自身旧页码 |
| 打开/返回楼中楼 | 记录对应动态详情来源；有有效内存来源时 POP 返回并恢复详情，无来源时 replace 到对应动态详情；楼中楼分页器的收起同返回 |
| 详情返回 | 只有确认存在有效站内列表来源及对应历史关系时才回退，恢复来源的全部或单 UP 范围；否则导航 `/` 全部列表首页 |
| 直接访问或刷新 | 若无有效内存快照则按地址建立新会话状态，详情仍可正常读取 |

导航模块从应用主动 push/replace 操作、浏览器历史变化与应用元数据识别导航意图，不假定 Vue Router 提供与 React Router 相同的 `PUSH`/`POP`/`REPLACE` 通知 API，也不能只根据 pathname 是否改变判断访问类型。首次加载与刷新须检查快照是否实际存在，不误恢复仅有历史标记而无内存的访问。

卡片整体导航与内部交互分离：图片预览、文字选择、展开/收起及其他内部操作不得冒泡触发详情导航，评论入口也不得先触发顶部入口。只有顶部 UP 选择项用于范围导航；内容中的动态、评论和回复头像昵称只展示，不筛选、不跳转，也不触发卡片导航。使用合法交互语义而非嵌套按钮；卡片提供可聚焦、可用键盘激活的入口及清晰焦点，具体结构在实施时验证。

## 7. 图片预览与历史记录

### 7.1 打开、切换与关闭

```text
页面访问 A
  ──打开图片──> 页面 A + 预览记录 P（同 URL，新增一条历史记录）
  ──预览内切图──> 更新 P 的内存状态，不新增记录
  ──关闭 / Esc / 后退──> 页面访问 A
  ──浏览器前进──> 恢复预览 P 及最后查看的图片
```

- 打开时保存底层位置和焦点标识；由唯一导航协调器通过 Vue Router 新增带 `previewId`、底层 `pageEntryId` 的同 URL 历史记录，尊重路由库自身 state。打开预览不创建第二份底层页面阅读快照，也不取消底层仍有效的读取；同 URL 导航及历史更新行为须针对固定版本验证，不能照搬旧 Router API。
- 下一阶段一级评论图片沿用同一预览、历史和焦点机制。owner 必须区分动态图片组与具体一级评论图片组，不能只用 `dynamicId`；切图限于当前组的有序集合，不串入同一动态的其他评论图片。触发标识包含所属组和图片，关闭及前进恢复仍定位到原触发点；不扩展回复图片。
- 切图及库支持的图片查看模式变化更新预览会话内存即可，不新增历史；如需替换导航元数据，须保持稳定的预览与底层访问 ID，不因路由变化重置页面。
- 关闭按钮和 `Esc` 交由导航模块撤销已确认由应用创建且有底层来源的预览记录；浏览器后退已经完成撤销时，只同步关闭，不再后退第二次。
- 只有确认当前历史关系有效才使用相对后退。异常或遗留元数据使用替换导航恢复底层页面，不盲目离站。
- 关闭不立即删除仍能通过前进到达的预览内存。若从底层页面开始新导航分支，浏览器前进分支可能被丢弃，应用不得凭空重建该历史分支。

### 7.2 刷新与无效标记

浏览器可能保留 `history.state`，但刷新会丢失本方案的内存状态。初始化时检查会话标识、页面快照及预览引用是否存在；失效时用替换导航清理预览标记，并按当前 URL 正常展示底层页面。

清理只修复当前记录，不试图通过自动连续后退清空浏览器历史，避免离站或形成循环。刷新后不承诺预览恢复；出现重复同 URL 历史条目时也必须保持可正常导航。

### 7.3 焦点与触控

Element Plus 负责预览本体，应用连接层负责与导航、焦点、滚动及业务图片状态衔接。优先使用公开配置和事件；验证库已有焦点/滚动管理后再补缺口，不能叠加双重滚动锁或恢复，也不依赖库私有 DOM 重造预览。关闭时先解除锁定，再恢复底层位置与焦点，避免默认聚焦覆盖阅读恢复。

触发元素不可用时使用底层页面合理的后备焦点。手机切图可采用按钮，长图可采用库原生查看方式，不强制旧滑动/适宽实现。iPhone Safari 长图可读性、焦点约束、底层不跳位与资源加载均须实测；不默认增加双指或自由缩放能力。

## 8. 阅读位置恢复

### 8.1 保存结构

读取位置包含：当前可见动态、评论或回复的稳定定位标识，相对视口顶部的偏移，以及像素滚动位置后备。回复定位需能区分其所属一级评论，避免跨列表误定位。

导航前保存位置，必要的持续记录采用轻量更新方式，避免每次滚动都重绘整个应用。快照同时保存已加载数据范围及展开状态，否则位置本身不足以恢复页面。

### 8.2 恢复顺序

1. 识别本次是主动入口、历史返回还是预览关闭。
2. 还原对应数据范围和展开状态，等待目标区域完成必要渲染与布局。
3. 主动入口执行顶部或评论区定位；历史返回按定位标识与偏移恢复。
4. 定位点缺失时使用像素后备，并限制在有效滚动范围内。
5. 完成恢复后停止纠正；若用户已主动滚动，不继续用迟到的恢复任务把用户拉回。

不等待无关图片全部下载才定位；图片尺寸占位降低布局变化。未知尺寸、失败数据或用户中断时需有限次地结束或回退，不能无限轮询目标元素。

### 8.3 唯一恢复责任方

应用统一管理自定义恢复，并在自身生命周期内使用浏览器手动滚动恢复模式；卸载时清理相关副作用。

Vue Router 的 `scrollBehavior`、浏览器自动滚动和应用锚点恢复不能各自执行相互竞争的恢复；采用单一应用协调路径，具体接法在实施时验证。不使用持久化阅读历史，也不把旧 React Router 的 `ScrollRestoration` / `preventScrollReset` API 照搬为 Vue 设计。

## 9. 图片与样式设计

### 9.1 图片展示模型

每张图片表达缩略图 URL、预览图 URL、顺序及可用的原始宽高。尺寸缺失时先使用合理占位，图片加载后获取实际尺寸并更新展示。

- 旧基线已准备真正的小尺寸缩略素材，不仅用 CSS 将原图缩小。下一阶段动态和一级评论图片有序归档到公共读 OSS，实际缩略/预览变体方案留实施时确定，不能声称文档确认等于已生成变体。
- 页面网格使用缩略 URL 和懒加载；进入预览时才请求需要的预览 URL，不要求下载全部原图。
- 根据尺寸信息预留空间，使用 `el-image` 配合库栅格或少量 CSS Grid/Flex，按新版设计确定缩略图列数、比例及展示数量，不强制旧九格规则；未展示缩略图仍需有入口访问完整组。
- 预览采用由应用控制挂载的 `el-image-viewer`，避免同时开启 `el-image` 内置预览形成双层。原生缩放/旋转/长图能力优先使用，不重造查看引擎；owner/索引、未上传或失败图、局部重试仍通过业务边界表达。
- 是否挂载/请求整组图片尚未验证，须以冷缓存、区分缩略/预览 URL 的样例检查真实请求；公开配置和必要连接层仍无法满足 SRS 底线时重新讨论，不静默放宽按需加载要求。
- 使用浏览器图片元素直接加载，不增加画布读取、图片下载或服务端转发。
- 组件原样使用经读取层认可的 URL，不自行追加 OSS 参数或查询串。生产业务图片只使用已归档的公开 OSS URL，未上传成功时表达待处理/失败，不回退到 B 站业务图片地址；上游头像 URL 可继续用于身份展示，不要求本期归档全部外部资产。
- 浏览器加载失败和重试属于单张图片状态，沿用重试原地址的基线；与服务器媒体待上传/上传失败状态分开。首期采用公共读 OSS，不引入浏览器签名续期或权限机制，URL 映射由读取层统一负责。

### 9.2 CSS 与安全展示

以 Element Plus 为唯一 UI 库，通过主题变量统一颜色、间距、圆角和字号；业务内容布局使用少量 scoped CSS 或 CSS Modules。通用控件直接使用库，只有确有业务行为时才封装，不创建逐组件转发的平行基础库。不引入 Tailwind，不以大量深层选择器覆盖库内部 DOM 来复刻旧像素。

使用折叠的动态列表、详情内一级评论和宽屏内联回复按实际渲染行数判断，宽度变化后重新测量。独立楼中楼的根/回复正文与窄屏 UP 回复预览按当前代码直接显示文本，不新增 6 行折叠。用真实浏览器验证布局；所有外部文字安全文本渲染，来源回复前缀仅在渲染期剥离，条件化目标单独表达，不执行 HTML。

头像、时间、空值等兜底遵守 SRS，不增加 UP 主简介区域。视口、触控区域和键盘要求通过 SRS 验收，不在本文另建一套视觉标准。

### 9.3 下一阶段页面呈现边界

- 顶部以可横向滑动的“全部 + UP 头像昵称”导航切换范围；选择条可自身横向滚动，但不能使整个页面横向溢出。UP 入口来自已保存身份和归档，不只来自当前启用配置，确保停止或删除配置后旧归档仍可从单 UP 范围访问。“全部”的卡片作者来自每条 `dynamic.author`，不能显示成某个固定 `reader.creator`；评论及回复的 UP 主标识同样按该动态作者 ID 判断。
- 列表、详情、评论及回复保留居中阅读主栏、手机单列和原内容层级，沿用浅青背景、白卡、青蓝选中态、粉色作者信息；具体尺寸、字体、图标和控件外观按新版组件库主题重设，不再承诺 B站像素级复刻。可显示充电标志，不实现交易或权限功能。
- 卡片整体进入动态详情顶部，评论入口进入同详情的一级评论区；窄屏回复预览进入指定根评论的独立楼中楼页。该页显示根文字与回复页码，不渲染图片；不提供转发图标、数量或功能。
- 保留当前各区域的折叠/全文边界，不因截图扩大截断。发布时间使用绝对北京时间到秒；编辑时间只保留字段和来源精度，阅读页不恢复编辑信息/整块归档面板。
- 一级评论图片按来源顺序展示和预览；无文字但有图的评论仍正常展示，不补“暂无评论内容”。不扩展回复图片，不复制参考图中的视频、榜单、发布框或转发区块。
- `/manage` 先按动态列表的卡片形式列出 UP 身份与监控状态，点卡片进入 `/manage/ups/:upId` 管理该 UP；列表不汇总所有 UP 的配置与检查状态，也不提供“全部归档”式范围切换。单 UP 页以 UID 新增并自动取得昵称头像，不提供手改身份或凭据 UI；提供启停、互斥模式、每 UP 的 N 或指定 ID，以及最近检查、最近成功同步和分项错误。聚合状态须区分未检查、检查无变化、同步中、部分完成与失败，不把检查成功显示为全部同步成功。管理页采用与新版阅读页相同的主题和层级，通用表单、操作和状态优先使用库组件，截图另行确认而非伪称 B站管理截图复刻；不改变操作、独立草稿、错误和只读重读；无鉴权风险由部署文档声明，页面不常驻风险横幅。

视觉规范见 [界面参考说明](ui-reference.md)。旧参考图与 #35 量测仅作为历史来源；新版受控截图由用户确认后成为回归基准，覆盖阅读、图片和管理页。参考图不是官方 API 文档或已通过的验收证据，不把未确认的截图功能带入产品；数据与行为冲突时以修订后的 SRS 为准。

### 10.1 测试层次

| 工具与测试面 | 验证对象 | 设计原则 |
| --- | --- | --- |
| Vitest：确定性规则与接口契约 | 时间/计数转换、排序、分页标记、空值、会话状态公开操作 | 从公开接口验证结果，不逐个测试私有辅助函数 |

### 10.2 必须验证的架构风险

旧前端基线的编号范围为 AC-01 至 AC-20，当前 SRS 已调整其中明确改变的行为，必须按当前规则回归；新增 AC-21 至 AC-34 的追踪见第 12 节。以下原架构风险仍需验证，不把旧验收结论扩展到新功能：

- 同一动态两次访问使用不同排序与位置，前进后退分别恢复对应快照。
- 列表及详情分别打开预览，切多张后关闭、前进恢复，再后退关闭；没有多退一级或底层状态重置。
- 直接访问详情、预览期间刷新、遗留历史标记无内存，以及重复开关预览，均无空弹层或导航循环。
- 导航元数据替换时，应用访问 ID 保持正确，不依赖路由 key 是否变化。
- 快速切换排序，旧成功、旧失败及旧完成回调都不能污染新状态；模拟忽略取消后仍满足要求。
- 同批次连续点击与失败重试不重漏；请求未完成时离开再返回，不停留在永久加载状态。
- 展开正文、追加一级评论和宽屏回复页码切换后的详情恢复；图片慢加载、视口变化及缺失锚点采用可结束策略。独立楼中楼重新挂载首屏、不记旧页码的例外单独测试。
- 页面打开时未请求全部预览原图；坏图可跳过和重试，未改写签名形式的样例 URL。

### 10.3 数据装配与测试可信度

当前部分回复 E2E 仍断言累计追加、无回复目标或窄屏内联，与已采用页码/独立页的代码和组件测试冲突。用户已指定按代码修正测试；可复用的是替换边界与有效场景，不是所有旧预期。先记录测试漂移，再验证新 Vue 实现，不能凭未执行的静态比对声称测试已失败或通过。

保留原前端边界样例，不将原模拟数据规模当成真实规模或容量指标。下一阶段真实规模参考为近期约 10 条/UP、指定模式目前 1 个 UP 的 2 条目标，不再以 100 条作为真实基线；为覆盖分页或异常而构造的更多测试数据只是测试夹具。正常模拟与故障场景分开装配；测试通过读取接口控制异步结果，不依赖随机延迟碰巧制造竞态。

故障入口仅供开发与测试，不通过正常页面按钮或公开参数切换正常发布版本的故障模式。针对专用测试装配的行为验证与针对正常静态产物的构建/导航验证都需保留，不能只测试另一套运行路径。

## 11. 构建与部署设计

### 11.1 构建交付

前端继续在本地或 CI 进行类型检查、测试及构建，服务器接收静态产物，不在 2 核 2GB 目标机上执行日常前端构建。原 Nginx 配置、缓存说明和静态验证记录见 [static-delivery](../deployment/static-delivery.md)，它仍只是旧静态基线，不表示 FastAPI、采集进程、SQLite 或 OSS 已部署。

本期运行单 API 进程和单采集进程，优先评估二者与 SQLite 同机，不把必须在 2 核 2GB 同机稳定承载作为交付承诺。Python 通过 uv 管理，前端构建使用 nvm/pnpm。具体进程托管、反向代理规则、云环境及 OSS 配置留部署实施阶段；API 路径必须与 SPA 回退隔离，不能把 API 错误返回成 HTML 入口。

优先阿里云 2 核 2GB，但这不是并发、性能或容量保证；真实 API、采集与 SQLite 同机资源占用需测量，默认节拍（2.7 秒 ±10%）也不构成性能承诺。图片归档上传到公共读 OSS，浏览器直取；首期不引入权限系统、备份或容量不足治理。Cookie 与 OSS 密钥仅保存在服务器、仓库之外，不进入版本库、前端产物、UI、API 返回或日志，错误诊断须脱敏，本文不记录秘密路径或值。首期管理页面及 API 无鉴权；“个人自用”、隐藏入口或前端页面本身不构成访问保护，公网访问者可能读取归档或修改监控；公开图片 URL 可被直接访问或外链，站点将来增加登录也不会自动保护图片。无备份和容量治理意味着损坏、误操作或存储耗尽可能导致数据丢失或服务失败，不承诺容灾或自动清理。

### 11.2 缓存与回退

| 资源类别 | 策略 |
| --- | --- |
| 页面入口 | 每次使用前重新验证，避免旧入口长期引用旧产物；可使用 `Cache-Control: no-cache` 表达该语义 |
| 带内容哈希的脚本/样式 | 长期缓存，内容变化生成新文件名；只有版本化资源才适用不可变缓存 |
| 演示图片 | 使用版本化文件名或适当缓存时长，未版本化文件不统一设置永久缓存 |
| 应用页面路径 | 回退到入口，由前端匹配全部、单 UP、详情、管理或未找到页面 |
| API 路径 | 交由后端处理，成功与错误响应均不回退到 SPA HTML |
| 缺失静态资源 | 返回资源错误，不回退到 HTML，不缓存成成功资源 |

静态资源应具有明确的资源路径规则，避免仅靠任意 URL 的文件扩展名猜测页面与资源；具体目录命名在实施时与构建产物一致。

静态 SPA 的前端未找到页面，不等同于服务器已返回 HTTP 404；下一阶段也不为此引入 SSR。服务器资源错误、API 结果和应用内无效路径展示分别验收。

### 11.3 部署验证

保留静态基线验证：直接访问和刷新有效详情、未知页面路径、缺失脚本或图片、入口与哈希资源的缓存头，以及一次构建更新后入口能获取新资源。下一阶段增加 `/ups/:upId` 和 `/manage` 的入口回退、API 路径不被 SPA 接管、OSS 浏览器直取及单 API/单采集进程部署验证。Vite 开发或预览服务器的正常表现不能替代 Nginx 回退与缓存配置检查；没有对应环境时如实记录未验证项，不把本文当成部署记录。

## 13. 风险、待验证项与后续设计

| 风险 | 约束与处理 |
| --- | --- |
| 自行维护请求协调逻辑 | 集中在模块内，以取消失效、乱序成功/失败和重复提交测试守住契约 |
| 响应式依赖过宽 | 按职责组织状态和 composables，避免让无关页面部分读取频繁变化的整份状态 |
| 库预览与应用导航不匹配 | 先验证长图、焦点、滚动、错误图片及资源请求，再扩大重写；不以官方演示代替项目实际验证 |
| 历史栈与预览交错 | 使用应用自有访问 ID 和来源关系，避免直接对 pathname 或库 key 作错误假设 |
| 长会话快照占用内存 | 共享不可变内容、只保存必要阅读状态；不声称无限历史容量，真实规模接入前测量 |
| 异步布局导致恢复偏差 | 尺寸占位、锚点定位、有限回退和用户操作优先；通过浏览器场景验证 |
| 真实数据与模拟契约有差异 | API 接入前复核字段、计数与分页语义，不让页面层直接兼容多种原始协议 |
| 公共读 OSS 图片尺寸与加载成本 | 实际缩略/预览变体及缓存留后续确定，前端原样使用 URL 不代表已解决；首期无签名续期设计 |
| 编辑信号精度与页面结构 | 分钟内多改可能漏检，持续编辑未实测；安全解析失败保留旧状态，不改为内容比对 |
| 评论计数检测边界 | 接受增删抵消和纯编辑漏检；来源失败/拒绝不归零，不承诺全部受限评论可读 |
| 观察与同步进度分离 | 持久化待处理状态与成功 checkpoint，验证重启及新旧工作交错，避免“已观察”等于“已归档” |
| SQLite 写入与同机资源 | 单采集进程、短事务、网络不占长事务；飞书扩展增加通知进程的领取/提交竞争，须新增三进程验证；实际性能待测，不承诺 2 核 2GB 容量 |
| 飞书投递与精确链接 | 外部成功响应丢失可能重复；路由缺失保留队列且不串群；业务凭据与日志隔离；定位未加载评论和飞书内置浏览器兼容须按 AC-35 新验 |

总体技术栈与单 API/单采集架构已经确认，不再列为待决选型。库版本、具体函数签名与文件划分、动态数据分页一致性的具体协议及云部署细节留后续实施规格细化；实际图片变体、格式处理、缓存及 CDN 尚未决定，不由实现者擅自选定，也不把方案确定写成开发完成。

下一阶段功能范围不含权限系统、备份和容量不足治理，不默认增加 Kafka/Redis/Celery、采集退避、自适应频率或每日全量校准；已确认的飞书投递退避是独立扩展。若需改变已确认的架构或用户可见行为，应先取得确认。

## 14. 官方依据与核验范围

下表保留原 React 设计阶段经 Context7 核对的历史依据，本次未重新核验这些 React API；它们不是 Vue Router 的 API 保证，不能直接照搬。文档核验不是实现测试，同 URL 预览导航、历史快照、刷新降级和锚点恢复均须在 Vue 目标实现中重新验证。

| [React Router：ScrollRestoration](https://reactrouter.com/api/components/ScrollRestoration) | 内建恢复默认使用 location.key 和 sessionStorage；本设计不与之叠加 |
