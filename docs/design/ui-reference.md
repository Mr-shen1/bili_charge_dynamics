# 页面视觉规范与历史参考（含监控管理）

## 1. 使用方式与范围

当前新增的目标是 [Vue 3 + Element Plus 前端重构](frontend-migration.md)，票据 12 已交付仅含 Vue 的候选产物，新版视觉签收仍待票据 14。保留整体布局方向、品牌配色、内容层级及桌面/手机阅读体验；允许重新确定尺寸、间距、字体、图标和控件外观，不再锁定旧像素值，也不再以 B站参考图一比一复刻作为新版门槛。通用组件及图片展示/预览优先采用 Element Plus，行为例外与底线以修订后的 [SRS](../product/SRS.md) FR-08/09 为准。

以下两张图来自用户 2026-10-14 提供的列表卡／详情参考。它们及第 6 节的授权量测，是旧 #35 阶段的视觉基准与本次布局/配色来源，不是 Vue 新版实现截图、测试结果或完整功能清单。原 [35：B站视觉复刻与监控管理统一改版](../../.scratch/backend-integration/issues/35-bilibili-visual-replica.md)、旧图和验收证据保留历史，不追改为本次通过。

新版基准按第 5 节建立并由用户确认；不能把参考图中的账号、正文或图片硬编码成数据，也不恢复裁剪掉的 B站功能。管理页与阅读页使用同一组件库主题和层级，不只是背景色相同。

既有行为与旧文档/测试发生差异时，用户已指定一律以当前代码逻辑为准；本次源码基线及证据见[基线差异记录](../../.scratch/frontend-vue-migration/baseline-differences.md)。Vue、组件库及明确放宽的图片/视觉规则仍按本次目标调整，不反过来锁回当前像素实现。

## 2. 列表参考

![B站动态列表的用户提供参考](../assets/ui-reference/current-35/dynamics-list.png)

采用的结构与视觉：

- 浅青色页面背景、白色内容卡片，以留白和浅色分隔表达层次。
- 顶部为可横向滑动的“全部动态 + UP 头像与昵称”选择条，青蓝色表达当前选中项。
- 卡片头部保留头像、作者昵称、时间及可用的充电标识；作者名称参考粉色样式。
- 正文与图片采用适合桌面和手机阅读的间距、字号、宽度与圆角。
- 评论气泡小图标和评论总数是进入评论区的入口，不是评论图片缩略图。

交互裁剪：

- `/` 展示全部已归档动态；选择 UP 后使用 `/ups/:upId` 查看该 UP 的归档，不启动全历史采集。
- 卡片主体点击进入 `/dynamics/:dynamicId` 顶部；完全移除原“查看详情”按钮。
- 动态评论入口进入同一动态详情并定位一级评论区；某条一级评论的楼中楼有独立路由 `/dynamics/:dynamicId/comments/:rootId`，不是把整个一级评论区移出动态详情。
- 图片点击打开图片预览；文本选择、正文展开、内部操作不能因冒泡触发卡片导航。卡片入口需要可用的键盘语义。
- 图片展示使用 `el-image`，预览优先使用原生 `el-image-viewer`；栅格或少量 CSS 负责排列。缩略图列数、展示数量、倍率、工具栏与遮罩按公开能力与新版设计确定，不复刻旧规则；移动端以左右滑动切图（首尾不相连）、双指或双击缩放当前图片，未放大时图片固定不拖动，桌面保留库原生图标工具栏与键盘；完整图片组、长图可读、手机可操作、失败处理、后退关闭及位置/焦点恢复仍须成立。
- 顶部 UP 选择项可导航，内容中的头像和昵称仍只展示，不新增个人主页跳转。
- **不显示转发图标、转发数量或任何转发操作，不保留空占位。**

## 3. 详情与评论参考

![B站动态详情及评论的用户提供参考](../assets/ui-reference/current-35/dynamic-detail.png)

采用的结构与视觉：

- 顶部作者信息，下方为动态正文与图片；评论入口及数量连接到评论区域。
- 评论标题、总数以及“最热 / 最新”切换，参考截图的信息层级、颜色与间距。
- 一级评论包含作者、时间、正文及有序图片；UP 标识按该动态作者判断。
- 宽屏回复内联预览最多 3 条，展开后按每页 10 条替换当前页；窄屏采用可用的 UP 回复预览与入口，进入独立楼中楼页。回复仍扁平呈现，对回复另一条回复的内容显示条件化“回复 X:”目标，不重复来源自带前缀，不增加无限嵌套。
- 一级评论图片可点击预览，与动态图使用相同的新版组件能力及导航恢复机制，但保持每条评论独立图片组，不扩展回复图片。
- 监控管理分为两级：`/manage` 按卡片列出 UP 身份与监控状态（不做“全部归档”式范围切换，也不汇总配置），点卡片进入 `/manage/ups/:upId`。单 UP 管理页使用统一主题下的居中主栏、身份头部、配置表单、指定目标、检查／同步状态及操作反馈；表单和通用控件优先用库，不以只换颜色作为完成。新版管理截图独立确认，不伪称 B站管理页像素复刻，也不引入后台新功能。原 UID／配置／启停／目标／删除／重读能力及真实状态保留；无鉴权风险由部署文档声明，页面不常驻风险提示。

## 4. 不因参考图而改变的行为

- 列表按发布时间倒序；评论沿用当前 SRS 中来源明确置顶优先的规则，其余“最热”按点赞数降序、发布时间降序、ID 字符串升序，不从作者身份推断置顶，也不新增热度算法。
- “最新”按发布时间倒序，回复按时间正序；动态每批 10、一级评论每批 20 仍以 cursor 追加。宽屏回复先预览最多 3 条，展开后使用实时页码、每页 10 条，不累计为 3/13/23/25；窄屏独立楼中楼使用同一页码读取。
- 时间展示沿用北京时间绝对时间规则；不因截图中的“3天前”改为相对时间。来源编辑字段只有分钟精度时，不伪造秒级编辑精度。
- 详情动态正文保持完整展示；动态列表、详情内一级评论和宽屏内联回复沿用 6 行折叠。独立楼中楼根/回复正文及窄屏 UP 回复预览直接显示文本，不扩大折叠规则；独立页当前不展示图片。
- 普通列表/动态详情的返回恢复、预览历史、焦点、局部失败重试均保留，全部与各 UP scope 隔离。独立楼中楼沿用当前无自身阅读快照的行为：重新进入或历史前进重新挂载时从第 1 页/顶部开始，返回有来源的动态详情则恢复详情状态；不在迁移中另加楼中楼历史页码记忆。
- 正文受限时不妨碍实际可读取的评论；失败、真实空内容和无权限不能混为同一状态。
- 2026-10-14 用户预览后明确取消列表及详情正文下方的整块归档信息：移除该块中的编辑时间、来源／本地评论与回复统计、正文／媒体／评论归档状态，也不增加折叠入口或替代提示。这替代此前将该信息块作为阅读页次级信息保留的布局决定；接口数据及管理检查状态不变，发布时间、正文、图片及评论入口保留，独立的页面读取错误、逐图状态和评论／回复区域不在本次删除范围。

截图中的视频、转发动态、转发按钮、评论输入框、真实点赞、关注、排行榜、推荐、勋章付费业务等不自动进入范围。允许展示充电标识，但不提供价格、购买、解锁或会员权限系统。一级评论图片明确新增，楼中楼回复图片不额外扩展。

## 5. 新版视觉与功能验收

- 以统一的 Element Plus 主题和阅读层级建立新版基准，记录颜色、字体、间距、圆角及内容宽度的实际设计选择；不以旧图像素值限制重构，也不只靠套用默认组件就宣称视觉完成。
- 提供受控内容下的列表、详情/评论/回复、独立楼中楼、图片预览、管理列表及单 UP 管理页截图，覆盖四宽度和代表性空/错状态。记录构建版本、浏览器、CSS 视口、缩放、字体和内容条件，由用户确认后用于回归；未经确认的当前实现不能自建黄金图证明通过。
- 旧图未记录的视口、DPR 或缩放仍保留证据限制，不虚构来源条件。它们只作历史设计参考，不用于直接判断新版像素通过。
- 旧字号、间距等断言按用户确认后的新版规范调整；实际超过 6 行才折叠、位置恢复、图片可达、焦点及触控等行为断言不得因换库删除。后续视觉更新需说明原因，不以自动更新截图掩盖退化。
- 按 SRS 的 360px、390px、768px、1280px 检查；UP 条可自身横向滚动，整个页面不能溢出，主要触控区域约 44px。手机长图、工具栏和图片失败状态须实际可用。
- 正式兼容范围为 Linux Chrome 与 iPhone Safari，分别记录实际版本与结果；自动化、模拟器和真机不互相替代。组件库官方演示不能代替本项目验收。
- 验证卡片、评论入口、图片、展开和文本选择之间没有误跳转；预览后退/关闭、位置与焦点恢复无二次操作，无“查看详情”按钮或转发遗留。
- 新版图片能力、全部/单 UP、评论/回复与管理操作均需回归；旧 #33/#35 及此前通过记录不自动证明新版通过，不要求先补完旧版像素签收再重构。

## 6. 历史 #35 页面量测与布局决定

本节保留 React/#35 阶段的原始量测与设计决定，不是 Vue 新版的固定尺寸、网格或像素验收要求；与当前方案不同的部分由第 1–5 节及 SRS 的修订规则替代。

来源：用户指定的 <https://t.bilibili.com/> 与 <https://www.bilibili.com/opus/1258559532414533635>；2026-10-14正常页面加载后的安全DOM／CSS量测及限制见[#35当前取材记录](../../.scratch/backend-integration/visual-35-live-reference.md)。授权Cookie只用于本次隔离、非持久浏览器查看，不进入代码／日志／运行依赖，不触发业务采集，不绕过权限；正常网页渲染自身请求与另行构造采集请求明确区分。

- 列表裁剪两侧栏后采用来源1920视口的724px阅读列上限；发布时间13／18，作者头像48，正文沿昵称列。评论气泡居中独占底行，不为裁剪的转发／点赞留空控件槽。
- 当前详情采用708主栏、桌面56内距、作者上下12与48头像、正文17／29和`#2f3238`、正文底36；正文左缘与头像对齐，而非旧图昵称列。手机内距16为本站适配。
- 评论标题采用新图独立蓝色“评论 N”tab，排序另行；详情文章不再重复气泡数量。原定位功能移至唯一tab，来源／未知数量语义保留在可访问名称。蓝tab细节是新图参考，未冒称全部来自live computed style。
- 排序13px；根评论头像40、正文15／24、时间与只读点赞13／24；回复24头像与34缩进，昵称／目标／正文自然同段落流。可见点赞为图标＋数字，不伪造点赞操作；展开／收起的可见文案简化，ARIA仍区分正文／评论／回复正文。
- 单图限宽360；动态双图采用新图驱动的同高比例框（最高268、3:4–4:3约束），未知尺寸预留4:3，框内仍contain而不裁切真实长图。这部分有截图推定，不假称所有来源图片变体均已实测。该历史阶段保留评论图片、四图两列、九图三列、最多九张＋剩余数、详情所有图片及 owner／焦点／历史机制。Vue 新版的固定网格与数量规则已由 SRS FR-08 修订替代，完整图片组、owner 隔离及焦点／历史恢复底线仍适用。
- 对照新图按48CSS px作者头像等比归一至0.5，来源截图DPR／缩放仍未知。`frontend/scripts/capture-visual-35.mjs`（在仓库根执行）默认使用ignored的`current-35/`素材，在`evidence/visual-35-current/`保存四宽度完整图与卡片区未遮罩并排／差分、原尺寸／比例／仅补白且不裁掉两侧结构的条件；自定义素材可用`UI_REFERENCE_DIR`及`UI_REFERENCE_SCALE`指定。首轮证据不覆写，不从当前实现自建黄金基准，不声明全图像素通过或真机签收。
