## 2. 用语与页面身份

业务定义见根 [GLOSSARY](../../GLOSSARY.md)。下表只规定页面身份，避免把整条动态的评论区与某条评论的楼中楼混为一页。

| 本文名称 | 展示范围与界面名称 |
| --- | --- |
| 动态列表 | 全部或单 UP 的已保存动态；首个范围按钮为“全部动态” |
| 动态详情 | 一条动态的完整内容及一级评论区；桌面浏览器标签标题为“动态详情” |
| 一级评论区 | 桌面可在列表卡片内展开，也存在于动态详情中；本次不新增独立的全动态评论列表页 |
| 回复详情 | 一个一级评论及其楼中楼回复；手机现有左上角 `‹ 评论详情` 保留 |
| 会话列表 | 一段对话的专属阅读页；入口仍叫“查看对话”，左上角只显示 `‹ 会话列表` |

文案规则：

- 应用生成的可见文案、无障碍名称、空态和错误提示不再把阅读范围叫“归档”；例如“全部归档”改为“全部动态”。管理页也纳入文案检查。
- 动作与状态按语义重写：“评论尚未归档”→“评论尚未保存”，“已有归档保留”→“已保存的动态保留”。不能把保存动作机械替换成名词“动态”。
- 原始动态/评论正文、昵称忠实显示来源，不替换用户内容中的词语。
- API 路径、数据库字段、代码标识、日志及历史技术文档不进行全局字符串改名；已保存内容也不因此变成实时 B 站查询。

## 3. 阅读导航与 UP 选择条

### 3.1 宽窄屏入口矩阵

沿用 ≤640px 的窄屏语义。360/390/768/1280px 是验证宽度，不新增 768px 业务断点。

| 操作或区域 | 手机／窄屏 | 桌面／宽屏 |
| --- | --- | --- |
| 公共“充电动态／动态／监控管理”顶栏 | 所有阅读页移除 | 所有阅读页移除 |
| 动态正文／卡片内容入口 | 当前标签进入动态详情顶部 | 新开浏览器标签页进入对应动态详情顶部 |
| 卡片评论按钮 | 当前标签进入动态详情并定位评论区，保持现有路径 | 在当前卡片下方展开／收起一级评论；列表和 URL 不跳走 |
| 正常动态详情页头 | 只保留 `‹ 动态列表`，去掉重复的“动态详情”和旧“返回列表”按钮 | 不显示“动态详情”页头或“返回列表”按钮；标签标题仍为“动态详情” |
| 阅读页的管理入口 | 不提供 | 不提供 |

基线差异：用户确认其使用环境已有桌面列表内评论；但本次检出仓库仍把卡片评论接到详情跳转，详见基线核查。因此这里是已确认的目标行为，针对当前仓库仍须实际补齐，不把用户环境、原型和仓库源码混写为同一现状。

补充约束：

- 评论按钮保持**气泡图标＋数字**，不增加“条评论”等可见后缀；无障碍名称继续说明是评论数量。来源计数、未知与零的区别不变。
- 宽屏各卡片的评论展开、排序、分页互相独立。正文新标签打开后，原列表的 scope、滚动、评论和回复状态留在原标签；新标签不依赖 opener 或原标签内存才能读取详情。
- 图片预览、正文选择、折叠展开、作者展示与内部控件继续遵守既有事件隔离规则；点击图片不能被本次“正文新标签”规则抢走。原型配图只是导航示意，不是图片行为的新规范。
- 手机 `‹ 动态列表` 有有效列表来源时返回对应 scope 并恢复位置；无来源时回全部动态。保留原生浏览器历史，不另造整屏右滑手势。
- 删除的是正常阅读页顶栏和重复标题，不删除读取失败／无效地址时的必要恢复操作。
- 管理页仍由独立 `/manage` 地址进入，可保留自己的标题与“返回阅读”入口。去掉导航不是鉴权措施。
- 原有通知精确链接仍能定位目标；普通默认排序和页头变化不能破坏直达、刷新与历史恢复。

### 3.2 头像选择条

- “全部动态”的图标与各 UP 头像统一在上，文字在下；图标／头像约 48px，文字容器与图片同宽，字号 12px、行高 18px。
- 昵称完整换行，不省略、不靠横向拉宽文字容器容纳长名字；整块均可点击，选中态保持青色。
- 单排横向滑动，隐藏滚动条；支持触屏、触控板及键盘访问，页面本身不横向溢出。头像与选中轮廓、键盘焦点轮廓应完整可见，首项左侧和顶部不得被横滑容器裁切。
- 可见昵称底部至第一张卡片约留 12px。区域随可见项所需高度调整，屏幕外长昵称不预留整排空白；滑到长昵称时仍能读全，不用裁字换取紧凑。

## 4. 评论与回复排序

统一使用单个 `☰ 按时间`／`☰ 按热度` 控件，文字表示**当前排序**；点击立即切换为另一种。图标、字号和触控规则一致。

| 区域 | 无可恢复状态时默认 | 按时间 | 按热度 |
| --- | --- | --- | --- |
| 一级评论区，包括桌面列表内评论 | 按时间 | 发布时间新到旧 | 点赞数高到低 |
| 手机回复详情 | 按时间 | 发布时间旧到新 | 点赞数高到低 |
| 会话列表 | 固定时间序，无排序控件 | 发布时间旧到新 | 不提供 |
| 桌面内联楼中楼 | 保留原时间序与分页 | 发布时间旧到新 | 本次不增加控件 |

- 一级评论的来源明确置顶在两种排序下均优先；不从 UP 身份推断置顶。热度同赞时按发布时间降序，再按 ID 字符串升序；时间排序同时间按 ID 字符串升序。缺失值后置、ID 非数值且非语言环境比较的既有规则继续适用；回复热度采用相同的确定性次级规则。
- 排序作用于完整的对应本地集合，之后再分页；不能只重排当前已显示的一页。来源计数不用于推算本地可读页数。
- 一级评论仍每批最多 20 条追加；手机回复详情与桌面展开楼中楼仍每页最多 10 条、翻页替换；桌面回复预览仍最多 3 条。
- 一级评论切换排序重置该评论区首批与相应展开状态；手机回复切换排序回到第 1 页。请求代次隔离、错误局部重试、过期响应防覆盖继续有效。
- 一级评论排序与手机回复排序独立。回到有快照的访问恢复原排序，不用默认值覆盖用户选择。
- “评论 N”用 14px，小于动态正文；“相关回复共 N 条”与右侧排序均为 13px、常规字重。

## 5. 手机“查看对话”

### 5.1 集合与入口

一段对话从某条楼中楼回复起，经真实回复关系包含其全部后代分支；同属一个一级评论并不意味着属于同一段对话。一级评论只作为所属上下文，不计入对话条数、不重复出现在会话列表。

| 已保存关系 | 按钮与结果 |
| --- | --- |
| 只有 A | 不展示“查看对话” |
| A→B | B 下展示入口，打开后显示 A、B；A 下不展示入口 |
| A→B→C，C→D 且 C→E | B/C/D/E 下均展示入口，任一入口都展示 A/B/C/D/E |
| 同一一级评论下另有独立发言 X | X 不混入上述对话 |
| 关系跨回复分页 | 仍判断、显示整段对话，不按当前页截断 |

因此门槛是**至少两条可确认关联的本地回复**，不是最初讨论的“超过三条”。入口放在对话中除起点外的每条回复下，仅手机回复详情提供；桌面暂不增加会话入口。

### 5.2 会话页与返回

- 打开独立的会话列表页，左上角仅一个 `‹ 会话列表` 返回控件，不另列 `‹ 回复详情` 或重复标题。其样式与 `‹ 评论详情`、`‹ 动态列表` 完全相同：操作色、14px/22px、常规字重，点击区域至少 44px。
- 整段对话按时间正序完整展示，不提供热度切换或分页控件；前端一次读取完整集合，不循环请求各分页。进入会话后自动把刚才点击的回复定位到视口中央，保留轻微高亮并在昵称旁显示“刚才查看”；前后文仍可自然上下滚动阅读。**定位位置夹在真实可滚动范围内，不为居中给列表补留白**：短会话与首条停在顶部、末条停在底部，入口始终完整可见且不出现空白带。定位只在新进入/直达/刷新时执行一次，不持续抢夺用户滚动；同一访问的历史位置恢复继续有效。
- 返回控件或同一次会话内浏览器返回，回到来源回复详情，恢复其**排序、页码和滚动位置**。这是本次新增的恢复能力；其他独立回复页的直达、刷新等行为继续遵循既有基线，不顺带增加持久阅读历史。
- 桌面不改用整页路由：宽屏内联楼中楼同样显示“查看对话”，以弹窗承载同一份会话视图（`ConversationView`），不离开详情页、不写地址，关闭后回到那一楼原来的阅读位置；弹窗自己滚动，入口定位同样是“夹在可滚动范围内、不补留白”，关闭时焦点归还触发按钮。手机仍是独立会话页，两种形态共用读取、标记与落点实现。
- 会话页身份至少包含动态、一级评论和目标回复，不以某一楼的当前页作为身份。直接打开、刷新、无来源返回继续沿用现有身份与导航约定；单次整段读取契约由整改票 13 同步真实 HTTP、生产/mock Adapter 与浏览器测试。原回复详情仍分页，不受会话取消分页影响。

### 5.3 不完整上下文

- 只读本地已保存数据，按真实父回复关系组织；昵称、正文里的“回复某人”和 @ 提及不能替代关系证明。
- 父回复未保存／不可用时在断点止步，展示能确认关联的部分，并提示“部分上下文暂不可用”；不把整楼其他回复兜底拼入，不伪造缺失作者或内容。
- 关系缺失与读取失败分开：前者允许阅读可用部分，后者按局部错误重试。以本地可确认条目判断入口数量，不从来源回复总数推断存在完整对话。
- 会话一次返回整段本地可确认回复，覆盖全部分支；不截成当前回复页或固定条数，不因整段读取而请求上游。缺祖先、异常环、跨根校验和局部错误重试继续有效。

## 6. 统一排版标尺

以下为第四版签收目标，单位为 CSS px。正式实现复用 Element Plus 主题与局部布局；单文件原型的 CSS、伪元素和模拟组件不是生产实现要求。

| --- | --- | --- |
| 必要页面标题 | 手机 18／26；桌面 20／28 | 600；主要用于管理页，不能据此恢复已删除的阅读标题 |
| 动态作者、管理身份昵称 | 16／24 | 600 |
| 动态正文 | 16／28 | 400 |
| 评论／回复正文 | 15／26 | 400；桌面内联回复同样可读 |
| 评论／回复昵称 | 14／22 | 600 |
| 返回、普通阅读链接 | 14／22 | 400；查看对话、展开等点击区至少 44px |
| 评论区标题 | 14／22 | 500；不抢动态正文层级 |
| 时间、计数、排序、回复数量标题 | 13／20 | 400；数字可用等宽数字排版 |
| UP 条昵称 | 12／18 | 完整换行 |
| 徽标、UP 主标识 | 12／20 | 辅助层级 |
| 管理区块标题 | 16／24 | 600；高于区块内普通说明层级 |
| 管理说明、表单标签、状态正文 | 14／22 | 400；长中文说明不再压成 13px 淡字 |
| 管理操作按钮、管理页返回链接 | 13／20（返回链接可沿用 22 行高） | 400；按钮尺寸见 §7 |
| 管理输入类控件 | 手机 16／22；桌面 14／22 | 可见外框与相邻按钮等高（桌面约 32px、手机约 36px），交互命中区域至少 44px；字号不随外框缩小 |

布局与颜色：

- 阅读和管理主栏继续居中，最大约 724px；手机单列。外侧留白、卡片、标题的左右边缘对齐。
- 卡片内边距手机约 16px、桌面约 24px；卡片间距手机 12px、桌面 16px；常用小间距采用 8/12/16/24px，管理分区可用手机 20px、桌面 24px。
- 保留浅青背景、白色卡片、青色操作与选中态、粉色作者；原型正文 `#30383d`、辅助文字 `#65727a`、操作色 `#287f8f`，避免时间和计数过浅。不要将所有文字一律缩小或加粗。
- 行高调整后重新按实际渲染行验证既有 6 行折叠；详情动态正文和独立回复正文的原有完整阅读规则保留。
- 窄屏输入字号 16px 是本轮已签收的视觉目标，不是 Safari 问题已修复的证据。优先使用公开配置／局部主题；若需覆盖库内部输入类，须补登记、自动化断言和实际 iPhone 聚焦/失焦验证，不能全局改基础字号而把按钮一并放大。

## 7. 监控管理页

- 保留两级结构：管理列表只展示 UP 身份与状态，点卡片进入单 UP 管理；启停按钮仍在单 UP 页。
- 单 UP 的监控控制行采用**状态在左、操作在右**。手机与桌面都右对齐、按钮适宽，不再在手机占满整行；长文案可换行，按钮仍靠右且不挤坏昵称。
- 启用、停止和重新添加共用同一右侧槽位；当前实现文案“启用监控”对应讨论中的“启动监控”，不另造第二个启动操作。
- 管理操作按钮文字 13px，视觉高度桌面约 32px、手机约 36px，四字按钮宽度约 76px；长按钮按文字自然增宽。实际点击区域至少 44px 高，视觉边框与可点击区域可以不同，但不能遮挡相邻控件。
- 启停、保存配置、删除配置保持分组。启停作用于已保存配置；保存只提交草稿，不隐式启停。删除维持独立危险操作区域与确认，不与日常启停混排。
- UID 新增、模式、数量、指定目标、检查/同步状态、通知开关、错误与重试等既有能力保留。原型里未完整展示的管理字段不是裁剪授权，模拟交互也不是新增业务契约。
- 同排表单标签、单选项文字、输入框和按钮应垂直居中，不因 Element Plus 默认标签行高或按钮命中盒造成文字忽高忽低。输入框与相邻按钮的可见外框等高（桌面约 32px、手机约 36px），同时保留至少 44px 的实际点击/聚焦区域、手机输入 16px 字号；窄屏换行后每行仍保持对齐，不挤坏相邻控件。
