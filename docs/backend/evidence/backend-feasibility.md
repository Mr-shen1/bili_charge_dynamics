# 后端可行性：脚本参考与只读验证记录

## 1. 记录范围与证据级别

本文件保存本轮讨论中已经完成的阅读和小样本验证，供 [FSR](../../product/FSR.md)、[SRS](../../product/SRS.md)、[HLD](../../design/HLD.md) 及后续实施规格引用。它不是上线验收报告，不证明新后端已经实现，也不包含凭据或采集到的正文、评论全文。

证据分为四类：

1. **用户经验**：两个 Python 脚本目前在线上长期稳定运行；充电图文识别逻辑已确认可用，直接沿用，不重新评估或增加筛选条件。
2. **本地源码**：静态阅读脚本能说明其实现行为，不能独立证明线上运行情况；没有执行或导入原脚本。
3. **第三方资料**：公共接口文档和响应样例用于定位字段，不是 B站官方可用性或限流保证。
4. **本轮实测**：经用户提供目标和本地凭据后，只对指定样本执行有限的只读 GET；请求结果只证明当次观察。

飞书消息发送不在分析、测试及新后端范围内。文档编写阶段没有继续发起上游请求。

## 4. 只读验证过程与请求预算

累计 **13 次 GET**：

| 阶段 | 请求 | 结果 |
| --- | --- | --- |
| 首轮小样本 | 4 次通用动态 detail、1 次 nav、1 次 feed 首屏、2 次 reply/count、2 次根评论首屏、1 次子回复首屏 | 共 11 次，均 HTTP 200、API code 0 |
| 图文 JSON 接口补查 | 1 次 `/x/polymer/web-dynamic/v1/opus/detail` | HTTP 412，无可用 API code；立即停止，没有重试或继续查普通样本 |
| 用户提供准确网页来源后 | 1 次 `https://www.bilibili.com/opus/1257029965692534788?spm_id_from=333.1365.0.0` | HTTP 200，HTML 初始化数据解析成功 |

只读进程使用本地凭据，未打印 Cookie、请求头、完整响应或评论用户信息；未执行网页 JS，未下载图片，未扫描历史，未获取全量评论，未启动轮询或压测。请求开启 TLS 验证，禁止自动重定向；没有尝试绕过 412。

验证程序使用 Python 标准库，经 `uv run --offline --no-project` 运行；未安装额外依赖，未将验证脚本、原始 HTML 或响应全文写入项目。这里记录的是本轮验证约束，不是后续生产运行的完成证明。

## 5. 编辑时间：页面数据与通用动态接口不同

### 5.1 通用动态详情观察

四条返回的动态 ID 与作者 UID 均与目标一致：

| 样本 | `major.type` | 通用 detail 的 `module_author.pub_time` | `pub_ts` |
| --- | --- | --- | --- |
| 编辑样本 `1257029965692534788` | `MAJOR_TYPE_OPUS` | `2026年10月09日 10:38` | `1791513496` |
| 普通样本 `1253304584111128595` | `MAJOR_TYPE_OPUS` | `2026年09月29日 09:41` | `1790646113` |
| 指定动态 `1220432497848877059` | `MAJOR_TYPE_BLOCKED` | `2026年07月02日 19:41` | `1782992484` |
| 指定动态 `1214018075872985176` | `MAJOR_TYPE_BLOCKED` | `2026年06月15日 12:50` | `1781499010` |

`pub_action` 均为空，未取得其他明确的编辑状态字段。近期 UP 的 feed 首屏返回 13 条，`has_more=true`；两个时间样本都在首屏，所以没有请求第二页。feed 的 `pub_ts` 是字符串，detail 是整数，规范化后值相同；feed 的显示时间分别为“3天前”和“9月29日”。

**普通显示文字会自然变化，不能将 `pub_time` 任意字符串变化都视为编辑。**

### 5.2 用户浏览器数据与页面 GET 实测

用户从浏览器开发者工具提供了上述图文页面 GET 的响应数据：作者模块包含 `pub_time = 编辑于 2026年10月09日 13:01`，而 `pub_ts` 仍为 `1791513496`。

随后同一页面的一次普通 GET 得到 `text/html; charset=utf-8`，响应 22,483 字节，单次总耗时约 253.7 ms。安全提取脚本中的 `__INITIAL_STATE__`，再用 JSON 解析器读取其 `detail`，取得相同动态 ID、作者 UID、编辑日期时间和评论总数 235。

语义定位方式：

```text
__INITIAL_STATE__.detail.id_str
__INITIAL_STATE__.detail.modules
  → module_type = MODULE_TYPE_AUTHOR
    → module_author.pub_time / pub_ts / mid
  → module_type = MODULE_TYPE_STAT
    → module_stat.comment.count
```

验证时数据恰好在某个脚本标签及数组位置，不构成固定下标契约。后续实现按初始化数据标记和 `module_type` 定位，不硬编码 `script[10]`、`modules[0]` 或 `modules[2]`，也不执行页面脚本。

### 5.3 已确认结论与限制

- 页面里的编辑时间与用户截图的 **13:01** 一致；通用动态详情显示 **10:38**，两者 `pub_ts` 相同。
- 因此不能将通用 `pub_ts` 单独作为可靠编辑版本。发布时间与编辑时间分别保存，不能因编辑改变发布时间排序。
- 用户选择通过“编辑于”标记和规范化后的日期时间判断变化，不比较正文、图片 URL 或图片字节来检测编辑。
- 第一次读取建立基线并同步；普通相对时间文案变化和空格差异不触发编辑；解析失败不覆盖已有成功状态。
- 显示字段仅到分钟，不能伪造秒级精度，同分钟连续编辑可能不可区分。
- 已验证的是一个编辑样本的一次成功页面获取；没有同一动态自然多次编辑前后的连续观测，也未验证全部目标页面都提供同样字段。
- 一次 254 ms 左右的成功不等于固定 15 秒长期轮询稳定，也不是上游允许请求频率的依据。

## 6. 评论读取与数量样本

| 样本 | 详情评论数 | `reply/count` | 根页 `page.count` / `page.acount` |
| --- | ---: | ---: | --- |
| 编辑样本 | 235 | 235 | 235 / 235 |
| 指定动态 `1220432497848877059` | 501 | 501 | 501 / 501 |
| 普通时间样本 | 287 | 未请求 | 未请求 |
| 指定动态 `1214018075872985176` | 201 | 未请求 | 未请求 |

另对编辑样本的一条根评论读取了一页子回复，该根的 `rcount=3`，子页 `page.count=3`。指定动态 1 的抽样根评论 `rcount=16`，未继续读取其子页。

已验证的结论：

- `MAJOR_TYPE_BLOCKED` 不等于所有数据不可获取。指定动态 1 正文受限，但本次评论第一页和计数请求成功。
- 页面上的“暂无权查看当前评论”不是后端跳过评论采集的充分条件；以实际评论接口结果为准。
- 两个抽样目标的详情计数与独立计数相同，但不能据此证明所有接口、权限状态和目标的计数口径都相同。
- 本轮没有全量枚举根评论和回复，不能用首屏和来源计数证明“全部评论已采齐”。

公开资料将根评论 `page.count`、`page.acount`、根条目 `rcount` 描述为不同范围的计数；参考脚本也有自己的计数处理。上述表格只记录真实返回值，不把文档说明或脚本假设当作已确认的跨接口恒等式。

来源总数与本地已归档数量必须分开保存。正式数据映射或省略独立计数请求前仍需验证；请求失败、字段缺失和明确拒绝不能当作 `0` 或成功空结果。

## 7. 图片与内容结构的验证边界

两个 OPUS 样本返回正文结构，图片数组存在但本次为空；两个 BLOCKED 样本没有取得对应正文/图片结构。未下载图片、未上传 OSS、未保存正文或评论全文。

因此，本轮不证明动态图、一级评论图的 OSS 归档已经可用，不推断受限动态原始内容，也不证明所有内容结构已覆盖。一级评论图片是用户新增的需求，仍需实现和验收；楼中楼图片不纳入本期扩展。

## 8. 后续验证清单

本轮不再自动发请求。后续验证需限定目标、次数和环境，避免把讨论或测试变成持续采集：

1. 自然发生的多次编辑后，页面编辑时间是否变化；不同目标是否都能解析时间模块。
2. 根评论、回复计数与来源总数的映射，部分采集、关闭或失败时的状态表达。
3. 有序动态图和一级评论图片的下载、上传、失败恢复及浏览器预览。
4. 两种模式、同目标跳过、失败不推进成功检查点、停止监控但保留归档的确定性测试。
5. 当前实际规模下的持续运行、检查成功率及资源使用；不以本轮单次耗时作性能承诺。
6. 新前端的多 UP、管理页、卡片入口和评论图回归；本次接口验证不是 UI 验收。
