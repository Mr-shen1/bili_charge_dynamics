# 近期目标发现与窗口生命周期（票据 27 / 28）

## 边界与顺序

近期模式沿用原 `is_charge` 的两条 OR 规则：`modules.module_author.icon_badge.text == "充电专属"`，或 `modules.module_dynamic.major.type == "MAJOR_TYPE_BLOCKED"`。不增加正文关键词、图片存在、OPUS/DRAW 类型等条件；规则来源与虚构协议输入见[来源证据](../evidence/source-protocol-evidence.md#27-近期-feed-发现)。发现候选不表示已取得正文，更不表示归档完成。

通过 `/x/polymer/web-dynamic/v1/feed/space`，从首屏沿返回的 `offset` 读取。按 feed 来源顺序保留首次出现的合格字符串 ID；不合格或重复候选不占 N。凑满 N 立即停止，不继续回填历史；不足 N 时只有严格有效的 `has_more=false/0` 才表示耗尽。原通知流程的数字 ID 升序是后续处理次序，不是近期窗口截断算法；本票不新增 ID 或时间排序。来源可能包含置顶，结果保持来源次序，不宣称为发布时间排序或事务快照；源在分页期间移动可能漏项，真实一致性另需证据。

feed 与 UP 空间预热同受[跨进程风控暂停](collector-api.md#跨进程风控暂停03)约束：任一 HTTP 412／429 触发全局暂停后，发现不再领取也不再发送；被暂停打断的发现不登记「发现失败」，保留在途领取由重启恢复，错过的槽不补发，恢复节奏由 04／05 落地。缺失/无效字段、业务拒绝、HTTP/JSON/网络失败、需要翻页但缺少 items/offset、重复或循环 offset 均失败，不当作耗尽。允许不同 offset 下的重复页/候选，去重后继续读取；没有未经确认的页数、UP 数或 100 目标截断。成功空集合与首次失败无可信结果不同。`exhausted=false` 表示已到 N 而不再扫描，不保证历史是否还有合格项。

## 只读管理 HTTP

`GET /api/manage/ups/{uid}/discovery` 返回下列字段。未知身份 `404 NOT_FOUND`，非法 UID、未知或重复查询参数 `422 INVALID_INPUT`。不接受查询参数，不发上游请求；删配置后的持久身份仍可读取历史结果。

| 字段 | 含义 |
| --- | --- |
| `uid` | 字符串 UP ID |
| `mode / recent_n / enabled` | 当前配置；删配置后 mode/N 为 null、enabled=false |
| `active` | 当前启用且为 recent；指定模式不进行发现 |
| `status` | `undiscovered` 未发现、`running` 本轮进行中、`discovered` 本轮发现成功、`failed` 本轮未完整完成；均不是归档状态 |
| `attempt` | 未开始为 null；否则 `{recent_n, started_at, finished_at, ids, error}`，保存本轮累计候选和错误，失败时也可有部分候选；running 的 finished_at=null |
| `trusted_result` | 尚无完整成功结果为 null；否则 `{recent_n, ids, exhausted, discovered_at}`。仅整轮成功可替换，并在同一提交中发布为近期窗口。进行中或失败的部分结果不会覆盖此值；ids=[] 且 exhausted=true 可表示可信成功空 |
| `current_ids` | 当前启用且为 recent 时取已发布可信窗口的字符串 ID；尚无可信窗口、停用、指定模式或删配置时为 []。它不是指定关联，也不是成功归档集合 |
| `retryable` | 当前 active，且非 running，本轮失败/未发现或旧成功 N 与配置不同；下一固定节拍可以重试。成功状态也继续按节拍刷新，这个字段不是调度开关 |
| `incomplete` | 本轮未成功、无可信结果或旧成功 N 与当前不同。与 `active` 一起解释；discovered 只表示发现完成，内容仍未归档 |

时间使用 UTC、带时区 ISO 字符串。`attempt.error` 为 null 或固定脱敏码：`SOURCE_UNAVAILABLE`（请求/HTTP/业务拒绝）、`SIGNAL_INVALID`（JSON/响应包/候选字段无效）、`PAGINATION_INVALID`（分页不完整/循环）、`DISCOVERY_STOPPED`（在途配置改变）、`DISCOVERY_INTERRUPTED`（采集进程重开恢复中断）。不保存或回显来源 message、offset、请求参数、异常原文和凭据；仅持久字符串 ID 及固定状态。

## 调度、持久化与停止

独立采集进程在原固定节拍（生产默认 2.7 秒 ±10%）中增加按 UP 的发现阶段；默认最多 2 个同时发现，按 UID 轮转，不与指定目标的 4 个检查或 4 个归档执行共用名额。上一轮该 UP 未结束即跳过，无积压/退避。慢发现不会等待其他检查或 HTTP 归档读取完成；不承诺任意负载下所有 UP 每个节拍都能发现完成。API 不含定时器，也不提供浏览器触发发现/归档的写接口。

公开 `Collector.discover_once(uid)` 用当前启用 recent 配置尝试一次；停用、指定模式、删配置或同 UP 忙时不开始。每次新分页请求前复核领取与配置；配置改变在同一短事务内使旧令牌失效，已有 I/O 可返回但不得再翻页、更新进度或发布旧结果。失败留待后续固定节拍从首屏重试。只在取得采集进程锁后将残留 running 恢复为 failed/`DISCOVERY_INTERRUPTED`；API 重开不擅自恢复在途任务。`--once` 一次登记指定检查及近期发现，不执行归档，不恢复中断领取。

schema v12 新增按持久身份关联的发现尝试、可信结果及内部领取令牌（令牌不经 HTTP 返回）。v0–v11 原子迁移，保留旧配置、检查、正文、评论、回复、媒体与 cursor；未来版本拒绝。删监控不 cascade 发现历史；网络读取不占 SQLite 长事务。SQLite 操作不可用时沿用采集进程的固定安全错误退出，未实现数据库故障的自动自愈；恢复存储后重启采集进程，再恢复残留 running。28 直接将 v12 的 `trusted_result` 作为持久已发布窗口，不重复保存 ID、不新增 schema；已有 v12 可信结果在升级后也按当前启用模式参与选择。指定 `targets` 仍只保存手工关联，不混入近期 ID。

## 28 发布、配置与归档生命周期

- 只有整轮发现成功并通过当前领取令牌、启用、模式与 N 核验，才能原子替换窗口。部分进度、失败、旧配置的迟到响应均不发布；可信成功空才会移出全部近期目标。
- N 改动不截断或清空旧可信窗口；新 N 发现完成前继续检查旧窗口，失败也保留它。`recent_n` 表示期望配置，`trusted_result.recent_n` 表示当前发布窗口依据，`incomplete=true` 明确新配置发现尚未完成。N 缩小也要等成功结果发布，不能把配置保存当作已扫描。
- 停用、切换指定模式、删除配置立即阻止新的近期检查/领取；在途检查提交前再次核验入选资格。在途已领取同步沿用既有完成规则，归档和未完成工作保留；更细的在途分项收口由 #29 验证。指定模式只选当前关联 ID。
- 再启用 recent、切回 recent 或重建 recent 配置时，保留的最后可信窗口可重新参与选择，随后按固定节拍刷新；旧发现令牌不会因此复活。历史窗口的 N 与新配置不同时仍显示未完成，直到新的可信发布。
- 新成员由后续固定检查调用既有 `record_check` 登记首次工作，再由独立 `execute_pending` / `sync_target` 完成正文、根回复及动态图/评论图；没有编辑标记也初始化实际可读内容。发现本身不做耗时归档，不额外发起一套同步实现。显式 `/api/sync/initial` 同样只选当前启用模式的入选集合，不扫描历史。
- 重复发布不重置检查、revision、checkpoint 或成功内容；移出只改变入选资格，不删除身份、归档、评论、回复、媒体或 pending。重新纳入恢复原未完成工作，已成功部分不删除重建。API/数据库重开不改变窗口或工作状态；仅持锁采集进程恢复中断领取。
- `/manage` 提供手动“读取发现状态／重新读取发现状态”，分别展示已保存 N/模式、本轮部分候选/错误、最后可信结果及当前启用近期目标；不自动轮询、不触发上游。检查面板继续展示当前与保留历史目标的实际归档分项。发现就绪不代表内容归档成功。

## 证据限制

测试仅使用结构保持的虚构 JSON、受控外部时钟/传输、真实 SQLite 和 HTTP。该阶段自动化为匿名来源证据；后续允许通过[服务端私有 Cookie 文件](../../../backend/README.md#可选-b站登录-cookie仅服务端)显式配置登录态，但不增加 WBI、解锁或风控绕过，匿名或登录态请求被拒绝都如实失败。Cookie 增补尚未做本地/真实验证，不改变本节历史证据边界。原脚本使用 WBI，但本票不运行/导入其通知主循环，也不依赖 ignored 文件。有限历史首屏和静态协议不足以证明真实多页、当前匿名可用性或长期稳定；这些仍由 #34 限定授权验证。
