# 固定节拍采集与检查状态（票据 23）

## 运行边界

单独 Python 进程从同一 SQLite 中选取 `enabled=true`、`mode=specified` 的关联目标。API 不启动调度器；浏览器阅读、管理读取不触发同步。启动时为第一个节拍，此后按单调时钟固定每 15 秒触发；不是任务完成后再等 15 秒。同目标检查忙时跳过，不叠加、补发或排队。默认最多 4 个同时检查，容量不足的目标跳过当前槽，轮转选择防止长期偏向头部；不承诺每目标在所有负载下都能完成每个节拍。进程停顿错过的槽不追赶。

检查只读取普通 opus HTML 并复用安全初始化 JSON/AUTHOR 解析，登记可信信号与待处理。无编辑标记仍登记初始化；无效编辑信号保存失败与其他可读信号，不清除旧可信版本。网络失败不覆盖旧观察或归档。评论计数只保存观察，本票不按计数变化登记评论工作。

同进程另有一个有限串行执行阶段，每个节拍在空闲时遍历已持久登记的 pending，逐目标重新核验配置并领取；复用 #02 单目标归档能力（正文、根评论、回复、媒体）。慢同步不禁止任何目标的新检查。失败留待下次固定节拍，不即时无限重试。成功必须同时满足实际文本版本匹配领取观察、归档全部 work 成功及根评论媒体成功；未配置 OSS 时有图目标仍待处理。检查 HTTP 同时公开归档分项 `parts` 与实际 `synced_version`；详细最近尝试及 checkpoint 仍从归档 API 读取，检查成功不冒充同步成功。

目标状态 revision 仅在首次登记或可信编辑版本改变时增加。同步期间新观察仍持久登记，旧执行不能清除较新 revision。#24 仍负责完整编辑分项触发/版本流程及管理 UI；本票没有近期发现、计数触发策略、每日校准、退避、自适应频率或无限并发。

## 状态 HTTP

`GET /api/manage/ups/{uid}/checks` → `200 {"checks":[Check,...]}`。未知身份 `404 NOT_FOUND`；不接受查询参数，非法或重复参数 `422 INVALID_INPUT`。只读 SQLite，无上游请求。ID 按 BINARY 字符串排序。

| 字段 | 含义 |
| --- | --- |
| `id` / `active` | 动态字符串 ID / 当前是否启用且入选指定集合 |
| `check_status` | `unchecked` 未检查；`checked` 首次/新可信版本；`unchanged` 未登记新版本；`failed` 来源或编辑信号失败 |
| `last_checked_at` | 最近一次检查完成时间；未检查为 null，不是配置保存时间 |
| `observed` | 最近可读信号：作者、发布时间、编辑信号/版本、来源评论数；未知缺失不替代旧可信值，不含正文或图片 |
| `revision` | 持久观察代次，未检查为 0；不以计数、正文差异或相对时间触发 |
| `work` | `pending` 待处理；`running` 正在执行；`complete` 已完成对应观察工作。未检查的 pending 仅表示尚无初始化，不可领取直到登记检查 |
| `parts` / `synced_version` | 实际归档的正文、动态图、评论、回复及评论媒体状态 / 正文成功版本；部分成功可直接区分。当前待处理版本不同于成功版本时，旧分项成功不冒充新版本完成 |
| `last_succeeded_at` | 对应观察的实际整轮归档成功时间；检查、建立已有归档基线均不补此时间 |
| `check_error` | null、`SOURCE_UNAVAILABLE` 或 `SIGNAL_INVALID`；不回显来源原文 |
| `sync_error` | null 或固定脱敏错误，通常 `SYNC_INCOMPLETE`；成功检查不会清除同步错误 |

`unchanged` 不表示全部信号已知或同步成功，必须独立读取 work/错误/分项归档。`observed.edit_status` 表示最近信号可用性，旧可信 `observed_version` 可在 unknown/error 时保留。归档自身的 observed/synced 表示执行阶段处理过的版本；最新检查观察以 checks 为准，待执行时两者可以不同。

管理 UP 的现有 `monitor.last_checked_at`、`last_succeeded_at` 分别为该 UP 持久目标记录的最大检查时间、最大实际成功时间，包含已移除历史；不表示该 UP 所有目标均已成功。时间为带时区 ISO（运行时 UTC）；来源发布时间和分钟编辑时间继续保留 `+08:00` 与原精度。

## 持久与停止

schema v10 新增检查、可信 observed、revision、work、独立错误和时间；v0–v9 短事务迁移，保留旧配置/归档，未来版本拒绝。已有归档未检查时读取其旧可信信号，首次登记将其作为保存基线；来源失败/未知不令旧版本从新状态接口消失，也不制造检查/成功时间。网络/媒体 I/O 不持有 SQLite 事务。

Linux/Unix 上使用同一数据库规范路径旁的 `.collector.lock` 文件与内核 flock，只运行一个采集进程；不能删除运行中的锁文件，不能用硬链接别名或多主机共享文件规避锁。退出/崩溃自动释放内核锁，文件可留存。采集运行入口取得锁后将中断 `running` 恢复为 pending；API 启动不恢复、不领取。`--once` 只检查登记，不执行归档或恢复执行工作。

停用、切换到 recent、移除目标或删监控配置阻止新检查与新领取；已领取工作允许结束，未完成信息和归档保留。检查返回时再次核验关联，停止后的旧检查结果不写入。重新纳入可继续 pending。

启动、停止和无真实来源演示见 [后端 README](../../../backend/README.md#23-独立采集进程)。本票只有受控节拍/虚构来源与实际本地进程证据，不能证明真实上游长期稳定性。
