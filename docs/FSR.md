# UP 主动态与评论查看页面：可行性分析报告（FSR）

- 状态：需求与方案已由用户确认，可作为后续实施规划的依据。
- 本期目标：完成可交互的前端页面展示，不实施真实数据采集、存储或服务端功能。
- 部署目标：后续部署至阿里云 2 核 2GB 云服务器；图片由用户自有阿里云 OSS 直接交付。
- 文档边界：本报告记录可行性、范围、方案及验收标准，不表示页面已实现、部署已完成或容量已验证。

## 1. 结论

**本期方案可行。** 使用 React + TypeScript + Vite 构建静态前端，配合模拟数据即可实现动态浏览、评论阅读、图片预览和移动端适配，不依赖爬虫、数据库或后端上线。

后续由 Nginx 提供静态前端产物，无需为页面展示运行常驻 Node.js 应用或 SSR 服务。构建在本地或 CI 执行，降低目标服务器的运行与构建资源压力。2 核 2GB 可作为本期部署目标，但未进行压测，不承诺具体并发数、响应时间或未来全链路容量。

未来图片上传到用户自有 OSS，后端只返回图片 URL，浏览器直接请求 OSS。云服务器不承担业务图片存储和图片流量转发。图片体验仍受图片体积、OSS 访问速度、用户网络和缓存策略影响，不能仅凭服务器配置或使用 OSS 就保证性能。

## 2. 使用场景与领域边界

### 2.1 用户与核心流程

面向个人自用，只展示一个固定 UP 主。核心流程为：

1. 按时间浏览动态列表。
2. 进入某条动态详情，阅读完整正文和图片。
3. 阅读评论，切换排序，展开楼中楼回复。
4. 返回列表，继续原来的浏览位置。

界面参考 B站动态及评论的信息层级与交互习惯，采用简化布局，不做像素级复刻，也不引入无关推荐和导航。

### 2.2 “充电”不属于本系统的业务规则

后续上游爬虫获取的内容在 B站属于充电图文动态，但进入本系统后统一视为普通的**动态**。

- 页面与数据读取接口使用“动态”这一概念。
- 不增加充电专属标识、价格、购买入口、解锁流程或充电会员体系。
- 不根据“是否充电”进行逐条内容权限判断。
- 本期内容类型限于图文，不包含视频或转发动态。

内容的合法获取和未来站点访问保护是独立的数据接入与部署约束，不转化为本期的充电业务功能。

## 3. 本期功能范围

| 模块 | 已确认的行为 |
| --- | --- |
| 动态列表 | 展示头像、昵称、发布时间、正文、图片及评论数；按发布时间倒序；正文展开/收起；通过“加载更多”分批展示 |
| 动态详情 | 展示完整正文、图片和评论；点击列表中的详情入口或评论按钮进入；支持通过详情 URL 直接访问 |
| 评论 | 展示头像、昵称、时间、文字、emoji 和点赞数；为 UP 主本人添加标识 |
| 评论排序 | 支持“最热 / 最新”，默认最热；本期以点赞数模拟最热，不声称复现 B站热度算法；最新按发布时间倒序 |
| 楼中楼 | 一级评论下先显示少量回复，支持展开更多；回复以扁平列表展示，通过“回复 @某人”表达关系，不做无限嵌套 |
| 图片预览 | 点击放大、上一张/下一张、关闭；手机左右滑动切图；桌面键盘切换和 `Esc` 关闭 |
| 浏览恢复 | 从详情返回列表时恢复已加载的动态和滚动位置，避免退回列表顶部或丢失已加载内容 |
| 展示状态 | 加载中、空列表、无评论、图片加载失败、数据加载失败及重试 |

评论与动态均分批展示，不采用无限滚动。排序切换应作用于对应的模拟数据集合，而不只是当前已渲染的一批。

### 3.1 明确不做

- B站接口调用、爬虫、数据库、真实后端 API。
- 账号系统、多用户权限和真实数据鉴权功能。
- UP 主搜索、添加或切换；动态搜索、复杂筛选和统计分析。
- 视频、转发动态、评论图片和复杂表情包。
- 真实点赞、发布评论、转发等写操作。
- 图片下载、原生 App 式双指缩放等高级图片操作。
- 深色模式、主题设置和离线功能。
- OSS 上传、存储桶配置、图片处理服务配置及云服务器实际部署。
- 大型性能压测、付费服务采购和未验证的容量承诺。

## 4. 数据与图片方案

### 4.1 本期模拟数据

使用虚构的 UP 主身份、动态和评论，演示图片由项目自身提供并确保可合法使用。不复制真实充电内容，不依赖 B站图片外链。

模拟样例覆盖长正文、长昵称、单图和多图、大量评论、楼中楼、UP 主回复及各类空态、失败态。失败态和重试应可通过确定性的模拟机制复现，而非依赖随机故障。

### 4.2 数据读取边界

展示组件通过统一的数据读取接口获取动态列表、动态详情、评论和回复。本期由模拟实现提供数据，后续替换为后端 API 实现。

接口设计建议遵守以下边界；具体类型和函数签名留到实施阶段确定：

- 动态、评论和回复具有稳定标识；保留 UP 主标识，不据此增加多 UP 主界面。
- 分批读取结果能表达“还有更多”或“已加载完毕”。
- 排序、加载和失败状态与页面渲染分离，便于替换数据来源及测试。
- 组件接收图片 URL，不自行拼接 B站地址、本地目录或 OSS 存储桶地址。
- 为展示所需的缩略图与预览图 URL 保留表达能力；本期可使用项目内不同尺寸的图片。
- 正文与评论按文本安全渲染，避免把外部数据作为未经处理的 HTML 注入页面。

以上是前端替换点，不是数据库设计或最终后端协议；本期不提前选定爬虫语言、数据库和后端框架。

### 4.3 后续 OSS 图片交付

```text
后续采集/入库流程 ──上传图片──> 用户自有阿里云 OSS
后端 API ──返回动态、评论及 OSS 图片 URL──> 浏览器
浏览器 ──通过图片 URL 直接请求──> OSS
```

- 图片不经应用服务器代理或转发，图片存储与交付负载同应用服务分开评估。
- 前端对列表图片采用懒加载，进入图片预览时按需加载预览图或原图。
- 懒加载只推迟请求，不减少已请求文件的体积；OSS URL 也不意味着自动压缩。
- 缩略图可以由独立文件或后续配置的 OSS 图片处理提供，本期不实施该配置。
- 真实接入时再确定缓存、图片尺寸和格式策略；本期保留加载失败提示。
- 公开读或私有桶签名 URL 暂不决定。若采用签名 URL，接入阶段需设计过期后的地址刷新，不能只反复重试已过期的 URL。
- OSS 权限、费用以及是否增加 CDN，属于后续部署决策，不是本期依赖。

## 5. 技术方案与取舍

### 5.1 已确认选型

| 层次 | 方案 | 选择理由 |
| --- | --- | --- |
| 页面 | React + TypeScript | 支持组件化交互和明确的数据类型边界 |
| 构建 | Vite | 生成可静态部署的产物，开发与生产运行分离 |
| 路由 | React Router | 组织列表、详情和直接访问地址 |
| 样式 | 轻量、自定义响应式样式，不引入大型全站 UI 框架 | 当前页面数量少，重点是贴合动态与评论结构 |
| 数据 | 统一读取接口 + 本地模拟实现 | 本期独立验收，未来替换为后端 API |
| 托管 | Nginx 静态托管 | 无需常驻 Node.js 应用或 SSR 服务 |
| 工具约束 | 使用 nvm 管理 Node.js，使用 pnpm 管理依赖与运行脚本 | 遵循仓库约定；具体版本实施时固定 |

### 5.2 未采用的方案

| 方案 | 本期不采用的原因 |
| --- | --- |
| 纯静态效果图或无交互 HTML | 无法验证图片预览、评论展开、排序及返回恢复等核心流程 |
| SSR 或全栈前端服务 | 当前无搜索引擎收录需求，也无必须服务端渲染的功能，增加运行与部署成本 |
| 同步实现爬虫、数据库和后端 | 超出本期边界，会把页面验收绑定到数据获取与服务端风险 |
| 大型 UI 框架 | 当前主要是少量定制内容组件，没有足够收益支持额外依赖与样式适配成本 |

### 5.3 实施注意事项

- 手机使用单列列表与独立详情页，避免用多层弹窗承载正文及评论；图片预览可使用覆盖层。
- 列表恢复需要同时保留列表数据与滚动位置，不能假设路由库会自动保留所有组件状态。
- 手机滑动切图与页面滚动、预览关闭之间应避免手势冲突。
- 部署时为 SPA 页面路由配置入口回退，确保直接访问或刷新详情页可用；缺失的静态资源应返回资源错误，而非被回退为 HTML。

## 6. 资源、经济与运行可行性

### 6.1 本期资源判断

生产环境只需提供前端静态文件，不在目标服务器执行日常构建，不部署 SSR、数据库或爬虫。该架构避免了不必要的常驻应用进程，适合以 2 核 2GB 主机作为起点。

未实施页面、未对目标环境测试，因此不提供内存占用、并发用户数或加载时间的虚构指标。资源验证应覆盖实际构建产物、演示图片、带宽和缓存配置。

### 6.2 后续同机运行风险

若后续爬虫、数据库和后端也部署在该主机上，需要独立评估内存、CPU、磁盘、数据库连接和采集任务峰值。图片由 OSS 承担并不消除这些资源竞争；本期结论不外推为全链路可行性保证。

### 6.3 成本边界

本期不依赖新购付费服务，主要成本是前端开发、测试和后续静态托管。未来除云服务器外，还可能产生 OSS 存储、请求、流量和图片处理费用；金额取决于图片规模与访问模式，本报告不进行缺少用量依据的报价。

## 7. 验收标准

所有条目均属于本期验收，无法在真实设备执行的检查应标明验证方式和限制，不将桌面模拟器结果写成真机结论。

| 编号 | 验收条件 |
| --- | --- |
| A1 核心流程 | 可以从列表进入详情、阅读正文和评论，再返回原列表位置；已加载的列表内容不丢失 |
| A2 列表行为 | 时间倒序、正文展开/收起、分批加载和加载结束状态符合预期 |
| A3 评论行为 | 最热/最新排序有效，楼中楼能展开更多，UP 主和回复目标可辨识；分批加载不重复或遗漏模拟数据 |
| A4 图片行为 | 可打开、关闭并前后切图；手机滑动切图可用；桌面键盘切图与 `Esc` 关闭可用；失败图片有可理解的提示 |
| A5 状态覆盖 | 加载中、空列表、无评论、数据失败与重试可复现；长正文、多图、多评论和楼中楼样例正常展示 |
| A6 响应式 | 检查 360px、390px、768px、1280px 宽度，无横向溢出；长昵称、长正文和图片不撑坏布局 |
| A7 可操作性 | 主要触控按钮提供约 44px 的点击区域；桌面支持基本键盘操作及可辨识的焦点；图片预览关闭后可继续操作原页面 |
| A8 浏览器 | 本期仅验收 Linux Chrome 与 iPhone Safari；记录实际测试版本及设备，不承诺其他设备/浏览器、老旧版本或 B站 App 内置浏览器兼容 |
| A9 路由与构建 | 可以生成静态产物；在符合部署说明的服务器上直接访问或刷新详情地址正常，缺失静态资源不返回页面 HTML |
| A10 自动化测试 | 覆盖“进入详情 → 看图 → 评论排序 → 展开回复 → 返回恢复列表”的关键交互，并覆盖数据失败与重试；移动端布局另行检查 |
| A11 范围一致性 | 页面无充电专属业务处理，不发起真实 B站请求、不依赖数据库或真实后端，展示素材符合本报告的数据约定 |

测试工具与具体用例组织方式在实施阶段选择，不以测试覆盖率数字替代上述用户可观察行为。

2026-10-12 用户明确确认仅使用 Linux Chrome 与 iPhone Safari，本期正式兼容验收范围据此收窄。其他设备/浏览器不再是本期待办，也不因此被视为通过；其他功能、四种响应式宽度及可操作性要求不变。

## 8. 主要风险与应对

| 风险 | 影响 | 应对与验证时点 |
| --- | --- | --- |
| 模拟数据过于理想化 | 真实长内容或大量回复接入后布局失效 | 本期使用边界样例并按第 7 节验收 |
| 列表状态恢复不完整 | 用户每次返回都需重新定位 | 显式维护已加载数据与位置，纳入核心流程测试 |
| 移动端图片手势冲突 | 切图、滚动和关闭难以操作 | 本期检查手机布局及手势；真实设备限制如实记录 |
| 图片过大或缓存不合理 | 即使使用 OSS，流量与等待时间仍偏高 | 本期按需加载；真实接入时确定缩略图和缓存策略 |
| 签名 URL 过期 | 私有图片在长时间浏览后不可用 | 若采用签名 URL，在接入阶段实现地址刷新 |
| 私有内容被当作公开静态资源发布 | 内容可被未授权者直接获取 | 本期仅放模拟内容；真实接入前决定站点及 OSS 访问策略，前端隐藏不能代替授权 |
| 深链接回退配置错误 | 刷新详情失败或资源请求返回 HTML | 部署说明区分路由与资源，并进行构建后验证 |
| 后续服务争抢 2GB 内存 | 应用或采集任务不稳定 | 真实后端、数据库及爬虫接入前另做资源评估 |

## 10. 后续决策门槛

以下事项有意延后，不阻塞本期页面开发：

1. **真实数据接入前**：确定合法的数据获取方式、后端 API、数据库和爬虫方案；确认真实数据字段与前端读取接口的映射。
2. **真实内容部署前**：确定站点访问保护和 OSS 权限策略；若使用签名 URL，确定有效期与刷新流程。该保护不依赖充电业务概念。
3. **图片规模确定后**：确定缩略图生成、格式、缓存、OSS 费用预算及是否需要 CDN。
4. **服务同机运行前**：评估爬虫、数据库、后端在 2 核 2GB 环境中的资源竞争，必要时限制作业并发或调整部署。
