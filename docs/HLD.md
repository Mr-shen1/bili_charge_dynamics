# UP 主动态与评论查看页面：总体设计（HLD）

- 状态：总体设计经用户确认，作为后续实施规格与任务拆分的依据。
- 依据：[FSR](FSR.md) 与 [SRS](SRS.md)。产品行为及验收条件以 SRS 为准，本文说明实现这些行为的架构与协作方式。
- 当前仅完成设计，不代表依赖已安装、页面已实现、浏览器行为已实测或容量已验证。
- 本期范围：单个固定 UP 主、模拟数据驱动的图文动态与评论查看页面；无充电专属业务、真实后端、数据库和爬虫。

## 1. 架构概览

### 1.1 技术与运行方式

采用单个前端工程，不建立多包仓库。使用 React + TypeScript + Vite + React Router；声明式浏览器路由承载列表和详情。状态采用 Context + reducer，样式采用 CSS Modules + CSS 变量，测试采用 Vitest、React Testing Library 和 Playwright。

运行分为三个环境：

| 环境 | 职责 |
| --- | --- |
| 开发与测试 | 页面开发、模拟数据装配、可控故障、自动化及浏览器验证 |
| 构建 | 本地或 CI 生成静态产物，不占用生产服务器执行日常构建 |
| 生产静态托管 | Nginx 提供入口、脚本、样式及本期演示素材；无需常驻 Node.js 应用或 SSR |

后续图片存储在用户自有阿里云 OSS，后端只返回图片 URL，浏览器直接加载；应用服务器不承担图片代理与流量转发。

```text
浏览器中的前端应用
  ├─ 应用导航与会话状态
  │    ├─ 动态浏览模块：列表、详情、正文阅读
  │    ├─ 评论阅读模块：排序、分页、楼中楼
  │    └─ 图片预览模块：切图、长图、手势、关闭
  │
  ├─ 统一数据读取接口
  │    ├─ 本期：正常模拟 Adapter
  │    ├─ 开发/测试：可控故障与延迟 Adapter
  │    └─ 后续：真实 API Adapter（本期不实现）
  │
  └─ 图片 URL ──直接请求──> 本期静态素材 / 后续 OSS

本地或 CI ──构建产物──> Nginx ──静态文件──> 浏览器
```

### 1.2 关键取舍

| 决定 | 收益 | 代价或限制 |
| --- | --- | --- |
| 单工程、按职责组织模块 | 满足当前规模，减少跨包维护 | 不预先建设可独立发布的通用组件库 |
| React 原生状态机制 | 避免 Redux、Zustand、TanStack Query 等额外依赖 | 请求去重、竞态与阅读快照需自行集中实现和测试 |
| 异步接口 + 本地模拟 | 独立验收页面，无需模拟 HTTP 服务 | 本期不验证真实 HTTP、跨域、鉴权或 API 协议 |
| 每次访问独立阅读快照 | 准确恢复同一动态的不同历史访问 | 内存及导航逻辑比按动态 ID 单份保存更复杂 |
| 自定义锚点恢复 | 更适合多图、长正文和响应式布局 | 必须处理布局就绪、图片尺寸与回退定位 |
| 轻量自定义样式 | 贴合动态与评论结构 | 基础按钮、状态提示和弹层样式需自行维护 |

具体依赖版本在工程初始化时核对兼容性并固定，通过 nvm 管理 Node.js、pnpm 管理依赖与脚本。本文不把文档选型当作已安装版本。

## 2. 模块职责与协作

模块是具有公开接口和内部实现的职责单元，不等同于一个 React 组件或一个文件。复杂行为应收敛在模块内部，页面通过少量公开操作使用它，而非直接改写内部状态。

| 模块 | 公开能力 | 内部负责 | 不负责 |
| --- | --- | --- | --- |
| 应用导航 | 打开详情、返回列表、打开/关闭预览、接收历史导航 | 路由匹配、访问标识、入口意图、历史有效性判断、恢复调度 | 业务排序、图片下载 |
| 会话状态 | 读取当前访问状态、提交领域操作、保存/恢复阅读快照 | 内容引用、访问快照、预览会话、请求状态的归属 | 浏览器存储持久化、HTTP 协议 |
| 动态浏览 | 展示列表/详情、追加动态、展开正文、发出导航意图 | 该页面的读取状态、文本阅读和列表展示 | 操作原始模拟文件、直接改写历史栈 |
| 评论阅读 | 选择排序、追加评论、展开/收起回复、局部重试 | 评论状态转换、请求代次、分页进度和回复显示范围 | 改变动态正文、导航离站 |
| 图片预览 | 展示图片、前后切换、切换长图模式、请求关闭 | 图片加载状态、手势、焦点与滚动锁定 | 拼接 OSS 参数、独立操作历史栈 |
| 数据读取 | 读取动态列表、详情、一级评论及回复 | 数据规范化、排序/分页契约、读取结果语义 | 页面展开、滚动位置和路由恢复 |

依赖约束：

- 展示模块依赖读取接口，由应用装配具体 Adapter；正常模拟和可控测试实现使该替换点在本期即可验证。
- 导航模块统一管理历史操作；图片预览和动态页面只发出意图，不分别调用底层 History API。
- reducer 描述纯状态转换；请求、取消、DOM 测量和导航副作用由相应协调逻辑执行，不放进 reducer。
- 日期、计数等确定性工具按实际复用需要共享；不建立只做一层转发的大量空模块。
- 模块的具体文件布局、组件拆分及函数名称由实施规格细化，不改变本文职责分配。

## 3. 数据表示与读取接口

### 3.1 统一展示模型

实体字段语义沿用 SRS 的 DR-01，仅补充以下内部表示约定：

- 动态、用户、评论、回复 ID 使用字符串，不将来源大整数先转为 JavaScript 数字；身份比较使用 ID，不使用昵称。
- 有效时间在读取 Adapter 中统一为明确时区的 ISO 8601 时间表示；缺失或无效时间为 `null`。来源未说明时区时不能由各页面自行猜测。
- 有效计数保留为非负整数，缺失或无效值为 `null`；显示兜底由 SRS 的 FR-12 决定，不在数据层伪造零值。
- 正文按文本表达；昵称、时间、图片及回复目标等必要字段在 Adapter 中统一检查，保留可展示的缺失状态。
- 数据检查只服务于安全展示和接口契约，不建设通用清洗系统，不提前引入复杂校验框架。
- 内容对象按不可变数据使用，可按 ID 复用；排序后的 ID 列表、已加载范围和展开状态属于具体阅读快照，不能被另一访问的操作原地改写。

排序字段依 SRS 确定：按每个比较字段逐级比较，空值排在该字段有效值之后，再进入下一比较字段；最终使用 ID 的固定字符串升序打破并列，采用非语言环境相关比较，不将字符串 ID 当作数字或时间推断新旧。

### 3.2 读取接口的语义

接口提供以下异步能力；表中是契约语义，不是最终函数签名或真实 HTTP 路径。

| 读取能力 | 输入语义 | 成功结果 |
| --- | --- | --- |
| 动态列表 | 首次或下一批标记、批量大小、取消信号 | 动态集合与下一批标记 |
| 动态详情 | 动态 ID、取消信号 | 对应动态 |
| 一级评论 | 动态 ID、排序、首次或下一批标记、批量大小、取消信号 | 评论集合与下一批标记 |
| 楼中楼回复 | 一级评论 ID、首次或下一批标记、批量大小、取消信号 | 回复集合与下一批标记 |

固定 UP 主信息由本期应用数据装配提供，不因头像与昵称展示额外设计真实资料接口。

读取结果区分：

| 结果 | 含义与调用方处理 |
| --- | --- |
| 成功 | 数据可展示；空集合也是成功，不抛成异常 |
| 动态不存在 | 合法详情请求找不到对应动态，进入内容不可用状态 |
| 读取失败 | 本次操作未成功，保留已有内容并提供局部重试 |
| 已取消 | 操作不再需要，不向用户显示读取失败 |

未知路由由导航模块处理，不通过数据接口伪装成“动态不存在”。原始技术错误可供开发诊断，但用户提示使用可理解的错误语义。

### 3.3 不透明分页标记

分页成功结果包含 `items` 与 `nextCursor`；首次请求不带标记，`nextCursor = null` 表示已结束。

- 调用方仅传递标记，不解析、递增或推导后端页码；结束状态不再维护另一份可能冲突的 `hasMore` 真值。
- 模拟 Adapter 可以在标记内表达偏移，但标记需绑定数据资源、父级 ID 和排序条件；错误条件的标记不得被静默复用。
- 完整集合先按稳定规则排序，再分页；批量大小采用 SRS 的已确认数值。
- 失败不推进标记，重试使用相同标记；只有接受了本次有效成功结果才更新下一批位置。
- 根据稳定 ID 防止重复展示，同时保持 Adapter 返回顺序；去重不能被用来掩盖漏批或跳批。
- 回复初始预览和后续追加通过批量参数表达；收起只改变可见范围，不丢弃已加载结果及其下一批标记。
- 本期模拟集合固定，允许采用偏移实现；未来真实数据变化时的分页一致性由 API Adapter 和后端契约另行设计，不能将本期标记视为既定服务器游标协议。

### 3.4 Adapter 装配

正常构建装配正常模拟 Adapter。开发及测试可注入可控 Adapter，按操作指定延迟、结果、失败和返回顺序；不通过随机失败制造验收样例。

页面不导入模拟集合、故障配置或未来 API DTO。未来新增 API Adapter 时，在此处完成协议转换、字段检查和图片 URL 映射，不要求页面理解后端分页形式。

## 4. 异步状态与请求保护

### 4.1 状态归属

每个独立读取区域维护加载状态、已有结果、下一批标记及失败操作上下文。首次读取与追加读取相互区分，评论和每条楼中楼也相互区分。

```text
尚未读取 ──发起──> 首次加载 ──成功──> 成功有内容 / 成功为空
                         └─失败──> 首次错误 ──重试──> 首次加载

成功有内容 ──加载更多──> 保留内容并追加加载
                           ├─成功──> 追加结果 / 已加载完毕
                           └─失败──> 保留内容并显示追加错误
```

取消不是错误态。若离开页面导致请求被取消，快照中的瞬时加载状态应转为可再次读取的状态；返回时恢复已成功内容，必要时重新发起未完成批次，不能永久停留在“加载中”。

### 4.2 双重保护

请求身份由访问 ID、资源类型、所属动态或评论 ID、排序、批次标记及请求代次组成。代次按读取区域维护，某条回复重试不能使无关区域的请求失效。

1. 发起前检查相同批次是否正在读取；除了禁用按钮，协调逻辑也需阻止重复启动。
2. 排序变更或页面访问被替换时，使旧代次失效，并尽量通过取消信号中止旧请求。
3. 成功与失败返回都检查归属和代次；过期结果、错误及完成回调均不得改写当前状态或提前清除新请求的加载标记。
4. 有效成功结果才可追加内容、推进分页位置；有效失败仅更新所属区域。
5. 重试绑定原失败条件，不把旧排序的失败批次重试到新排序中。

取消是节省工作量的补充，不是正确性的唯一条件。模拟 Adapter 即使故意忽略取消，也必须能通过代次保护测试。

### 4.3 切换排序时序

```text
选择目标排序
  → 更新当前选择、递增评论区域代次
  → 重置目标排序的已加载范围与展开状态
  → 使旧评论及其回复请求失效，保留上方动态
  → 定位评论区并读取目标首批
  → 仅接受匹配当前访问与代次的结果
```

即使切回此前用过的排序，也按 SRS 从首批及收起状态开始，不能恢复旧排序的分页进度。缓存的数据可以复用，但可见范围不能因此越过首批。

## 5. 会话状态与阅读快照

### 5.1 生命周期

会话 Provider 稳定挂载在路由页面之上，与导航协调逻辑共同工作；不以 pathname 或每次变化的路由 key 为 Provider 的 React key。页面、详情和预览变化不能重建整个会话。

Context 提供状态与操作入口，reducer 管理确定性转换。可按职责拆分 Context 和状态片段，避免一次图片切换让整个评论树订阅无关变化；不另引入状态管理或数据缓存库。

不写入 `localStorage` 或 `sessionStorage`。浏览器 `history.state` 只存轻量导航元数据，不保存完整评论、展开快照或图片数据，因此它不构成持久化阅读历史。

### 5.2 状态模型

以下名称是设计概念，最终类型定义留到实施阶段。

| 状态 | 标识与内容 |
| --- | --- |
| 当前会话 | 新启动的会话标识，用于识别遗留历史元数据是否仍有对应内存 |
| 内容数据 | 按稳定 ID 引用的动态、作者、评论及回复；避免无意义的实体复制 |
| 页面访问快照 | 应用生成的 `pageEntryId`；路由、来源访问、排序、已加载顺序与范围、下一批标记、文字/回复展开状态、阅读位置 |
| 预览会话 | 应用生成的 `previewId`；底层 `pageEntryId`、所属动态、图片顺序、当前图片、显示模式和触发焦点标识 |
| 请求运行状态 | 每区域的请求身份、代次与加载/错误状态；取消控制器由副作用协调逻辑持有 |

每次主动进入建立独立访问记录。同一动态先后两次访问的排序、分页和阅读位置互不覆盖；内容实体可以共享，视图快照不可共享可变引用。新访问可初始化为默认状态；即使复用内容，也以入口指定位置为准。

本期不做后台自动刷新或跨标签页同步。为满足当前会话恢复，仍可返回的访问记录不随意淘汰；长时间浏览导致的快照内存增长列为风险，不在没有测量时承诺无限历史容量。

## 6. 路由与历史协调

### 6.1 路由与元数据

| 路径 | 处理 |
| --- | --- |
| `/` | 动态列表 |
| `/dynamics/:dynamicId` | 动态详情 |
| 其他页面路径 | 前端未找到页面状态 |

URL 只表达所看页面与动态，不携带评论排序、批次、展开或图片预览参数。分享详情地址不承诺携带阅读进度。

历史元数据区分页面记录与预览记录，包含必要的会话标识、应用访问 ID、来源和导航意图。`location.key` 可以辅助观察路由变化，但不作为跨替换操作稳定的业务访问 ID；`replace` 时须保留需要延续的应用 ID。

### 6.2 页面导航流程

| 操作 | 设计处理 |
| --- | --- |
| 主动查看详情 | 保存当前快照，创建新的页面访问记录，记录顶部定位意图 |
| 主动查看评论 | 同上，但定位意图为评论区 |
| 历史前进/后退 | 按历史元数据查找对应快照，恢复该次访问；不按动态 ID 取“最后一次状态” |
| 详情返回 | 只有确认存在有效站内列表来源及对应历史关系时才回退；否则导航列表首页 |
| 直接访问或刷新 | 若无有效内存快照则按地址建立新会话状态，详情仍可正常读取 |

导航模块结合路由动作 `PUSH`、`POP`、`REPLACE` 与应用元数据区分意图，不能只根据 pathname 是否改变判断访问类型。历史初次加载也可能表现为 `POP`，仍须检查快照是否实际存在。

## 7. 图片预览与历史记录

### 7.1 打开、切换与关闭

```text
页面访问 A
  ──打开图片──> 页面 A + 预览记录 P（同 URL，新增一条历史记录）
  ──预览内切图──> 更新 P 的内存状态，不新增记录
  ──关闭 / Esc / 后退──> 页面访问 A
  ──浏览器前进──> 恢复预览 P 及最后查看的图片
```

- 打开时保存底层位置和焦点标识；通过 React Router 新增带 `previewId`、底层 `pageEntryId` 的历史 state。打开预览不创建第二份底层页面阅读快照，也不取消底层仍有效的读取。
- 切图和长图模式变化更新预览会话内存即可；如需替换当前导航元数据，须保持稳定的预览与底层访问 ID，不因路由 key 变化重置页面。
- 关闭按钮和 `Esc` 交由导航模块撤销已确认由应用创建且有底层来源的预览记录；浏览器后退已经完成撤销时，只同步关闭，不再后退第二次。
- 只有确认当前历史关系有效才使用相对后退。异常或遗留元数据使用替换导航恢复底层页面，不盲目离站。
- 关闭不立即删除仍能通过前进到达的预览内存。若从底层页面开始新导航分支，浏览器前进分支可能被丢弃，应用不得凭空重建该历史分支。

### 7.2 刷新与无效标记

浏览器可能保留 `history.state`，但刷新会丢失本方案的内存状态。初始化时检查会话标识、页面快照及预览引用是否存在；失效时用替换导航清理预览标记，并按当前 URL 正常展示底层页面。

清理只修复当前记录，不试图通过自动连续后退清空浏览器历史，避免离站或形成循环。刷新后不承诺预览恢复；出现重复同 URL 历史条目时也必须保持可正常导航。

### 7.3 焦点与触控

预览内部负责焦点约束、底层滚动锁定、图片加载状态及横纵手势判定；导航模块负责历史语义。关闭时先解除滚动锁，再恢复底层位置与触发焦点，避免默认聚焦额外滚动覆盖恢复结果。

触发元素不可用时使用底层页面中合理的可聚焦位置作为后备，不保留指向已卸载 DOM 的无效引用。移动端手势和键盘切图遵守 SRS 的 FR-09，不增加自由缩放。

## 8. 阅读位置恢复

### 8.1 保存结构

读取位置包含：当前可见动态、评论或回复的稳定定位标识，相对视口顶部的偏移，以及像素滚动位置后备。回复定位需能区分其所属一级评论，避免跨列表误定位。

导航前保存位置，必要的持续记录采用轻量更新方式，避免每次滚动都重绘整个应用。快照同时保存已加载数据范围及展开状态，否则位置本身不足以恢复页面。

### 8.2 恢复顺序

1. 识别本次是主动入口、历史返回还是预览关闭。
2. 还原对应数据范围和展开状态，等待目标区域完成必要渲染与布局。
3. 主动入口执行顶部或评论区定位；历史返回按定位标识与偏移恢复。
4. 定位点缺失时使用像素后备，并限制在有效滚动范围内。
5. 完成恢复后停止纠正；若用户已主动滚动，不继续用迟到的恢复任务把用户拉回。

不等待无关图片全部下载才定位；图片尺寸占位降低布局变化。未知尺寸、失败数据或用户中断时需有限次地结束或回退，不能无限轮询目标元素。

### 8.3 唯一恢复责任方

应用统一管理自定义恢复，并在自身生命周期内使用浏览器手动滚动恢复模式；卸载时清理相关副作用。

不同时挂载 React Router 的 `ScrollRestoration`，避免与自定义锚点恢复竞争，且不引入其默认 sessionStorage 存储。声明式路由方案也不依赖仅在其他路由模式提供的 `preventScrollReset` 选项。

## 9. 图片与样式设计

### 9.1 图片展示模型

每张图片表达缩略图 URL、预览图 URL、顺序及可用的原始宽高。尺寸缺失时先使用合理占位，图片加载后获取实际尺寸并更新展示。

- 本期准备真正的小尺寸缩略素材，不仅用 CSS 将原图缩小。
- 页面网格使用缩略 URL 和懒加载；进入预览时才请求需要的预览 URL，不要求下载全部原图。
- 根据尺寸信息预留空间，采用 Grid/Flex 与比例约束完成 SRS 的图片布局；长图判定及显示高度阈值在实现时确定并用样例验证。
- 使用浏览器图片元素直接加载，不增加画布读取、图片下载或服务端转发。
- 组件原样使用经读取层认可的 URL，不自行追加 OSS 参数，不通过随意添加查询串刷新图片而破坏签名。
- 加载失败和重试属于单张图片状态；本期重试原地址，未来签名过期时需读取层获取新地址，不能依靠无限重试旧签名解决。

### 9.2 CSS 与安全展示

CSS Modules 隔离模块样式，少量 CSS 变量统一颜色、间距、圆角和字号。只提取确实复用的按钮、状态提示等样式，不建设完整设计系统，不引入 Tailwind 或大型全站 UI 框架。

正文折叠依据实际渲染行数而非字符数，宽度变化后需重新判断是否溢出；用浏览器布局验证补足无真实排版环境的测试限制。所有外部文字走安全文本渲染，不使用未经处理的 HTML。

头像、时间、空值等兜底遵守 SRS，不增加 UP 主简介区域。视口、触控区域和键盘要求通过 SRS 验收，不在本文另建一套视觉标准。

## 10. 测试设计

### 10.1 测试层次

| 工具与测试面 | 验证对象 | 设计原则 |
| --- | --- | --- |
| Vitest：确定性规则与接口契约 | 时间/计数转换、排序、分页标记、空值、会话状态公开操作 | 从公开接口验证结果，不逐个测试私有辅助函数 |
| React Testing Library：模块及页面行为 | 展开、排序、分页、局部错误、重试与竞态 | 替换读取 Adapter，通过界面和用户操作断言，不直接修改组件内部状态 |
| Playwright：真实浏览器流程 | 路由、前进后退、预览历史、位置/焦点恢复、视口布局与资源请求 | 覆盖必须依赖浏览器 History、DOM 布局和图片行为的结果 |
| 兼容检查 | 手机手势、实际 Safari 等环境差异 | 明确记录真实设备、模拟器或自动化浏览器，不相互冒充 |

不默认使用全页面像素截图作为验收标准。测试库只服务开发和 CI，不加入生产运行服务。

### 10.2 必须验证的架构风险

除 SRS 的 AC-01 至 AC-20 外，实现验证应包含以下组合场景；它们是对既有行为的验证细化，不是新增产品功能：

- 同一动态两次访问使用不同排序与位置，前进后退分别恢复对应快照。
- 列表及详情分别打开预览，切多张后关闭、前进恢复，再后退关闭；没有多退一级或底层状态重置。
- 直接访问详情、预览期间刷新、遗留历史标记无内存，以及重复开关预览，均无空弹层或导航循环。
- 导航元数据替换时，应用访问 ID 保持正确，不依赖路由 key 是否变化。
- 快速切换排序，旧成功、旧失败及旧完成回调都不能污染新状态；模拟忽略取消后仍满足要求。
- 同批次连续点击与失败重试不重漏；请求未完成时离开再返回，不停留在永久加载状态。
- 展开正文、追加评论和回复后恢复位置；图片慢加载、视口变化及缺失锚点采用可结束的恢复策略。
- 页面打开时未请求全部预览原图；坏图可跳过和重试，未改写签名形式的样例 URL。

### 10.3 数据装配与测试可信度

最小数据规模和边界样例引用 SRS 第 8 节，不另设容量指标。正常模拟与故障场景分开装配；测试通过读取接口控制异步结果，不依赖随机延迟碰巧制造竞态。

故障入口仅供开发与测试，不通过正常页面按钮或公开参数切换正常发布版本的故障模式。针对专用测试装配的行为验证与针对正常静态产物的构建/导航验证都需保留，不能只测试另一套运行路径。

## 11. 构建与静态部署设计

### 11.1 构建交付

本地或 CI 进行类型检查、测试及构建，生成可复现的静态产物。部署目标服务器只接收产物；本期交付 Nginx 配置示例、缓存说明和验证步骤，不实际安装或配置服务器、OSS 及新的 CI 平台。

阿里云 2 核 2GB 是部署目标，不是并发和性能保证。后续真实后端、数据库、爬虫同机运行需要独立评估；图片交付则由 OSS 承担。

### 11.2 缓存与回退

| 资源类别 | 策略 |
| --- | --- |
| 页面入口 | 每次使用前重新验证，避免旧入口长期引用旧产物；可使用 `Cache-Control: no-cache` 表达该语义 |
| 带内容哈希的脚本/样式 | 长期缓存，内容变化生成新文件名；只有版本化资源才适用不可变缓存 |
| 演示图片 | 使用版本化文件名或适当缓存时长，未版本化文件不统一设置永久缓存 |
| 应用页面路径 | 回退到入口，由前端匹配有效详情或未找到页面 |
| 缺失静态资源 | 返回资源错误，不回退到 HTML，不缓存成成功资源 |

静态资源应具有明确的资源路径规则，避免仅靠任意 URL 的文件扩展名猜测页面与资源；具体目录命名在实施时与构建产物一致。

静态 SPA 的前端未找到页面，不等同于服务器已返回 HTTP 404；本期不为此引入 SSR。服务器资源错误和应用内无效路径展示分别验收。

### 11.3 部署验证

至少验证：直接访问和刷新有效详情、未知页面路径、缺失脚本或图片、入口与哈希资源的缓存头，以及一次构建更新后入口能获取新资源。Vite 开发或预览服务器的正常表现不能替代 Nginx 回退与缓存配置检查；没有对应环境时如实记录未验证项。

## 13. 风险、待验证项与后续设计

| 风险 | 约束与处理 |
| --- | --- |
| 自行维护请求协调逻辑 | 集中在模块内，以取消失效、乱序成功/失败和重复提交测试守住契约 |
| Context 更新过宽 | 按职责组织订阅和 reducer，避免让无关页面部分读取频繁变化的整份状态 |
| 历史栈与预览交错 | 使用应用自有访问 ID 和来源关系，避免直接对 pathname 或库 key 作错误假设 |
| 长会话快照占用内存 | 共享不可变内容、只保存必要阅读状态；不声称无限历史容量，真实规模接入前测量 |
| 异步布局导致恢复偏差 | 尺寸占位、锚点定位、有限回退和用户操作优先；通过浏览器场景验证 |
| 真实数据与模拟契约有差异 | API 接入前复核字段、计数与分页语义，不让页面层直接兼容多种原始协议 |
| OSS 地址过期或图片过大 | 留到接入阶段确定签名刷新、尺寸变体和缓存；前端原样使用地址不代表问题已解决 |

本期没有尚待用户确认的总体设计决定。具体函数签名、文件划分、长图判定阈值、样式数值和库版本在实施阶段确定；若需改变已确认的架构决定或用户可见行为，应先确认变更。

真实 API、数据库、爬虫、访问保护、OSS 配置、CDN 及同机资源安排继续遵守 FSR 的后续决策门槛。本文不把未来 Adapter 扩展点当作这些能力已经实现。

下一阶段可据 FSR、SRS 和本文件编写 `.scratch/<feature-slug>/spec.md`，再按 [issue tracker 约定](agents/issue-tracker.md) 拆分可独立验证的任务；任务引用 SRS 编号及本设计章节，不复制另一套需求真值。
