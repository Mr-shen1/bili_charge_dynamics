## 1. 结论

**已有证据支持进入后端实施规格阶段，但持续运行的性能与可靠性尚待验证。** 两个用户提供的 Python 脚本为动态来源、评论分页和去重提供了参考；本轮少量只读请求进一步验证了目标样本的动态读取、评论读取和页面编辑时间提取。证据与限制单独记录于 [后端可行性验证记录](../backend/evidence/backend-feasibility.md)。

前端目标已调整为 Vue 3 + TypeScript + Vite + Vue Router + Element Plus，复用合适的框架无关契约与逻辑；Python + FastAPI 后端、SQLite 持久化及现有 API 不变。API 与采集各运行一个进程，不引入 Redis、Celery 或微服务。前端仍可静态托管，不需要常驻 Node.js 或 SSR。图片展示/预览接受库原生交互，但完整图片组、手机可用性、导航/焦点恢复及按需加载仍须验证；选型不证明这些组合行为已经成立。

动态内容、一级评论图片上传到用户自有阿里云 OSS，首期采用公开读，浏览器直接请求图片 URL，应用服务器不代理浏览器图片流量。采集端下载与上传图片仍消耗网络及运行资源，OSS 不等于零成本或性能保证。

普通动态接口的时间字段不能直接替代页面显示的编辑时间。已验证可通过普通页面 GET 安全解析 HTML 初始化数据，获得带“编辑于”的时间；不执行网页脚本，不需要通过正文或图片内容比较判断编辑。本轮单样本成功不证明所有目标页面或连续固定节拍轮询均稳定可用。

## 2. 使用场景与领域边界

### 2.1 用户与核心流程

面向个人自用，支持管理和采集多个 UP。核心流程为：

1. 在管理页通过 UID 添加 UP，获取其昵称与头像，配置监控模式、目标及启停状态。
2. 后台按固定节拍（生产默认 2.7 秒 ±10%）检查目标，发现变化后同步归档。
3. 默认浏览全部已归档动态，或通过可横向滑动的 UP 头像和昵称选择器查看某一 UP。
4. 点击动态卡片进入详情顶部，或点击评论气泡图标与数量进入同一详情页的评论区。
5. 阅读动态、一级评论图片和楼中楼：宽屏内联预览后页码翻页，窄屏从回复预览进入独立楼中楼页；返回详情/来源列表按各自现有恢复语义继续阅读。

视觉保留 B站参考所形成的布局方向、品牌配色和阅读层级，采用统一组件库主题建立新版基准，不再锁定旧像素尺寸。具体规则见 [UI 规范](../design/ui-reference.md)；不复制截图中未确认的产品能力。

### 2.2 内容来源与充电边界

- 数据范围仅为本人账号有权使用的数据来源中的充电图文动态及关联图片、评论、回复；不绕过访问限制。
- 充电动态识别**直接沿用参考脚本现有逻辑**，作为用户已确认前提，不新增筛选条件或重新评估识别规则。
- 两种监控模式只决定监控哪些动态，不限制目标可采集的内容；不增加“仅评论 / 完整采集”配置。
- 可以显示充电标识，但不建设购买、解锁、价格或会员权限体系。
- 动态正文受限与评论可读取是独立情况。不能因正文遮挡或网页显示“暂无权查看当前评论”就跳过评论接口；按接口实际成功或失败结果处理。
- 上游明确拒绝、网络失败和缺失字段不等于零评论，也不证明内容已删除。
- 内容类型仍不包含视频和转发动态。页面不提供转发图标、数量或操作。

## 3. 下一阶段功能范围

| 模块 | 已确认的行为 |
| --- | --- |
| UP 管理 | 数据库保存 UP 与监控配置；通过 UID 添加，昵称、头像来自上游，不手工覆盖；配置模式、扫描数、指定 ID 和启停状态 |
| 近期动态模式 | 每 UP 默认扫描最近 10 条，可单独配置 N；翻页累计符合既有识别逻辑的 N 条动态或直到上游耗尽，不按原始候选条数截断 |
| 指定动态模式 | 动态 ID 与 UP 关联，只监控已配置 ID，忽略该 UP 的其他动态；不限制为仅评论 |
| 固定周期检查 | 每个节拍触发（生产默认 2.7 秒 ±10%），同一目标上一轮检查未完成则跳过，不叠加；评论计数每节拍读取，页面信号默认每 60 秒 ±2 秒采样；不预先改为退避或自适应周期 |
| 变化检测 | 通过页面的编辑标记和编辑时间检测动态编辑；通过来源评论总数变化检测评论变化 |
| 同步与归档 | 检查与耗时同步分离；观察到变化不等于同步完成；失败保留旧归档和未完成状态 |
| 全部 / 单 UP 列表 | 对所选范围的完整归档集合排序再分页；各范围独立维护列表恢复状态 |
| 详情与评论 | 保留正文阅读、最热/最新和一级评论 cursor 追加；回复采用当前宽屏预览最多 3 条后页码每页 10 条、窄屏预览入口进入独立楼中楼页；正文受限不阻断可用评论 |
| 图片归档与预览 | 图片归档不变，动态图与一级评论图保持归属和顺序；展示及预览优先使用组件库，允许调整网格/倍率/手势等细节，保留完整组、长图可读、手机/键盘可用及导航恢复底线 |
| 页面改版 | 参考 B站浅青背景、白卡片、青蓝选中态、粉色作者及评论层级；删除“查看详情”按钮和全部转发元素 |
| 运行状态 | 管理页展示最近检查、最近成功同步、进行状态及错误，避免将未完成同步展示为完成 |

动态列表和一级评论继续采用 cursor 分批追加而非无限滚动；展开后的楼中楼使用实时页码读取、每页最多 10 条，不累计成 3/13/23/25。来源明确置顶优先，其余“最热”使用点赞数降序及稳定并列规则，不声称复现 B站热度算法。SRS 按代码基线同步具体交互，不用旧追加或禁止独立评论页的措辞约束迁移。

### 3.1 明确不做

- 首期站点/API 权限管理、账号注册、多用户角色体系；后续增加，不由本轮自行提前建设。
- 首期备份和容量不足治理；不自动淘汰旧归档来腾出空间，也不承诺故障可恢复。
- 自动回填近期窗口外的全部历史动态；这不排除初始化纳入监控动态的已有评论。
- 通过正文、图片内容或图片字节摘要比较来检测动态编辑。
- 保证发现评论纯编辑或等量新增/删除；前端迁移不新增或移除当前后端已有的逐根检查、重试或校准机制，不用旧方案的排除项回退现行采集逻辑。
- UP 关键词搜索、动态搜索、复杂统计、个人简介、粉丝数、关注或独立个人主页。
- 视频、转发动态、楼中楼回复图片、复杂表情包和完整 B站富文本功能。
- 真实点赞、评论发布、转发、图片下载、自由缩放或双指缩放。
- 深色模式、离线功能、持久化阅读历史，以及截图中的排行榜、推荐和付费装饰业务。
- Redis、Celery、大型压测、自动扩容、新增付费资源采购或未经验证的容量承诺。

## 4. 数据与图片方案

### 4.1 已验收模拟基线与真实归档

原有虚构 UP、动态、评论和项目内演示图继续服务于独立前端回归、故障及边界测试，不作为下一阶段真实数据交付的替代品。已有验收数据集不是生产规模指标。

真实数据分为三类：

- **配置**：UP 身份、监控模式、近期扫描数、指定目标与启停状态。
- **归档**：动态内容、图片、一级评论与回复，供前端从数据库读取。
- **运行状态**：最近观察值、成功同步检查点、错误、未完成工作及图片上传状态。

删除或停用监控配置、动态离开近期窗口，均不删除已保存的身份及归档。上游消失或读取失败不触发自动删除。发布时间与编辑时间分开保存，编辑不改变列表按发布时间排序的语义。来源评论总数与本地已归档条数也分开表达。

### 4.2 数据读取与采集边界

- 浏览器通过后端读取归档，不直接调用 B站采集接口，也不在每次浏览时触发上游同步。
- 页面使用统一读取接口；mock Adapter 保留，新增真实 API Adapter 在读取层完成协议与数据映射。
- 所有外部 ID 使用字符串；时间、排序、分页、空态、失败和取消语义遵循 SRS/HLD。
- 采集端使用已有脚本的接口经验，但不直接运行包含飞书通知等副作用的脚本主循环。
- 编辑时间从图文页面 HTML 的初始化 JSON 提取，按模块类型定位作者数据，不执行 JS，不依赖固定脚本或数组下标。
- 普通相对时间变化不算编辑；带“编辑于”的时间按日期时间规范化，空格差异不算变化。仅到分钟的字段不伪造秒级精度，同分钟多次编辑可能漏检。
- 初次纳入监控建立基线并同步；后续观察到的变化只有在相应同步成功后才推进成功检查点。正文、评论和图片分别记录完成状态。
- 采集凭据仅保存在服务端仓库外，不交给前端、不进入日志或版本库；管理页不负责编辑凭据。

### 4.3 OSS 图片交付

```text
采集进程 ──下载并上传图片──> 用户自有阿里云 OSS（公开读）
API ──返回动态、一级评论及 OSS 图片 URL──> 浏览器
浏览器 ──直接请求图片──> OSS
```

动态图片与一级评论图片分别关联其归档记录，并保留顺序、可用尺寸和上传状态。某张图失败不使整条评论或其他图失效；无文字但有图的评论仍是有效内容。

列表缩略图懒加载，预览按需请求。尺寸变体、图片处理、缓存与 CDN 方案留到接入设计，不把公开读或懒加载等同于自动压缩。首期不做签名 URL 刷新机制。

公开读意味着任何拿到图片 URL 的人均可能直接访问或外链；未来增加站点登录也不会自动保护这些图片。

## 5. 技术方案与取舍

### 5.1 已确认选型

| 层次 | 方案 | 选择理由与限制 |
| --- | --- | --- |
| 前端 | Vue 3 + TypeScript + Vite + Vue Router + Element Plus | 目标方案；重写框架相关实现，复用合适的纯 TS，保留业务契约及静态交付；旧测试不直接继承为新版通过 |
| 状态与样式 | composables / 必要的 provide/inject；库主题变量 + 局部 CSS | 以完整组件库替代通用 UI，不默认加 Pinia、请求缓存框架或 Tailwind；复杂业务协调仍需项目维护 |
| 后端 | Python + FastAPI | 便于复用现有 Python 采集经验；具体依赖版本待固定 |
| 数据库 | SQLite | 首期无需独立数据库服务；并发写入与资源使用仍需验证 |
| 运行 | 一个 API 进程、一个采集进程 | 隔离耗时采集与页面读取；避免 API 多实例重复启动调度 |
| 数据读取 | 后端归档读取 + 前端 API Adapter | 保留 mock/可控 Adapter 做确定性测试 |
| 图片 | 用户自有 OSS 公开读 | 浏览器直接加载；费用与公开访问风险明确保留 |
| 托管 | Nginx 静态文件与 API 反向代理 | 前端不依赖 Node.js 常驻或 SSR；API 错误不能回退为页面 HTML |
| 工具 | Python 使用 uv；Node.js 使用 nvm，依赖和脚本使用 pnpm | 遵循仓库约束，不在此声称版本已安装 |

### 5.2 不采用的方案

- 不直接将两个脚本的通知主循环包装成 HTTP 接口；采集、持久化与读取职责需分离。
- 不建设微服务、Redis 或 Celery，先以双进程和持久化同步状态满足当前规模。
- 不采用 SSR；无搜索引擎收录或必须服务端渲染的需求。
- 不基于静态效果图或组件库官方演示宣称交互已完成；视觉改版仍需回归真实阅读流程。
- 不长期混用 React/Vue 或多套 UI 库，不做页面级生产灰度；完整重构并验证后统一上线。开发分阶段验证高风险行为，避免最后才发现图片或历史导航不适配。
- 不把通用动态接口 `pub_ts` 单独当作编辑版本；已有样本表明它与页面编辑时间不等价。

### 5.3 实施注意事项

保持 SQLite 事务短小，不把上游网络读取和 OSS 上传放进长事务；具体并发、持久化任务结构及失败恢复由 HLD 和后续规格细化，不用无限并发强行满足节拍。

卡片整体可进入详情，但图片、文本选择、展开及评论入口具有独立行为，不能因事件冒泡误导航。全局列表中的 UP 标识按每条动态作者确定，不能继续使用单个固定 UP 身份。

## 6. 资源、经济与运行可行性

### 6.1 实际规模与目标

当前用户计划：近期模式的 UP `550494308` 关注约 10 条充电动态；指定模式的 UP `3493130286402061` 当前配置 2 条动态。系统支持多 UP，这组数据是实际起始规模，不是产品硬上限。此前讨论的 5 UP / 100 条指定动态只是早期评估假设，不作为实际负载基线。

每个目标每个节拍触发检查，不等于每次都能在该节拍内完成。忙目标跳过本次触发，检查与耗时同步分离；不预设自动退避。少量顺序请求的耗时不能外推持续运行、并发能力或平台允许的请求频率。

### 6.2 单机运行与已知风险

优先以 2 核 2GB 评估 API、单采集进程及 SQLite 同机方案。HTML 读取、评论翻页、图片上传和数据库写入都占用资源，OSS 不消除这些竞争。CPU、内存、磁盘、请求耗时、Cookie 有效性与上游响应变化均需在后续实施验证中观察。

首期不做备份和容量不足治理，数据损坏、误操作、磁盘耗尽可能造成不可恢复的丢失或服务失败。该取舍不意味着这些情况已被系统处理。

### 6.3 成本与暴露范围

新增资源或付费服务需另行确认。OSS 存储、请求、流量可能产生费用，不给出缺少用量依据的报价。

首期无权限管理；若站点/API 暴露公网，可访问者可能读取归档或修改监控配置。图片公开读是独立的暴露面。用户已将权限系统延后，本报告记录风险，不擅自把鉴权或备份重新列为首期前置功能。

| 编号 | 当前阶段验收条件 |
| --- | --- |
| A1 核心流程 | 全部或某 UP 列表进入详情、评论、图片再返回，恢复正确来源范围的位置与已加载内容 |
| A2 列表行为 | 按发布时间全局或单 UP 排序，正文展开/收起、分批加载和结束状态正确 |
| A3 评论行为 | 最热/最新及来源置顶排序正确；宽屏预览/页码替换、窄屏独立楼中楼及其现有返回行为保留，嵌套回复的条件化目标前缀正确 |
| A4 图片行为 | 按修订后的 SRS 验证原生预览、完整图片组、长图可读、手机切换/关闭、键盘和局部失败处理；不强制旧滑动手势、网格或倍率 |
| A5 状态覆盖 | 加载、空态、失败、受限内容和缺失字段可区分；错误不覆盖旧归档或伪装零值 |
| A6 响应式 | 360px、390px、768px、1280px 宽度下无页面横向溢出；UP 选择条允许自身横向滑动 |
| A7 可操作性 | 主要触控目标约 44px，键盘和焦点可用；卡片入口不吞掉内部操作 |
| A8 浏览器 | 原阅读范围为 Linux Chrome 与 iPhone Safari，记录版本、设备及实际验证方式；后续 FR-21 另行增加飞书内置浏览器/手机精确链接验证，按 SRS AC-35 取证，不继承本项旧证据 |
| A9 路由与构建 | 全部/单 UP/动态详情/楼中楼/两级管理深链接可用；静态资源和 API 错误不被回退为入口 HTML |
| A10 自动化测试 | 保留原关键阅读流程，增加多 UP、一级评论图片、监控管理及采集状态行为测试 |
| A11 范围一致性 | 无交易解锁、真实写回及转发功能；浏览器不持有采集凭据、不直接调用上游采集接口 |
| A12 配置与目标 | 两种模式互斥、N 按符合条件条数计、指定 ID 关联 UP；模式不限制内容能力 |
| A13 检查与同步 | 固定节拍（默认 2.7 秒 ±10%）、忙目标跳过、编辑时间与评论总数触发；失败不提交同步成功检查点 |
| A14 归档保留 | 停用、删除配置、窗口外及上游读取失败不自动删除归档；不自动回填全部历史动态 |
| A15 图片交付 | 动态与一级评论图片正确归属并有序上传/读取；浏览器直取公开 OSS，失败按图片局部处理 |
| A16 视觉改版 | 符合用户确认的新版受控视觉基准，保留整体布局方向、配色和阅读层级，不按旧图像素复刻验收；卡片与评论入口正确，无“查看详情”按钮和转发元素 |

验收条件的细节与追踪以 SRS 为准；未验证的新能力不得被描述为已通过。浏览器正式范围沿用 2026-10-12 的用户确认，不扩展到其他浏览器或 B站 App 内置浏览器。

## 8. 主要风险与应对边界

| 风险 | 影响与处理 |
| --- | --- |
| HTML / 接口字段变化 | 解析和同步可能失败；安全解析、区分失败与空值、保留上次成功状态，不执行页面 JS |
| 编辑时间精度及可用性 | 分钟内多次编辑可能不可区分；不是所有目标或连续编辑都已验证，不默认内容比对兜底 |
| 评论计数语义差异 | 抽样一致不等于全局等价；保留来源计数和同步状态，是否省略独立计数请求待映射确认 |
| 上游拒绝或限流 | 一次 opus API 请求曾返回 412；验证当时停止，无绕过或压测。首期固定周期不等于上游可用性保证 |
| 采集与读取竞争 | 双进程隔离、短事务、目标去重；具体并发与运行容量仍待验证 |
| 页面改版回归 | 排序、分页、导航、焦点等行为测试迁移并重跑；图片按明确放宽后的契约测试，新版视觉另行确认 |
| 组件库预览与应用协调 | iPhone 长图操作、底层滚动锁、历史/焦点及是否全组下载未在项目验证；先核实公开配置和必要连接层，失败则重新讨论，不静默牺牲底线 |
| 重构成本与维护收益 | 框架和组件测试需迁移，业务协调并不会由 UI 库消除；以替换清单与真实回归结果评估收益，不承诺删行比例或未经拆分的工期 |
| 公开内容及管理暴露 | 应用不内建账号系统；已有部署代理保护与客户端 401 提示须保留，不能把它们等同于所有入口都已保护。公开 OSS URL 仍可直接访问，未受保护的管理接口仍有暴露风险 |
| 无备份和容量治理 | 可能丢数据或停止写入，不宣称自动恢复或自动清理能力 |

## 9. 实施阶段与工作量边界

上一阶段“约 4–7.5 人日”的估算仅覆盖模拟前端，不适用于本轮新增后端、图片归档和页面改版。当前不重新给出未经任务拆分的工期承诺，也无硬性上线日期。

需求/设计与 Vue 实施规格已按代码基线整理；下一步确认端到端任务切片和阻塞关系，再逐项实现、测试及验收。本轮不自动拆票或执行后续步骤，不修改历史已验收的 spec、tickets 或验收记录。

## 10. 已确认决定与后续验证

Python/FastAPI/SQLite、双进程、两种监控模式、固定节拍检查（默认 2.7 秒 ±10%）、页面编辑时间检测、OSS 公开读均保持已确认决定。Vue 3 + Element Plus 前端重构、新版视觉基准及图片交互例外亦已确认，不再列为未决选型；依赖兼容组合与项目内行为仍须实施验证。

后续需细化或验证：

1. 前后端具体协议、数据库迁移和读取时数据变化下的分页一致性。
2. 不同目标页面的编辑时间可获取性、自然多次编辑后的时间更新与评论计数映射。
3. 图片尺寸变体、缓存、OSS 配置及实际费用；不在验证时自动采购云资源。
4. API/采集同机持续运行情况和默认节拍下的实际成功率；单次成功不能代替该验证。
5. 将来增加权限、备份与容量治理时另行确认，不作为本期实现者可自行加入的功能。
