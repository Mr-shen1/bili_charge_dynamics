## 1. 文档职责与需求边界

### 1.1 文档优先级与历史边界

FSR 负责本期可行性、技术取舍、资源与证据限制；本文负责用户可观察行为、展示数据语义、监控与归档状态及验收条件；HLD 负责满足这些需求的架构、模块协作与总体设计。三份文档已同步本期范围，产品行为与验收条件以本文为准，不能把需求或设计文本当作实现证据。

“固定单 UP、仅 mock、排除真实后端和评论图片、OSS 权限未定”等只属于旧阶段约束，不再约束本期。现有 `src/data/contracts.ts` 仍反映旧实现，需要按本期需求演进；不得把旧接口的全局 `creator` 当作多 UP 身份真值。

[后端可行性与只读证据](../backend/evidence/backend-feasibility.md) 记录 13 次只读样本及限制；[UI 参考裁剪](../design/ui-reference.md) 记录视觉参考及排除项。它们分别是证据与样式依据，不替代本文的产品需求，不构成新前端或后端验收。旧版验收仅是历史基线，当前通过与否必须另有本期证据。

本次明确改变多 UP、管理、真实数据与图片归档、卡片入口和视觉要求；未改变的分页、正文折叠、图片预览、排序及浏览恢复规则继续有效。后续若需改变已确认行为，应先更新需求并获得用户确认，不由实现阶段静默扩大范围。

编号前缀：`FR` 为功能需求，`DR` 为数据要求，`NFR` 为非功能要求，`AC` 为验收场景。同一规则以其需求条目为准；验收场景引用规则并给出可验证结果。

### 1.2 目标用户与系统范围

面向个人自用，通过 `/manage` 维护多个 UP 主及各自监控目标，浏览全部或单 UP 的已归档图文动态、详情、图片、评论和回复，再返回继续浏览。目标选择与归档阅读相互独立，停止监控不会移除已归档内容。

页面统一处理“动态”。数据范围仅为本人账号有权使用的数据来源中的充电图文及关联图片、评论和回复，不绕过上游访问限制；正文受限时仍可按 FR-18 同步实际可读评论。上游充电图文的识别沿用原 `script_demo` 规则，不重新评估或扩展识别；允许充电专属展示标识，但不增加购买、解锁、会员权限或逐条权限系统。

生产数据来自后端与 SQLite 归档；mock 保留为独立回归测试来源，不作为本期生产数据。动态图与一级评论图片上传用户自有阿里云 OSS，采用公开读 URL，浏览器直接请求 OSS，应用服务器不代理图片。

### 1.3 范围排除

- 账号与权限系统、凭据管理 UI；不自行增加上线前置鉴权要求，风险见 NFR-04。
- UP 主搜索、动态搜索、复杂筛选和统计分析；UP 主新增只输入 UID，不提供昵称或头像手动覆盖。
- UP 主简介、粉丝数、关注入口及归档页以外的个人主页功能；排行榜、推荐及截图中的付费装饰业务。
- 视频、转发动态内容、回复图片、复杂表情包和 B站专用富文本解析。
- 真实点赞、评论发布、转发图标/数量/功能、图片下载及自由缩放或双指缩放。
- 深色模式、主题设置、离线功能和持久化阅读历史。
- Redis、Celery、自动退避或自适应检查频率、默认每日全量校准、自动全历史动态回填。
- 首期备份、容量不足治理、CDN 配置、大型压测与具体容量承诺；图片尺寸变体、缓存及 CDN 尚未决定，不由实现者代为选定。

## 2. 术语与用户流程

| 术语 | 本文含义 |
| --- | --- |
| 动态 | 某 UP 主发布并归档的一条图文内容；可以只有文字或只有图片 |
| 监控目标 | 当前按某 UP 的近期 N 条或指定 ID 模式选中、启用检查的动态；不等于全部归档 |
| 归档 | 已成功保存的动态、评论、回复及图片记录；停止监控或上游消失后仍保留 |
| 列表 scope | 全部归档或某一 UP 归档的读取范围；分页、访问身份和阅读快照须隔离 |
| 检查 / 同步 | 检查观察来源信号；同步获取并保存对应内容，两者及其成功状态分离 |
| 一级评论 | 直接归属于某条动态的评论 |
| 回复 / 楼中楼 | 归属于某条一级评论的回复；用回复目标表达对话关系，界面不递归嵌套 |
| 动态评论总数 | 来源提供的该动态一级评论与所有楼中楼回复总数；与本地实际归档数量分别记录 |
| 回复数 | 某条一级评论下的回复总数 |
| 当前会话 | 当前标签页在不刷新、不关闭的情况下进行的站内浏览；不承诺跨标签页或重启后的状态恢复 |
| 主动进入 | 点击动态卡片或评论气泡图标及数量打开详情，而非通过历史导航返回 |
| 历史导航 | 浏览器前进/后退，或详情页返回到其站内列表来源 |

主要用户流程：

1. 打开默认全部归档列表，或通过顶部横向 UP 选择条进入单 UP 归档；阅读并按需展开动态正文、加载后续动态。
2. 点击卡片进入详情顶部阅读完整动态，或通过评论气泡图标及数量直接进入同一详情的评论区。
3. 在列表或详情点击图片进行预览，然后回到原位置。
4. 切换一级评论排序、加载评论、展开或收起楼中楼。
5. 返回来源列表，保留该 scope 已加载内容与原浏览位置。
6. 在 `/manage` 添加 UID、管理每个 UP 的启停、模式、N 或指定 ID，并查看最近检查、成功同步及错误状态。

## 3. 页面与内容需求

### FR-01 页面结构与身份展示

- 列表顶部提供可横向滑动的 UP 头像昵称选择条，含“全部”和单 UP 选项；默认全部。下方为居中的动态内容主栏，不展示简介或占位。
- 桌面不增加复杂的两侧导航；手机使用单列布局。
- 每张动态卡片显示头像、昵称、发布时间、正文、图片及评论数。
- 详情使用独立页面，包含返回入口、完整动态内容、图片及评论区，不以多层弹窗承载详情和评论。
- 评论和回复显示作者头像、昵称、发布时间、正文及点赞数；作者 ID 等于当前动态 `author.id` 时展示 UP 主标识，不与 reader 全局 `creator` 比较，也不以昵称判断。
- 只有顶部 UP 选择条的头像昵称用于筛选；内容区域的动态、评论及回复头像昵称只展示，点击不筛选、不跳转，也不因卡片事件冒泡进入详情。点赞数只读。
- 以 [UI 参考](../design/ui-reference.md) 两张图为一比一视觉基准：保留的列表、详情、评论及回复阅读区域对齐其布局、比例、字号行高、间距、图标、图片容器与配色；包括浅青背景、白色卡片、cyan 选中态、pink 作者信息。不是仅使用相近主题色，也不恢复裁剪掉的 B站功能。视觉比较基准及业务内容差异按 UI 参考记录，历史验收不自动证明本次复刻通过。
- [列表图例](../assets/ui-reference/dynamics-list.png) 与 [详情图例](../assets/ui-reference/dynamic-detail.png) 作为保留阅读区域的一比一视觉基准，不复制其中未经确认的功能、相对时间或正文截断；详情动态正文仍完整展示。

### FR-02 导航入口与有效地址

- 动态卡片整体可点击进入对应详情页顶部，完全移除“查看详情”按钮，不保留第二套同名按钮入口。
- 评论入口为气泡图标加数量，进入同一详情页并定位评论区；不增加独立评论详情页，不用真实评论图片作为入口。
- 图片预览、选择正文、展开/收起及其他内嵌操作不冒泡误导航；卡片和评论入口均可键盘访问并具有明确焦点。
- 点击动态图片或一级评论图片直接打开所属图片组的预览，不要求先跳转页面。
- 固定页面路径：`/` 为全部已归档动态，`/ups/:upId` 为单 UP 归档，`/dynamics/:dynamicId` 为动态详情，`/manage` 为管理页面；有效地址均支持直接访问和刷新。
- 详情返回按钮有站内列表来源时返回该 scope 的列表；无站内列表来源时回到 `/`，而非将用户带离本站。
- 无效地址与请求失败分别按 FR-13 处理；状态恢复及定位优先级按 FR-10 处理。

### FR-03 文字阅读

- 动态列表正文、一级评论正文和回复正文在当前布局下超过 6 个渲染行时，初始折叠至 6 行，并提供展开/收起操作。
- 未超过 6 行时不显示多余的展开入口；详情中的动态正文始终完整展示。
- 展开与收起只改变对应文本，不触发页面导航或改变其他评论的状态。
- 保留原有换行，正常显示普通文字和 emoji；长单词及长 URL 可换行，不能撑宽页面。
- URL、话题和 `@用户` 均按普通文本展示，不自动变成外链、用户跳转或话题入口。
- 楼中楼已嵌套在所属根评论下，不再重复显示“回复 @某人”前缀；关系由层级表达，也不提供真实回复操作。

### FR-04 时间与计数

- 有效发布时间仍按北京时间（`Asia/Shanghai`）显示为 `YYYY-MM-DD HH:mm:ss`，不随浏览设备时区变化，也不因参考图的相对文案改为相对时间。
- 编辑时间是独立字段，不覆盖发布时间，不参与发布时间排序；来源只有分钟精度时按该精度展示，不伪造秒值。若原始发布时间不能可靠取得，不得把“编辑于”时间当作发布时间，按 FR-12 处理。
- 计数显示完整非负整数，可添加千位分隔符，不缩写为“万”等单位。
- 动态评论数使用来源动态评论总数，不用已加载或本地归档评论数量代替；每条一级评论另显示其回复数。本地归档数量与来源计数分开，来源未知时不拿本地数量补齐。
- 时间、计数缺失与真实零值必须区分，兜底规则见 FR-12。

### FR-05 动态列表排序与分批加载

- 动态按发布时间倒序，每批最多 10 条，通过“加载更多”追加，不使用无限滚动。
- 相同发布时间以 ID 字符串升序确定顺序，采用非语言环境相关比较，不转为数值比较；缺失排序字段排在该字段有效值之后，再比较下一字段。
- `/` 对全部已归档动态先全局排序再分页，不按 UP 分页后拼接；单 UP scope 对该 UP 全部归档排序后分页。停止监控、移出窗口或移除目标的旧归档仍在集合内。
- 全部与各单 UP scope 的 cursor、访问身份和阅读快照相互隔离；跨 scope 的标记不能静默复用，迟到结果不能污染新的选择。
- “加载更多”保留已有动态及交互状态，不重置为首批，不无故跳回顶部。
- 无后续数据时明确显示已加载完毕，不再允许发起下一批加载。
- 列表加载中、空态和失败处理遵守 FR-11。

### FR-06 一级评论排序与分页

- 进入尚无会话状态的详情时默认选择“最热”；每批最多 20 条一级评论。
- 来源明确置顶的一级评论在“最热”和“最新”下均优先排列，并显示“置顶”标识；不以作者身份或点赞数推断置顶。其余评论再按所选规则排序。置顶计入每批 20 条，不与普通列表重复展示。
- “最热”：点赞数降序，同点赞数按发布时间降序；仍相同则以 ID 字符串升序确定顺序。
- “最新”：发布时间降序，相同时间以 ID 字符串升序确定顺序。字符串比较及缺失值规则沿用 FR-05。
- 排序作用于该动态的完整已归档一级评论集合，再进行分批读取，不只排序已展示的一批；不声称复现 B站热度算法或拥有全部来源评论。
- 一级评论的排序不改变楼中楼的时间正序。
- 切换排序后定位评论区顶部，重置为目标排序的首批，并重置评论文字和回复的展开状态；不沿用旧排序的分页进度。
- 切换时保留上方动态，显示目标排序正在加载。切换失败仍停留在目标排序的错误状态并可重试，不能把旧排序结果冒充为新排序。
- 连续切换以最后一次选择为准，较早返回的数据不得覆盖新选择；加载更多也不得把旧排序批次追加到新排序。

### FR-07 楼中楼回复

- 每条一级评论按时间正序预览最早的最多 3 条回复；相同时间以 ID 字符串升序确定顺序，缺失值规则沿用 FR-05。
- 存在更多回复时可展开，每次最多追加 10 条，直到全部展示。
- 回复列表采用扁平结构，显示可用的回复目标，不增加无限嵌套层级。
- 展开更多后提供“收起回复”，收回最初最多 3 条，并将所属一级评论的开头滚回可见位置；同一排序与会话状态下，再次展开恢复此前已加载的回复，不重复请求已有内容。
- 回复数为零时不显示展开入口；全部加载后不再显示可继续加载的操作。
- 切换一级评论排序时，按 FR-06 重置回复展示状态；某条回复列表失败不影响其他评论。

## 4. 图片与浏览状态需求

### FR-08 页面内图片布局

- 单图按比例展示，限制列表内展示高度；超长图通过预览阅读。
- 多图网格：4 张时两列，其他多图场景三列；网格不能造成页面横向溢出。
- 列表最多展示 9 个缩略图位置；超过 9 张时，在最后一格叠加未显示图片的数量，预览仍能访问全部图片。
- 详情展示全部图片缩略图，不把全部原图直接铺开；9 个位置不是数据图片数量上限。
- 预览顺序与数据中的图片顺序一致；点击缩略图打开对应图片。
- 一级评论图片可展示及预览，沿用图片顺序、比例、网格和局部失败规则；图片组与动态图片分开，不扩展到楼中楼回复图片。
- 图片加载策略见 NFR-03，失败处理见 FR-11，归档与 OSS 边界见 FR-20、DR-03。

### FR-09 图片预览

- 可从列表、详情或一级评论图片打开预览，默认保持比例、完整显示当前图片，不裁切；显示所属图片组的当前张数与总张数，不串入其他动态或评论的图片。
- 提供上一张、下一张和关闭操作；第一张不能继续向前，最后一张不能继续向后，不循环切图。
- 只有一张图片时隐藏切换按钮。
- 手机支持左右滑动切图，桌面支持左右方向键切图、`Esc` 关闭。
- 对长图提供“适应宽度 / 完整显示”切换；适应宽度时允许在预览内纵向滚动阅读，不增加自由缩放。
- 切换图片时重置长图的纵向阅读位置；纵向阅读不应误触发横向切图，也不应带动底层页面滚动。
- 手机浏览器返回操作优先关闭当前预览，保留底层页面，而非直接离开列表或详情。
- 关闭后恢复触发预览的页面位置和操作焦点；失败图片仍允许关闭或切换其他图片。

### FR-10 会话内浏览恢复

| 情境 | 要求 |
| --- | --- |
| 从详情返回有来源的列表 | 恢复已加载动态、正文展开状态及滚动位置 |
| 历史导航返回已访问详情 | 恢复该详情的评论排序、已加载评论、回复展开状态及阅读位置 |
| 主动点击动态卡片 | 可以复用已有会话数据和交互状态，但必须定位详情顶部 |
| 主动点击评论气泡图标及数量 | 可以复用已有会话数据和交互状态，但必须定位评论区 |
| 全部与单 UP scope 切换、历史返回 | cursor、访问身份、已加载范围与阅读快照按 scope 隔离；返回恢复对应访问，不借用其他 scope 的进度 |
| 关闭图片预览 | 恢复触发预览的底层页面位置，遵守 FR-09 的关闭与焦点规则 |
| 直接打开详情且无列表来源 | 正常加载该动态；页面返回按钮回到列表首页 |
| 刷新、关闭后重开 | 允许重置加载进度、排序和展开状态；无需持久化阅读历史，但有效详情地址仍可访问 |

入口指定的位置优先于旧滚动位置；历史导航则恢复历史阅读位置。列表数据必须先具备恢复条件，再恢复滚动，避免只保存坐标而丢失前面已加载的内容。

## 5. 加载、空态与异常需求

### FR-11 局部状态与重试

每个可独立读取的区域应区分加载中、成功有内容、成功无内容和失败。分页区域还需区分有更多与已加载完毕。成功无内容不是请求失败。

| 区域或操作 | 加载、空态与失败行为 |
| --- | --- |
| 列表首次加载 | 显示加载状态；无动态显示空列表；失败提供错误提示与重试 |
| 详情首次加载 | 显示加载状态；请求失败提供错误提示、重试和返回列表 |
| 评论首次加载或排序切换 | 只更新评论区；无评论显示无评论状态；失败在评论区重试，保留动态正文与图片 |
| 动态或一级评论加载更多 | 保留已展示内容；失败在原加载位置重试，不回到第一页 |
| 单条一级评论的回复加载 | 只改变对应回复区域；失败保留此前内容并在该区域重试 |
| 内容图片加载 | 加载失败显示占位和重试入口；不阻止其他图片查看及预览切换 |

- 请求进行中禁用对应的重复加载操作，避免相同批次被重复追加；不同区域的操作不应被无关请求全局锁定。
- 重试针对失败操作；成功后按稳定标识保证展示无重复，且不跳过失败批次的数据。
- 错误提示应说明受影响区域并提供可执行操作，不以技术堆栈替代用户提示。
- 头像加载失败使用 FR-12 的默认头像，无需占用内容图片的错误界面。

### FR-12 缺失字段兜底

| 缺失或无效内容 | 展示规则 |
| --- | --- |
| 头像缺失或加载失败 | 使用默认头像 |
| 昵称缺失 | 显示“未知用户” |
| 动态无正文但有图片 | 正常展示图片，不强行补正文 |
| 动态无图片但有正文 | 正常展示正文，不保留空图片区域 |
| 动态正文与图片均为空 | 显示“暂无内容”，不推断为已删除 |
| 一级评论无正文但有图片 | 正常展示图片，不写“暂无评论内容” |
| 一级评论正文与图片均为空，或回复正文为空 | 显示“暂无评论内容” |
| 回复目标缺失 | 不拼接错误的 `@用户`，保留回复本身 |
| 时间缺失或无效 | 显示“时间未知” |
| 计数缺失 | 显示“—”，不伪装成零；有效的零仍显示 `0` |

本规则只约束展示，不要求实现数据清洗。模拟数据中用于正常排序的样例需具备有效排序字段；缺失字段样例的读取顺序应确定、可重复，不允许因展示兜底值导致随机顺序。

### FR-13 无效地址与内容不可用

- 对合法详情路径中的不存在动态 ID，显示“动态不存在或不可用”和返回列表入口，不将其表现为无限加载或普通网络重试。
- 对未知页面路径显示未找到页面状态，并提供回到列表的入口。
- 请求失败使用 FR-11 的可重试状态，不断言内容已删除或 ID 不存在；上游消失或受限不等于本地归档不存在，已有归档仍可阅读。
- 不存在的 UP 归档地址与已知 UP 的成功空归档列表应区分，均提供回到 `/` 的入口。
- 部署后的页面入口回退与静态资源错误必须区分，见 NFR-05。

### FR-14 多 UP 管理

- `/manage` 维护数据库中的 UP 配置，不靠前端写死名单或编辑配置文件管理业务目标；新增 UP 只输入 UID，昵称、头像从上游获取，不提供手动覆盖。
- 每个 UP 可启用/停止监控，选择互斥的“近期 N 条”或“指定动态 ID”模式；N 按 UP 配置，默认 10；指定 ID 可增加或移除并关联该 UP。
- 可删除 UP 的监控配置；删除只移除监控配置并停止相关监控，不删除已保存的 UP 身份、内容归档或已归档媒体，保留后的列表与详情读取遵守 FR-19。
- 展示每个 UP 当前配置、最近检查时间、最近成功同步时间及错误状态；能区分未检查、检查无变化、同步中、部分完成和失败，不能只用一个“成功”掩盖未完成内容。
- `/manage` 也按两张 UI 参考图的同一视觉体系重做 UP 身份卡片、配置表单、指定目标及检查／同步状态；主栏、头像信息、字号、间距、分隔、控件及主次层级应统一，不仅共享背景色。参考图没有对应管理功能布局，记录视觉规则映射，不伪称 B站后台一比一截图；现有管理操作、真实状态、错误及显著无鉴权风险提示保留。
- 无凭据管理 UI，不在浏览器读取 B站采集凭据。资料获取失败应显示失败，不伪造昵称头像获取成功；缺失展示仍遵守 FR-12。

### FR-15 目标选择与模式边界

- 近期模式按原 `script_demo` 充电图文识别规则逐页读取 UP 动态，直到凑够 N 条符合规则的动态或上游耗尽；N 不是“只检查最新 N 条普通动态”。不重新评估识别依据、不新增判定规则。
- 指定模式只监控关联该 UP 的指定动态 ID，忽略该 UP 其他动态；不自动把近期结果并入指定集合。需校验来源作者与所关联 UP 的归属；不符或无法确认时明确表示错误/未确认，不强行关联，也不伪装成校验成功。
- 模式仅决定目标选择，不限制内容采集。两种模式均采集目标可取得的正文、评论、回复及本期图片，不增加“仅评论 / 完整采集”配置。
- 当前实际规模参考：UP `550494308` 近期约 10 条，UP `3493130286402061` 指定目标目前 2 条。这是需求样本，不是容量验收；不设置“最多 5 个 UP / 100 个目标”等硬上限。

### FR-16 固定检查与独立同步状态

- 固定每 15 秒触发一次检查调度；同目标上一轮检查未结束时跳过该次，不叠加、不积压同目标检查任务，不自动改变为退避或自适应间隔。15 秒是触发检查频率，不承诺每 15 秒完成全量同步。
- 轻量检查与耗时内容同步分离；某目标评论分页或图片上传耗时，不应把全局调度变成“全部同步完成后再等 15 秒”。
- “已观察到的变化”与“已成功同步的版本/信号”分别保存。初次检查建立基线并发起同步；失败不得提前推进成功基线，下一轮仍可重试未完成内容，即使来源信号未再次改变。
- 正文、评论/回复、图片分别记录完成状态、最近成功和错误；一部分失败不把整条动态误标为全部完成，也不阻断其他可读取部分。可信的无变化检查不是成功同步，最近检查与最近成功时间分开。

### FR-17 正文编辑检查

- 编辑信号通过普通动态网页 GET 获取 HTML，从 `__INITIAL_STATE__.detail.modules` 中按 `module_type = MODULE_TYPE_AUTHOR` 定位作者模块，读取 `module_author.pub_time` 所含“编辑于”日期时间；不是通用动态接口的同名显示字段，也不依赖 `opus/detail` JSON 接口。先安全提取初始化 JSON，再用 JSON 解析器读取，不执行网页 JS、`eval` 或脚本，不固定脚本标签或模块数组下标。
- 识别“编辑于”标记后，按来源语义规范化日期、时间、时区及精度，规范化空白后比较；不能仅靠 `pub_ts` 判断编辑。普通“几分钟前”等相对发布时间文案及其自然变化不是编辑时间，也不因文案变化触发正文同步；不以正文或图片内容比对作为变化检测，不新增正文哈希或图片差异检测规则。
- 初次纳入目标建立可用观察基线并同步可读取内容，不以没有“编辑于”标记为由跳过首次同步；后续可信编辑时间变化触发正文及其动态图片的更新同步。模块或字段缺失、解析失败或带编辑标记的时间不可用应保留未知/失败状态与旧归档，不当作“未编辑”或空正文成功；某一信号不可用不阻断其他可读取部分。
- 发布时间与编辑时间分别保存及展示，遵守 FR-04。只具分钟精度时可能漏掉同一分钟内的编辑；用户接受此限制，不虚构秒精度。多次自然编辑的持续检测及所有页面的时间可用性尚未验证。

### FR-18 评论变化与受限内容

- 除初次同步和失败重试外，仅当来源评论总数变化时触发该目标的评论及回复同步；不因正文编辑或相对时间变化默认重扫评论。
- 同步范围包含目标已存在、可读取的一级评论及其回复，并按上游分页获取，不仅采“启用之后”的新评论；不把“不回填全历史动态”误解成“不采目标已有评论”。
- 接受评论新增/删除数量抵消、评论纯编辑但总数不变等漏检；不默认移入原脚本的每日全量校准、退避或其他未确认机制。
- 正文受限及网页显示“暂无权查看当前评论”不应阻断评论接口实际可读的数据；正文、网页提示和评论接口的结果分别判断。
- 请求失败、业务失败、缺失或无效计数字段不当作 `0`；分页或字段失败不当作成功空结果，不推进对应成功状态，也不覆盖或清空旧归档。来源计数与本地归档量分别记录，不强行令两者相等。

### FR-19 监控生命周期与归档保留

- 停止 UP、删除 UP 监控配置或指定目标、模式切换后不再入选的目标及移出近期 N 窗口的动态，均保留已保存的 UP 身份及归档正文、评论、回复和图片，但不再监控；重新纳入后可继续同步。全部/单 UP 列表及已有详情仍可读取这些归档，顶部 UP 筛选不能仅依赖当前启用的配置而使旧归档失去入口。
- 上游动态、评论或图片消失，不自动删除已归档数据；读取失败或不可用也不能覆盖旧成功内容。
- 不自动扫描并回填某 UP 全部历史动态；近期模式为凑够 N 条所需的翻页，以及已选目标的已有评论分页，不属于被排除的全历史动态回填。

### FR-20 图片归档与读取

- 本期归档动态图和一级评论图片；两类图片的归属关系分开保存，均保留顺序、尺寸、来源地址及 OSS 上传状态，复用同一上传能力，不扩展回复图片。
- 图片完成状态独立于正文、评论文本，失败可重试；文本成功不代表图片已归档，图片失败不得清除旧的成功归档或阻止可读正文/评论展示。
- 归档图片由后端提供公开读 OSS URL，浏览器直取，不经应用服务器代理，也不以 B站业务图片地址作生产展示回退。未上传成功的图片应表达未完成/失败，不能冒充已归档。
- 一级评论图片可按 FR-08、FR-09 预览；无文字但有图的评论正常展示。头像 URL 与业务归档图片区别对待，现有 B站头像 URL 可沿用，不据此要求全部外部资产禁止访问 B站。

## 6. 数据与外部边界

### DR-01 展示数据语义

本表描述页面需要的信息，不指定 TypeScript 字段名、数据库表结构或 HTTP 协议。

| 数据对象 | 所需语义 |
| --- | --- |
| UP 主 / 评论作者 | 稳定用户标识、昵称、头像 URL；评论/回复作者与当前动态作者 ID 比较，不依赖全局 creator 或同名判断 |
| 动态 | 稳定动态标识、所属 UP/作者、发布时间、独立的编辑时间及精度、正文、按顺序排列的图片、来源动态评论总数 |
| 图片 | 可供缩略展示与预览使用的 OSS URL、顺序及可用尺寸；不要求前端从文件路径推断来源 |
| 一级评论 | 稳定评论标识、所属动态、作者、发布时间、正文、按顺序排列的图片、点赞数和回复总数 |
| 回复 | 稳定回复标识、所属一级评论、作者、发布时间、正文、点赞数及可缺失的回复目标 |
| 分批读取结果 | 本批数据及是否还有后续数据；可准确区分读取失败与成功空结果 |

稳定标识使用字符串，不能用分页位置、数组下标或经 JavaScript 数字转换的大整数替代。时间数据保留可信时区与精度，避免通过无时区字符串猜测时间或给分钟精度补造秒；展示格式遵守 FR-04。

独立 mock 正常数据的总数、回复数与完整测试集一致。生产归档可能只有部分可读内容：来源总数、本地一级评论数量、本地回复数量分别表达；前端不得用当前已加载或归档条数覆盖来源总数，缺失不伪装为零。

### DR-02 真实读取契约与独立 mock 回归

- 展示层通过统一读取接口获取动态列表、详情、一级评论和回复，生产接入真实 API；浏览归档不隐式触发上游同步，采集异常不使旧归档失去可读性。mock 作为独立回归测试实现保留，失败触发方式确定、可重复，不混入生产归档。
- 排序、分页、取消、空结果、不可用与失败可通过接口分别表达，展示组件不直接依赖数据库或测试文件组织方式。
- 列表读取显式表达全部或某 UP 的 scope；不透明 cursor 绑定 scope、资源、父级 ID、排序及其读取上下文，不能跨范围混用。访问快照与请求身份同步隔离，错误或过期结果不污染当前视图。
- 对完整已归档集合先排序再分页；失败不推进 cursor，重试仍读取失败批次，不以去重掩盖遗漏。真实数据更新期间的具体分页一致性协议留给实施设计，但必须保证约定读取范围内不重不漏、快照不串 scope。
- 现有 `DynamicReader.creator`、无 scope 的列表接口、无图片的 `Comment` 等只是旧契约，需要按本期语义演进；不能把当前代码形状当作已满足新需求。本文不固定 HTTP API 路径、DTO 和表结构，由 HLD 及后续实施规格在这些语义约束下细化；页面路径仍遵守 FR-02。
- mock 使用虚构身份、模拟内容与合法演示素材，不依赖真实采集凭据或服务；生产页面的采集接口边界见 NFR-04。

### DR-03 图片 URL 边界

- 组件接收可直接用于展示的图片 URL，不自行拼接 B站域名、OSS 桶地址或本地目录。
- 生产业务图片由后端返回公开读 OSS URL，浏览器直接请求，不经应用服务器转发；项目内图片 URL 仅供独立 mock/回归素材使用。
- 缩略图和预览图可使用相同或不同 URL；是否生成尺寸变体、使用 OSS 图片处理、缓存或 CDN 尚未确定，不自行做决定，也不把 CSS 缩小宣称为已压缩。
- 本期已选择公开读，不引入签名 URL 续期需求；公开 URL 可被直接访问的风险见 NFR-04。头像边界遵守 FR-20。

### DR-04 持久化配置与归档关系

- SQLite 保存 UP 的 UID、上游昵称/头像、启停、模式、N 和关联指定 ID；配置由 `/manage` 维护，重启后不丢失，不提供手动覆盖昵称头像。
- UP 身份、监控配置与归档集合分开建模，保留 UP—动态—一级评论—回复关系；停止、删除 UP 监控配置或指定目标、移出窗口或上游消失不级联清除身份及归档。
- 动态图片与一级评论图片使用各自归属关系，保留顺序、尺寸、source、OSS 地址/上传状态与错误；共用上传能力不等于混用图片组或丢失归属。

### DR-05 检查、观察与同步状态

- 持久保存最近检查、最近成功同步及错误；按目标区分观察到的编辑信号/评论计数与各部分已成功同步信号，来源未知与有效零值不同。
- 正文、评论/回复、图片具有独立完成状态及持久化未完成工作；失败不更新该部分的成功 checkpoint，重启后仍可恢复未完成工作，后续无新变化仍可重试，不把“检查成功”或“一部分成功”写成全部同步成功。checkpoint 只对应实际完成的观察版本，不能借同步期间较新的 observed 冒充该版本已同步或清除其未完成工作。
- 编辑时间保留规范化值、时区及来源精度，发布时间独立；计数同时保留来源总数和实际本地归档数量，不能互相覆盖。
- 管理页面聚合状态必须能追溯到未完成部分与最近错误；原始凭据不得通过状态、接口响应或错误提示暴露。

## 7. 非功能需求与约束

### NFR-01 响应式与浏览器

- 检查 360px、390px、768px、1280px 视口宽度，页面不得横向溢出；长昵称、正文及图片不能撑坏布局。顶部 UP 选择条允许自身横向滑动，但不能使整个页面横向溢出。
- 本期正式兼容验收仅面向 Linux Chrome 与 iPhone Safari（2026-10-12 用户明确确认）；其他设备/浏览器移出本期目标，不承诺其兼容，也不承诺老旧版本或 B站 App 内置浏览器兼容。
- 验收记录实际浏览器版本、设备或模拟方式。桌面模拟、自动化浏览器与真机结果分别标明，不能互相冒充。

### NFR-02 可操作性与焦点

- 主要触控按钮提供约 44px 的点击区域；桌面交互支持键盘访问及可辨识的焦点。
- 图片预览的关闭、切换和长图显示方式操作应可通过键盘完成；预览打开时焦点应位于预览内，关闭时返回触发处。
- 图片失败、空态及加载状态有可理解的文字提示，不只依靠颜色或失效的图片表达。
- 手机横向切图、长图纵向阅读与底层页面滚动相互区分，遵守 FR-09。

### NFR-03 加载与资源

- 采用 FR-05 至 FR-07 的分批展示规则，不在页面打开时一次渲染全部动态和评论。
- 列表缩略图懒加载，预览图或原图按需加载；打开一张预览不要求预先下载所属动态或一级评论图片组的全部原图。
- 图片应预留合理展示空间，避免加载完成后严重扰动阅读与位置恢复；具体尺寸和实现方式在开发阶段确定。
- 懒加载不等于压缩，使用 OSS 也不保证图片性能。本期不设置未经基准测试的加载时间、并发或内存指标。

### NFR-04 文本安全与范围隔离

- 正文、昵称、评论及回复作为文本安全渲染，不将输入中的标签或脚本作为可信 HTML 执行。
- 生产浏览器读取本应用 API 和 OSS 业务图片，不直调 B站采集接口，不读取、持有或接收 B站采集凭据及 OSS 上传凭据；上游请求和上传由服务端执行。采集与上传凭据仅保存在服务端、仓库之外，不进入版本库、前端产物、UI、API 响应或日志，错误与诊断也必须脱敏；管理页不提供凭据编辑。已有 B站头像 URL 可用于显示，不扩大为“浏览器禁止访问所有 B站资产”。
- 首期无账号/权限系统，管理页面及 API 无鉴权；若部署公网，第三方可能读取归档或修改监控配置，公开 OSS 图片也可被直接访问。该风险已明确，不把“个人自用”、隐藏入口或仅前端页面当作访问保护，不擅自增加前置鉴权。
- 真实内容的合法获取与公开暴露风险不因只读样本成功而消失；不实现购买、解锁或会员权限。mock 隔离运行时不依赖真实服务或凭据。
- 失败样例通过开发/测试入口触发，正常用户页面不增加故障控制面板。

### NFR-05 技术与构建交付

- 前端保持 React + TypeScript + Vite + React Router 及原有轻量样式/测试技术，不引入大型全站 UI 框架；Node.js 仅使用 nvm 管理，依赖和脚本仅使用 pnpm。
- 后端采用 Python + FastAPI + SQLite；Python 环境与依赖仅使用 uv。运行架构为一个 API 进程与一个独立采集进程，不引入 Redis、Celery 或多 API worker；优先评估二者与 SQLite 同机运行，不把必须在 2 核 2GB 同机稳定承载作为已确认能力或交付承诺。
- 前端构建在本地或 CI 完成，由 Nginx 托管静态产物；不需要常驻 Node.js 应用或 SSR。采集进程承担上游检查与同步，API 进程提供归档读取与管理，不能把耗时采集直接绑定为浏览器请求生命周期。
- 优先以阿里云 2 核 2GB 为运行目标，不承诺并发、目标数量、响应时间或内存容量；当前未实测该环境的全链路，也未持续验证 15 秒调度。不得用样本规模推导“已可稳定承载”。
- 首期不建设备份或容量不足治理；磁盘/OSS 增长、SQLite 同机读写竞争与长期运行风险需如实记录，不能宣称具备未要求的容灾能力。
- 本期后续实施交付应覆盖真实服务、数据库及采集、前端、多 UP 管理、图片归档、独立 mock 回归、测试与可复现运行/构建说明；当前文档任务不执行实现、云部署或资源配置。
- 部署说明区分 API、SPA 页面路由与静态资源：有效列表、单 UP、详情及管理地址刷新可用；API 错误与缺失资源不能回退成入口 HTML。

## 10. 后续决策与变更管理

### 10.1 已确认与待设计的区别

Python + FastAPI + SQLite、一个 API 进程与一个独立采集进程、固定 15 秒检查、两种目标选择、失败重试和归档保留、公开读 OSS、无首期权限/备份/容量不足治理均已确认，不再列为“未来接入再决定”。本文规定的四类页面路径也已固定。2 核 2GB 同机是优先评估方案，不是必须同机或容量已验证的承诺。

具体 API 路径、DTO、数据库表结构、进程间协调、真实数据变化时的分页一致性、组件划分、样式数值和接口函数签名属于后续实施设计，必须满足本文，不得借设计增加目标硬上限、退避、自适应或新的采集模式。图片尺寸变体、格式处理、缓存、CDN 与费用预算尚未决定，不由实现者替用户决定。

### 10.2 证据与风险边界

- [后端可行性记录](../backend/evidence/backend-feasibility.md) 中 13 次只读 GET 只证明对应样本在当时的表现：11 次 API 成功、1 次 `opus/detail` HTTP 412 后停止该探测、1 次普通页面 HTTP 200。编辑样本页面时间为 13:01，通用详情为 10:38，但 `pub_ts` 相同；正文 BLOCKED 样本的评论计数与首屏可读（来源计数 501），另一个抽样评论计数为 235。这些不是全量评论归档、所有页面稳定可读、持续 15 秒性能、数据库、OSS、管理页或新 UI 的验收，不从首屏和计数推断全部已采齐。
- 仍未实测持续 15 秒运行、2 核 2GB 同机全链路、所有动态页面的编辑时间可用性，以及多次自然编辑后的持续更新。分钟精度编辑漏检、评论总数抵消/纯编辑漏检是已接受的检测限制，不靠未确认策略补齐。
- 公开无鉴权管理和 OSS 图片存在暴露风险；无备份和容量治理存在数据丢失及存储增长风险。记录风险不等于已增加访问保护、容灾或容量承诺。
- [UI 参考](../design/ui-reference.md) 及图片作为保留阅读区域的一比一视觉基准，监控管理页按同一视觉体系改版；不把截图里所有功能、相对时间或展开方式引入产品。视觉基准、必要差异、管理规则映射及本期验收分别记录，历史截图不自动成为新目标的通过证据。
