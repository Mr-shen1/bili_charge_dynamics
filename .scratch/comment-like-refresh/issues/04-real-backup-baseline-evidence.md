# 04：真实备份基线与请求账本验收

Status: resolved

**What to build:** 拿维护者服务器上取回的真实备份当基线，证明夜间刷新「只改点赞、不改别的、不加删除」，并记录一次刷新的真实请求数与耗时，与规格估算对照。产出可复核的证据文档。

**Blocked by:** 01 — 凌晨窗口驱动的根评论点赞刷新；02 — 楼中楼整楼点赞刷新；03 — 刷新会话的副作用隔离。

## 验收标准

- [x] 基线：用仓库外的真实备份（3 动态 / 167 根 / 16,594 楼）做基线，记录刷新前的点赞快照与「最热」排序结果。
- [x] 替身刷新：用替身传输跑一次完整刷新，替身部分点赞上调、部分已归档评论故意不返回。
- [x] LR-03 逐字段 diff：根评论与楼中楼的行数与主键集合完全不变，只有计数类字段变化，正文/媒体/作者/时间戳完全相等。
- [x] LR-04 不删除：来源已缺失的评论在本地原样保留。
- [x] LR-05 缺失不擦除：来源返回空点赞时旧值保留；返回真实 0 时写入 0。
- [x] 成本核对：记录一次刷新的请求总数与总耗时，与父规格中的规模估算对照。
- [x] 证据落盘：证据文档包含来源库标识、样本范围、命令入口与明确的未验证项；真实上游、OSS、飞书与部署未验证时如实标注。

## 验证范围

本票不新增生产代码，只做验收与取证。真实备份只用于基线与只读比对，不得对着真实来源跑全量刷新。备份库留在仓库外（`~/bili-testdata/likes-baseline.sqlite`），不提交。

## Answer

证据文档：`.scratch/comment-like-refresh/evidence/04-real-backup-baseline.md`；可复跑脚本：`.scratch/comment-like-refresh/evidence/refresh_baseline_acceptance.py`；机读产物（逐行 diff、请求账本、副作用快照）在同目录 `04-real-backup-baseline/`。本票无代码提交。

基线库 55.2 MiB、sha256 `7b5e58d5…68df`，运行前后字节与 mtime 一致（只读）。样本是全量而非抽样：3 动态 / 167 根 / 16,594 楼 / 143 个非空楼，备份 schema v28 由产品自身迁移到 v29。

结果：行数 167→167、16,594→16,594，新增与消失均为 0；16,761 行逐字段比较，变化只落在 `like_count`、`is_pinned`、`source_reply_count`，正文/媒体/作者/时间等内容指纹全等，未解释字段 0。故意不再返回的 2 根 + 8 楼共 10 行原样保留；空点赞保留旧值（23 / 155），真实 0 写入 0（48→0、166→0）。

请求账本 1,241 次（根页 16 / 楼页 1,218 / 计数 7），与按备份算出的预期完全一致；最近邻间隔仍是根 0.329 秒、楼 0.108 秒。墙钟 270.5 秒，按生产等待参数记账的标称耗时 246.9 秒，补上真实上游往返后约 7–9 分钟——父规格原估 918 请求 / 5–8 分钟偏乐观约 34%，已按实测修正。
