# 05：飞书通知同群严格按评论时间保序

Status: resolved

**What to build:** 同一个飞书群里，评论通知严格按评论发表时间先后到达：前一条没有出结果（成功或放弃）之前，后一条不会被发出——即使前一条正在失败退避、正在限速顺延、或者配置还没就绪。一条永远发不出去的消息只耽误十几秒就会被放弃并留痕告警，然后队列继续推进。三个群各自独立排队，一个群卡住不影响另外两个。

**Blocked by:** 无。

## 验收标准

- [x] NO-01 排序键生效：事件入队时记录可比较的排序时刻（评论类取发表时间，公告类取入队时刻）；以末页倒序读入的一组回复（较新先入库），实际发出顺序按发表时间从早到晚。
- [x] NO-02 同群严格排队：每个投递角色（UP 群、全部群、系统群）同一时刻最多一条在途，领取时逐角色取排序时刻最早的一条；队头处于失败退避中时同群后续一条都不发出，另外两个群照常推进。
- [x] NO-03 限速顺延不插队：触发主动限速时，被顺延消息仍是该群队头，同群后续消息不被领取。
- [x] NO-04 退避与放弃：退避保留指数步长但上限收到 8 秒，实际间隔为 2、4、8 秒；真实失败最多重试三次（共四次尝试），仍失败则进入既有终态、写入可辨错误原因、登记既有类别系统告警，队头推进到下一条。
- [x] NO-05 平台限流不消耗额度：平台返回的限流响应（HTTP 429 与业务限流码）按平台给出的等待时间顺延，不计入那三次重试。
- [x] NO-06 配置未就绪兜底：路由缺失或写错的记录仍按 60 秒粒度复检，但受 10 分钟驻留上限约束，超过则放弃，不永久占住队头。
- [x] NO-07 公告类有确定位置：系统告警与小时心跳按入队时刻参与排序，不排到最前或最后；心跳原有有效期仍作为额外约束生效。
- [x] NO-08 类型一致：评论、动态变化、系统告警与心跳在同样的失败序列下表现一致，不按角色区分规则。
- [x] NO-09 旧库迁移：用已有待发事件的旧库升级后领取顺序仍可用，空排序键不被当成最早或最晚。
- [x] NO-10 串行不降低吞吐：限速受限的积压场景里，每目标串行的实际发送速率不下降（瓶颈仍由限速决定）。
- [x] 现状保持：主动限速额度（每目的地 5 次/秒、100 次/分钟，系统群独立额度且领取优先）、逐目标故障隔离与跨群不承诺同时到达全部保持原样。证据：`test_no10_per_group_serialization_keeps_the_rate_limit_as_the_bottleneck` 与既有通知限速用例。
- [x] 迁移：通知事件表新增排序时刻列，旧行按入队时刻补齐；与 01 的迁移在同一个版本内协调顺序。

## 验证范围

覆盖 NO-01—NO-10。使用真实 SQLite＋真实 outbox 与投递循环＋替身飞书传输＋受控时钟，只替换外部 HTTP 与时间。真实飞书群、真机与部署未验证。本票与 01—04 互不依赖，仅共享一次迁移。

## Answer

排序键：`notification_events.sort_at` 与 `notification_deliveries.waiting_since` 与票 01 的锚点同处数据库版本 29；五处入队点写入排序时刻（评论类取发表时间、公告类取入队时刻），旧行按 `created_at` 回填，查询用 `COALESCE(sort_at, created_at)` 所以空键既不会掉到最前也不会到最末。

同群单飞：`outbox` 的领取改为逐角色取排序时刻最早的待发记录（系统群优先的老口径保留），在途谓词是 `state='inflight' AND lease_until > now`；一拍内循环补位，吞吐仍由限速（5 次/秒、100 次/分钟）决定而不是被轮询节拍压到 1 条/秒。退避仍是 `failures` 的 2 → 4 → 8 秒指数步长，上限从 300 秒收到 8 秒。

确定性放弃：真实失败第 4 次尝试后进既有终态 `expired`、写入 `retry_exhausted`；路由缺失的 `waiting_config` 仍按 60 秒复检但受 10 分钟驻留上限约束，超时写 `config_timeout`。两条都发既有类别系统告警并写 `delivery_abandoned` WARNING 日志；平台 429 与业务限流码按平台给的等待时间顺延且不计失败。系统目标自己不再登记新告警（否则递归），留痕边界写在 `docs/backend/api/notification-process.md`，断言保留行内原因与日志。

证据：`backend/tests/test_notification_ordering.py`（NO-01—NO-10 各至少一例），另按新契约更新了 `test_notification_delivery.py`、`test_notification_rate_limit.py`、`test_notification_recovery.py`、`test_notification_alerts.py`、`test_notification_heartbeat.py`、`test_notification_combinations.py`，并在 `docs/design/feishu-notifications.md` 用同群保序取代了原来的非目标声明。
