# 04：桌面正文新标签与手机详情返回

Status: resolved
Blocked by: 03

依据：[实施规格](../spec.md)。覆盖 UI-04、UI-06、UI-07 和 UI-15 的详情直达部分。

## 交付内容

桌面点击动态正文，在独立“动态详情”标签中从顶部阅读，原列表及内联评论保持原样；手机继续站内打开详情并通过 `‹ 动态列表` 返回来源。按宽窄屏去掉重复详情页头，不影响错误恢复或通知精确入口。

## 验收条件

- [x] 桌面普通正文入口实际打开新标签，页面对应正确动态，标签标题为“动态详情”，来源列表 URL/滚动/评论排序/回复页码均不改变。
- [x] 新标签具有可直接访问的详情 URL，刷新/复制地址仍可读取；不依赖 opener 内存，正确设置 opener 隔离，组合键/中键不重复开窗。
- [x] 正常桌面详情没有“动态详情”页头和“返回列表”按钮；必要的错误/无效地址恢复操作仍存在。
- [x] 手机正文进详情顶部、评论按钮定位一级评论区；正常详情只保留 `‹ 动态列表`，不再重复旧按钮和标题。
- [x] 手机有有效来源时返回正确 scope 并恢复列表状态；直达或刷新失去来源时返回全部动态，不意外把用户带离本站。
- [x] 图片、头像展示、文字选择、正文展开及其他内部控件保持现有事件隔离和键盘焦点语义。
- [x] 根/回复通知精确链接与普通详情分别设置正确标题和定位，不因新标签规则重写精确链接意图。
- [x] 浏览器测试实际观察新页面、opener 隔离和原列表状态保留；模拟浏览器历史及四宽度检查通过，不以调用 open 的 spy 代替用户结果。

## 依赖理由

03 先交付来源列表的内联评论快照，本票才能证明正文新标签没有破坏那套真实状态，而非只检查一个尚无评论的静态列表。

## Answer

宽屏正文入口改为**真实新标签**：卡片正文点击 `window.open(href,'_blank','noopener,noreferrer')`，卡片链接自带 `target="_blank"`/`rel="noopener"`，因此 popup 的 `window.opener` 为 `null`，新标签只靠 URL 与只读接口取内容；本标签完全不导航，列表 URL、滚动、卡片内联评论的展开/排序/已读批次与楼中楼页码原样保留。组合键与中键一律交回浏览器原生语义（应用不再调用 `window.open`），文字选择、图片、作者展示、评论入口与评论正文继续被既有 `closest(...)` 判定挡在正文导航之外。窄屏保持站内入口：正文进详情顶部，评论按钮定位一级评论区。

正常详情不再有可见页头：宽屏没有“动态详情”标题与“返回列表”，窄屏只留一个 `‹ 动态列表`（14/22、常规字重、点击区 ≥44px），`h1` 保留为视觉隐藏的页面结构标题；`error`／`cancelled`／`not-found` 两端都保留 `‹ 动态列表` 与既有“重试”，删掉的是正常阅读的重复页头而不是恢复能力。手机有来源时 `‹ 动态列表` 真实后退并恢复来源 scope 与位置，直达/刷新无来源时 `replace` 到全部动态，不离站。

标签标题统一由 `documentTitle.ts` 按路由决定（`detail`/`comment-locate` = 动态详情，`reply-locate`/`thread` = 回复详情，`conversation` = 会话列表），直达、刷新与新标签一致；通知精确链接仍按 URL 定位并高亮目标，本票只改“标题怎么来”，不改“定位怎么算”。

验证：合并 07 已集成的 `01716b2` 后，`pnpm check`（32 文件／346 passed）、`pnpm check:dist`、主 e2e 235 passed／18 skipped／0 failed（独占 4318/4319/4320）、manage e2e 8 passed。`pnpm test:e2e:delivery` 停在 `beforeAll`“等待三链实际投递消息”，在主仓 `01716b2`（不含本票改动）上以同样方式失败，判定为与本票无关的既有 delivery 缺陷，未扩范围修复；Nginx 静态交付用例属 09 范围未运行。真机、正式视觉签收与部署未验证；黄金图未更新，留给 09／10。

证据与限制见 [04 证据](../evidence/04-detail-tabs-and-mobile-navigation.md)。本票交付后 09 可做组合回归。
