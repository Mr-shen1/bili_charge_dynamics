# 03：桌面卡片内展开评论与独立阅读状态

Status: resolved
Blocked by: 02

依据：[实施规格](../spec.md)。覆盖 UI-05、UI-07 及 UI-08 的列表内评论部分。

## 交付内容

桌面点击卡片的评论图标和数字，在该卡片下方展开/收起完整一级评论阅读区，留在原列表；多张卡片可以分别排序、加载评论和分页阅读回复。当前检出仓库尚无此挂载能力，本票要交付实际功能，不能仅修文案。

## 验收条件

- [x] 气泡＋数字外观及计数语义不变；宽屏点击不跳详情、不改列表 URL，再次点击可收起；窄屏原评论入口不变。
- [x] 复用 02 的评论区域能力，绑定各自动态/访问身份；不同卡片的排序、cursor、正文展开、回复展开/页码及错误独立。
- [x] 一级评论分页、置顶、评论图片和现有文本折叠可用；桌面楼中楼保留最多 3 条预览、展开每页 10 条替换，仍为时间正序。
- [x] 评论、图片、分页及文本选择均不触发动态正文导航；收起后焦点/位置落在可理解的卡片入口附近。
- [x] 列表加载更多、scope 切换和有效历史返回正确保留或恢复所属访问的卡片状态；旧快照缺少新增字段可安全按未展开处理。
- [x] 展开/收起及切换卡片、scope 时取消或隔离旧请求；某一卡片失败不清空列表或其他卡片，不把旧数据当新结果。
- [x] 实际生产 Adapter 浏览器覆盖两张卡片同时展开、独立排序和回复翻页；既有列表/详情及手机回复流程回归通过。
- [x] 布局和无障碍关系不依赖重复 DOM ID，768/1280px 无横向溢出；窄屏切换时不出现一套额外内联评论入口。

## 依赖理由

02 提供带独立访问上下文和新排序行为的评论区域。本票在同一能力上新增列表宿主与快照，不另造第二套评论读取状态机。

## Answer

宽屏卡片评论按钮改为在当前卡片下方展开／收起完整一级评论阅读区，列表与 URL 都不跳走；窄屏仍走原站内入口进入详情并定位评论区，没有第二套入口。卡片区域复用 02 的 `CommentSection`／`useCommentsRead` 与 `adoptCommentSnapshot`，身份为 `list:{动态 ID}`，没有新建评论读取状态机：每张卡片的排序、cursor 批次、正文展开、回复展开与页码因此天然独立。

列表访问快照新增按动态 ID 索引的 `comments`（键存在即展开），旧快照缺该字段按未展开恢复，异区状态被丢弃；收起只停读并隐藏、再展开沿用同一面板状态，卸载时仍在读取的面板记作已取消并可从原 cursor 继续。卡片点击忽略 `[data-comment-region]` 内的全部目标，评论正文、图片、分页与文本选择都不触发正文导航；内联区标题改为静态计数，避免同一卡片里出现两个同名按钮；收起后焦点交还该卡片评论入口。

验证：`pnpm check`（29 文件／328 passed）与 `pnpm check:dist` 通过；主 e2e 224 passed／15 skipped／0 failed（独占 4318/4319/4320，含新 spec 在桌面与移动项目各自的有效用例）。顺带把 `list.spec.ts` 中“设完 scrollLeft 立刻读测量结果”的既有竞态断言改成轮询（阈值不变，产品行为未改）。真机、正式视觉签收、四宽度全截图与部署未验证；黄金图未更新，留给 09／10。`test:e2e:location` 的 4178/4325 属本轮 05 的窗口，本票未占用（不改接口）。

证据与限制见 [03 证据](../evidence/03-desktop-inline-card-comments.md)。本票交付后 04 可开始。
