# 13：人工反馈变更——完整会话与入口定位

Status: resolved
Blocked by: 无（10 首轮反馈）

依据：[正式设计](../../../docs/design/reading-ui-refresh.md) §5；[实施规格](../spec.md) 决定 8–9；[反馈与截图](../evidence/10-feedback-round-1.md)。

## 交付与验收

- 手机点击“查看对话”，前端单次请求完整本地会话并一次呈现，无分页控件、无 page/limit 分页查询、无循环请求旧分页拼整段、无隐藏条数上限；原回复详情每页 10 条和排序不改。
- 内容仍按真实关系、整段时间正序；缺祖先/环/跨根等安全边界与只读不触发上游保持。API、production/mock Adapter和页面契约同步；如保留显式 page 的旧 HTTP 兼容行为，前端不得使用它。
- 新进入/直达/刷新后，将入口回复定位到视口中央并显示“刚才查看”文字及轻微高亮；位置夹在真实可滚动范围内，不为居中给列表补留白（短会话与首条停顶部、末条停底部，不留空白带），不被默认回顶部覆盖、不持续抢夺用户滚动。
- 历史返回/前进与会话返回恢复来源排序/页码/阅读位置；同访问已有阅读位置优先恢复，不每次重置定位；无来源 replace 返回所属回复详情时间序第 1 页不变。
- 先红后绿，沿用既有真实 HTTP＋临时 SQLite 与生产装配浏览器边界：11 条以上会话一次完整读取、入口原在旧后续页/整段末尾仍能定位且完整可见、标记唯一且准确、直达/刷新/返回恢复，兼容回复定位与旧显式分页（如保留）。
- 本票负责会话实现、相关 API 文档/前端 README/测试与证据；勿修改管理或 UP 条样式；正式设计/规格由主线程维护。
