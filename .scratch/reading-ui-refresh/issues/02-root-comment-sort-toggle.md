# 02：一级评论默认按时间与单按钮排序

Status: resolved
Blocked by: None

依据：[实施规格](../spec.md)。覆盖 UI-08 的一级评论部分及 UI-12 的评论标题/排序层级。

## 交付内容

用户首次读取一级评论时默认按时间，点击 `☰ 按时间` / `☰ 按热度` 切换；当前详情内的评论区是本票的完整演示入口。把该用户区域做成可承载独立访问上下文的公共能力，供 03 挂载到列表，而非先做无可见结果的大范围重构。

## 验收条件

- [x] 无快照的新访问显式读取已有 latest 排序；有快照时恢复原排序，服务端省略 sort 的 hot 默认不被破坏。
- [x] 控件只显示当前排序，图标、13px 字号与至少 44px 点击区域一致；“评论 N”14px，小于动态正文。
- [x] 来源明确置顶在两种排序下优先；完整本地集合排序后每批最多 20 条，次级排序、缺失值与 ID 规则不变。
- [x] 切换排序重置首批及相应文字/回复展开状态，并定位评论区；加载中、失败重试和快速反复切换不会混用旧批次。
- [x] 根评论精确定位显式传入当前排序，不能显示“按时间”却用 hot 的位置结果；原通知定位仍落到目标。
- [x] 读取与交互状态由显式区域身份隔离；现有详情入口可直接使用，不依赖唯一全局排序或固定 DOM ID。
- [x] 生产 Adapter 与受控浏览器用例证明请求参数、返回内容及延迟响应隔离；不能只通过 mock 控件文字测试。
- [x] 保留现有根评论分页、评论图片、折叠、只读点赞及错误边界，更新变更范围的契约/测试预期。

## 边界

不新增回复热度、不改桌面楼中楼时间序。提取共享区域仅服务本票可验证的排序和后续多区域复用，不提前把列表挂上半成品评论。

## Answer

已交付：一级评论新访问显式读 `sort=latest`（`emptyCommentSnapshot()` 默认 `latest`），有快照时恢复原排序；服务端省略 `sort` 的 `hot` 默认未改并新增回归测试。排序改为单按钮 `☰ 按时间`／`☰ 按热度`，文字只显示当前排序，13px、44px 点击区；“评论 N”14px 小于动态正文。切换重置首批与文字/回复展开状态并定位评论区，旧排序迟到结果不覆盖新选择；根评论定位始终显式带当前排序。评论区带显式区域身份（详情默认 `detail:{dynamicId}`，`data-comment-region`），快照记录 `regionId` 且不采纳别的区域状态，03 可直接按该身份挂载多区域。既有分页、评论图片、折叠与错误边界保持。

验证：`pnpm check`（typecheck + 299 单测 + e2e 项目守卫）与 `pnpm check:dist` 通过；主 e2e 209 passed / 2 个与本案无关的既有 `app-shell.spec.ts` 严格模式失败（已在基点 `eca658b` 复现）；`pnpm test:e2e:location` 4 passed（实际 API＋隔离 SQLite）；后端根评论与定位 29 passed。真机、正式视觉签收与部署未验证；黄金图差异留给 09/10。

证据与限制见 [02 证据](../evidence/02-root-comment-sort.md)。
