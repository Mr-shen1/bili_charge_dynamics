# 动态阅读与监控管理界面优化：实施规格

Status: resolved（01–13 均已收口；最终代码候选 `b1dec5c`，10 由用户明确确认验收完成；设备留证限制保留，黄金图已按后续授权更新至版本 2，独立复拍 63/63 通过，未部署；用户授权整理提交、合 main 并 push）

依据：[已确认需求与设计](../../docs/design/reading-ui-refresh.md)及其第四版原型。用户已签收原型，并要求直接生成规格与票据；本规格最初用于实施规划；当前实现、测试与用户验收已完成，证据与留证限制见[10 验收记录](evidence/10-visual-and-device-acceptance.md)，不表示允许部署。业务规则与视觉数值以正式设计为单一来源，以下用用户故事和实施边界组织交付。

## 问题陈述

阅读页面的公共导航和重复标题占用空间，UP 选择条的长昵称、留白及滚动条影响手机阅读；字号、行高与按钮视觉大小缺少一致层级。桌面用户希望留在原列表看评论，并在独立标签阅读动态正文。手机用户在分页楼中楼中难以追踪关联回复，回复区也缺少热度切换。管理页的启停位置与偏大的按钮妨碍快速识别和操作。

## 解决方案

保留现有数据读取、监控和通知业务，在统一排版下收敛阅读导航，明确宽窄屏入口差异，改用默认按时间的单按钮排序，为手机提供按真实关系组织的会话列表与返回恢复，并收紧管理操作区。

实施结果必须覆盖正式设计 UI-01–UI-15；原型中没有展示完整的图片、管理字段和错误状态继续遵守现有契约，不按原型的简化程度裁剪正式能力。

## 实施决定

1. **增量改版**：沿用唯一 Vue 应用、Element Plus、导航协调器、reader/adapter 和现有管理边界。复用既有组件和主题语义，不把独立 HTML 或另一套原型工具栏带入生产。
2. **领域关系**：对话按同一动态及一级评论下的真实父回复 ID 组织；起点本身计入数量，一级评论不计入。复用已有持久关系，目标是不新增持久化“会话表”或触发采集。
3. **文案边界**：改应用生成文案与无障碍标签，不批量改业务数据、API 标识、日志和历史技术术语。
4. **导航边界**：宽屏评论保留列表内展开；正文使用可直接读取的独立详情标签，并隔离 opener。窄屏保持站内正文/评论入口。共享顶栏裁剪与各页面局部返回入口分别处理。
5. **状态隔离**：scope、动态、一级评论、排序和访问身份共同界定读取与阅读状态。卡片间不共用评论分页；新标签不复制原标签内存；历史恢复和新访问默认值分开。
6. **排序兼容**：一级评论普通新访问显式请求已有 `latest`，服务端省略参数的 `hot` 默认保持兼容；根评论定位显式使用当前排序。回复页码读取增加可选 `sort=time|hot`，省略时仍为原时间正序；热度仅用于 page 模式，不扩展 cursor 预览。原时间 cursor 资源标识和有效 token 保留，不使旧 token 全体失效；热度不生成新的持久 cursor 快照。回复定位的参数与时间序页码语义不变，响应允许增加下一条规定的可空对话投影，旧字段保持兼容；通知直达显示时间排序；历史热度访问按自身快照恢复，不能把定位页码当热度页码。
7. **对话入口资格**：回复 page 读取及返回同类页内容的回复定位响应，为当前页每个条目增加可空的 `conversation` 投影，提供对话起点 ID、本地关联条数与上下文不完整标记；定位参数和时间序页码语义不变，通知直达也能展示入口；UI 由“至少两条且当前项不是起点”决定入口。投影从完整本地同根关系一次计算后映射到本页，不返回整个楼的关系全集，不逐个可见回复发请求；cursor 预览不需要此新增信息。生产和 mock Adapter 同步该语义，过渡期缺少投影不能触发用户名推断或当前页猜测。
8. **对话读取**：按动态、根评论、入口回复定位的只读 conversation 子资源，先对完整本地同根集合求关联分支，再按时间正序一次返回整段；前端单次请求，不循环分页，也不显示会话分页控件。不引入新的持久 cursor 表。响应提供所属身份、起点 ID、完整条目、本地对话总数和上下文不完整标记；根评论仅作为身份校验上下文，不在会话正文重复显示。不存在目标或跨父级身份返回既有 NOT_FOUND 类错误；缺失祖先与临时读取失败分别表达。同名、正文前缀、跨根数据、重复与异常环不能错误合并或无界遍历。原回复详情的分页与通知定位语义不变；如保留旧显式分页 HTTP 兼容入口，不得成为本轮 UI 的读取路径。本条由票 10 人工反馈更新，替代 06 首次实施时的会话分页方案。
9. **会话导航**：业务实体及代码命名用 `conversation`，与应用浏览 `session` 区分。新阅读路由包含动态、根评论和入口回复；支持刷新/直达。有效来源返回恢复回复访问；无来源时以 replace 返回所属回复详情的时间排序第 1 页，不跳出本站。会话完整显示后一次性将入口回复定位到视口中央，高亮并在昵称旁标注“刚才查看”；定位位置夹在真实可滚动范围内，不为居中给列表补留白（短会话/首条停顶部、末条停底部，不出现空白带）。同访问历史恢复不被重复定位覆盖，用户滚动不被迟到定位抢回。回到会话来源是新增的短期快照例外，不扩展成持久阅读历史。
10. **视觉与触控**：采用正式设计的字号/行高/间距标尺；管理按钮区分可见外观和实际点击区域。手机输入类控件的 16px 单独作用于输入，不全局放大按钮；旧 iOS 限制在实机验证前保留为未关闭。
11. **管理语义**：启停与重新添加共用右侧槽位，保持已保存配置与草稿分离、操作防重、过期响应隔离和独立危险操作区。表单同排文字、单选项、输入与按钮垂直居中，输入与按钮可见等高（桌面约 32px、手机约 36px），实际点击/聚焦区域仍至少 44px、手机输入 16px。通知和目标规则不因布局变化修改。
12. **工程约定与契约定稿**：以上分页、默认排序兼容、投影与无来源返回是本轮拆票采用的工程方案，不是已交付 API 声明。具体公开 URL、DTO 字段拼写由承接纵向票在现有风格下固定，并同步契约和真实 HTTP 测试；相邻票引用该已实现契约，不再另造一套。先复用现有父 ID 与查询，不预建迁移、全局缓存或索引；用万条回复夹具记录单次读取成本和调用次数，若确有必要再另记优化依据，不虚构性能阈值或承诺。

## 测试决定

优先沿用现有测试入口，避免为本次排版新增一套测试框架。按用户要求直接推进规格，以下采用现有工程边界；未把本轮规划写成另一次测试设计人工签收。

1. **最高主边界：浏览器可观察行为**。覆盖正式 mock 装配的阅读/管理流程，以及生产 Adapter 对实际隔离 API/SQLite 的关键闭环；通过角色、可访问名称、URL、页面内容和阅读位置判断，不依赖私有组件状态或 CSS 类名来证明业务成立。
2. **必要辅助边界：真实只读 HTTP 与临时 SQLite**。对全局排序、跨页关系、分支、缺失父级、来源/本地数量差异、定位和无副作用做契约测试；构造小而明确的真实记录，不以大批内部函数 mock 代替生产查询。
3. **沿用导航与竞态先例**。已有精确链接、详情/回复位置恢复、排序切换受控延迟和图片历史测试提供范式；扩展到列表内多卡片、新标签、会话返回与无来源场景，特别覆盖“通知定位页的时间序第N页/目标锚点→查看对话→返回原定位访问”，不重新搭建独立导航框架。
4. **沿用管理先例**。已有管理写入、草稿保存、启停、删除与真实 API 替身测试继续使用；视觉变更不能使这些语义覆盖消失。
5. **最小关系样例**。单回复、A→B、带双分支、跨两页、父级未保存、同名不同身份、跨动态/跨根、缺失时间/点赞、异常关系；断言完整成员、确定顺序、入口资格与不会触发上游调用。
6. **异步行为**。分页/排序旧成功、旧失败及完成回调均不能覆盖新选择；切换后读取失败仍表示目标排序失败，可局部重试，不拿旧页冒充成功。
7. **视觉与设备分层**。四宽度检查换行、可点击区域、管理按钮右边缘、输入字号与正常详情页头；布局截图与正式视觉确认另计。真实 Chrome、iPhone Safari、飞书深链接以及隔离静态交付按受影响范围取证；不能拿无头 Chromium 替代真机结果。
8. **冻结内容边界**。复用同一组受控内容比较布局，另外检查真实长正文/昵称、折叠、图片预览、失败与空态；明确哪些只在原型中演示、哪些已在正式装配重跑。

## 范围排除

- 正式代码实施、部署和真实外部服务调用不在“生成本规格与票据”这次操作内。
- 不重做采集、限流、通知资格、归档存储策略或监控业务；读取不请求 B 站。
- 不进行 API/数据库标识的大范围改名，不替换来源正文里的“归档”。
- 不增加桌面会话列表入口、独立的全动态评论列表页、真实点赞/发评论或回复图片。
- 不重写图片预览引擎，不改变原图归属、已有折叠规则或通知精确链接语义。
- 不把临时浏览恢复扩展为跨重启或跨标签页同步的阅读历史。
- 不将原型省略的管理字段当作功能裁剪，不改变保存/启停/删除与通知开关的业务关系。
- 不以原型验证替代生产测试、视觉签收或真机验收，不自动更新黄金图掩盖回归。

## 补充说明

- 票 10 本轮三张人工反馈图与整改要求见 [10 首轮反馈](evidence/10-feedback-round-1.md)。12 承接头像裁切与管理对齐；13 承接会话整段单次读取、入口定位与标记。旧候选及既有测试证据保留历史，新候选必须另行复验；任何自动化绿灯不代替人工签收。
- 已核实的版本差异见[基线与测试边界](evidence/baseline-and-seams.md)：用户确认其使用环境已有桌面列表内评论，但本次检出仓库仍跳详情。针对该仓库，卡片内评论与正文新标签都需要实际补齐；不是只改文字或修原型，也不以仓库旧逻辑推翻用户确认的目标。
- 文档阶段不增加架构 ADR：本次主要是可逆的 UI/读取扩展，既有技术栈与进程边界保持不变。
