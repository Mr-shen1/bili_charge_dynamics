# 03：跨进程风控暂停与状态查询

Status: ready-for-agent

**What to build:** 任一 B 站源入口收到 HTTP 412／429 后，API 和 collector 统一持久暂停发送；执行者可只读查询状态，需要联网的管理操作明确暂不可用，不依赖源站的工作仍可继续。

**Blocked by:** 01 — 统一 B 站请求发送入口。

## 验收标准

- [ ] 仅 HTTP 412／429 触发全局保护；其他 HTTP 状态、业务码、凭据、网络和内容受限的原处理不扩大，尤其不把业务码 -412 当 HTTP 412。
- [ ] SQLite 原子保存全局状态、状态代次、首档 1 分钟冷却期限及触发接口；不按 UP 拆开，重启不清零，迟到的一波风控响应不会连跳多档。
- [ ] API 与 collector 的真实独立进程共用保护状态；业务接口、预热、图片下载、手动初始化／媒体重试以及重定向后续请求都不能绕过。
- [ ] 响应层在上层吞掉异常前报告风控，包括原本忽略错误的预热；触发后不再继续翻页、预热或自动重试。已在途返回的数据只按原版本／令牌规则安全提交。
- [ ] 新增 GET /api/manage/risk，仅读取本地状态，返回状态、进入时间、档位、可空探测时间、脱敏触发信息及可用探测摘要，不触发采集或泄漏内部 owner／令牌。
- [ ] 需要源请求的管理及手动同步返回 503 SOURCE_RISK_PAUSED、固定安全提示、状态和可空时间；有未来截止时间时附 Retry-After。原有输入校验／本地冲突仍正常，不创建半成品或返回伪成功统计。
- [ ] 归档阅读、纯本地管理、停用／删除、已下载数据提交及 OSS 上传仍可用；后台保留 pending 和已有错误，不每个节拍新增失败或伪造成功时间。
- [ ] 状态存取失败时禁止新源请求，返回存储错误；原子迁移保留归档、媒体、阅读 cursor 与未完成工作，不预占后续迁移版本。
- [ ] 记录可关联的首次触发、暂停及被拒绝原因日志并保持脱敏，避免每 2.7 秒重复同一警告；补齐接口契约与必要的既有操作固定错误提示，不新增页面。
- [ ] 真实双进程、同一临时 SQLite 与上游账本证明一进程触发后另一进程停止发送；重开保留剩余期限，普通错误对照及本地可用性回归通过。

## 验证范围

主要覆盖 RC-05、RC-09 及持久暂停部分 RC-06。本票到期不自动清除保护，也不添加临时强制解锁入口；定时探测和恢复由 04／05 完成，中间态不用于生产发布。
