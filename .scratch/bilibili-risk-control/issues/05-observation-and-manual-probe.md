# 05：恢复观察期与人工探测

Status: ready-for-agent

**What to build:** 探测通过后先保留退避档位观察正常采集，稳定 10 分钟才清零；自动恢复耗尽后，执行者可幂等请求一轮人工探测，但不能强行解除保护。

**Blocked by:** 04 — 六档冷却与分接口探测。

## 验收标准

- [ ] 全部必需类型通过后进入 observing，恢复正常发送与等待策略，不为观察期额外降低正常吞吐。
- [ ] 连续正常采集 10 分钟且确有成功业务请求后才回 normal、清零档位；无请求空闲或停机不抵扣观察期，重启重新累计观察时间并保留档位。
- [ ] 观察期间再次遇 HTTP 412／429 进入上一档的下一档，不从 1 分钟重来；第六档后再次触发转 manual，不无限卡在末档。
- [ ] 新增 POST /api/manage/risk/probe，仅在 manual 登记一轮，202 仅表示已登记；正式 collector 领取执行，API 不直接发起探测。
- [ ] 同一人工态代次重复登记幂等，不排多轮；collector 未运行时保持已登记。冷却未到期、正在探测及普通／观察态不可借该入口提前请求，不适用状态返回 409 RISK_PROBE_NOT_ALLOWED。
- [ ] 不接受 query 或可写状态字段，不允许通过请求体清零档位、改截止时间或绕过检查；沿用已有管理入口部署保护，不新增页面、按钮或鉴权体系。
- [ ] 人工探测仍验证全部必需类型；通过进入同样观察期，失败保持人工态；无“强行恢复发送”入口。
- [ ] 状态查询能表达登记、观察、稳定恢复和人工态；对应日志关联到原风控代次、探测轮次及档位，不泄漏内部领取令牌，不产生业务通知。
- [ ] 真实应用及进程装配、临时数据库和受控时间覆盖 10 分钟边界、空闲／停机、重复请求、旧 owner 迟到提交、人工成功／失败及观察期再风控，更新管理与运行契约。

## 验证范围

主要完成 RC-08，并补齐 RC-06／RC-07 中的人工恢复闭环；系统群生命周期告警由 09 接入。
