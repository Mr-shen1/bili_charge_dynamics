# 04：六档冷却与分接口探测

Status: ready-for-agent

**What to build:** 冷却每次到期后自动串行验证各必需接口，全部通过才恢复采集；未通过按六档延长等待，最后仍失败转人工，进程崩溃后也不会重复探测或错误放行。

**Blocked by:** 02 — 楼中楼分页等待与基础流程日志；03 — 跨进程风控暂停与状态查询。

## 验收标准

- [ ] 六档按 1、2、4、8、15、30 分钟等待，每档到期都实际执行一轮探测；任一类型未通过立即结束整轮并只推进一档，第六档失败进入 manual，不采用旧三次失败方案。
- [ ] 合法 Retry-After 不被更短本地期限覆盖；受控时间验证恰到期／未到期、重启剩余期限和异常时钟，不能以启动或时间异常绕过暂停。
- [ ] 每轮冻结“触发接口类型与当前待执行任务所需类型的并集”，以主机和路径模板划分，不按动态 ID／根 ID／页码逐一探测；图片分片域按受信图片域族归类。
- [ ] 真实需要的计数、根页、楼中楼、feed、detail、动态网页、UP 资料、首页／空间预热及图片类型分别有最小有效 GET 和对应原解析校验；不以 count 或资料成功替代其他类型，也不用 HEAD 代替图片 GET。
- [ ] 使用正式凭据、代理及统一发送／等待规则；楼中楼探测同样等待 100ms。探测不暗中补做预热，不无限寻找样本，没有已知有效样本时记录未确认恢复而非假通过。
- [ ] HTTP 200 但业务／资源校验失败仍不放行；非 412／429 的探测失败只表示本轮未通过，不扩大普通业务的错误分类。一个失败后其余类型不继续请求。
- [ ] SQLite 持久保存探测轮次、结果及唯一 owner 租约，真实多进程验证不能同时领取；崩溃后租约到期方可接管，旧 owner 不能提交结果，接管重新确认本轮类型。
- [ ] 探测只验证可用性，不推进归档 checkpoint、目标成功时间或通知基线，不生成业务通知；各类型全部通过后进入 observing 并允许正常调度，不补发冷却错过的检查。
- [ ] 状态查询能区分本轮待探测、通过、失败及下一档时间；记录接口类型、轮次、耗时、等待、失败原因及可用业务 ID，保持脱敏。
- [ ] 用实际 API／collector、真实临时 SQLite、受控时钟和传输账本验证完整阶梯、类型覆盖、失败短路、跨进程重启及无业务副作用，更新恢复与状态契约。

## 验证范围

主要覆盖 RC-06、RC-07 及探测相关 RC-03／RC-10。全部通过后的观察窗口清零和人工探测写入口由 05 完成；本票不在探测成功时提前重置档位。
