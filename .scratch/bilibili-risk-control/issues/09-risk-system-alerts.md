# 09：风控生命周期系统告警

Status: ready-for-agent

**What to build:** 系统群收到首次风控、自动恢复耗尽转人工及稳定恢复等关键生命周期告警；逐页及逐接口细节留在日志，告警遵守已有开关、去重和节流，不改变业务通知。

**Blocked by:** 05 — 恢复观察期与人工探测。

## 验收标准

- [ ] 由真实风控状态转换登记首次触发、转人工与稳定恢复告警，而不是根据日志文本或全表扫描猜测；探测刚通过但尚未稳定 10 分钟不冒充稳定恢复。
- [ ] 复用既有 SQLite 事务发件箱和独立通知进程，状态事实与告警登记保持一致；登记故障沿用原安全处理，不把通知失败变成风控旁路。
- [ ] 沿用系统群路由、已有类别／固定原因目录扩展方式、去重和节流，不把每页 412、每档等待或每接口结果分别刷群。
- [ ] 通知 off 不发送也不暗中改变开关；system_only 与 all 均仅按既有系统告警资格投递，风控不改变通知起点或业务消息资格。
- [ ] 重复触发、迟到响应、重启、人工重复登记和 owner 接管不会重复产生同一生命周期告警；复用既有去重／节流语义，不新建并行投递机制。
- [ ] 消息只包含固定安全状态／原因及必要时间，不携带正文、完整 URL、Cookie、凭据或内部 owner／令牌；逐接口资源定位信息保留在结构化日志。
- [ ] 用真实状态机、临时 SQLite、实际通知领取路径及飞书传输替身验证告警闭环、失败／重启及三态开关；同时证明探测不产生动态变化／新增评论通知，正常归档通知去重和资格不退化。
- [ ] 同步系统告警及运行契约，清楚说明告警可被既有开关关闭；不新增页面、告警专用文件日志或真实飞书发送。

## 验证范围

主要完成 RC-11，与 05 的稳定恢复事实联动；不依赖根／回复续采和公平调度的实现细节。
