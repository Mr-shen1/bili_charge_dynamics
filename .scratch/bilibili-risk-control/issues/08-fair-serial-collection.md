# 08：单路重型归档与分页公平轮转

Status: ready-for-agent

**What to build:** 不同动态、后台与手动入口共享一路重型归档，每完成一个可提交分页／下载步骤就有机会轮转；轻量检查可穿插，但历史大目标也能持续推进。

**Blocked by:** 03 — 跨进程风控暂停与状态查询；07 — 楼中楼续采与热帖持续追赶。

## 验收标准

- [ ] API 与 collector 共用全局发送许可和目标互斥，B 站源请求统一串行排队，不因独立线程、客户端或进程叠加成请求洪峰；OSS 上传与本地处理不占来源许可。
- [ ] 全局只推进一路重型归档，根页、楼中楼页及单图下载均以可安全提交步骤为调度片，不等整栋楼或整条动态结束才允许其他目标推进。
- [ ] 轻量计数、到期网页检查及必要发现可在分页之间穿插；有可运行重型分页时，有限轻量批次后必须让出分页机会，双方均不长期饿死。
- [ ] 原有固定节拍、忙时跳槽、同目标不叠加和错过槽不追赶保持；不得用无限队列保留所有 2.7 秒检查，风控期间和恢复时均不形成待补发洪峰。
- [ ] 每次轮转复用持久断点及原领取／版本规则；租约或 owner 失效后只能安全接管，不允许 API 手动初始化与后台对同一目标重复执行。
- [ ] 同步管理入口保留原完成统计语义，不把已排队误报为同步成功；实际需要网络但被风控阻止仍明确暂不可用，不创建异步校验工作流。
- [ ] feed、根页等待与楼中楼 100ms 规则在跨目标、跨进程轮转时依然生效，正常解析、会话缓存与其他故障处理不扩改。
- [ ] 任务取消、进程重开和风控触发后不继续下一次发送；已取得内容可以安全提交，归档阅读和已下载图的 OSS 上传不受影响。
- [ ] 调度日志能说明当前目标／页、领取或合并／跳过、让出执行权和暂停原因，并可关联后续页与提交，不泄漏内部令牌。
- [ ] 至少 8 目标、其中含万条楼中楼回复的真实应用／collector＋临时 SQLite 回放中，证明所有可运行目标持续推进、轻量检查有机会、总归档完整；双进程请求账本证明串行和无旁路，更新运行与调度契约。

## 验证范围

主要完成 RC-01、RC-02，并复验 RC-03／RC-04／RC-09／RC-10；性能数字及风控完整生命周期的整体验收由 10 收口。
