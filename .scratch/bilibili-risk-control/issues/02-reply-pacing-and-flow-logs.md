# 02：楼中楼分页等待与基础流程日志

Status: ready-for-agent

**What to build:** 每次真实楼中楼分页请求结束后等待至少 0.1 秒，并在正常发现、检查和归档流程中提供可定位到动态、楼层和每页评论／回复的结构化日志。

**Blocked by:** 01 — 统一 B 站请求发送入口。

## 验收标准

- [ ] 首次全量、末页倒序增量、失败重试、空尾复查及其他实际楼中楼 GET 都执行请求结束后的至少 100ms 异步等待；第一请求前不额外添加该等待，最后一页后仍执行。
- [ ] 等待通过统一协调执行，以多调用者的发送／完成时间账本证明不能交错绕过；为 04 的探测复用同一路径，而不是预留另一条无等待的请求路径。
- [ ] 整楼跳过和未真实展开楼中楼的根不额外等待；实际展开后的楼级等待对齐参考策略，feed 和根页原有等待不重复增加。
- [ ] 时间可注入，现有仅针对楼级 0.3—0.4 秒的测试替身不误吞、误约束新增页后等待；网络与等待不占 SQLite 写事务。
- [ ] INFO 日志能够串起已有正常发现、检查、领取／跳过、正文、根页、楼中楼页、媒体及整轮结果；后续票负责增加其新行为对应的断点／风控／调度事件。
- [ ] 阶段可得时记录字符串 UID、dynamic_id、root_id、独立关联号、页码、方向、接口类型、数量、结果、耗时与等待；每页全部已校验评论／回复 ID 批量输出，超长按关联号分块而非静默截断。
- [ ] 不为每条回复单独刷 INFO；成功、失败和跳过均可定位，不将旧领取令牌当关联号，不泄漏 Cookie、密钥、正文、完整 URL、任意异常原文或内部令牌。
- [ ] 日志继续使用现有标准输出／错误输出链路，不增加独立日志文件、轮转器或固定保留天数；原始传输调试日志保持关闭。
- [ ] 用真实归档链、受控时间和日志捕获同时验证等待及 ID 正向出现、秘密负向缺席；同步日志规则和分页节奏契约。

## 验证范围

主要覆盖 RC-03 与正常流程的 RC-10。04 接入真实探测后须补齐探测用例，08／10 须复验多进程与统一调度下仍不可绕过；本票不把后续场景标为已验收。
