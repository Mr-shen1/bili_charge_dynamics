# 06：一级评论分页持久续采

Status: ready-for-agent

**What to build:** 一级评论逐页保存可验证进度，中断、失败或重启后从有效断点继续；热帖新增只登记后续工作，不因计数变化无条件重复读取全部已确认根页。

**Blocked by:** 01 — 统一 B 站请求发送入口。

## 验收标准

- [ ] 每页根评论和对应上游处理进度在同一短事务提交，包含目标／locator、处理代次、阶段、方向、页锚点、已确认 ID、下一位置及必要计数；不复用归档阅读 cursor。
- [ ] 通过真实初始化／待处理执行链驱动中途失败、关闭重开及新进程接续，证明已得内容保留、进度可复用，不默认从第一页完整重扫；必要头页／重叠页校验须在账本中解释。
- [ ] 续采验证定位资源与页锚点；新增、插入、删除或移动页时重定位受影响区段，不能只保存 pn+1 就盲跳，也不以重复 ID 假装推进。
- [ ] 采集中可信计数／revision 增长只登记后续待处理工作，不撤销有效分片；旧领取不能覆盖新观察、清除新工作或伪造最新 complete。
- [ ] 保留根页现有作者／资源校验、置顶与热门去重、明确空尾确认、可信未知／失败和来源数口径；只有根集合确认后才推进根 checkpoint 及相应元信息，失败不删历史根。
- [ ] 新增进度结构能供后续楼中楼步骤沿用一致的分片／版本规则，但不提前实现楼中楼持久续采、全局公平调度或放宽 revision 校验。
- [ ] 原子迁移保留旧归档、有效阅读 cursor、媒体及未完成工作；网络和等待不占写事务，旧 generation／领取／入选代次隔离回归不退化。
- [ ] 日志可定位动态、页码、完整本页根 ID、续采／重定位原因及 checkpoint 是否被接受；遵守父规格的字段／脱敏规则，不能输出内部令牌或正文。
- [ ] 用真实临时 SQLite、上游分页 fixture 与归档 GET 验证最终集合完整、重复读有界、来源计数变化不导致每轮清空进度，更新根分页与续采契约。

## 验证范围

覆盖根评论部分 RC-04；风控后自动恢复的跨链验证放在 10，不为制造独立验证而绕过 03／04 的保护规则。
