# 07：楼中楼续采与热帖持续追赶

Status: ready-for-agent

**What to build:** 楼中楼正序全量与末页倒序增量都能复用持久分片进度；单页失败、重启或热帖持续新增时继续推进，不反复整楼重抓，也不把旧观察的完成误当最新全量完成。

**Blocked by:** 02 — 楼中楼分页等待与基础流程日志；06 — 一级评论分页持久续采。

## 验收标准

- [ ] 沿用根分页建立的分片／定位／代次规则，逐楼、逐页原子保存回复数据与进度；保留既有楼级成功记录和未变化楼的跳过优化。
- [ ] 正序首次采集、失败重试、末页倒序增量、命中已知页后的必要重叠、空尾确认均能恢复，并保留每次真实请求后的 100ms 等待。
- [ ] 请求中断、关闭重开、新进程接续后复用已验证回复页，不默认将失败楼从头全扫；必要复查请求有明确原因且不能静默漏页。
- [ ] 根元信息／回复数变化时保留可验证进度并登记后续工作；locator 或分页锚点失效时仅重定位必要区段，不能沿用错误资源或通过放宽版本判断假完成。
- [ ] 根页集合、必要楼中楼及最新观察分别表达完成，失败或较新待处理工作仍为 pending／部分完成；不因本地数小于来源数就无限追赶或删除旧回复。
- [ ] 保留根 rcount 与楼中楼来源数的既有口径容忍、不可见回复处理、独立根／回复成功时间及已有增量语义，不引入新校准策略。
- [ ] 旧领取、旧 generation、停止后重纳入及迟到响应不能覆盖新状态或吞掉新工作；媒体与业务通知仍走原真实提交及资格校验，不由恢复断点伪造成功。
- [ ] 页级日志包含动态／根 ID、全部已校验回复 ID、方向、等待、重叠／漂移／续采原因及提交结果，不逐条刷 INFO 或泄漏敏感数据。
- [ ] 固定热帖样本在多轮新增和页移动下最终取得全部可获取回复；以真实临时数据库重开、请求账本、状态与归档 GET 证明持续推进、重复读有界、无无条件全目标重扫，更新楼中楼续采契约。

## 验证范围

完成楼中楼与热帖部分 RC-04，保持 RC-03，并补充相关 RC-10；多目标公平性及跨进程完整组合由 08／10 验证。
