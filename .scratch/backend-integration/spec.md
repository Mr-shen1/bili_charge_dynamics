# 真实归档后端与多 UP 阅读集成规格

Status: ready-for-agent

## 问题陈述

现有页面能用虚构数据阅读单 UP 的动态、评论、回复和图片，但用户无法通过页面维护多个 UP 的监控目标，也不能读取持久保存的真实归档。固定 UP 身份、无 scope 的读取接口及旧路由不足以支持全部归档、单 UP、管理与一级评论图片。

用户希望在停止监控、目标移出窗口或上游不可用后继续阅读已有内容，并能区分“检查到变化”“部分同步成功”“全部完成”。正文受限、评论可读、图片上传失败等情况不能合并成空内容或假成功。旧模拟前端验收和有限上游样本不能证明本期已经实现或可持续运行。

## 解决方案

在现有阅读体验上接入 Python/FastAPI/SQLite 真实服务，一个 API 进程负责管理与归档读取，一个独立采集进程负责目标选择、固定 15 秒检查及独立同步。通过 UID 管理每个 UP 的互斥监控模式，持久保存身份、配置、归档、可信观察、分项成功 checkpoint 和未完成工作。

默认 `/` 阅读全部已归档动态，`/ups/:upId` 阅读单 UP，`/dynamics/:dynamicId` 阅读完整动态与评论，`/manage` 管理监控。保留阅读区域按两张参考图一比一视觉复刻，监控管理按同一视觉体系重做，而非只套 B站主题色；卡片进入详情顶部，评论气泡进入同页评论区。保留排序、分批加载、文本阅读、图片预览和会话恢复，增加多 UP scope 隔离及一级评论图片。生产通过 API Adapter 读取归档，业务图片通过公开 OSS URL 直取，独立 mock 回归继续保留。

本规格综合当前需求与设计，并提供可拆分的故事、职责、测试入口和验收映射；SRS 仍是产品需求真值。所有本期新增和变更均待实现、待验收。

## 用户故事

以下编号用于后文追踪，每条均为本期实现或集成回归目标。

1. 作为阅读者，我希望默认看到全部已归档动态，以便跨 UP 阅读而不受当前监控目标限制。
2. 作为阅读者，我希望通过横向头像昵称选择条切换全部或某个 UP，以便浏览该范围的归档且不使页面横向溢出。
3. 作为阅读者，我希望每条动态显示其实际作者、发布时间、正文、图片和来源评论数，以便识别内容归属而不是看到固定的全局 UP。
4. 作为阅读者，我希望评论和回复按当前动态作者 ID 显示 UP 标识，以便同名不同 ID、多 UP 内容之间不会误标身份。
5. 作为阅读者，我希望保留的列表、详情、评论和回复区域按两张参考图一比一对齐布局、字号、间距、图标及配色，以便获得一致的 B站阅读视觉而无多余业务区块。
6. 作为阅读者，我希望点击或键盘激活动态卡片进入详情顶部，以便直接阅读全文且无需“查看详情”按钮。
7. 作为阅读者，我希望点击评论气泡图标和数量进入同一详情的评论区，以便直达讨论而不进入独立评论页。
8. 作为阅读者，我希望图片、文本选择、展开及内嵌操作不触发卡片导航，以便完成当前操作而不被误带走。
9. 作为阅读者，我希望内容头像昵称仅展示、点赞数只读，以便阅读时不会误筛选、跳个人主页或触发真实写回。
10. 作为阅读者，我希望四类有效页面支持直接打开和刷新，并区分无效地址、未知 UP、已知 UP 空归档及网络失败，以便理解当前页面状态。
11. 作为阅读者，我希望详情返回到有效的站内列表来源，无来源时回到全部首页，以便继续阅读且不会意外离站。
12. 作为阅读者，我希望列表动态、评论和回复超过六个渲染行才折叠，而详情动态始终全文展示，以便兼顾扫描和完整阅读。
13. 作为阅读者，我希望换行、emoji、长词和 URL 正常展示，URL、话题、@用户及标签只作文本，以便阅读安全且不产生未确认跳转。
14. 作为阅读者，我希望发布时间固定显示绝对北京时间到秒，编辑时间独立并保留来源精度，以便不受设备时区影响且不误认编辑为发布。
15. 作为阅读者，我希望计数显示完整非负整数，来源总数与本地归档数分开、未知与零分开，以便不把部分采集或失败误认为没有评论。
16. 作为阅读者，我希望动态在所选完整归档集合排序后按每批十条加载，以便稳定阅读全部数据而不重复遗漏或无限滚动。
17. 作为阅读者，我希望全部及各 UP 的 cursor、缓存、请求身份和阅读快照隔离，以便切换范围及乱序响应不会串入其他内容。
18. 作为阅读者，我希望一级评论默认最热，支持最新并在完整归档集合排序后每批二十条加载，以便按一致规则阅读讨论。
19. 作为阅读者，我希望切换评论排序定位评论区、重置首批及展开状态，并只接受最后选择的结果，以便旧排序、旧失败或迟到回调不会污染当前视图。
20. 作为阅读者，我希望回复按时间正序先看三条、每次追加十条，收起后回到所属一级评论开头且可再展开恢复已加载范围，以便逐步阅读而不丢失上下文或重复请求已有内容。
21. 作为阅读者，我希望回复以扁平楼中楼展示可用回复目标，局部失败仅影响该根评论，以便理解对话且不因一处失败中断全部阅读。
22. 作为阅读者，我希望动态图片和每条一级评论图片保持各自顺序和图片组，以便预览不会串入其他动态或评论，也不额外增加回复图片。
23. 作为阅读者，我希望单图保持比例、四图两列、其他多图三列，列表超过九图提示剩余数量而详情可看全部，以便布局清晰且不限制真实图片数量。
24. 作为阅读者，我希望从列表、详情和一级评论直接预览所点图片，显示组内张数、首尾不循环且单图隐藏切换，以便明确当前阅读范围。
25. 作为阅读者，我希望桌面用方向键和 Esc、手机用横向滑动切图，以便在不同设备操作且坏图不阻止关闭或切换。
26. 作为阅读者，我希望长图可切换完整显示和适应宽度、纵向阅读不滚动底层且切图重置位置，以便读完长图而不误切图。
27. 作为阅读者，我希望手机返回优先关闭预览，关闭后恢复底层位置和触发焦点，历史前进可恢复预览，以便不多退一页或丢失操作位置。
28. 作为阅读者，我希望从详情返回时恢复来源 scope 的多批列表、文本展开及位置，以便接着此前内容阅读。
29. 作为阅读者，我希望历史返回详情恢复该次访问的排序、评论、回复展开与位置，以便同一动态的不同访问互不覆盖。
30. 作为阅读者，我希望主动卡片或评论入口的位置优先于旧滚动快照，以便分别到达详情顶部或评论区。
31. 作为阅读者，我希望刷新后可正常读取有效地址、失效预览标记不会造成循环，以便无需持久化阅读历史也能稳定导航。
32. 作为阅读者，我希望各区域区分加载、成功空、有内容、失败和结束，以便不把失败误认为空集合或无限加载。
33. 作为阅读者，我希望追加、回复或图片失败保留已有内容并在原位置局部重试，以便无需从第一页重新开始且单图不影响其他内容。
34. 作为阅读者，我希望重复加载不会重复追加，取消和迟到结果不会改变新访问，以便快速操作仍可得到确定结果。
35. 作为阅读者，我希望缺失头像、昵称、时间、计数、回复目标及空正文图片有明确兜底，以便不出现错误值或把纯图评论当作无内容。
36. 作为管理者，我希望只输入 UID 就从上游取得昵称头像并保存配置，以便无需前端写死名单、手工编辑业务配置或手改身份。
37. 作为管理者，我希望资料读取或目标归属确认失败被明确提示，以便不把未取得的信息当作成功保存的身份。
38. 作为管理者，我希望每个 UP 只能选择近期 N 条或指定动态 ID 一种模式，以便明确当前目标集合且没有额外的仅评论采集开关。
39. 作为管理者，我希望近期 N 默认十条且按 UP 单独配置，以便按各 UP 的需求调整监控窗口。
40. 作为管理者，我希望近期模式沿用原充电图文识别逻辑，逐页凑够 N 条合格动态或直到耗尽，以便普通候选不会提前占满窗口。
41. 作为管理者，我希望指定 ID 关联并校验所属 UP，只监控指定集合，以便错误或未知归属不会被强行关联，也不会混入近期目标。
42. 作为管理者，我希望两种模式均采集目标实际可读的正文、评论、回复和本期图片，以便目标选择不会缩减内容能力。
43. 作为管理者，我希望启停监控并查看未检查、无变化、同步中、部分完成和失败及相应时间错误，以便知道实际进度而不是只看到一个“成功”。
44. 作为管理者，我希望删除 UP 监控配置或指定目标只停止监控而保留身份和全部归档媒体，以便业务配置变化不会销毁阅读内容。
45. 作为阅读者，我希望模式切换、窗口移出及上游消失后旧归档仍可阅读，以便不因目标生命周期或来源失败失去历史内容。
46. 作为阅读者，我希望停止或删配置后的 UP 仍能从顶部选择进入其归档，以便旧内容有入口而不只依赖启用名单。
47. 作为管理者，我希望首次纳入目标同步已有可读内容和已有评论回复，但不自动回填 UP 全部历史动态，以便初始化完整且范围受控。
48. 作为管理者，我希望检查固定每十五秒触发，同目标上一检查未结束就跳过而不积压，以便节拍明确且不叠加工作。
49. 作为管理者，我希望检查和耗时同步分离，同步未结束仍允许新的检查，以便评论分页或上传不把调度变成全量完成后再等待。
50. 作为管理者，我希望通过页面安全解析的可信“编辑于”时间变化触发正文及动态图同步，以便不单靠 pub_ts 或正文图片比对判断编辑。
51. 作为管理者，我希望相对时间文案和空白变化不算编辑，无编辑标记也不跳过首次同步，以便减少假变化且不漏掉初始化。
52. 作为管理者，我希望编辑信号缺失、不可用或解析失败保留可信旧值和旧归档，分钟精度不伪造秒，以便未知状态不会被冒充未编辑或精确版本。
53. 作为管理者，我希望初次和失败重试之外只在来源评论总数变化时同步评论回复，以便按已确认信号工作并透明接受抵消及纯编辑漏检。
54. 作为管理者，我希望正文受限或网页评论无权提示不阻断实际可读评论，计数及分页失败不归零、不清空归档，以便独立保存各部分的真实结果。
55. 作为管理者，我希望正文、评论回复、图片分别记录成功和失败，observed 与成功 checkpoint 分开持久化，以便观察成功或文本成功不会冒充全部归档完成。
56. 作为管理者，我希望旧同步完成只提交其实际处理的观察版本，不清除期间产生的新观察工作，以便更新不会被旧任务吞掉。
57. 作为管理者，我希望无新信号时失败仍能重试、重启后配置和未完成工作仍可恢复，重复处理不损坏归档，以便异常不会永久丢失更新。
58. 作为管理者，我希望动态图和一级评论图保存归属、顺序、尺寸、来源及上传状态并独立重试，以便某张图失败不使文本或其他图片失效。
59. 作为阅读者，我希望生产业务图片由公开 OSS URL 直接提供，首次未上传明确未完成而不回退 B站业务图，以便展示实际归档结果。
60. 作为阅读者，我希望生产页面通过统一 API Adapter 读取归档而不触发上游采集，以便采集异常时旧内容仍可读，展示层也无需理解来源协议。
61. 作为维护者，我希望独立 mock 和可控读取故障回归继续可运行，并以虚构夹具验证真实 Adapter，以便测试确定且无需真实服务或凭据。
62. 作为阅读者，我希望四种约定宽度无页面溢出、主要触控目标约 44px 且焦点可辨识，以便在 Linux Chrome 和 iPhone Safari 上操作阅读。
63. 作为阅读者，我希望分页、缩略懒加载、预览按需加载和合理图片占位保留，以便不在打开页面时请求全部原图或严重扰动阅读位置。
64. 作为维护者，我希望来源文字安全渲染、HTML 初始化数据只用安全 JSON 解析，凭据仅留服务端仓库外且诊断脱敏，以便页面、接口和日志不执行恶意输入或暴露秘密。
65. 作为管理者，我希望明确知道无鉴权管理/API、公开图片及无备份容量治理的风险，以便接受本期取舍而不被隐藏入口或虚假保护承诺误导。
66. 作为维护者，我希望静态交付支持四类页面深链接且 API 和缺失资源错误不回退 HTML，以便部署后导航和接口错误仍准确。
67. 作为维护者，我希望沿用前端技术并以 uv、nvm、pnpm 管理 Python/FastAPI/SQLite 双进程服务，以便可复现运行且无 Redis/Celery 或未经验证的容量承诺。
68. 作为验收者，我希望分别记录本期自动化、部署、真机、上游样本及持续运行证据，以便历史验收、样本成功和模拟设备不会冒充本期完整通过。

## 实现决定

### I1. 技术、职责和交付边界

- 沿用 React、TypeScript、Vite、React Router、Context/reducer、CSS Modules 与 CSS 变量，不引入大型 UI 框架、额外状态/缓存框架或 SSR。后端采用 Python/FastAPI/SQLite；Python 仅 uv，Node.js 仅 nvm，依赖与脚本仅 pnpm。具体依赖版本在实施时核对并固定，本规格不新增版本决定。
- 运行一个 API 进程和一个独立采集进程，不采用多 API worker、Redis、Celery或微服务。API 不承载定时器、不把耗时同步绑定浏览器请求；同一采集进程内分离检查与同步阶段。
- 职责单元为监控管理、上游读取、采集同步/媒体上传、归档读取，以及前端读取 Adapter、导航会话、阅读展示和预览。优先演进已有边界，不建立大量只转发的空 interface。
- 优先评估阿里云 2 核 2GB 与 SQLite 同机，不强制同机、不承诺容量、并发或时延，不自动采购付费资源。交付包含真实服务、数据库迁移、前端、采集、独立 mock、测试及可复现构建运行说明。
- 追踪：NFR-05；故事 60、61、66–68；AC-19、AC-20、AC-33、AC-34。

### I2. 身份、配置与目标选择

- 身份、监控配置、当前目标和归档分离。管理按 UID 新增并由服务端获取昵称头像，无身份手改或凭据 UI；资料失败不得伪造成功。每 UP 保存启停、互斥模式、独立 N（默认 10）及指定 ID 关联，重启后保留。
- 管理页也按两张 UI 参考图的同一视觉体系重做 UP 卡片、配置表单、目标与检查／同步状态；排版、字号、间距、控件及信息层级统一，不仅换颜色。其管理布局记录为参考规则的映射，不伪称 B站管理截图复刻。#35 交付视觉，原管理操作、独立草稿／错误、真实状态及只读重读保持不变；风险提示改由部署文档声明，页面不常驻横幅。
- 近期模式原样沿用参考脚本充电图文识别行为，逐页累计 N 条合格动态或到上游耗尽；不能按前 N 条原始候选截断，不能新增识别条件。实施时将必要无敏感识别逻辑和结构保持的脱敏夹具纳入可版本化实现及测试，禁止依赖未跟踪本地脚本才能运行。
- 指定模式仅选关联 ID，验证来源作者与 UP 一致；不符或无法确认明确表示错误/未确认，不强行关联、不附加近期目标。模式只选目标，均同步可取得的正文、评论、回复、动态图和一级评论图，无“仅评论/完整采集”开关。
- 当前起始规模为近期 UP `550494308` 约 10 条，指定 UP `3493130286402061` 两条；不是规模验收，也不设置 5 UP/100 目标上限。
- 追踪：FR-14、FR-15、FR-18、DR-04；故事 36–42、47；AC-22–AC-24。

### I3. 归档生命周期

- 停止、删除 UP 监控配置/指定目标、模式切换不再入选、窗口外只停止后续监控；保留 UP 身份、动态、评论、回复及媒体，不以配置删除 cascade 清除内容。上游消失或读取失败也不自动删归档或覆盖旧成功内容；重新纳入后可继续同步。
- 导航身份集合包含已保存且有旧归档的 UP，不只取当前启用配置。全部与单 UP 读取范围包含保留归档。
- 不自动发现并回填 UP 全部历史动态；近期凑 N 的必要翻页及已选目标已有评论回复初始化仍必须执行。
- 追踪：FR-19、DR-04；故事 44–47；AC-13、AC-29。

### I4. 固定检查与独立同步

- 固定 15 秒触发检查。同目标上一轮**检查**未结束则跳过本次，不叠加、不积压；同步未结束不是禁止新检查的条件。慢目标同步不能阻塞全局节拍，不采用“同步完再等 15 秒”、自动退避、自适应频率或默认每日校准。节拍不是同步完成时限。
- 首次纳入建立可用基线并登记首次同步；没有编辑标记或一项信号不可用，不阻止其他可读部分初始化。检查只获取变化信号并保存待处理工作，耗时正文、评论分页和图片上传独立执行。
- 按目标持久保存最近可信 observed、各分项成功 checkpoint、未完成工作、检查时间、分项成功时间、进行与错误状态。正文、评论/回复、图片分别推进；无变化检查不等于成功同步，部分成功不等于全部完成。
- 同步绑定实际开始处理的观察版本。只有对应内容成功归档才提交该版本 checkpoint；失败保留旧归档与未完成状态，即使来源未再变也可在后续固定节拍重试。同步期间新 observed 仍登记工作，旧完成不能冒领新版本、覆盖新观察或清除较新待处理。
- 重启恢复持久化未完成工作，重复领取、执行及提交需保持幂等。事务短小，网络读取、图片下载和 OSS 上传不进长事务；协调、有限并发及 SQLite 参数后续设计，不通过无限并发许诺节拍完成率。
- 管理状态能区分未检查、检查无变化、同步中、部分完成、失败及具体未完成分项，显示最近检查、最近成功和脱敏错误。
- 追踪：FR-14、FR-16、DR-05、NFR-05；故事 43、48、49、55–57；AC-22、AC-25、AC-28。

### I5. 正文编辑信号

- 普通网页 GET 的 HTML 是编辑信号来源；安全提取 `__INITIAL_STATE__` 的初始化 JSON，用 JSON 解析器读取 `detail.modules`，按 `module_type = MODULE_TYPE_AUTHOR` 找到 `module_author.pub_time` 中“编辑于”的日期时间。不执行 JS、eval 或任意脚本表达式，不依赖固定脚本标签/模块下标，不依赖 opus/detail JSON 接口。
- 根据来源语义规范化空白、日期时间、时区与精度，可信编辑时间变化触发正文及动态图同步；普通相对文案自然变化和空白差异不触发。不能仅用 pub_ts，也不通过正文、图片 URL、字节或摘要比对检测编辑。
- 无编辑标记仍初始化；信号缺失、解析失败或带标记但日期时间不可用，保留未知/错误及旧可信值、旧成功 checkpoint，不写空值、当前时间或“确认未编辑”。其他可读部分继续处理。
- 发布时间独立，不能用编辑时间补未知发布时间。编辑信号只有分钟精度时保存/展示该精度，不伪造秒；接受同分钟多次编辑漏检。所有页面可用性及自然多次编辑更新仍须另证。
- 追踪：FR-04、FR-17、DR-01、DR-05；故事 14、50–52、64；AC-04、AC-26、AC-28、AC-34。

### I6. 评论信号和访问结果

- 除初始化和失败重试外，仅来源动态评论总数变化触发一级评论与回复同步；正文编辑不默认重扫评论。同步包含目标已有可读根评论与回复并完整处理该轮所需分页，不只采启用后新增内容。
- 来源总数含一级评论及楼中楼回复，与本地根评论数、回复数分开；字段映射需用结构真实的样本验证，不从首屏或抽样推定跨接口永久恒等。是否省略独立计数请求尚未决定。
- 接受数量抵消、纯评论编辑但总数不变等漏检，不新增每日全量校准等兜底。缺字段、无效计数、拒绝、业务/网络/分页失败不是零或成功空结果，不推进对应成功状态、不清空旧归档。
- 正文受限、网页“暂无权查看当前评论”与评论接口结果独立；实际可读评论仍同步，拒绝如实保留受限/失败语义，不承诺所有受限评论都能读取。
- 追踪：FR-16、FR-18、DR-01、DR-05；故事 15、47、53–55；AC-24、AC-27、AC-28。

### I7. 媒体归档与交付

- 动态图及一级评论图各自关联 owner，保存顺序、可用尺寸、来源地址、公开 OSS 地址、上传状态和错误，共用上传能力但不混图片组；不增加回复图。
- 上传完成独立于文本/评论完成；单图失败保留其他成功结果和旧成功媒体并可重试。首次未上传的图明确待处理/失败，不假成功、不以 B站业务图片生产回退。浏览器加载失败与服务端未归档状态分开表达。
- 浏览器直接使用后端给出的公开 OSS URL，不拼接桶地址或来源域名，应用不代理业务图片。头像与业务归档图片区分，可沿用已有 B站头像 URL。
- 缩略及预览 URL 可同可异；尺寸变体、格式处理、缓存、CDN、费用及物理对象去重尚未选定，不把 CSS 缩小、懒加载或 OSS 当成压缩/性能证明，不引入签名续期。
- 追踪：FR-08、FR-09、FR-12、FR-20、DR-03、DR-04、DR-05；故事 22–27、35、58、59、63；AC-09–AC-11、AC-15、AC-17、AC-28、AC-30。

### I8. 统一读取、排序和分页

- 生产读取 API 归档，不直连采集接口、不因浏览隐式同步。保留独立 mock 与可控 Adapter；演进旧读取边界，显式支持全部/单 UP scope、保存身份、分项状态、独立编辑时间与一级评论图片。不能把旧全局 creator、无 scope 列表或无图评论形状当成新契约。
- 所有实体/关联 ID 为字符串；时间保留明确时区与可信精度，计数未知区别于非负整数零。数据按不可变内容共享，访问视图不可共用可变快照。作者及 UP 标识以 `dynamic.author` 为真值。
- 全部归档先跨 UP 全局排序再分页，单 UP 对该 UP 完整集合排序；一级评论对该动态完整本地归档集合排序，不声称拥有全部来源评论或复现 B站热度算法。
- 动态按发布时间降序、ID 字符串升序；最热评论按点赞降序、时间降序、ID 字符串升序；最新评论按时间降序、ID 字符串升序；回复按时间升序、ID 字符串升序。逐字段比较时缺失排在该字段有效值之后，再比较下一字段；ID 非语言环境相关比较，不转数字。
- 动态每批最多 10，评论最多 20，回复预览最多 3、随后每批最多 10；显式加载更多，不无限滚动，结束不再请求。回复收起保留已读取内容，只缩回最初最多三条可见范围，并将所属一级评论开头滚回可见位置；再展开复用已加载内容。
- 不透明 cursor 绑定 scope、资源、父级、排序及读取上下文，不跨范围静默复用。失败不推进 cursor，重试同批；去重不能掩盖漏批。真实更新期间在约定读取范围内不重不漏、快照不串 scope；具体分页一致性协议须在实现相应模块前明确并配套测试，本规格不擅定协议。
- 读取结果分别表达成功有/无内容、失败、取消、动态不存在及未知 UP。归档 HTTP 成功可携带分项采集失败，不冒充已全部同步。
- 追踪：FR-01、FR-04–FR-07、FR-13、DR-01、DR-02；故事 1–4、14–21、34、60、61；AC-01、AC-04–AC-08、AC-13、AC-17、AC-21。

### I9. 路由、入口与会话恢复

- 页面产品路径固定为 `/`、`/ups/:upId`、`/dynamics/:dynamicId`、`/manage`。详情和评论在同页；卡片整体及键盘入口到顶部，气泡图标及数量到评论区，移除“查看详情”按钮。内部图片、文本选择、展开、内容头像昵称等不误导航，避免嵌套冲突交互语义。
- 有有效站内列表来源的详情返回其全部/单 UP 访问，否则回 `/`；未知地址、未知 UP、已知 UP 空归档、不存在本地动态与网络失败分别处理。上游消失不把本地归档变成不存在。
- 导航统一协调历史，稳定会话挂在路由之上。每次主动访问有独立访问身份及 scope 快照；同动态不同历史访问互不覆盖。快照保存已加载数据、cursor、文字/回复展开、排序、稳定锚点/偏移及像素后备，不仅保存滚动坐标。
- 恢复先具备数据与布局，再定位；主动入口位置优先，历史导航恢复该次位置。有限回退处理缺锚点、慢图片与宽度变化；用户主动滚动优先，迟到恢复不拉回。不叠加另一套自动滚动恢复。
- 预览由导航协调同 URL 历史记录，切图不逐张压栈；后退优先关闭、前进可恢复有效预览，不能重复后退。预览身份包括 owner 类型、owner ID、组内图片及触发焦点，关闭恢复原底层访问、位置和焦点。
- 会话仅当前标签页内存，不持久化阅读历史。刷新或遗留标记无有效内存时清理当前失效引用并按 URL 读取，不盲目连续后退、不承诺刷新恢复预览。
- 追踪：FR-02、FR-09、FR-10、FR-13、DR-02、NFR-02；故事 6–11、17、24–31；AC-02、AC-10–AC-13、AC-21、AC-30。

### I10. 阅读、异步和局部异常

- 列表动态、评论、回复按实际布局超过 6 行才折叠，宽度变化重新判断；详情动态全文。文字安全展示并保留换行/emoji，长词可换行；URL、话题、@用户不自动链接。
- 每个独立区域分别维护首次/追加加载、结果、失败批次及结束；请求期间禁止对应重复操作而非全局锁定。取消尽量减少工作，但还需按访问、scope、父级、排序、批次及代次拒绝旧成功/错误/完成回调，不能只依赖 AbortSignal。
- 评论初访默认最热；切排序定位评论区，重置首批、文本/回复展开及旧请求，保留上方动态。失败留在目标排序并可重试，不能显示旧排序充当新结果。回复失败只影响对应根评论。
- 追加失败保留已有内容，原位重试同操作且不重复遗漏。昵称未知显示“未知用户”，头像缺失/失败用默认头像，时间无效显示“时间未知”，计数未知显示“—”、零显示 `0`，缺回复目标不拼错误 @。动态正文图片都空显示“暂无内容”；评论都空或回复空显示“暂无评论内容”；纯图动态/评论不补空文案，无图不留空区域，不推断已删除。
- 追踪：FR-03、FR-06、FR-07、FR-11、FR-12、NFR-01、NFR-04；故事 12、13、19–21、32–35、64；AC-03、AC-07、AC-08、AC-14、AC-15、AC-18。

### I11. 图片阅读、视觉和可操作性

- 图片保比例：单图限制列表高度，四图两列、其他多图三列；列表最多 9 个缩略位置，最后格提示剩余量，详情缩略及预览可访问全部。动态图和每条一级评论图分别预览。
- 预览完整显示、不裁切；显示当前/总数，首尾不循环、单图无切换，支持方向键、Esc 和手机横滑。长图可完整/适宽阅读，纵向不切图、不滚底层，切图重置纵向位置。预览焦点留在内部，关闭回触发处或合理后备，坏图可重试/切走/关闭。
- 以 [UI 参考](../../docs/design/ui-reference.md) 两图对保留的列表、详情、评论及回复区域做一比一视觉复刻；布局比例、头像与文字排列、字号行高、间距、圆角、分隔、图标和图片容器须对齐，不能仅做浅青背景、白卡、青蓝选中和粉色作者的主题近似。视觉专项由 [#35](issues/35-bilibili-visual-replica.md) 交付，包含监控管理同风格改版；阅读原图对照与管理规则映射的基准条件、业务内容遮罩及必要行为差异分别记录。不增加桌面复杂侧栏，手机单列；保留绝对发布时间及详情全文，不照抄截图相对时间或详情展开，不恢复已裁剪功能。
- 检查 360、390、768、1280px 无页面横向溢出，仅选择条允许内部横滑；主要触控约 44px、键盘焦点明确。正式兼容为 Linux Chrome 和 iPhone Safari，其他浏览器及 B站内置浏览器不承诺。
- 保留分页、列表缩略懒加载、预览按需加载及合理尺寸占位，不要求打开一图就下载整组原图，不承诺未经测量的资源指标。
- 追踪：FR-01、FR-03、FR-04、FR-08–FR-10、NFR-01–NFR-03、DR-03；故事 5、12、14、22–27、62、63；AC-03、AC-09–AC-11、AC-16、AC-17、AC-30、AC-31。

### I12. 安全、运行风险与协议细化

- 凭据仅服务端、仓库外保存，不进入前端产物、UI、API、日志和诊断；管理页不编辑凭据。上游请求及 OSS 上传只由服务端执行，浏览器允许来源头像但不直调上游采集接口。故障入口只供独立开发/测试装配，不出现在正常页面。
- 首期无鉴权、备份或容量不足治理。公网管理/API 可能被第三方读取或修改，公开 OSS URL 可直接访问/外链，未来站点登录也不会自动保护图片；无备份和容量治理可能丢数据或停止写入。透明说明，不自加鉴权前置门槛或宣称隐藏入口是保护。
- 静态前端本地/CI 构建，Nginx 托管并反向代理 API，无常驻 Node.js。四类页面深链接与刷新可用，API 成功/错误及缺失静态资源不回退入口 HTML；页面入口再验证、带哈希资源可长期缓存。
- 后续设计需明确 HTTP 路径/方法/DTO/错误及管理输入校验、迁移表列、进程协调和分页一致性，再实现其契约测试；不在本规格擅定未决协议、库版本或数据库列。图片变体、缓存/CDN及付费配置保持未决，不擅自启用。不得以设计细化改变已定产品路径、节拍、目标规则或范围。
- 追踪：DR-03、DR-05、NFR-04、NFR-05；故事 64–68；AC-18、AC-19、AC-32–AC-34。

## 测试决定

### 已确认的三个高层测试入口

以下 seams 已获用户确认，属于确定决定，不再重新访谈。测试观察公开结果、页面操作、HTTP 结果、持久化后可读状态和外部调用效果，不绑定内部私有函数、SQL 列名、锁实现或线程数；数据库不能全部 mock。

| 入口 | 固定装配与验证行为 | 主要验收 |
| --- | --- | --- |
| T1 前端统一读取接口与用户交互 | 延续 mock/受控 reader，通过 Vitest 契约、RTL 操作、Playwright 浏览器验证真实 API Adapter、多 UP/scope、管理、一级评论图片、入口隔离、分页、局部失败、历史/焦点/阅读恢复。HTTP 替身只替换传输，不用另一份假 Adapter 绕过生产映射；少量场景连接实际测试 API | AC-01–AC-21、AC-22、AC-30、AC-31 |
| T2 后端管理与归档 HTTP 接口 | 启动受测 FastAPI 应用并使用隔离临时 SQLite；模拟上游资料获取，但真实写入、读取、关闭重开数据库。验证身份、模式、指定归属、配置持久化、归档生命周期、完整集合排序分页、scope/cursor 误用、更新中读取一致性、未知/空/失败语义及 API 脱敏。用真实 SQLite 检查两进程职责下读写协调，而非全 mock 仓储 | AC-04–AC-08、AC-13、AC-17、AC-21–AC-24、AC-28–AC-30、AC-32、AC-33 |
| T3 一次检查与同步执行入口 | 以受控时钟驱动固定 15 秒，用固定脱敏上游 HTML/JSON、可延迟/失败的传输及模拟 OSS，经公开执行入口产生归档、状态及外部请求。验证目标选择、忙检查跳过、慢同步期间仍检查、编辑/计数触发、首次/失败重试、分项成功、新旧版本交错、checkpoint 和重启恢复；结果通过公开状态/归档读取观察 | AC-23–AC-30、AC-32–AC-34 |

上游接入模块的协议解析必须从固定 HTML/JSON fixtures 穿透到这些入口，不能只喂预先解析好的领域对象而遗漏真实协议。必要的接入契约用少量公开读取操作补足，不新建大量测试专用空接口。不依赖真实 Cookie、真实上游或真实 OSS；夹具身份、内容、图片与凭据占位均为虚构，保留协议结构与字段类型，敏感真实 HTML/响应不入版本库。

### 关键测试组与确定结果

- **T1 数据及阅读**：至少 25 条动态、45 条一级评论、25 条回复，验证 10/10/5、20/20/5、累计 3/13/23/25；交错时间的至少两 UP、同时间/同点赞/字符串 ID 并列及缺失排序字段，确保先完整排序再分页。校验时间转换、分钟精度、来源计数与本地数差异、零/未知、同名不同 ID 的 UP 标识及六行真实布局。
- **T1 竞态及导航**：受控 reader 故意忽略取消，旧成功、旧失败、旧完成分别迟到；测试跨 scope、排序及访问互不污染，同批连点和失败原批重试。浏览器覆盖卡片键盘/点击、气泡定位、图片/选文字/展开不导航，同动态多访问、跨 scope 返回、多批列表/评论/回复恢复、主动定位优先、预览后退/前进、刷新遗留标记及用户滚动优先。
- **T1 图片与局部态**：纯文字、纯图评论、单图、4 图、9 图、超过 9 图、长图及坏图；动态图与不同一级评论组隔离，动态/评论/回复各局部加载空失败重试、默认头像/缺字段。检查预览非循环、按需请求、焦点恢复、横纵手势与底层滚动隔离；测试模拟触控不宣称 iPhone 真机通过。
- **T2 管理及保留**：UID 获取成功/失败、身份不可手改、默认和独立 N、互斥模式、指定归属正确/不符/未知、启停和删除后数据库重开。删除配置/指定目标、模式切换、移出窗口、上游消失后身份、评论、回复、媒体及导航仍可读、不再新调度。无凭据 UI、无内容 scope 开关、无 5 UP/100 目标硬上限。
- **T2 分页与真实存储**：在临时 SQLite 上对全部/单 UP/评论排序分页及失败重试，拒绝跨 scope/父级/排序 cursor；按最终协议在读取期间插入或更新归档，验证声明读取范围不重不漏和快照隔离。重开后配置、可信 observed、成功 checkpoint 与待处理工作仍在。暂停模拟网络/OSS 操作时，另一读取/配置操作仍能完成，以外部行为验证网络不占长事务，不断言某个私有锁实现或毫秒阈值。
- **T3 目标与节拍**：多页候选夹杂不合格内容，按原识别规则凑 N 或耗尽；指定模式不混其他动态，初始化包含目标已有根回复但不全历史动态回填。受控时钟在连续固定节拍验证上一检查阻塞时跳过且无积压，释放后下次节拍继续；单独阻塞同步证明后续检查及其他目标不因同步占用而停摆。
- **T3 安全协议与编辑**：HTML 调整脚本标签和模块顺序仍按 AUTHOR 解析；恶意脚本、非 JSON 表达式和结构/字段失败均不执行 JS、不覆盖旧可信值。fixture 重现页面“编辑于 13:01”、通用“10:38”但同 pub_ts 的结构性差异；普通相对文案、空白差异、首次无编辑标记、可信时间变化、分钟精度及无效编辑时间均验证。正文/图片内容改变但可信信号不变不引入内容比较触发。
- **T3 评论与分项失败**：总数变化/不变/抵消/缺失/无效、正文 BLOCKED 或网页无权而评论接口可读、根页及回复页失败、来源数大于本地数分别验证；初始化和重试之外只有计数变化重扫根回复。正文、评论、图片任意一项失败不使其他项倒退，分页失败不成功归零，首次上传失败不产生假 OSS 成功或 B站业务图回退。
- **T3 持久化交错**：在观察后、同步中、归档提交前后注入失败并重启；不绑定内部辅助函数，使用执行入口/受控 I/O 和重新打开的临时数据库。旧版本处理中观察新版本，旧完成后旧 checkpoint 只能表达真实完成版本，新工作仍可继续；失败且无新信号仍重试，重复同步提交无重复/缺漏，管理聚合不把部分完成显示为全部成功。
- **穿透与交付**：少量“管理 UID/目标 → fixture 检查同步 → 真实 SQLite → HTTP/API Adapter → 页面/评论图 → 返回”端到端串联三个入口，OSS 仅模拟，浏览器请求可控图片服务。保留正常静态产物及故障装配各自验证；检查 Nginx 深链接、API/缺资源错误不回退 HTML、入口与哈希资源缓存。静态部署不只用 Vite preview 冒充。
- **安全和证据**：以明显虚构的秘密标记注入受控失败，验证响应、日志、UI及产物不泄漏，不读取真实凭据。四种视口和键盘由自动化验证；Linux Chrome、iPhone Safari 真机记录版本、设备与实测方式。后续需另行安排有限授权上游协议核验、自然编辑验证和实际规模持续调度/资源观察，它们不进入无凭据自动化测试依赖，也不能由本次写规格代执行。
