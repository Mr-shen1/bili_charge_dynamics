# 21: 一级评论媒体归档与独立恢复

**What to build:** 在根评论同步中保留并归档一级评论图，复用 #19 下载/上传能力，以真实 HTTP 读出按评论隔离的有序媒体及状态。

**Parent:** [07](07-comment-images.md)

**Blocked by:** [15](15-root-comment-archive.md)、[19](19-dynamic-media-archive.md)

**Status:** ready-for-agent

## 依据与交付边界

- [规格](../spec.md)：故事 22、35、54、55、58、59、64；I3、I4、I6、I7、I12；T2、T3。
- [SRS](../../../docs/product/SRS.md)：FR-08、FR-12、FR-19、FR-20、DR-01、DR-03–DR-05、NFR-04；AC-15、AC-17、AC-28–AC-30、AC-32 的评论媒体数据部分。
- 遵守[共同交付要求](../implementation-plan.md#所有执行子票的共同交付要求)。无需等待 #16/#20 页面；本票不复制上传实现，预览和纯图评论 UI 由 #22 交付。
- 不增加回复图片、对象回收、图片变体/CDN或真实 OSS 操作；周期计数联动由 #25/#30 接续。

## 核验标准

- [ ] 原始虚构根评论 JSON 经公开同步入口解析所有图片，复用下载/模拟 OSS 上传，写真实 SQLite 并经 HTTP 可读；保存评论 owner、动态关联、顺序、尺寸、来源/公开 URL 与状态/错误。
- [ ] 两条评论与动态图即使 ID 或来源 URL 形状相似也不串组；重复同步不重复关联、不丢顺序，不处理回复图片。
- [ ] 纯图评论的媒体存在性不因未上传而丢失，不把空正文误判为整条评论无内容；文本、根回复完成和每图上传独立，评论文本完成不等待图片完成。
- [ ] 单图失败保留其他图、评论文本及旧成功媒体，无新计数信号也能重试；重开数据库恢复媒体待处理，旧版本完成不清较新工作或错误替换关联，复用 #19 版本提交语义。
- [ ] 正文受限/网页无权不挡实际可读评论图；评论分页失败不清旧媒体或推进假成功，不因媒体错误回退评论成功 checkpoint。
- [ ] HTTP 返回归档状态及服务端给出的公开 URL，无 B站业务图回退、代理或前端拼接要求；慢 I/O 不占长事务，停止/删除配置不删除任何已有评论媒体，虚构秘密不泄漏。

## 测试与完成证据

T3 从评论 JSON、可阻塞/失败下载和模拟上传贯通；T2 验证真实 SQLite/HTTP、跨 owner 隔离、纯图/未上传语义、版本交错、重开与保留。公开结果应能证明评论已成功但某图尚未完成，而非只有内部单测通过。
