## 核验标准

- [ ] `/` 读取所有保留归档，`/ups/:upId` 只读取该 UP；导航可用身份包含停止/删除配置后仍有归档的 UP，不依赖启用名单。所有读取都不触发上游。
- [ ] 用两 UP 交错/并列时间共 25 条真实 SQLite 归档验证全部集合先排序再 10/10/5 分页；单 UP 独立排序。发布时间降序、字符串 ID 升序，逐字段缺失排有效值后，不转数字或按语言环境比较。
- [ ] 写明读取期间插入/更新的声明范围、cursor 绑定及失效处理，经真实 HTTP 测试范围内不重不漏；跨 scope/资源 cursor 明确拒绝，失败不推进，重试同批，结束不继续请求。
- [ ] 生产 Adapter 与独立 mock 都显式接收 scope；请求、数据缓存不串 scope。受控 Reader 忽略取消时，旧成功/失败/完成不污染当前最小页面或清掉新加载态。
- [ ] 直接打开/刷新全部、单 UP 列表及详情有效；未知 UP、已知 UP 空归档、本地动态不存在、网络失败与未知路由分别表达，保留 #02 详情不存在的独立回归，上游消失不使已有本地记录变成不存在。动态使用实际 author，来源/本地数及未知/零不混淆，编辑和发布时间独立。
- [ ] 重开数据库仍可按上述 scope 读取旧归档；保留 #02 读取、详情和独立 mock 回归，不用虚构评论冒充生产归档。

## 测试与完成证据
