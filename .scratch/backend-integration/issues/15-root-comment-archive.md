## 核验标准

- [ ] 结构真实的虚构 JSON 经公开首次同步入口处理目标已有可读根评论的必要来源分页，真实 SQLite 中保存字符串 ID、动态/作者关系、时间、正文、点赞、来源回复数以及回复和图片所需元信息；不只采启用后新增内容。
- [ ] 从 #02 已归档记录（含 `comment_locator`）升级/重开后，公开同步入口能定位正确评论资源；用动态 ID 与评论定位字段不同的结构真实 fixture 验证请求归属，不能直接假定二者相同。定位缺失/无效时明确未确认或失败，不伪造成功空评论；若协议证据要求改用其他定位来源，记录依据并测试兼容旧归档，不静默丢字段。
- [ ] 正文受限或网页“暂无权查看当前评论”不阻断实际评论接口；可读就归档，明确拒绝/业务/网络失败不伪装成空集合，不承诺绕过权限。
- [ ] 来源动态评论总数、本地根数、本地回复数分开；未知不等于零，错误不覆盖旧可信数。根评论完成只代表本分项，不冒充回复和媒体完成。
- [ ] 任一必要页失败保留已取得内容及旧归档，不清空、不推进本轮根评论成功状态；无新信号也能重试，重开数据库仍有待处理，重复执行不重复或损坏记录。
- [ ] 用 45 条归档验证最热按点赞降序/时间降序/字符串 ID 升序，最新按时间降序/ID 升序；逐字段缺失排有效值后，完整集合先排序再 20/20/5 分页，不冒称 B站热度算法。
- [ ] cursor 绑定动态、排序及读取上下文；跨父级/排序拒绝，更新期间按声明范围不重不漏，普通读取失败原批重试、结束不再产生下一批。明确并测试 cursor 失效/过期（若采用过期机制）的错误及恢复契约：何时可重试同批、何时须显式重新开始；不静默切换读取范围或混入旧页，不在本票预设 TTL。停止/删除配置和来源失败不删除根评论。

## 测试与完成证据

T3 用原始 JSON fixtures、来源中途页失败、受限正文和重试穿透执行入口；T2 用真实 SQLite/HTTP 验证排序、计数、分页、重开及保留。以公开归档/状态证明结果，不绑定 SQL 列或私有函数；HTTP 读取不调用上游。
