## 核验标准

- [ ] 从原始虚构回复 JSON 经公开首次同步入口遍历目标已有可读回复及必要来源分页；保存回复、根评论、动态、作者和可用回复目标，ID 全为字符串，数据库重开关系不丢。
- [ ] 根页或任一必要回复页失败，不推进整轮根评论/回复成功 checkpoint；保留成功部分及旧归档，不写零、不清空，未完成工作可重试、重开恢复，文本成功与媒体成功独立。
- [ ] 真实 HTTP 在每根完整集合按时间升序、字符串 ID 非语言环境升序读取，逐字段缺失排有效值后。25 条验证首批最多 3、随后每批最多 10，可累计 3/13/23/25；同时间、大整数形状 ID 和缺时间不破坏顺序。
- [ ] 明确读取期间更新的一致性协议，cursor 绑定动态、根评论及读取上下文；跨父级拒绝，声明范围不重不漏、普通读取失败原批可重试，结束不继续分页。明确并测试 cursor 失效/过期（若采用过期机制）的错误及恢复契约，区分原批重试与显式重新开始，不静默混入另一读取范围或根评论；不预设 TTL。
- [ ] 来源回复数、本地数、未知和零独立返回；缺失回复目标不伪造作者，首次受限/失败不当成已成功空归档。
- [ ] 重复初始化幂等；停止、删除配置/目标或来源失败后已归档回复仍可经 HTTP 读取，网络分页等待不占 SQLite 长事务。
