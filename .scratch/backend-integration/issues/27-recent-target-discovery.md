# 27: 沿用原识别规则分页发现近期 N 条

**What to build:** 近期模式通过公开发现入口按原充电图文规则跨页凑够 N 条合格目标或到耗尽，结果/失败可持久化并经管理 HTTP 查看。

**Parent:** [10](10-recent-window.md)

**Blocked by:** [23](23-fixed-cadence-checks.md)

**Status:** ready-for-agent

## 依据与交付边界

- [规格](../spec.md)：故事 38–40、43、47、57、67；I1–I4；T2、T3。
- [SRS](../../../docs/product/SRS.md)：FR-14–FR-16、DR-04、DR-05、NFR-05；AC-22、AC-23、AC-25、AC-29、AC-33 的发现部分。
- 遵守[共同交付要求](../implementation-plan.md#所有执行子票的共同交付要求)。提取必要无敏感识别/解析逻辑和结构保持的 fixtures 纳入版本管理；不运行/导入带通知副作用的原脚本。
- 本票交付“发现→持久可信结果/错误→HTTP”，#28 负责把结果转成当前窗口并初始化/移出。候选结果不是已归档成功，不提前改变目标生命周期。

## 开工门槛

除 #23 依赖完成外，领取前必须确认能访问可信的原充电图文识别规则和用于验证的协议材料，并在 `## Comments` 记录脱敏参考位置及来源。本次文档复核未检查 `script_demo` 的实际可用性，不能据此宣称材料齐备。

如果材料缺失或不足以核对原行为，将本票改为 `needs-info` 并列出需维护者提供的脱敏材料；在材料补齐前不得自行设计替代识别规则。满足门槛后，必要的无敏感逻辑和结构保持的虚构 fixtures 随实现纳入版本管理，不依赖 ignored 本地文件才能运行。

## 核验标准

- [ ] 原识别行为保持不变，不重新设计或新增条件；以原始虚构 feed HTML/JSON 经公开发现入口验证。若 ignored 本地参考缺失，明确缺少规则/夹具并请求脱敏材料，不臆造、不 force add 敏感文件。
- [ ] 默认 N=10、每 UP 独立；不合格候选不占名额，跨页累计 N 条合格目标或真正耗尽，不能先截前 N 条再筛。达到 N 后不自动回填全部历史。
- [ ] 至少两 UP 不同 N，重复页/候选不重复占窗口，ID 字符串保存；识别结果次序/取舍遵守来源及原规则，不新增未确认截断算法。
- [ ] 发现成功结果与本轮进行中结果分开；字段/请求/业务/中途分页失败不冒充耗尽，不用失败空集合替换旧可信结果/窗口。错误和可重试状态持久化，重开仍在。
- [ ] 经 #23 可控调度调用发现，慢候选读取不阻塞其他目标检查或归档读取；后续固定调度可重试，停用不继续发起新发现，I/O 不占长事务。
- [ ] 管理 HTTP 可观察 N、模式、本次发现结果/错误及未完成，不把发现成功称作内容归档完成；指定模式不混近期发现，无 5 UP/100 目标硬限，诊断脱敏。

## 测试与完成证据

T3 用多页夹杂、耗尽不足 N、重复、跨 UP 和中途失败 fixtures；T2 用实际 SQLite/HTTP 及重开验证旧结果保持。证明可从来源协议得到可信目标集合，而非只有私有筛选函数测试；识别材料是否齐备须在领取时复核。
