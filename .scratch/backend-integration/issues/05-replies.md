## 核验标准

- [ ] 首次同步通过真实结构的虚构/脱敏回复 JSON fixture，处理目标根评论下已有可读回复及必要来源分页，保存到实际临时 SQLite；不只采启用之后新增内容、不只保存上游预览三条。
- [ ] 回复、根评论、动态和作者/回复目标关系正确，所有 ID 为字符串；扁平显示可用“回复 @某人”，缺目标不拼错误文本，无无限嵌套、回复发布或回复图片。
- [ ] 实际归档 API 在根评论完整集合内按发布时间升序、ID 字符串非语言环境升序，逐字段缺失排有效值后；同时间和大整数形状字符串 ID 排序确定，UI 兜底不改变读取顺序。
- [ ] 25 条回复累计显示 3/13/23/25；来源回复数为零不显示展开入口，全部加载后不再请求；来源未知不以本地已加载数伪装为零或来源总数。
- [ ] 收起仅恢复最初最多三条可见范围，再展开复用此前已加载回复和 cursor，不重复请求已读内容；切根评论排序则重置回复展示状态，不继承另一排序的展开范围。
- [ ] cursor 绑定根评论、动态及读取上下文，跨父级误用明确拒绝；在实施时细化更新中分页一致性并验证声明范围不重不漏，追加失败重试原批，不以去重掩盖遗漏。
- [ ] 回复首次/追加失败只影响对应根评论，保留已有回复与其他评论；同批连点不重复，受控读取忽略取消时旧成功、旧失败和旧完成也不能改变新排序/访问状态。
- [ ] 根页或任一必要回复页失败不推进整轮评论/回复成功 checkpoint、不归零/清空旧内容；成功的可读部分保留，未完成工作可重试和重开恢复，不等待媒体完成才承认文本成功。
- [ ] UP 标识按当前动态作者 ID 而非全局 creator/昵称；同名不同 ID、只读点赞、未知用户/默认头像/时间未知/计数“—”及真实零分别正确，内容头像昵称不导航。
- [ ] 回复超过六个实际渲染行才折叠，保留换行/emoji/长 URL 并安全文本展示；无内容显示“暂无评论内容”，缺字段不泄漏 `undefined`，不增加转发或真实写回。
- [ ] 同一详情不同历史访问分别恢复其排序、多批评论、文本/回复展开、cursor 与阅读锚点/位置；先恢复布局数据再定位，有界后备且用户滚动优先，主动顶部/评论入口覆盖旧位置。
- [ ] 数据库重开及重复初始化后关系、内容和本票成功/未完成状态保持；停用、删配置/目标或来源失败不会删除已归档回复，实际 API 可继续读取。

## 测试入口与实施边界

T3 从协议 fixture 穿透首次根回复同步及失败注入，T2 用真实临时 SQLite/HTTP 验证关系、排序、cursor 和重开，T1 用生产 API Adapter、受控 reader、RTL 与浏览器覆盖累计数量、局部态、排版和历史恢复。观察公开归档/状态与用户动作，不绑定私有函数或 SQL 列名，不读取真实凭据。

本票不加入周期计数触发（由 09）、评论图片或回复图片。初始化完整处理必要根回复是现有目标范围，不是全历史动态补扫。媒体失败独立，不使本票文本状态倒退；原身份、读取、导航及焦点测试继续保留。
