# 02: 指定动态首次归档与阅读

**What to build:** 用户在已有管理页为 UP 添加或移除指定动态 ID，明确看到归属校验结果；经公开初始执行入口或最小独立采集进程完成一次初始化后，可通过真实归档 API 在基础列表及详情阅读正文、身份和独立时间，即使上游随后失败也能读旧归档。

**Blocked by:** [01: UP 管理与配置持久化](01-up-monitoring-management.md)

**Status:** ready-for-human

## 核验标准

- [x] 指定 ID 使用字符串，服务端读取来源作者校验其与 UP 的关系；正确、不符、未知/读取失败分别经管理 HTTP 和 UI 验证，不符或无法确认不强行关联、不伪装校验成功。
- [x] 指定模式仅初始化关联的指定集合，不混近期或该 UP 其他动态；增加/移除关联持久化，停止或删除配置/目标只停止后续处理，身份与已有归档不删除。
- [x] 通过公开一次初始化执行入口或最小采集进程，从固定 HTML/JSON fixture 经真实协议解析写入实际临时 SQLite，再由实际归档 API、生产 API Adapter 和基础页面读出结果；不把采集挂在浏览器读取生命周期上。
- [x] 保存动态 metadata、实际作者、正文内容状态和来源发布时间；成功空正文、正文受限、读取失败分开表达。失败保留旧成功内容，未知时间不以编辑时间补值，无正文无图才显示“暂无内容”。
- [x] 编辑时间仅从页面 HTML 的 `__INITIAL_STATE__.detail.modules` 按 `MODULE_TYPE_AUTHOR` 定位 `module_author.pub_time` 的“编辑于”日期时间，安全 JSON 解析，不执行 JS/eval，不固定脚本标签或数组下标、不依赖 opus/detail JSON。
- [x] 发布时间与编辑时间分别保存/展示；发布时间为绝对北京时间到秒，编辑信号保持来源时区及分钟精度而不伪造秒。普通相对文案和空白变化不算编辑，不仅靠 pub_ts、不比正文或图片。
- [x] 首次无编辑标记仍同步可读正文；编辑字段缺失、非 JSON、解析失败或无效日期保留未知/错误与旧可信值，不写当前时间或“确认未编辑”，不阻断其他已可解析 metadata。
- [x] 保存后续所需的有序媒体来源/可用尺寸以及评论区定位、来源计数等元信息，不因本票不上传/不采评论而丢弃。来源总数与本地归档数、observed 与正文 synced 分开，未知与零不同，计数错误不归零覆盖。
- [x] 基础 list/detail 使用真实归档读取，保留已有排序分页、详情全文、安全文本、缺失身份兜底和有效站内返回；未知本地动态、成功空归档、网络失败分别表达。读取不请求上游，同一归档在来源不可用时仍可读。
- [x] 首次同步及重复执行幂等，正文成功只推进实际处理版本的成功状态，失败留可重试工作；数据库重开仍读到目标、归档及本票待处理状态，不把观察或文本成功冒充媒体/评论完成。
- [x] 从脱敏协议 fixture 穿透验证正常、受限、空、失败及恶意输入，使用虚构秘密检查 API/UI/诊断不泄漏；生产装配不混 mock，独立 mock 回归继续可运行。

## 测试入口与实施边界

T3 为公开首次同步入口，T2 验证真实临时 SQLite、HTTP 和重开，T1 验证生产 Adapter 与基础页面。由本票形成可扩展的最小公开同步能力，后续逐票加入评论、媒体和周期，不提前建设纯横向空框架。细化本票所需归档状态、读取一致性及接口契约并测试，不擅定最终全量协议。

不包括周期检查、评论/回复采集、OSS 上传或多 UP 卡片改版；不添加未批准的手动刷新 UI，测试/执行入口足以证明初始化。两种模式最终只选目标，不限制内容能力。必要无敏感识别/解析逻辑和结构保持的虚构/脱敏 fixtures 随实现纳入版本；原脚本是本地 ignored 参考，禁止运行或导入其带副作用主循环，不 force add。新环境参考缺失时请维护者提供脱敏参考，不臆造识别规则；不读取真实 Cookie 或请求真实上游。
