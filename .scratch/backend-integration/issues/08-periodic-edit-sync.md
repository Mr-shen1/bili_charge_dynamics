# 08: 固定 15 秒检查与编辑同步

**What to build:** 启用目标在独立采集进程中按固定 15 秒接受检查，可信页面编辑时间变化后通过已有公开同步能力更新正文；慢同步不阻断新检查，失败与新旧版本交错可恢复，用户在管理页看见真实检查和正文同步状态。

**Blocked by:** [23: 固定检查](23-fixed-cadence-checks.md)、[24: 编辑同步](24-versioned-edit-sync.md)

**Status:** needs-triage

**票据角色:** 汇总（等待维护者根据子票证据核验收口，不直接派工实施）

## 核验标准

- [ ] 受控时钟驱动连续固定 15 秒节拍：同目标上一检查仍忙时跳过当次，不叠加、不积压，释放后下一固定节拍继续；不采用同步完成再等 15 秒、退避、自适应或每日校准。
- [ ] 检查和耗时同步为同一独立采集进程中的分离阶段；阻塞正文同步时该目标仍可新检查，其他目标节拍也继续，API 不启动定时器或将耗时同步绑定浏览器请求。
- [ ] 检查只读取信号并持久登记 observed 与待处理，同步调用 02 形成的公开能力执行整条内容更新；无编辑标记或信号部分不可用时首次可读内容仍初始化，基线不是成功 checkpoint。
- [ ] 编辑时间唯一来自普通页面 HTML 的 `__INITIAL_STATE__.detail.modules`，按 `MODULE_TYPE_AUTHOR` 找 `module_author.pub_time` 的“编辑于”日期时间；安全 JSON 解析、不执行 JS/eval、不固定脚本/数组下标、不依赖 opus/detail JSON。
- [ ] 按来源语义规范化日期、时区、精度和空白，可信编辑时间变化才触发后续正文/动态图工作；普通相对文案、空白差异不触发，不单靠 pubts，不比较正文/图片 URL、内容、字节或摘要。
- [ ] 编辑信号缺失、非 JSON、结构错误、带标记但无效日期时保留旧可信值、旧归档及成功 checkpoint，记录未知/错误、不写空值/当前时间/确认未编辑；其他可读部分不被阻断。发布/编辑独立、分钟精度不补秒，明确同分钟漏检。
- [ ] 最近可信 observed、正文成功 checkpoint、媒体等分项未完成工作及检查/成功时间真实持久化；无变化检查不推进同步成功，正文成功不宣称评论或媒体全部完成。
- [ ] 在公开检查/同步边界注入失败，来源后续无新信号仍可在固定节拍重试；关闭重开临时 SQLite/重启采集后恢复配置和待处理，重复领取/执行/提交不重复、不损坏旧归档。
- [ ] 旧版本同步中观察新版本，旧完成只提交实际处理版本，不覆盖新 observed、不冒领新 checkpoint、不清较新待处理；随后新版本仍能被执行，并由公开归档/管理状态验证。
- [ ] 停用或移除目标后不再发起新检查/领取新工作，已归档内容与持久未完成信息不删除；本票覆盖所属检查与正文安全边界，完整模式/媒体在途整合由 11 验证而非届时才补保留。
- [ ] 管理 UI/API 能读未检查、检查无变化、同步中、失败/部分完成及最近检查、最近成功和脱敏错误；检查成功不冒充整条同步成功，浏览归档不会发起上游检查。
- [ ] 固定 HTML fixture 覆盖脚本/模块顺序变化、相同 pubts 不同可信编辑时间、无标记首次、恶意非 JSON、内容改变但编辑信号不变；实际临时 SQLite/HTTP 与生产 Adapter 穿透验证状态及内容，慢网络不占长事务。

## 测试入口与实施边界

T3 通过公开一次检查/同步入口、受控时钟及延迟/失败传输验证节拍和交错；T2 验证真实临时 SQLite、重开和状态 HTTP；T1 验证管理状态及正文阅读映射。仅使用虚构/脱敏 fixtures 和秘密占位，不读取真实 Cookie、不请求真实上游。

06 可并行，不列为阻塞：本票不实现 OSS，也不提前搭纯横向空框架；在 02 的最小同步能力上扩展调度和持久版本语义，保留触发整条正文及动态媒体更新的公开路径，06 接入后复用它。编辑后图片自动联动在 11/12 组合验证。评论计数变化同步由 09，近期发现由 10。受控节拍通过不等于实际持续 15 秒稳定；13 GET、一次成功和分钟精度样本不证明全部页面或自然多次编辑已验证。
