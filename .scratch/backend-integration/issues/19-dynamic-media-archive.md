## 核验标准

- [ ] 原始动态协议 fixture 经公开同步入口完成下载/模拟上传→真实 SQLite→HTTP，保存动态 owner、顺序、可用尺寸、来源 URL、公开 OSS URL、上传状态/脱敏错误；保存全部图，不把九格当存储上限。
- [ ] 正文与每张图分别成功/失败，首次未上传明确待处理或失败；单图失败保留其他图和旧成功媒体，不伪造公开 URL、不返回 B站业务图作为生产回退。
- [ ] 未完成媒体持久化、无新信号也可独立重试，关闭重开可恢复；重复执行不重复关联、不改变顺序，单图重试不要求重新宣称正文完成。
- [ ] 同一公开同步入口可按实际处理版本更新整条正文及媒体来源；旧版本上传完成不覆盖较新关联/清除较新工作，失败保留旧成功媒体。细化并测试来源变化、关联切换和提交语义，不以图片差异作为编辑检测。
- [ ] 慢下载/上传暂停时其他归档读取和配置写入仍可完成，以真实 SQLite 外部行为验证网络不占长事务，不断言线程数或毫秒阈值。
- [ ] HTTP 明确区分归档待处理/失败与可用公开 URL；浏览器后续直接用该 URL，不需拼桶/域名、代理、签名续期。凭据只服务端仓库外；虚构秘密不出现在响应和诊断。

## 测试与完成证据

T3 用协议 fixtures、可阻塞/失败下载和模拟 OSS 覆盖单图失败、旧/新版本交错及重复处理；T2 验证公开状态、顺序、重开和并行读写。图片变体、压缩、CDN、物理去重和付费策略仍未决，不由本票静默选择；实际云上传证据归 #34。
