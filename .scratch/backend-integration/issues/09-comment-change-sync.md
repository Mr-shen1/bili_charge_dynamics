# 09: 评论数量变化后的增量同步

**What to build:** 已启用目标的来源评论总数变化后，采集进程通过既有根评论/回复同步能力更新可读归档，页面和管理状态分别显示来源计数、实际归档及完成情况；初始化或失败可重试，正文受限不阻断真实评论。

**Blocked by:** [25: 计数触发同步](25-comment-count-sync.md)、[26: 评论同步状态](26-comment-sync-status.md)

## 核验标准

- [ ] 经 08 的公开检查入口读取可信来源动态评论总数并持久保存 observed；除初始化和失败重试外，仅总数变化触发根评论及回复同步，总数不变或仅正文编辑不默认重扫。
- [ ] 来源总数语义含一级评论和楼中楼，与本地根数/回复数、已加载数及各根来源回复数分开；用结构保持的虚构/脱敏 JSON fixture 核验字段映射，不拿首屏或 235/501 抽样恒等推定所有接口口径，不擅自省略未验证计数读取。
- [ ] 变化驱动的“增量”同步通过已有公开能力完整处理该轮必要根评论及回复分页，包含目标已有可读历史根回复；不新增未确认的见旧 ID 即截断等算法而漏必要历史，不自动补扫 UP 全历史动态。
- [ ] 首次计数未知、无编辑标记或正文受限仍可初始化实际可读根回复；网页“暂无权查看当前评论”与实际评论接口结果独立，可读照常保存，实际拒绝如实失败而非空集合。
- [ ] 计数缺字段、无效、网络/业务失败不写零、不覆盖旧可信值、不登记假成功；真实零与未知不同，API/UI 明确区分来源和本地，不用本地数补来源数。
- [ ] 根页或任一必要回复页失败时保留可读成功部分和旧归档，不清空、不推进整轮评论/回复成功 checkpoint；无新计数信号仍能重试同一未完成工作。
- [ ] 评论成功 checkpoint 只绑定实际完整处理的观察版本；旧同步中观察新计数，旧完成不冒领新版本、不清新待处理，较新工作仍可执行，重复处理幂等且重开恢复。
- [ ] 正文、根回复及媒体状态独立推进，评论文本成功不等待全图上传、媒体失败不使评论成功倒退；公开同步路径允许后续 07 共用评论媒体工作，不自行实现 OSS、不增加媒体票阻塞。
- [ ] 在受控时钟下阻塞评论分页，新的检查和其他目标仍能继续，上一检查忙只跳过当次而无积压；慢来源 I/O 不占长数据库事务，HTTP 读取旧归档仍可完成。
- [ ] 管理状态/读取 API/页面可观察可信来源数变化、同步中、部分失败、最近检查与分项成功及脱敏错误；归档读取成功不冒充采集全部完成，保留原排序、分页、局部重试及导航恢复测试。
- [ ] fixture 覆盖总数增加/减少/不变、增删抵消、纯评论编辑、缺失/无效/真实零、正文受限评论可读、根/回复分页失败和重启；明确抵消与纯编辑但总数不变可漏检，不加入每日全校准、内容比对或退避兜底。

## 测试入口与实施边界

T3 用公开检查/同步入口、固定时钟及真实结构的虚构 JSON 控制计数、分页和新旧版本交错；T2 使用实际临时 SQLite/HTTP 验证 observed/synced、来源/本地数、重开与失败保持；T1 经生产 API Adapter 验证管理及评论读取状态。不能只输入预先解析领域对象而省略协议解析，测试只用虚构凭据标记。

无需 03/06/07 作为额外依赖，本票不重写图片上传或列表展示。评论变化后一级评论图片联动在 11/12 验证；本票保留公开扩展和分项待处理语义。启停/删除不得删除归档或未完成信息，各票所属数据保留即时成立，整合不增加未确认截断/校准机制。
