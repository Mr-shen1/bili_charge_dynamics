## 核验标准

- [ ] 编辑信号仅从普通 HTML 中安全 JSON 解析的 `__INITIAL_STATE__.detail.modules` 按 `MODULE_TYPE_AUTHOR` 找 `module_author.pub_time` 的“编辑于”；不执行 JS/eval、不固定脚本/模块下标，不依赖 opus/detail JSON。
- [ ] 规范化日期、时区、精度与空白，可信编辑时间变化才登记后续正文/动态图更新；相对文案/空白变化、pub_ts 相同或正文/图变化都不能替代可信信号。无标记首次仍初始化。
- [ ] 缺失、恶意非 JSON、结构/日期失败保留旧可信值、旧归档和 checkpoint，公开未知/错误而非“确认未编辑”；不补当前时间，编辑分钟精度不伪造秒，不用编辑补发布时间，其他可读分项不被阻断。
- [ ] 同步绑定实际处理观察版本；旧任务执行中出现新观察，旧完成只提交自己成功版本，不覆盖新 observed、不冒领新 checkpoint、不清较新工作，随后新版本仍可执行。
- [ ] 在观察后、同步中、提交前后注入失败，重开 SQLite/重启后恢复；即使无新信号也可在固定节拍重试，重复领取/执行/提交幂等。正文成功不冒充评论/媒体完成，媒体待处理不丢。
- [ ] 管理 API/UI 经生产映射显示未检查、无变化、同步中、失败/部分完成、最近检查/实际成功及脱敏错误；归档正文更新可读，读取不触发检查，停用保留旧内容与未完成工作。
