# 04: 一级评论归档与详情评论区

**What to build:** 已选目标经公开首次同步入口保存实际可读的一级评论，阅读者在已有动态详情中看到 B站风格评论区，可切最热/最新并每批读取 20 条；正文受限或评论同步局部失败不影响已有内容阅读。

**Blocked by:** [02: 指定动态首次归档与阅读](02-target-initial-archive.md)

**Status:** ready-for-agent

## 依据

- [父规格](../spec.md)：故事 4、7、9、12–15、18、19、30、32–35、42、47、54、55、60；I5、I6、I8–I12；T1–T3。
- [SRS](../../../docs/SRS.md)：FR-01–FR-04、FR-06、FR-10–FR-12、FR-18、FR-19、DR-01、DR-02、DR-04、DR-05、NFR-02、NFR-04；AC-01–AC-04、AC-06、AC-07、AC-12、AC-14、AC-15、AC-18、AC-24、AC-28、AC-31（根评论范围）。
- [HLD](../../../docs/HLD.md)：第 2.3、3–6、9、10 节；[UI 文字规范](../../../docs/ui-reference.md)。

## 核验标准

- [ ] 从结构保持的虚构/脱敏上游 JSON fixture 穿透公开首次同步入口，将目标已有可读根评论按实际来源分页归档到临时 SQLite，不只采启用之后的新评论；重复执行不重复、不破坏旧记录。
- [ ] 保留字符串评论 ID、动态归属、作者、发布时间、正文、点赞、来源回复数及后续回复关系/评论图片所需元信息，不因本票未实现回复或上传而丢字段。
- [ ] 正文受限或页面“暂无权查看当前评论”仍尝试实际评论接口；可读评论正常归档和读取，明确拒绝/失败仍如实表达，不承诺所有受限内容可读、不以受限正文当空评论。
- [ ] 来源动态评论总数（含根及回复）、本地根数和本地回复数分开，未知与零不同，卡片/评论区不以已加载条数补来源总数；字段不足、无效、请求或业务错误不写零、不覆盖旧可信计数。
- [ ] 只有本轮根评论所需分页归档成功才推进本票根评论成功状态；中途页失败不当成功空结果、不清空旧归档，待处理可重试且数据库重开仍在；根评论完成不冒充回复/媒体已完成。
- [ ] 实际归档 API 对完整本地集合先排序再分页：最热按点赞降序、时间降序、ID 字符串升序，最新按时间降序、ID 字符串升序；逐字段缺失排有效值后、ID 不转数字、不声称 B站热度算法。
- [ ] 45 条根评论按 20/20/5 展示，cursor 绑定动态、排序和读取上下文，跨父级/排序误用被明确拒绝；细化更新期间一致性并测试不重不漏，失败原批重试、结束不再请求。
- [ ] 详情初访默认最热；切排序定位评论区、重置首批及文字/回复展开，保留上方动态。目标排序失败停留其可重试状态，不拿旧排序冒充结果；取消被忽略时旧成功/失败/完成也不能串入。
- [ ] 在已有详情与评论气泡入口接入真实数据：气泡图标及数量进入同一详情评论区，非真实评论缩略图、无独立评论页；不要求先完成新多 UP 列表，不引入“查看详情”或转发元素。
- [ ] 评论按参考白卡、粉色作者及层级显示作者/绝对北京时间/正文/只读点赞/回复数，UP 标识按当前动态作者 ID；头像昵称只展示。同名不同 ID、缺头像/时间/计数和安全脚本文本均测试。
- [ ] 评论正文超过六个渲染行才折叠，动态详情保持全文；加载、成功空、有内容、失败、追加及结束分开，局部重试保留已有内容、同批防重复，动态读取仍不触发上游。

## 测试入口与实施边界

T3 验证 fixture 首次根页同步、受限独立性及失败重试；T2 验证真实 SQLite/HTTP、分页和重开；T1 验证生产 Adapter、已有详情、气泡定位和排序竞态，并用浏览器验证六行布局。保留原身份、读取、导航和焦点测试。

不依赖 [03](03-multi-up-reading.md) 的新列表，本票在已有入口即可独立演示，跨票卡片与评论组合最终回归。楼中楼实际展开由 [05](05-replies.md)，一级评论图上传/预览由 [07](07-comment-images.md)，周期数量触发由 [09](09-comment-change-sync.md) 扩展；本票不伪装这些分项已完成。保留全图元信息但无回复图、无全历史动态补扫。
