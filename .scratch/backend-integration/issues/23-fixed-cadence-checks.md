# 23: 独立采集进程的固定节拍检查

**What to build:** 在 #02 的指定目标与同步底座上交付可运行的独立采集进程，按固定 15 秒检查并持久登记观察/待处理，公开 API 可读实际检查状态。

**Parent:** [08](08-periodic-edit-sync.md)

**Blocked by:** [02](02-target-initial-archive.md)（用户确认已完成）

**Status:** ready-for-agent

## 依据与交付边界

- [规格](../spec.md)：故事 43、48、49、55–57、64、67；I1、I4、I5、I12；T2、T3。
- [SRS](../../../docs/product/SRS.md)：FR-14、FR-16、FR-17、DR-05、NFR-04、NFR-05；AC-22、AC-25、AC-28、AC-33、AC-34 的检查与运行边界部分。
- 遵守[共同交付要求](../implementation-plan.md#所有执行子票的共同交付要求)。先明确固定节拍、检查占用、持久工作和重启语义；复用 #02 安全信号解析与公开同步能力，不只写定时器单元测试。
- 本票负责可运行调度与公开检查结果，#24 负责完整编辑触发/版本提交及管理 UI；#25 评论计数策略、#27 近期发现均不在本票。

## 核验标准

- [ ] 单独 Python 采集进程从持久配置选取启用指定目标；API 进程不启动定时器，不把后台同步绑定浏览器请求，不引入多 worker、Redis/Celery 或第二套采集服务。
- [ ] 受控时钟连续固定 15 秒触发，同目标上一检查忙就跳过当次，不积压、不叠加；释放后下一固定节拍继续，不变成同步完成再等 15 秒，也不加入退避/自适应/每日校准。
- [ ] 检查只读取信号、记录观察及待处理；耗时同步在同一采集进程的独立执行阶段复用 #02 能力。阻塞一个目标同步时，该目标可继续检查，其他目标也继续；不用无限并发许诺节拍。
- [ ] 首次纳入无编辑标记/部分信号未知仍登记可读部分初始化工作；检查成功或建立基线不等于同步成功。公开 HTTP 区分未检查、检查无变化、检查失败及待处理，检查/成功时间不混用。
- [ ] 配置、可信 observed、待处理和检查时间持久化；重启不会把中断工作静默视为完成，重复登记幂等。停用/移除后不发起新检查/领取新工作，已有归档和未完成信息保留。
- [ ] 来源失败不覆盖旧可信观察和归档；慢检查/同步 I/O 期间实际 SQLite 读取及配置变更仍能完成，错误脱敏。可用无真实上游的隔离配置启动进程并观察至少连续多个受控节拍。

## 测试与完成证据

T3 经公开运行/一次检查入口、受控时钟、原始 HTML/JSON 和阻塞传输验证节拍与检查/同步分离；T2 验证实际 SQLite、状态 HTTP、进程重启恢复。提供采集进程启动/停止命令及最小隔离演示；长期实际稳定性不是本票验收结论。
