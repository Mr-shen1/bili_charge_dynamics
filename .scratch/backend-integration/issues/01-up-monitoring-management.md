# 01: UP 管理与配置持久化

**What to build:** 用户在 `/manage` 只输入 UID 即可获取并保存 UP 昵称头像，按 UP 设置互斥监控模式、近期 N 与启停、删除监控配置；刷新页面或重启服务后配置仍真实可读。本票独立交付最小 FastAPI、SQLite 持久化与管理 UI，不等待采集或完整归档。

**Blocked by:** 无（可立即开始）

**Status:** ready-for-human

## 依据

- [父规格](../spec.md)：故事 36–39、43、44、57、64、65、67；I1–I4、I12；T1、T2。
- [SRS](../../../docs/SRS.md)：FR-12、FR-14、FR-19、DR-04、DR-05、NFR-04、NFR-05；AC-15、AC-22、AC-29、AC-32、AC-33（本票范围）。
- [HLD](../../../docs/HLD.md)：第 1、2.1、3.5、9.3 节。

## 核验标准

- [x] `/manage` 经实际受测 FastAPI 管理接口新增 UID；上游资料传输可替换，身份实际写入临时 SQLite，页面通过生产映射读取保存结果，不靠写死名单或假仓储。
- [x] 新增只接受 UID，不提供昵称头像覆盖或凭据编辑；字符串 UID 不经大整数数值转换。所需输入校验、重复新增及错误契约在实施时明确并测试。
- [x] 资料获取失败、拒绝或字段不足明确提示失败/未取得，不伪造成功身份，不破坏已有成功资料；已保存资料的显示兜底符合未知昵称、默认头像规则。
- [x] 至少两 UP 分别保存近期 N；默认 10，修改一人的 N 不影响另一人。无未经确认的 5 UP/100 目标硬限。
- [x] 每 UP 只能选择“近期 N 条”或“指定动态 ID”一种模式；切换和保存可回读，没有“仅评论/完整采集”开关，列表 scope 不是采集配置。
- [x] 每 UP 启用/停止可独立操作并持久化；未接入检查时显示“未检查”，最近检查/成功时间不伪造为当前时间或保存配置时间。
- [x] 删除 UP 监控配置后身份仍可读，既有归档关系不得随配置删除级联清除；本票以已保存身份验证，后续各票继续保证其新增数据的保留。
- [x] 关闭并重新打开实际临时数据库、重启受测应用后，从 HTTP 和 UI 仍能读取身份、模式、N、启停及删除结果；不以全 mock 数据库替代持久化验证。
- [x] 管理 UI 覆盖加载、成功、失败、原位重试和操作中防重复提交；失败不显示保存成功、不将另一 UP 的状态覆盖，控件键盘可用、焦点明确。
- [x] API 进程不包含周期调度或浏览器请求绑定的耗时同步；采用 Python/FastAPI/SQLite，Python 仅 uv，前端沿用原技术与 nvm/pnpm，本票所需管理契约及迁移有测试。
- [x] 用虚构秘密标记验证错误、响应和 UI 脱敏；浏览器不接收上游/OSS 凭据、不直调采集接口。明确首期无鉴权管理/API 的公网风险，不增设鉴权前置要求。

## 测试入口与实施边界

T2 使用隔离临时 SQLite 和模拟上游资料响应，经过 HTTP 写读及关闭重开；T1 替换 HTTP 传输而非绕过生产管理映射，并保留少量连接受测 API 的页面操作测试。细化本票所需 HTTP/输入/迁移契约后实施，不预选 SQL 表名或库版本。

指定动态实际增加/移除与归属校验由 [02](02-target-initial-archive.md) 交付；本票只保存模式，不以无效的假目标 UI 冒充其能力。近期发现、周期检查、完整归档及完整运行状态不在本票。删除/停用的数据保留约束现在就成立，不延后到整合票。
