# 32: 本期自动化回归与全量验收台账

**What to build:** 跑通本期自动化/隔离部署回归，建立 AC-01–AC-34 可复核证据台账，将已通过、失败及未验证严格分开，不把历史或人工待测项算作通过。

**Parent:** [12](12-delivery-acceptance.md)

**Blocked by:** [31](31-reproducible-deployment.md)、[35](35-bilibili-visual-replica.md)

**Status:** ready-for-agent

## 依据与交付边界

- [规格](../spec.md)：故事 1–68；I1–I12；T1–T3、穿透和证据核验。
- [SRS](../../../docs/product/SRS.md)：FR-01–FR-20、DR-01–DR-05、NFR-01–NFR-05；AC-01–AC-34 台账，自动化主责 AC-20 与 AC-34 的证据区分。
- 遵守[共同交付要求](../implementation-plan.md#所有执行子票的共同交付要求)，按父 #12 与[拆分索引](../implementation-plan.md)定位实现责任，不重编号或复制一套产品 AC。
- 本票交付“自动化结果和完整台账”，不要求代理代做真机/真实上游。#33/#34 可并行，尚无结果就标未验证；本票完成不代表父 #12 整体验收完成。

## 核验标准

- [ ] 执行本期 T1/T2/T3、生产 Adapter、独立 mock/可控故障和少量真实 API 浏览器穿透回归，记录实际命令、版本、环境、结果和证据路径，失败如实保留，不以“已有测试文件”代替运行结果。
- [ ] 全流程覆盖全部/单 UP→卡片/气泡→详情→两类图→排序→回复→返回，及 UID/模式/目标/启停删除/窗口、编辑图更新、评论图更新、分项失败/重启/版本交错；复用 #30 证据但核对其属于本期代码。
- [ ] 四宽度 360/390/768/1280px、键盘焦点/约 44px 触控、六行折叠/详情全文、绝对时间/分钟编辑精度有自动化/检查证据；汇入 #35 阅读参考图保留区域的一比一视觉基准、截图/差异图及管理页同风格规则映射/截图/操作回归，必要业务差异明示，不能以功能通过代替 AC-31 对齐；无查看详情/转发/独立评论页/真实写回。
- [ ] 为 AC-01–AC-34 建台账：关联需求/执行票、自动化/部署/真机/上游/持续运行类别、环境方法、通过/失败/未验证、原因和证据。一个 AC 多类证据未齐不能整体标通过，不继承旧同号 AC。
- [ ] 汇入 #31 双进程/Nginx/缓存/风险说明及虚构秘密脱敏检查；分别记录 #33 正式浏览器、#34 上游/实际 OSS/持续运行的已得证据或待补项，不把 13 GET、移动 Chromium 或模拟 OSS 当替代。
- [ ] 输出剩余失败/未验证清单、对应执行责任和复测步骤；必需项缺失时明确“不能宣称完整验收”。不擅自读凭据、发真实请求、自动采购或运行持续采集。

## 测试与完成证据

交付本期验收记录及可复现命令，台账供 #33/#34 补证。台账记录工作可完成但测试失败仍阻止相关功能验收；不得把文字记录的完成状态转成未经证实的功能通过。
