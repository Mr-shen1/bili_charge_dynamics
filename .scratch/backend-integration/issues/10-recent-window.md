# 10: 近期 N 条目标发现

**What to build:** 用户为各 UP 选择近期 N 模式后，采集进程沿用原充电图文识别规则逐页凑足 N 条合格目标或直到耗尽，新目标通过已有首次同步入口初始化；移出窗口只停止监控，旧归档仍可读。

**Blocked by:** [08: 固定 15 秒检查与编辑同步](08-periodic-edit-sync.md)

**Status:** ready-for-agent

## 依据

- [父规格](../spec.md)：故事 38–42、44、45、47、48、57、67；I1–I4；T2、T3。
- [SRS](../../../docs/SRS.md)：FR-14–FR-16、FR-18、FR-19、DR-04、DR-05、NFR-05；AC-22–AC-25、AC-29、AC-33（近期目标范围）。
- [HLD](../../../docs/HLD.md)：第 2.1、2.2、3.5、10.3 节；[脚本经验与证据边界](../../../docs/backend-feasibility.md)。

## 核验标准

- [ ] 按原参考脚本的充电图文识别行为处理候选，不重新评估、不新增条件；必要无敏感识别/解析逻辑及结构保持的虚构/脱敏 fixtures 纳版本测试，不直接运行或导入带通知副作用的本地脚本主循环。
- [ ] 默认 N=10、按 UP 独立配置；多页候选夹杂不合格项时继续翻页累计 N 条合格目标，不能取前 N 条普通候选再筛选；来源耗尽允许不足 N 条，达到窗口后不自动全历史动态回填。
- [ ] 至少两 UP 的 N 和发现结果互不影响，候选/目标 ID 全为字符串，重复页/重复候选不重复占窗口；重复发现不会重复初始化或破坏已有归档。
- [ ] 指定模式只处理关联指定 ID，不合并近期目标；近期模式没有仅评论/完整采集开关，阅读 URI scope 不改变采集范围，两种模式只决定选哪些目标。
- [ ] 新纳入目标调用 02/08 已有的可扩展公开首次同步能力，即使没有编辑标记也初始化可读内容；不新建一条缩水采集路径，后续根回复与媒体扩展可以直接复用。
- [ ] 当前窗口持久化并供 08 固定检查调度读取，发现后仅当前启用目标发起后续检查；单目标检查忙仍遵守跳过、不叠加，发现和慢同步不把全局节拍改为完成后再等。
- [ ] 移出窗口只停止新调度，不删身份、正文、评论、回复、媒体或未完成信息；重新纳入可继续同步，全部/单 UP/详情读取保留归档，所属数据保留不留到 11 才实现。
- [ ] 候选请求/字段/分页失败明确显示发现未完成/错误，不当作来源耗尽、不以失败空窗口替代旧可信目标和归档；按失败语义可在后续固定调度重试，数据库重开恢复配置/目标及待处理。
- [ ] 受控 fixture 覆盖默认/独立 N、多页夹杂、耗尽不足 N、重复候选、发现中途失败、新增/移出/重新纳入和启停，公开状态/API 验证选择结果及同步外部调用，不绑定私有筛选函数或 SQL 列。
- [ ] 管理可读取实际 N、模式、已发现目标及未检查/发现错误，不把发现成功当归档全部完成；读取已有归档不隐式再扫描上游，诊断/响应不暴露虚构秘密标记。
- [ ] 不加入 5 UP/100 目标硬限；当前实际起始样本是近期约 10 条、指定 1 UP 的 2 条，测试为分页构造的更多记录不是负载/容量保证。

## 测试入口与实施边界

T3 由真实结构的虚构 feed HTML/JSON、受控时钟和可失败传输贯通发现、登记目标及公开首次同步调用；T2 使用实际临时 SQLite、管理 HTTP 和重开验证模式/N/窗口与保留。本票可通过已有基础阅读和公开状态独立验证，不要求 03 的新列表、09 的具体评论变化能力或 06 的媒体上传先完成；这些能力通过共同同步入口组合而非新增阻塞。

本地脚本和参考截图受 gitignore 排除，新 clone 缺失时应指出参考依赖并请维护者提供脱敏材料，不臆造识别、不 force add ignored。tracked UI 文字规范可用。本票不读凭据、不请求真实上游、不执行采集脚本，不引入通知、全历史动态回填、每日校准、退避或新的截断算法。
