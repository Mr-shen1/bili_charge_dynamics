# 07: 一级评论图片归档与预览

**What to build:** 阅读者能在真实归档一级评论中看到有序图片，包括纯图评论，并直接预览该评论自己的图片组；服务端复用动态图上传能力，单图失败不影响评论文本、其他图或其他评论。

**Blocked by:** [04: 一级评论归档与详情评论区](04-root-comments.md)、[06: 动态图片 OSS 归档与预览](06-dynamic-images.md)

**Status:** ready-for-agent

## 依据

- [父规格](../spec.md)：故事 22–27、32、33、35、54、55、58、59、63、64；I3、I4、I6、I7、I9–I12；T1–T3。
- [SRS](../../../docs/SRS.md)：FR-08–FR-12、FR-19、FR-20、DR-01、DR-03–DR-05、NFR-02–NFR-04；AC-09–AC-12、AC-14–AC-18、AC-28–AC-30、AC-32（一级评论图范围）。
- [HLD](../../../docs/HLD.md)：第 3.5、7–9 节；[UI 文字规范](../../../docs/ui-reference.md)。

## 核验标准

- [ ] 从结构保持的虚构根评论 JSON fixture 经已有公开首次同步入口解析图片，复用 06 的服务端下载/模拟 OSS 上传能力，写实际临时 SQLite，经真实 HTTP/生产 Adapter 在详情评论区读取展示，不复制一套上传实现。
- [ ] 保存一级评论 owner、动态关联、有序图片、可用尺寸、来源地址、公开 OSS 地址及上传状态/错误；不同评论和动态图关联分开，重复同步不重复或串组，不扩展任何回复图片。
- [ ] 纯图评论正常显示有序图片、不写“暂无评论内容”；有文无图不留空图区、两者都空才用空内容文案，图片尚未上传不抹去已有图片内容语义。
- [ ] 评论文本、根回复同步及单图上传独立成功/失败；一张上传失败不清除其他成功图/文本/旧成功媒体，待处理图可独立重试和数据库重开恢复，评论成功 checkpoint 不等待全图完成。
- [ ] 正文受限或网页无权提示不挡实际可读根评论及其图片处理；计数/分页/图片错误不归零、不覆盖旧评论归档、不将局部完成宣称全部成功。
- [ ] 生产业务图只使用后端给出的公开 OSS URL，浏览器直取不拼接、不代理、不回退 B站业务图；头像外链仍允许，服务端上传失败与浏览器加载失败有不同提示和重试语义。
- [ ] 评论单图、四图、其他多图和超过九图保持比例与布局，不丢任何来源图；使用适用的九格提示和详情全部缩略/预览规则，图片占位不严重扰动评论阅读位置。
- [ ] 预览身份包含 owner 类型、具体评论 ID、组内图片及触发处；点击某图即开该图，张数和前后切换只在该评论组，不串动态图、其他评论或回复。
- [ ] 复用原键盘/Esc、手机横滑、首尾不循环、单图无切换及长图完整/适宽规则；纵向读图不滚底层、不误切，切图重置纵向位置，坏图仍可重试/切走/关闭。
- [ ] 后退优先关闭，前进恢复原评论组和图片；关闭恢复对应评论位置和触发焦点或合理后备。不同组反复打开、排序切换导致触发处卸载、刷新遗留标记均不多退或循环，原历史/焦点测试保留。
- [ ] 评论图缩略懒加载、预览按需请求，不在打开一图时下载全部组原图；四宽度、长昵称/长图、触控区域与键盘焦点检查通过，移动自动化不冒充真机。

## 测试入口与实施边界

T3 以虚构 JSON、可延迟/失败下载及模拟 OSS 穿透归档执行，T2 验证真实 SQLite/HTTP、owner/顺序、重开与失败保持，T1 验证生产 Adapter、多个评论组及浏览器预览历史/焦点/局部故障。正常生产与独立 mock/故障装配分开；使用虚构秘密标记验证响应和诊断脱敏，不读取真实凭据。

不加入回复图片、独立评论页、转发、真实写回或自由缩放，不把评论气泡替换为实际评论缩略图。周期计数触发仍由 09 扩展；评论数量变化后评论图片的自动联动在 11/12 验证，不因本票不做调度丢弃媒体待处理工作。图片变体/CDN、对象回收和付费配置不擅自决定。
