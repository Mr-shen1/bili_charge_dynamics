# 14: 多 UP 导航、卡片入口与访问恢复

**What to build:** 在 #13 的真实读取上完成“全部 + UP”选择条、卡片改版以及按访问隔离的返回恢复，读者可跨 UP 连续阅读。

## 依据与交付边界

- [规格](../spec.md)：故事 2–13、17、28–35、46、62；I3、I8–I11；T1、T2。
- [SRS](../../../docs/product/SRS.md)：FR-01–FR-03、FR-05、FR-10–FR-13、FR-19、DR-01、DR-02、NFR-01、NFR-02、NFR-04；AC-01–AC-03、AC-12–AC-16、AC-18、AC-21、AC-29、AC-31 的导航展示部分。
- 遵守[共同交付要求](../implementation-plan.md#所有执行子票的共同交付要求)和 [UI 规范](../../../docs/design/ui-reference.md)。沿用现有导航会话和位置恢复，不增加第二套历史/滚动协调器。
- 不实现真实评论采集或 OSS；评论未归档时保留真实未同步提示。已有图片交互继续回归，真实图片接入由 #20 完成。

## 核验标准

- [ ] 选择条展示全部及保存的 UP 头像昵称，选中态与 URL/scope 一致，停止/删除配置但有旧归档的身份仍可选择；仅选择条内部可横滑。
- [ ] 卡片实际作者来自 dynamic.author；整体点击/键盘进入详情顶部，气泡图标与来源评论数进入同详情评论区，移除“查看详情”。图片、文字选择、展开、内嵌操作不导航；内容头像昵称仅展示、点赞只读，无冲突嵌套交互。
- [ ] 列表超过六个真实渲染行才折叠，宽度变化重判；详情始终全文。换行、emoji、长词/URL 安全文本显示，缺昵称/头像/时间/计数有既定兜底，编辑精度独立。
- [ ] scope、访问身份、cursor、缓存与快照隔离；忽略取消的旧成功/失败/完成不改变新视图。同动态多次访问不共用可变快照，连点不重复追加。
- [ ] 详情返回有效站内来源 scope 的多批列表、展开、cursor 与锚点/位置；无来源回 `/`。先恢复数据/布局再定位，主动卡片/气泡入口优先，用户滚动不被迟到恢复覆盖；刷新遗留状态不循环。
- [ ] 浅青背景、白卡、青蓝选中及粉色层级符合规范；360/390/768/1280px 无页面溢出，约 44px 主要触控、清晰键盘焦点。无复杂侧栏、转发、独立评论页、真实写回或新增业务区块。

## 测试与完成证据

T1 经生产 Adapter、RTL 受控乱序和 Playwright 验证卡片/气泡/内部操作、同动态多访问、跨 scope 返回、多批恢复、布局与焦点；少量 T2 实际归档联测验证旧 UP 入口。移动视口不等于真机验收。父 #03 仅在本票与 #13 均完成并核对原清单后收口。
