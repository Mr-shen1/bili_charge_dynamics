# 28: 近期窗口纳入、移出与重新初始化

**What to build:** 把 #27 的可信发现结果接入当前监控窗口，新目标走既有初始化与固定检查路径，移出只停止监控，管理页可见实际窗口状态。

**Parent:** [10](10-recent-window.md)

**Blocked by:** [24](24-versioned-edit-sync.md)、[27](27-recent-target-discovery.md)

**Status:** ready-for-human

## 依据与交付边界

- [规格](../spec.md)：故事 38–42、44、45、47、48、57；I2–I4；T1–T3。
- [SRS](../../../docs/product/SRS.md)：FR-14–FR-16、FR-18、FR-19、DR-04、DR-05；AC-22–AC-25、AC-29 的近期窗口生命周期部分。
- 遵守[共同交付要求](../implementation-plan.md#所有执行子票的共同交付要求)。明确可信发现结果到当前窗口的发布、配置变更冲突和重启语义；不自行增加另一条初始化实现。
- 不等待具体评论/媒体票；共用同步入口在它们接入后自然获得能力，完整类型组合由 #30 验证。本票自己的启停/保留不能延期到 #29。

## 核验标准

- [x] 可信发现结果发布为每 UP 当前窗口并持久化；只有当前启用/入选目标接受后续固定检查，指定模式只取关联指定 ID，切换后不混两种目标集合。
- [x] 新纳入调用 #02/#24 公开初始化与工作登记能力，无编辑标记仍初始化实际可读内容；模式只选目标、不缩减正文/根回复/媒体能力，无仅评论开关，不全历史动态补扫。
- [x] 重复发现同一窗口不重复初始化/破坏归档；新增、移出、重新纳入正确，重新纳入恢复应有未完成工作，不把旧成功内容删除重建。
- [x] 移出、停用和删除配置只阻止新检查/领取，身份、归档及持久未完成信息保留；详情/基础读取仍可访问。发现失败不发布假空窗口、不停止旧可信目标。
- [x] 发现进行中发生 N/模式/启停变化时，旧发现不能覆盖新配置的窗口或重新激活目标；重开数据库后窗口、配置和待处理一致，检查忙时继续遵守跳过而不积压。
- [x] 管理 API/UI 展示实际 N、模式、已发现/当前目标及发现未完成/错误，不把窗口就绪当归档成功；页面读取不再扫描上游，慢发现/同步不改固定节拍或阻塞配置写入。

## 测试与完成证据

T3 用原始 feed fixtures、受控时钟与可延迟传输覆盖新增/移出/重纳入、模式切换和旧发现迟到；T2 用真实 SQLite/HTTP 验证保留、重开和公开目标状态；T1 验证管理映射。与 #27 核对父 #10 原清单，更多 fixture 记录不是容量保证。

## Comments

### 实现与自动化交付

- 复用 #27/v12 `trusted_result` 的成功提交发布持久窗口，不新增重复表或迁移；当前启用模式互斥选取指定关联或近期窗口。固定检查、pending 领取及显式 initial 共用选择规则，归档仍走 #02/#24 的正文/根回复/媒体链。
- N 改动后新发现成功前保留上次可信窗口，期望 N 与已发布 N 分别展示；停用/指定模式/删配置立即阻止新近期检查/领取，保留身份、归档、pending。重新纳入恢复工作，不清空重建成功内容；旧发现通过原领取令牌隔离，不覆盖新配置窗口。
- 管理页新增只读发现状态读取/重读，展示本轮部分候选、可信结果、当前启用目标及未完成/固定错误；无自动轮询或上游扫描，发现成功不冒充归档完成。
