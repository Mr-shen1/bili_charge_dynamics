# #34：私有失败响应保留与静态审阅

## 授权、实例与请求范围

用户明确同意“保留呗”：对原授权 UID 再做一次资料请求，把失败正文留在服务器私有目录，不写日志、不入 Git、不执行 HTML。原目标值只留私有 context，不写本证据。

为避免影响页面或让默认近期监控被其他进程处理，本轮短时启动 `127.0.0.1:18446` 的 Uvicorn，仍加载真实 `backend.bili_monitor.app:app`、真实 `PacedSourceTransport`，但使用全新私有 SQLite。只向真实资料客户端追加只读 response hook，不替换 transport、请求头或响应；真实执行脚本不导入测试装配或 MockTransport。

**它不是 18444 的原进程，也不是旧请求的 body。** 新客户端的会话状态未复制，不能据此追溯所有旧 412 的原因。原 `18444/18445` 服务和数据库不修改、不重启；本次样本只能说明本次一个新请求。

本次驱动提交唯一一次本地业务 POST；生产代码发起一次原 card GET。另有 2 次本地 `/openapi.json` 就绪 GET，不请求来源。没有换接口、目标、循环重试、初始化、collector、图片或 OSS。监听 FD 由父进程保留并传给子进程，避免业务 POST 误连其他抢占端口的进程。

## 实测结果及可安全引用的正文

本地 API 返回 `502`；保存的来源响应 HTTP 为 `412`。对原件只做本地静态 HTML 解析，跳过 script/style，仅输出预审核固定短语是否确实出现在可见文本中；没有输出任意正文、URL、IP 或页面属性。

完整匹配到以下安全通用错误说明：

> 由于触发哔哩哔哩安全风控策略，该次访问请求被拒绝。

这是**本次真实正文中的说明**，不是根据 HTTP 412 猜测，也不是 fixture 文案。该句由本地静态审阅取得，不是现有 API 日志的 `upstream_message` 输出；当前应用对 HTML 仍记录 `message_state=html upstream_message=null`。

因此，本次可以确认平台页面声明了安全风控拒绝。**具体触发规则仍未知**：不能据此认定是 IP 封禁、Cookie、User-Agent、WBI、请求频率或某项权限，也不能推导出已获授权的绕过方式。正文检测到 4 个 script 元素，均未执行。

驱动的退出码 0 仅表示采样文件保留成功，**不是新增 UP 成功**。本地请求耗时 `0.317876` 秒，不是上游单独耗时或资源验收。
