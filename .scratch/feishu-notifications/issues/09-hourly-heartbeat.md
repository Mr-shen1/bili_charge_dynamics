# 09: 小时心跳闭环

**What to build:** 北京时间每小时第 40 分钟向系统群发送一次心跳，报告当前可观察运行状态；重启不重复生成，错过和过期的心跳不补发。

**Blocked by:** 01 动态变化通知首条闭环。

**Status:** ready-for-agent

## 上下文与范围

依据：[实施规格](../spec.md)、[正式需求与设计](../../../docs/design/feishu-notifications.md)、[领域词汇](../../../GLOSSARY.md)。对应用户故事 54–56；验收关联 FS-AC-13、14。

复用 01 的独立通知进程与持久投递能力，补充系统群角色和心跳时段/有效期。心跳不是故障告警，因此不依赖 08 的告警实现；不得为独立推进而另建一个时钟进程或放进 API 定时器。

## 验收条件

- [ ] 按 Asia/Shanghai 计算每小时第 40 分钟的心跳时段，不随服务器本地时区变化；时段身份及生成结果持久保存。
- [ ] 同一小时重复调度或进程重启不重复生成心跳事件；使用真实持久状态而非仅进程内标记去重。
- [ ] 停机错过的时段不追赶，过期心跳不投递，有效期不跨下一个心跳时段；不会在恢复后积压发送旧心跳。
- [ ] 心跳只发系统群；系统群缺失或暂时故障保留本地诊断并遵守心跳有效期，不转投业务群、不无限补发过期内容。
- [ ] 心跳报告当前能够观察的事实；采集失败、状态未知或进度滞后不能被描述为全部正常，通知进程存活不等于采集成功。
- [ ] 心跳拥有独立时段去重，不共用故障的 30 分钟节流键；不需要等告警实现才具备正确独立性。
- [ ] 动态变化和评论事件不应用心跳的过期丢弃规则；共用队列处理不会误删业务待发任务。
- [ ] 飞书 HTTP 保持事务外，凭据和错误仍脱敏；不承诺整机离线时的可达性或将一秒轮询视为精准送达时刻。
- [ ] 用受控时间覆盖第 40 分钟、跨小时、不同服务器时区、同小时重启、长停顿和网络故障后过期，验证受控系统群收到的实际消息。

## 验证方式

真实持久存储、通知调度与飞书 HTTP 替身，注入时区明确的时间而非真实等待一小时。重开数据库证明小时去重；最终与 08 告警并存时的节流隔离由 10 再集成验证。

## 完成与后续

交付心跳生成到系统群受控投递的闭环及时间边界证据。09 可在 01 完成后独立推进；系统角色和公共投递改动需与 06/08 集成协调，但不新增业务阻塞边。
