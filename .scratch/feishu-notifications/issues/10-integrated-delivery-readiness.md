# 10: 三进程集成与交付准备

**What to build:** 在隔离环境验证 API、采集、通知三个进程与本站阅读的完整链路，提供可复现启停恢复说明和全部验收条件台账，为真实飞书与设备验收准备明确候选版本。

**Blocked by:** 07 停用、重纳入与在途通知；08 系统告警闭环；09 小时心跳闭环。

**Status:** ready-for-agent

## 上下文与范围

依据：[实施规格](../spec.md)、[正式需求与设计](../../../docs/design/feishu-notifications.md)、[领域词汇](../../../GLOSSARY.md)。覆盖用户故事 1–58 的组合回归和 FS-AC-01–FS-AC-14 的自动化/隔离部分，重点 FS-AC-07、08、11、12、13、14。

直接依赖经传递关系覆盖 01–09。本票收口真实业务组合与交付产物，不以“前面票都绿”替代集成，不以部署文档存在替代进程验证。不执行真实外部投递或未经授权的目标环境部署。

## 验收条件

- [ ] 固定候选版本，建立 FS-AC-01–FS-AC-14 台账，每项链接对应证据并标注通过、失败或未验证；真实客户端和真实群部分明确留给 11，不继承旧 AC-01–AC-34 的通过结论。
- [ ] 从受控来源驱动实际采集和 SQLite 归档，独立通知进程产生消息到本地受控 HTTP 接收端，再用消息中的链接打开生产前端与真实 API，完成动态、一级评论、后续页回复三条链。
- [ ] 至少两个 UP 覆盖本人双群/其他人全员、标题回退、普通与长评论、纯图占位、路由缺失后修复、部分分页或媒体失败，确认通知资格与显示结果一致。
- [ ] 对正文、根评论、回复分别验证事务回滚、提交后中断及候选转事件中断；真进程终止与重新启动后去重、基线和目标投递状态保持。
- [ ] 三进程并行时，阻塞飞书请求不持有 SQLite 写事务，其他归档与读取仍可执行；记录写入竞争、资源与测试规模，不声称未经验证的 2 核 2GB 容量。
- [ ] 回归单通知实例、租约恢复与旧领取回写拒绝，证明 API 不启动通知定时器、页面/定位读取不触发来源采集。
- [ ] 告警与心跳共存：30 分钟故障节流不压制小时心跳，系统群失败不递归，过期心跳不连带淘汰业务消息，状态报告不虚报成功。
- [ ] 停用/重新纳入与失败队列、字段待补齐、在途采集交错时结果符合 07；旧归档及已有阅读入口保持可用。
- [ ] 回归宽窄屏精确链接、直开刷新、返回恢复、动态/评论归属隔离、不存在/临时失败与代理访问语义；静态托管能处理新链接，API 错误不冒充页面成功。
- [ ] 完成现有后端回归、前端类型/单测/相关浏览器项目及交付构建检查；保留各测试入口分类，记录命令、环境、版本与未运行原因。
- [ ] 交付第三进程配置、迁移、启停、恢复、单实例保护、失败排查及路由修复说明，给出安全示例而非真实凭据；明确升级/回退兼容限制，不承诺已有数据的破坏性降级。
- [ ] 从旧库迁移的隔离演练保留归档、配置及检查状态，证明重复执行或失败恢复可行；不在现有运行数据库做故障注入。
- [ ] 形成 11 可直接使用的授权事项、有限真实投递/设备验证步骤和预期结果；没有真实验证证据时，结论只到“可申请真实验收”，不能宣布完整交付或上线。

## 验证方式

遵守已确认三个入口：真实归档到受控飞书主链、生产浏览器到只读精确归档、少量真实进程和迁移。跨进程外部替身使用本地服务或现有隔离装配，不把进程内 MockTransport 当作网络服务。测试凭据、消息与身份均虚构；自动化与真实证据严格分开。

## 完成与后续

交付本功能集成证据、FS-AC 全台账、运行说明和明确候选版本。仅未获授权的真实部分可保留未验证并移交 11；自动化阻塞或已发现缺陷不得以“后续实测”名义跳过。父规格与历史验收不关闭、不改写。
