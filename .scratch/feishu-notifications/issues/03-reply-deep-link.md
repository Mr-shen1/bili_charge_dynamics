# 03: 楼中楼回复精确链接

**What to build:** 从本站链接直接看到某条具体楼中楼回复，包括后续页回复，自动加载、展开、定位并高亮，适配宽屏和手机独立楼中楼阅读。

**Blocked by:** 02 一级评论精确链接。

**Status:** resolved

## 上下文与范围

依据：[实施规格](../spec.md)、[正式需求与设计](../../../docs/design/feishu-notifications.md)、[领域词汇](../../../GLOSSARY.md)。对应用户故事 46–50、57；验收关联 FS-AC-11。

依赖 02 的身份定位读取与主动入口语义，将契约扩展为动态、所属根评论及目标回复。复用原宽屏回复页码和窄屏楼中楼页，不能把“到某个根评论”当成“到某条回复”。本票不依赖通知进程。

## 验收条件

- [x] 明确并实现稳定回复链接及只读定位响应，返回足以显示目标及所属根上下文的数据；校验动态、根和回复归属，不串楼。
- [x] 一根超过 10 条回复、目标不在首屏或首个预览的情况下，宽屏自动展开并显示目标所在页，定位高亮准确。
- [x] 窄屏独立楼中楼入口直接显示指定回复所在页并高亮，不强制把所有精确入口重置为第一页。
- [x] 首次打开、直开、刷新均不依赖旧内存或用户先读过根评论；回复正文在定位时可阅读，不被折叠隐藏。
- [x] 定位不一次渲染全部回复，原页内替换、后续翻页、收起及普通无精确目标的首屏行为保持。
- [x] 正常返回与历史恢复符合原有访问规则；主动定位完成后不持续拉回目标，迟到响应不污染新的动态或楼层。
- [x] 目标删除/缺失、归属错误与暂时读取失败有区分；明确提示并提供返回对应动态入口或局部重试，不静默显示楼层顶部冒充成功。
- [x] 归档定位不请求 B 站；链接不包含凭据，保持代理保护，不增加回复图片采集或额外上游查询。
- [x] 生产前端＋HTTP 替身覆盖宽窄屏及后续页，真实 API＋隔离数据库证明任意归档回复可定位；回归 02 的一级评论入口。
- [x] 记录供 05 使用的回复定位契约及结果，真实客户端未验证项单列。

## 验证方式

沿用现有回复 10/10/5 页内替换、窄屏楼中楼与历史恢复的生产装配场景，补目标处于后续页、实时数量变化、快速跨楼切换等受控测试。测试外部传输而不模拟浏览器定位函数；真实 API 测试只使用隔离数据库。

## 完成与后续

交付回复精确链接的完整读取到浏览器行为。05 将该链接接入消息，11 独立验证飞书客户端和手机实机；本票不发送真实飞书消息。

## Answer

已交付楼中楼回复精确链接的完整纵向切片：只读回复定位读取 + 生产前端入口
`/dynamics/{dynamicId}/comments/{rootId}/replies/{replyId}/locate`。同一条链接在宽屏走动态详情内的原回复区
（先按 02 契约取含所属根评论的批次，再取目标所在页），在窄屏走原独立楼中楼页直接显示目标所在页；
两者都不先读首批/第 1 页，展开折叠正文、定位到该条并高亮，分页停在目标页。目标不存在给固定提示与返回动态入口，
临时失败可局部重试（重试重发定位，成功后仍把目标带回视口）；用户已滚动后迟到结果不再抢占，
收起回到 3 条预览并把所属根评论定位到开头。定位读取不访问上游、不写归档、不冻结分页快照；链接只含字符串身份，无凭据。

## Comments

- 宽屏精确入口保留“两次只读定位”而不是造一个同时返回一级评论批次与回复页的新接口：一级评论批次仍走 02 的
  `/location`（含排序语义与 `up_reply` 上下文），回复页走 03 的新端点。这样既复用了既有 DTO，也让窄屏只需一次请求。
  若后续要压成一次往返，需要合并两套排序/分页契约，属于接口重构，不在本票范围。
- 定位端点返回“目标所在页 + 页码”，翻页继续走既有 `page` 模式，不新增游标模式：回复页码是正常 UI 的读取方式，
  引入第二套游标会让“页码/游标”两种状态并存，收益不抵复杂度。
- 回复定位时所属根评论只作上下文：`CommentSection` 的入口定位在“有回复目标”时不再抢滚动，`CommentList` 也不给根评论
  加高亮，避免同一屏出现两个“目标”标记；根评论仍按 02 的定位读取被加载，因此根在后续批时也能显示。
- `FoldableText` 的折叠按真实行高判定，jsdom 无排版，因此“目标正文默认展开”由浏览器用例断言（“收起回复正文”可见）。
- 重试语义与普通读取分开：定位失败的重试重发定位（不猜页码），成功后仍把目标带回视口——用户显式点击重试，
  不属于“持续抢占滚动”。
- 端口与并发：本票沿用正式 Playwright 端口（4318/4319/4320、4178/4325），运行前确认空闲，未修改正式端口，
  也未为本地并发新增专用端口；与 04/09 同时需要浏览器端口时应由主线程协调。
- 未覆盖（不属本票或未授权）：真实飞书内置浏览器/手机实机/目标环境运行（11，需授权）；消息模板、群路由与真实投递（04）；
  回复删除提示与视觉基准补充。
