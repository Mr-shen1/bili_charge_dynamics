## 2. 就绪任务与执行方式

- 当前可开始：**02**（01 已完成）。
- 只按直接阻塞边判断：01 已完成，09 待 01 的接口稳定后可开始；02 完成可解锁 03；01＋02 完成可解锁 04；04 完成可解锁 06；03＋04 完成可解锁 05；05＋06 完成可解锁 07；06 完成可解锁 08；07＋08＋09 完成可解锁 10；10 完成后，11 仍需授权。
- 编号是便于阅读的依赖顺序，不强制串行执行。可并行的票仍需协调共享模块和迁移冲突，不能仅为避免同文件编辑添加虚假业务阻塞边。
- 每张实现票可以在新会话中单独执行，以票据、父规格、正式设计和当前源码为依据，不依赖本轮聊天记忆。完成阻塞票的含义是其验收条件和必要证据成立，不只是文件存在或有提交。
- 不单开横向“建表”“写后端”“写前端”或预重构票。必要的小调整随对应行为完成；若发现确需大范围预重构或改变已批准依赖，先明确影响再调整计划，不静默增加工作。

## 3. 安全约束与阶段范围

01、04、05 从第一条事件开始就须满足同事务保存、稳定身份去重、有效通知阶段和凭据隔离。06、07 是复杂配置、故障与跨事件组合的完善，不是允许早期票先丢消息、乱发历史或忽略停用的豁免。

前三个可复用契约分别是动态通知事实/投递接口、一级评论精确读取入口、回复精确读取入口。后续票复用已验证接口而不是平行实现第二套。每票交付具体功能所需的数据、接口、界面或进程及测试；不强制不涉及 UI 的通知票凭空增加页面。

01–10 使用虚构身份、消息、配置、隔离 SQLite 与外部传输替身或本地受控服务。不能读取真实路由配置、对真实群试发、触发未经授权的 B 站采集或在现有运行数据库注入故障。隔离进程演练与目标环境部署必须区分。

11 的 `ready-for-agent` 表示验证步骤明确，并不表示外部操作已经授权。实际执行前须确认测试群、有限消息边界、凭据注入、访问地址/设备/环境及进程操作范围；缺少授权或设备时保留未验证，不自动勾选通过。真实验收不隐含生产部署授权。
