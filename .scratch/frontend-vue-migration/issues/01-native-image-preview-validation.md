# 01: 验证原生图片预览与浏览器历史的组合行为

**What to build:** 在最小 Vue 应用中完成打开图片、切换、关闭及浏览器后退/前进的完整路径，尽早证明 Element Plus 原生预览能满足图片、历史、焦点、滚动和资源请求底线；不是先搭一个无法验收的空架子。

**Blocked by:** 无（可立即开始）。

**Status:** ready-for-agent

**差异处理硬规则：既有文档、测试或历史验收描述与现有代码逻辑冲突时，一律以现有代码逻辑为准。** 按已记录源码基线核实后修正文档和测试，不为迎合旧描述恢复、删除或改变现有业务行为；后续发现同类差异也按此处理，无需重复请求裁决。明确授权的 Vue、Element Plus、新视觉及图片放宽属于目标变化，不被旧实现反向覆盖。代码基线不等于已经运行验收通过。

- [ ] 核实并固定 Vue、Vue Router、Element Plus、TypeScript、Vite 与测试工具的兼容版本，记录构建及验证环境；Node 使用 nvm，依赖与脚本仅使用 pnpm。
- [ ] 缩略图使用 Element Plus Image，预览使用应用协调的独立 ImageViewer；无双预览，不依赖私有 DOM、内部方法或深层样式覆盖，不重写缩放、旋转或手势引擎。
- [ ] 打开仅新增一条同 URL 预览历史，切图不新增；按钮/键盘关闭与后退不二次回退，有效会话前进恢复对应图片，刷新及失效标记安全清理。
- [ ] 唯一导航协调器负责历史与关闭来源；历史仅保存应用命名空间内可序列化轻量元数据，尊重 Vue Router 自有 state，不放入响应式代理、内容或阅读快照。
- [ ] 单图、多图、长图及成功/坏图/未上传/无效地址混合组保持 owner、顺序及所点索引；完整组可达，异常不阻断切换和关闭，浏览器加载失败可适当局部重试。
- [ ] 冷缓存并区分缩略/预览 URL 检查实际网络，打开单张不要求先下载整组原图；另验证生产共用 URL，不以缓存命中证明未请求，不新增“每次恰好一个请求”的限制。
- [ ] 预览期间焦点与操作留在预览内，底层不滚动；关闭恢复原位置及触发焦点或合理后备位置。覆盖触发器消失、重复开关及库/应用双重锁定风险。
- [ ] 四种约定宽度下工具栏可达、无页面横溢，主要触控区域约 44px；Linux Chrome 与实际 iPhone Safari 分别验证完整长图可读、切换和关闭，并记录版本及过程。
- [ ] 不暴露图片下载、自动轮播、双指/自由缩放等未确认功能；只使用后端公开业务图片地址，不回退来源业务图，不触发上游采集或上传。
- [ ] 记录公开配置、必要连接层、结果及可复核证据。底线失败或实际设备证据缺失时不得完成本票或绕过下游门槛；暂停受影响替换并反馈，不自行换库、恢复整套自研预览或放宽需求。
