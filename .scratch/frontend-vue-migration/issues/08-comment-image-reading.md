**Blocked by:** 04 — 在动态列表和详情查看完整图片组；05 — 阅读一级评论、切换排序并恢复讨论进度。

## Comments

已完成并留证：[08 评论图片阅读证据](../evidence/08-comment-image-reading.md)。
`pnpm check`（typecheck + `pnpm test` 143 + e2e 项目覆盖守卫）、`pnpm test:e2e`（147 passed / 10 skipped）、
`pnpm test:e2e:production`（3 passed / 3 skipped）与 `pnpm check:dist` 均通过。

实现要点：`CommentItem` 用 `DynamicImages` 接入 `comment.images`，owner 为 `{type:'comment', id}`，组 ID 沿用
`preview/groups.ts` 的 `comment-<id>`；缩略最多 9 张、末张带 `共 N 张` 与 `+N`，注册给预览的始终是完整组。
异常状态、重试与关闭恢复沿用 04 的连接层语义（异常不阻断切换/关闭，只重试既有公开 URL），预览历史与阅读状态保护
由唯一导航协调器负责：同 URL 打开只压一条记录、切图只 replace、关闭/后退不多退一级、前进恢复所看图片。

实施中发现并修正真实缺陷：`registerGroups` 在 `watchEffect` 内读同一 ref 再写它，形成自依赖；
评论区出现多条带图评论（同页三个组）时报 `Maximum recursive updates exceeded`。改为普通 `Map` 记录已注册组、
内容变化才写一次 `shallowRef`，合并注册语义不变。

mock 归档新增评论图片夹具（混合状态 6、单张长图、纯图 4、超量 12）；e2e 新增 `comment-images.spec.ts`（desktop + Pixel 7），
并在 `comments.spec.ts` 以生产装配 + HTTP 替身验证根评论 `media` 经真实 DTO 映射、预览不重读评论、不请求来源业务图。

真实 API/SQLite、iPhone Safari 与新版视觉签收不在本票：分别留待 13、15 与 14。回复图片与独立楼中楼根评论图片按范围不新增。
