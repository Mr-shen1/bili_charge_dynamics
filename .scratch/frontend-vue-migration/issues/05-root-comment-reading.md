# 05: 阅读一级评论、切换排序并恢复讨论进度

**What to build:** 用户从评论入口到达详情评论区，按最热/最新读取一级评论并继续加载；离开后返回可继续原讨论进度。

**Blocked by:** 03 — 进入动态详情并恢复列表与详情阅读位置。

**Status:** ready-for-agent

**差异处理硬规则：既有文档、测试或历史验收描述与现有代码逻辑冲突时，一律以现有代码逻辑为准。** 按已记录源码基线核实后修正文档和测试，不为迎合旧描述恢复、删除或改变现有业务行为；后续发现同类差异也按此处理，无需重复请求裁决。明确授权的 Vue、Element Plus、新视觉及图片放宽属于目标变化，不被旧实现反向覆盖。代码基线不等于已经运行验收通过。

- [ ] 无有效会话的新访问默认最热；评论入口进入同页评论区，主动入口优先于旧位置。
- [ ] 最热/最新对完整归档集合排序后分页，来源明确置顶优先且不重复；45 条一级评论按 20/20/5 cursor 追加，保留冻结语义、同批重试和结束后的不再请求行为。
- [ ] 切换排序定位评论区，重置目标排序首批、文字及回复展开状态；快速连续切换只接受最后一次选择的成功、失败与完成回调。
- [ ] 详情访问快照保留排序、cursor 进度、文字展开及稳定锚点；同动态多访问不混用状态，离开加载再返回可继续。
- [ ] 区分成功空、未归档、未完成同步、读取失败和正文受限；网络成功或本地零条不被解释为来源没有评论。
- [ ] 一级评论按实际超过 6 行折叠；安全文本、作者身份、只读点赞、来源置顶、计数及时间兜底正确。
- [ ] 不恢复编辑时间、整块归档/同步状态面板、状态读取按钮或旧评论结束结语。
- [ ] 随本票交付页面行为、排序/契约和真实浏览器锚点恢复测试，覆盖重复加载、忽略取消、迟到回调及内容布局变化。

## 依据与执行边界

依据本工作规格、行为基线差异及已确认迁移方案。一级评论为 cursor 追加，不迁成页码。回复由 06/07 交付、评论图片由 08 交付；这些后续票须验证本票排序重置与详情恢复的组合行为。保留后端协议，不执行部署。
