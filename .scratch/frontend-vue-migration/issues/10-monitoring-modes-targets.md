# 10: 维护互斥监控模式及指定目标

**What to build:** 用户可为各 UP 配置近期 N 或指定动态模式，添加/移除目标及删除配置，同时保持已有归档不受影响。

**Blocked by:** 09 — 按 UID 新增 UP、查看管理卡片并启停监控。

**Status:** ready-for-agent

**差异处理硬规则：既有文档、测试或历史验收描述与现有代码逻辑冲突时，一律以现有代码逻辑为准。** 按已记录源码基线核实后修正文档和测试，不为迎合旧描述恢复、删除或改变现有业务行为；后续发现同类差异也按此处理，无需重复请求裁决。明确授权的 Vue、Element Plus、新视觉及图片放宽属于目标变化，不被旧实现反向覆盖。代码基线不等于已经运行验收通过。

- [ ] 两种模式互斥，默认 N=10，校验及默认语义保持基线；各 UP 配置和草稿独立，不因换库改变后端协议。
- [ ] 指定动态 ID 使用字符串校验；添加目标通过现有接口校验作者归属，明确区分正确、不符与未知，移除目标反馈正确。
- [ ] 切换 UP 或模式时隔离草稿、请求身份与反馈；失败保留输入，重复写入被阻止，忽略取消的旧成功/失败/完成回调不改写新页面。
- [ ] 停用、移除目标及删除配置均不删除已归档内容；通过实际 API 与隔离 SQLite 验证归档仍可读取，不要求另一阅读票先实现页面。
- [ ] 使用 Element Plus 通用控件，键盘、焦点、四视口布局和主要触控区域可用；错误提示不泄露秘密或原始内部错误。
- [ ] 随本票交付页面操作、Adapter 映射和隔离集成测试，不以 mock 成功替代持久化/归档保留证据；不发起真实上游或 OSS 请求。

依据本工作规格、行为基线差异及已确认迁移方案。不新增采集模式、频率策略、手动初始化或业务 API，不把管理删除改为内容删除，不执行部署或操作当前运行实例。
