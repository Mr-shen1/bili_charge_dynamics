### 精确代码语义补充

补核仍为静态核对，没有运行测试。以下均随用户“代码为准”的裁决保留：

- **实时页与数量：** page 模式每页返回 root、本地 count/local_reply_count 与独立来源/同步信息，next_cursor 恒 null；请求 no-store。按本地 count 算页数，越界页空结果后再读有效末页。证据：`backend/bili_monitor/storage.py:888-929`、`src/data/archiveReader.ts:253-283`、`src/dynamics/useReplyPage.ts:38-45`。
- **重新读取：** 宽屏每次展开重读 page 1，翻页/同页重读不走页缓存；收起取消请求、记录收起页码 1，并滚回根。历史详情恢复成功预览，已展开回复则重读保存页码，不复用整页冻结结果。证据：`src/dynamics/ReplySection.tsx:29-70,116-127`、`useReplyPage.ts:13,61-63`。
- **窄屏入口：** 来源回复数正值才渲染，零/未知均无预览块；本地零但来源正仍有入口。有合法作者摘要时显示该作者最早回复，否则只显示数量。证据：`src/dynamics/ReplyPreview.tsx:9-24`、`CommentSection.tsx:133-138`。
- **独立页：** 每次重新挂载 page 1/顶部，root 来自页响应；额外读详情只为 UP 标识，失败不阻断主读取。页头优先来源数量再本地 count/items，分页用本地数。该页不渲染图片，无图片预览。证据：`src/dynamics/CommentThreadPage.tsx:13-39,65-102`。
- **折叠例外：** 独立页根/回复正文和窄屏 UP 回复预览均直接显示文本，不使用 FoldableText；不能从旧全局 6 行规则推导新增折叠。证据：`CommentThreadPage.tsx:65,86-96`、`ReplyPreview.tsx:18`。
- **错误语义：** readReplies 的 404/422 INVALID_INPUT 均为普通 error；仅 422 CURSOR_INVALID 映射 invalid-cursor，取消优先。独立页空 root 的备用文案在生产映射下不可达，不写成 not-found 需求。证据：`src/data/archiveReader.ts:268-275`、`src/dynamics/CommentThreadPage.tsx:59`。
- **兼容接口：** cursor 首 3/续 10 仍保留，正常回复展开不再触发累计追加。不能因 UI 改成 page 就删后端兼容协议；迁移仅对接现存能力。

## 2. 有历史依据的裁剪与文档滞后

### 编辑时间及归档面板

当前读取 Adapter 保留编辑时间，但阅读页不渲染；SRS 的 FR-04、FR-17 与 AC-04 仍有“展示编辑时间”的旧措辞。UI 规范保留的用户裁剪决定已明确取消阅读页整块归档信息，其中包括编辑时间；组件测试亦断言不显示这些信息。

证据：`src/data/archiveReader.ts:91`、`src/dynamics/DynamicContent.tsx:26-45`、`tests/archive-app.test.tsx:15,140`、UI 规范“不因参考图而改变的行为”中的 2026-10-14 裁剪记录。

处理方向：按已有明确决定同步需求，保留数据语义及接口字段，不因迁移恢复阅读页编辑信息/归档面板，也不凭本次审计新增管理页字段。发布与编辑时间仍不能混淆；字段被保留不表示每个页面都必须展示。

### 分页结束表达

列表仍显示“动态已加载完毕”；一级评论/回复已去掉旧结束文案。后续客户端增量契约已记录相关裁剪，而旧 SRS 局部状态的措辞容易被理解成各区域必须显示同一句结束提示。

证据：`src/dynamics/ListPage.tsx:59-60`、`CommentSection.tsx:143-147`、归档客户端契约的 18/26 增量。处理方向：区分逻辑上结束且不再请求与必须渲染结语，不恢复已明确删除的提示；回复结束表达还须随最终页码模型统一。

### 回复 API 的页码模式

前后端当前均实现页码读取，正式 HTTP 文档仍主要按 cursor 首 3/续 10 描述。首轮核对确认页码模式要求固定页大小并与 cursor 互斥，返回页总量及根评论等所需信息；精确输入校验、实时读取与错误边界在后续契约同步时按实际源码补齐，不凭本摘要猜测参数范围。

证据：`backend/bili_monitor/app.py:235-245`、`storage.py:894-925`、`src/data/archiveReader.ts:254-283`；正式归档接口文档已有 `up_reply/root` 的部分说明。处理方向：补齐已存在接口而非声称本次迁移新增后端协议。

## 4. 不上升为产品决策的项目

- 生产/mock/fault 隔离，以及已核对的 scope/cursor 错误映射、字符串 ID、管理错误白名单，前后端基本一致。
- `not-archived` 相关旧能力分支及无引用的归档统计组件，先作为待核实清理项；不能仅凭历史契约存在就要求新增用户界面。
- 管理 401 的固定提示与反向代理 Basic Auth 配置，不等于应用已内建账号权限系统。需准确记录部署与客户端错误边界，不擅自新增鉴权产品功能。
- 后端发布了某些 metadata 而页面不消费，不自动构成缺陷。除既有明确显示需求外，不补造诊断面板或要求前端映射全部字段。
- 当前网格数量、自研图片倍率/长图方式与新的原生组件方案不同，已经被用户授权调整，不再次要求恢复旧细节。
