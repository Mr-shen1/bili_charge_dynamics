## 4. 环境 A：局域网 mock 自检装配（阅读与图片）

```bash
cd frontend && pnpm check:dist                     # 先产出 dist 与 dist-mock（已跑过可跳过）
.scratch/frontend-vue-migration/evidence/device-15/serve-env-a.sh
```

脚本行为：先跑候选校验，再起图片夹具（4319）与 `dist-mock` 的局域网静态产物服务（4318），打印所有可用局域网地址；`Ctrl+C` 一并结束两个进程。本轮冒烟已实测：脚本起服后 `/`、`/__preview-fixtures`、`/images/thumb/long-1.svg` 均返回 200，局域网地址为 `192.168.8.20`，日志 `logs/env-a-smoke.log`。

夹具事实（用于把清单里的“第几条”落到具体内容，源自 `frontend/src/mock/`，与代码一致）：

- 归档 25 条动态，列表每批 10 条，「加载更多」→ 20 → 25 后按钮消失；归档范围导航是「全部归档」再加两个 UP：「纸飞机」（17 条）与「另一位 UP」（8 条）。
- 排序后第 1 条含 8 行正文（长 URL、注入脚本文本、emoji）与 `来源评论 45`；第 2/3/4 条分别是 1/9/12 图；第 5 条是「成功与异常混合」组且评论数为 0；第 6 条是 1200×6000 长图；第 7 条是 2 图；`publishedAt` 缺失的那条固定在最后。
- 一级评论 45 条（20/批 → 40 → 45），支持「最热/最新」；首个根评论 25 条回复，楼中楼共 3 页（10/10/5）。
- `/__preview-fixtures` 提供单图、四图、十二图、长图、成功与异常混合（坏图/未上传/无效地址/首次 503 后可重试）、缩略与预览共用地址、未上传组、两个评论组。

清单自检（`device-15/checklist-selftest.mjs`）本轮跑出 10 条全通，日志 `logs/checklist-selftest.log`；它只覆盖 A1–A6、A8、A9、A12、A13：逐条验证「加载更多」→ 20/25 条、范围切到 `/ups/123`、`来源评论 45`、`加载更多评论`→45、宽屏 `展开回复`→`回复分页`（共 3 页 + `收起`）、第 6 条长图预览 `naturalHeight` 6000、十二图计数 `2 / 12`、混合组 `重试`、窄屏 `共25条回复`→`相关回复共25条`/`共3页`→`返回评论`、窄屏无横向溢出。**A7（阅读恢复与迟到纠正）、A10（后退/前进/刷新）、A11（焦点与底层滚动）、A14（键盘）以及整个第 7 节不在自检范围内**，那些只能靠人工，不能拿“自检通过”当背书。

自检的字面价值是“清单里的按钮名与页数没写错”：本轮它先暴露了三处措辞与代码不符（窄屏入口在 mock 夹具上只有「共25条回复」，没有生产夹具的「UP主等人」前缀；`展开回复` 是可见文字按钮、没有 aria-label；批量断言要对齐视图实际渲染的条数），都按代码改清单而不是反过来改产品。**候选变化后要重跑这一步**，否则人工拿着过期步骤测到的是另一份界面。

## 12. 真机缺陷与补验（F-15-01、F-15-02）

第 1 轮（`946ed66`）在 iPhone Safari 上暴露两个缺陷，都已定位到根因、修复并加了自动化回归；**修复后必须在真机上补验**，修复本身不能当作已通过。

### F-15-01 指定目标「校验并添加目标」永久停在「正在校验…」

- **现象**（人工口头报告）：iPhone Safari 上给 202 与 555 添加指定目标，点击「校验并添加目标」后一直停在在途状态，不再返回；两台设备的同一操作在 Linux Chrome 上正常。
- **根因**：两层叠加，都在代码里可确认。
  1. `ManageTargets.vue` 在发请求前用 `AbortSignal.any([...])` 组合取消信号。该 API 要 Safari 17.4 才有，而目标设备基线是 iOS 16.4（票据 01 的真机记录），Vite 又不 polyfill Web API，于是这里有同步 `TypeError`。
  2. `useManagementRequests.run` 把 `await operation(...)` 之后的 `controllers.delete(uid)` 写在了 try 之外：operation 同步抛错时既不删锁也不 `sync()`，该 UID 的写锁永久占住。于是按钮停在「正在校验…」，连换一个动态 ID（555）也会在入口 `if (busy) return` 处被直接挡掉——与「202、555 都卡住」的现象一致。`useStatusRead` 走同一类组合信号，是同一根因的隐患。
- **修复**（候选 `32c9510`）：
  - `useManagementRequests.run` 改为 `try/catch/finally`：异常转成「管理接口响应异常，请重试。」的可见失败，`finally` 里按请求身份释放写锁。
  - 新增 `src/app/signals.ts` 的 `combineSignals`，替换三处 `AbortSignal.any`（目标添加/移除、状态读取）。
  - `ManageTargets` 的 `addPending`/`removingId` 在早退路径（请求被取消或不属于当前写入）也复位，避免在途标记残留。
- **回归**（自动化，已在第 2 轮全绿）：`tests/unit/manage-up-page.test.ts` 新增两条「同步抛错后释放写锁并可重试」；`tests/unit/signals.test.ts` 覆盖组合信号；`tests/unit/browser-baseline.test.ts` 静态守卫 iOS 16.4 缺失的 Web API（`AbortSignal.any`、`Promise.withResolvers`、`Object.groupBy`、`Map.groupBy`）。
- **待人工补验**：iPhone Safari 上重跑 B6（202 成功、555 被拒绝、405 移除目标）与 B7（读取检查/发现状态）；Linux Chrome 复跑 B6 确认未被改坏。
- **根因判定**：写锁泄漏这一层由代码与单元测试确定；触发它的同步抛错来自 `AbortSignal.any` 缺失——设备已确认为 **iPhone 13 Pro / iOS 16.4 / Safari 16.4**，而 `AbortSignal.any` 要 Safari 17.4，与代码路径吻合。同一版本的 Web 能力已顺手复查：`crypto.randomUUID` 有特性检测（Safari 15.4 起可用），未发现其它超出 iOS 16.4 的 API 或 CSS 特性；这类缺口的静态守卫由 `tests/unit/browser-baseline.test.ts` 承担。

### F-15-02 输入框聚焦后整页放大且不还原

- **现象**（人工口头报告）：环境 B 里在 iPhone Safari 输入框填完内容后，页面停留在放大状态，没有恢复。
- **根因**：iOS Safari 对 `font-size` 小于 16px 的输入控件在聚焦时自动放大整页，失焦后也不还原。项目此前没有给输入框单独设字号，Element Plus 默认算出 13px（`manage.spec.ts` 的断言实测值）。
- **修复**（候选 `32c9510`）：`theme.css` 给 `.el-input__inner`/`.el-textarea__inner` 统一 16px；不使用 `maximum-scale=1`（那会连带禁掉用户的双指缩放，与 A15 冲突）。该选择解释了为什么它属于「库内部类例外」，已在该文件注释里登记。
- **回归**：`tests/e2e/manage.spec.ts` 的四视口用例新增「文本输入框字号 ≥16px」（先红后绿：改前实测 13px）；`pnpm visual:compare` 仍通过（字号变化低于 0.02% 阈值，所以不更新票据 14 的黄金图）。
- **补验结果**（人工口头确认，无录屏）：2026-10-25 在 iPhone 13 Pro / iOS 16.4（候选 `32c9510`）上聚焦「近期 N 条」与「动态 ID」输入框后**不再整页放大**，失焦后比例不变；F-15-02 闭环。

补验统一在第 2 轮候选 `32c9510` 上做：`serve-env-b.sh` 启动前的 `--verify` 会拒绝与登记不一致的产物。补验只需覆盖受影响项（B6、B7、B3/B5 的输入框行为），A 节（阅读与图片）不受这两处改动影响，可沿用第 1 轮结论；但若补验时顺手复看 A9/A13，把结果记录在此即可。
