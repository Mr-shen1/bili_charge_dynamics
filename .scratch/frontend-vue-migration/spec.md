## 问题陈述

当前前端使用 React，阅读、管理和图片区域包含较多自行维护的组件与交互实现。用户希望改用 Vue 3，并通过完整 UI 组件库减少通用界面代码、统一交互和视觉、降低后续开发成本，而不是只把 React 语法逐文件翻译成 Vue。

现有归档读取、管理 API、回复实时页码、窄屏楼中楼和会话恢复已具备业务语义，迁移不能令这些能力退化；旧文档和部分 E2E 仍描述更早的累计追加模型，不能直接作为保留清单。旧版的图片布局与预览细节、B站像素复刻要求会限制库组件替代，因此用户明确允许调整这部分展示与交互；图片完整性、手机可用性、导航和阅读恢复仍是底线。

项目尚未正式全面使用，可在完整重构并验证后统一上线，无需以生产双框架或页面级灰度维持过渡。现有自动化、视觉及设备记录只证明各自旧版本，不能继承为 Vue 新版通过。

## 解决方案

采用 Vue 3、TypeScript、Vite、Vue Router 和唯一 UI 库 Element Plus，重写框架相关实现，复用经核实可用的纯 TypeScript 契约、数据适配与确定性逻辑。通用表单、按钮、提示、状态和图片展示/预览优先使用库组件，内容阅读仍由业务组件表达。

默认使用 composables 与必要的 provide/inject 组织状态及协调行为；库主题变量配合少量局部 CSS，不默认引入 Pinia、请求缓存框架或 Tailwind。保留整体布局方向、品牌配色和阅读层级，建立用户确认的新版视觉基准，不锁定旧版像素值。

业务规则、六条页面路由、后端 API、数据库及采集归档行为按固定代码基线保留；图片展示/预览仅在已确认例外内调整。回复保持宽屏预览最多 3 条后实时页码每页 10 条、窄屏 UP 回复预览入口到独立页的模型；不恢复旧累计追加或给独立页新增历史阅读快照。先验证原生预览与浏览器历史、资源请求、手机长图及焦点/滚动的组合行为，再铺开依赖这些能力的重写。最终完成全量回归、视觉确认、正式设备及静态交付验证，清理废弃 React 栈后统一发布。

## 实施决策

### 已确认架构与复用边界

1. 目标栈为 Vue 3 + TypeScript + Vite + Vue Router + Element Plus。默认采用 Vue 单文件组件和 Composition API；具体兼容版本在实施时核实并锁定，不把文档选型当作已安装或已运行。
2. 重写框架耦合的应用入口、路由协调、会话分发、读取与管理协调、页面及组件。纯 TypeScript 的契约、Adapter、状态转换、文本与格式处理按实际依赖和测试核实复用，不按目录或原文件名机械迁移。
3. Element Plus 是唯一 UI 库。优先直接使用表单、输入、选择、按钮、提示、状态及图片组件；只在确有业务行为时封装，不构建逐个转发的平行基础库。
4. composables 负责状态与副作用协调，必要时 provide/inject。会话实例在应用根部创建并高于路由页面存活，测试能创建独立实例；不默认依赖跨测试共享的模块级可变状态，不默认引入 Pinia 或请求缓存框架。
5. 内容实体、每次页面访问的阅读快照和请求运行态分开。全部/单 UP 的 scope、cursor、访问身份及迟到结果隔离；不以动态 ID 单份快照覆盖同一动态的多次访问。
6. 每个读取区域保留请求防重、取消与归属/代次校验。即使传输忽略取消，旧成功、旧失败和旧完成回调均不能污染新访问或清掉新加载态。管理写入同时保留生命周期隔离、防重锁和失败草稿。
7. 只读与管理接口继续由应用装配；展示层不理解原始 HTTP DTO、不拼接 OSS 地址、不解析或推导 cursor。默认使用真实 API，独立 mock 和开发故障装配不混入正常产物。
8. 后端 HTTP/DTO、排序分页协议、数据库结构、单 API/单 collector 架构及采集逻辑按代码基线保持，不用旧文档的排除项删改已有策略。不为 UI 库适配更改 API，不为测试新增业务公共接口；保留部署代理保护和管理 401 映射，不将它们误称为应用内账号系统。

### 阅读、路由与业务行为

9. 六条页面地址为 `/`、`/ups/:upId`、`/dynamics/:dynamicId`、`/dynamics/:dynamicId/comments/:rootId`、`/manage`、`/manage/ups/:upId`。动态详情保留一级评论区，独立楼中楼承载指定根的回复；不能因旧文档禁止独立评论页而删除当前路由。
10. 动态每批 10、一级评论每批 20 继续 cursor 追加和冻结语义，不改成页码。宽屏回复预览最多 3 条用 cursor 首读，展开及独立页使用互斥的 `page` 模式，每页最多 10 条实时读取、页内替换。保留时间正序、来源置顶规则及作者 ID 判断；旧 cursor 续批协议仍存在，但不是正常 UI 的累计展开方式。
11. 动态列表、详情内一级评论及宽屏内联回复按实际超过 6 行折叠，详情动态全文显示；独立楼中楼根/回复正文与窄屏 UP 回复预览直接显示文本，不新增折叠。所有文字安全渲染；时间与状态语义按当前代码保留，阅读页不展示编辑时间。独立楼中楼页头采用来源数→本地 count→items 数的现有回退，分页使用本地 count/localReplyCount，而非来源数。
12. 保留阅读信息裁剪，不恢复编辑时间、整块归档统计、同步状态面板或状态读取按钮。普通回复直接回根不显示目标，嵌套回复有目标昵称才显示“回复 X:”；窄屏作者摘要按可用 replyTo 显示，渲染期去除来源重复前缀，不改数据。列表保留结束提示，一级评论/回复不恢复旧结束结语；必要局部错误、空态及逐图状态仍保留。
13. 唯一导航协调器负责主动入口、历史返回、预览记录和位置恢复。使用应用自有的轻量可序列化历史元数据，尊重 Vue Router 自有 state；不写入响应式代理、完整内容或阅读快照，不照搬 React Router 的内部 key 或动作 API。
14. 列表/动态详情按主动入口或历史快照恢复，动态详情无有效列表来源时回首页。独立楼中楼无自身快照，直达、刷新或历史重新挂载均回 page 1/顶部；有有效详情来源时返回并恢复详情，无来源则 replace 到对应动态详情，分页器收起同返回。不新增持久化历史、跨标签页同步或楼中楼历史页码记忆。
15. 列表/动态详情恢复先还原数据与展开，再按稳定锚点定位，缺失有限回退且用户操作优先。宽屏回复详情快照保存预览、expanded、page、文字状态；历史恢复已展开的回复时实时重读保存页码，不缓存页结果来跳过请求。楼中楼自身按上一条首屏例外处理；各滚动责任方不竞争恢复，不无限等图。
16. 同 URL 预览历史、前进恢复、刷新失效标记及关闭来源判断必须针对实际固定版本验证；打开只新增一条预览记录，切图不增加记录，后退已经关闭时不再二次回退。

### 图片替代与明确例外

17. 当前已有图片区域的缩略图使用 Element Plus Image，预览采用应用协调的独立 ImageViewer，布局用库栅格或少量 CSS Grid；不为独立楼中楼新增根评论图片。避免双预览实例，不重写缩放、旋转和手势引擎。
18. 图片列数、缩略比例、显示数量、缩放倍率/步长、旋转/还原/工具栏形式、循环、滑动、遮罩关闭和变换复位细节采用库公开能力及新版设计，不强制旧九格、固定倍率、首尾不循环、单图按钮隐藏或专门长图适宽。
19. 保留不变形、完整图片组可达、顺序/所点索引正确、动态图与各根评论 owner 隔离、手机可查看/切换/关闭、长图可读、键盘与焦点可用。库默认不满足底线时不能据“直接用库”判定通过。
20. 区分上传 pending/failed、无效公开 URL 和浏览器加载失败；异常位置不串组或错位，仍可跳过、关闭及按实际能力局部重试。只重试既有公开图片地址，不在浏览器调用采集/上传重试或回退来源业务图。
21. 图片连接层负责组/序号、导航与会话、关闭来源、焦点/滚动协作。先验证库已提供的能力，再补必要缺口，避免双重锁定与恢复；不依赖私有 DOM、内部方法或深层样式覆盖维持正确性。
22. 按需加载底线不变；必须核实原生 viewer 是否全组挂载/请求，以及缩略图懒加载。生产缩略/预览共用 URL 不等于已生成尺寸变体或实现压缩，也不能用缓存命中掩盖整组请求。
23. 不自动启用库提供的下载、自动轮播或其他未确认功能；SRS 排除的双指/自由缩放、回复图片、深色模式等不因引入库而进入范围。
24. 前期以受控样例验证长图、工具栏、坏图/未上传混合组、历史、焦点/滚动及资源请求；iPhone Safari 实际结果不能由桌面模拟替代。若公开配置与必要连接层仍不满足保留项，暂停受影响替换并重新讨论，不擅自放宽需求、恢复整套自研预览或引入第二套库。

### 视觉、实施与发布

25. Element Plus 主题变量统一配色、字体、间距、圆角、焦点及状态表达，少量 scoped CSS 或 CSS Modules 负责内容布局，不引入 Tailwind。保留居中主栏、手机单列、浅青背景、白卡、青蓝选中与粉色作者信息，不照搬旧像素数值。
26. 新版列表、详情/评论/回复、预览、管理列表和单 UP 管理页以受控截图确认；记录构建、视口、浏览器、缩放、字体和内容条件。用户确认后才作为视觉回归基准，旧 B站参考及 #35 量测仅作历史来源。
27. 分阶段实施：记录当前版本/基线与已知缺陷 → 高风险验证 → Vue 装配与可运行的业务切片 → 全量回归/视觉与实际设备确认 → 清理废弃栈 → 完整产物统一上线。阶段不是按层拆票指令，后续 tickets 应各自形成可验证的行为路径并声明真实阻塞边。
28. 不长期保留生产 React/Vue 双入口，不要求每迁移一个页面就上线；可在隔离分支或工作区完成开发。最后移除废弃 React、React Router、React 测试适配、旧组件及重复样式，不删除历史证据或仍有用途的纯 TS。
29. 继续本地/CI 类型检查、测试和静态构建，Nginx 托管入口与资源并代理现有 API，无 SSR 或常驻 Node。Node 使用 nvm，依赖及脚本仅使用 pnpm；隔离后端验证仍使用 uv。
30. 发布保留必要旧哈希资源及回退产物，原子切换并验证入口缓存、所有引用 chunks、深链接及 API/资源错误边界。只切前端，不回退数据库、不因前端替换重启 collector；实际上线由后续获准的发布工作执行，本 spec 的创建不授权部署。
31. 维护收益通过已替换通用组件、已删除重复实现与仍保留业务逻辑的清单说明；记录构建资源与异常体积变化，不承诺删行比例、未经测量的性能指标或未经拆票的工期。
32. 回复页码输入为正的安全整数、固定 limit=10、与 cursor 互斥，请求使用 no-store。响应每页保留 root、本地 count 和独立来源/同步信息；count/每页 10 决定末页，越界空页时重读有效末页。不把每页 nextCursor=null 当作没有其他页，也不承诺实时页间冻结。
33. 宽屏每次展开重读 page 1，翻页/同页重读发真实读取，收起取消在途请求并滚回根，记录收起状态时 page 归 1。已有内存 live state 不构成再次展开缓存承诺；回复与根评论的迟到结果防护继续分开。
34. 窄屏当前阈值为 640px，无法判定按宽屏。仅正来源回复数显示预览/入口，可用 up_reply 是该动态作者在此楼最早一条；无作者回复仅数量入口，本地为零仍可进入，来源零/未知不显示。独立页每页响应取 root，另读一次动态仅用于 UP 标识，该辅助失败不阻断主读取；该页不展示图片。
35. 回复 Adapter 只将 422 CURSOR_INVALID 映射为 invalid-cursor；404、422 INVALID_INPUT 等为普通可重试 error，取消优先。独立页缺失根不新增详情式 not-found，生产不可达的空 root 兜底分支不作为新需求。

## 测试决策

### 用户已确认的测试边界

1. **主要边界是页面和真实浏览器的公开行为。** 从用户输入、点击、键盘、导航和可见结果验证阅读、管理、图片及恢复。不把 Vue 内部响应式结构、私有函数或 Element Plus 私有 DOM 当作契约。
2. **复用读取/管理接口及传输边界。** 页面行为测试注入可控 Adapter，确定性制造失败、延迟、乱序和忽略取消；生产 Adapter 契约测试仅替换 HTTP 传输，不绕过真实 DTO 映射。另保留实际 API + 隔离 SQLite 的集成验证，不以 mock 页面代替真实协议贯通。
3. **保留纯 TypeScript 确定性测试。** 验证既有规则与公开转换，不为迁移额外拆出大量测试接口。DOM 排版、资源请求、History、焦点与滚动使用真实浏览器，iPhone Safari 再做实际设备检查。

以上沿用当前可替换点，不新增业务 API 或专门供测试调用的公共接口。优先从最高可观察边界断言；单元测试只补充不宜完全依赖浏览器穷举的确定性规则与数据契约。

### 工具、既有实践与证据层次

| 层次 | 选择与既有实践 | 证据限制 |
| --- | --- | --- |
| 规则与契约 | 复用 Vitest 下的读取、映射、排序/分页、安全及状态规则测试；按需调整框架边界 | 原测试数量或历史通过数不等于新版已通过 |
| Vue 页面行为 | 使用 Vitest 与 Vue 行为工具，优先 Testing Library Vue，需要时使用 Vue Test Utils；沿用可控 Adapter 场景 | 按代码基线修正已漂移的 React/E2E 预期，不机械翻译内部断言或验证库私有状态 |
| 浏览器流程 | 沿用 Playwright 的 mock 阅读、生产归档、管理与静态交付路径，分别运行 | mock、生产 HTTP 替身、实际 API/SQLite、Nginx 结果不能互相冒充 |
| 布局与资源 | 真实 DOM 测量、键盘/焦点、History 和网络请求；控件查询优先角色/可访问名称，阅读锚点用稳定业务标识 | 旧像素断言可以按用户确认的新规范调整，但不可删除行为保护 |
| 实际兼容 | Linux Chrome 与 iPhone Safari，记录设备、浏览器版本、构建及实际过程 | 自动化 Chromium 或模拟手机不能冒充正式设备结果 |
| 视觉 | 新版受控截图先由用户确认，再进行差异回归 | 当前实现自建黄金图、旧 #35 截图或功能通过均不能自证新版视觉通过 |

目前没有本次 Vue 原型、自动化或设备结果；本节是已确认的测试设计，不是执行记录。已核实部分组件测试采用回复页码/目标前缀，旧 E2E 仍要求累计追加或窄屏内联；按代码重写旧断言，不能用“原测试应全绿”迫使 Vue 回退。

### 必须覆盖的场景

- **读取完整性：** 动态 25 条按 10/10/5 追加、一级评论 45 条按 20/20/5 追加；25 条本地回复宽屏先预览最多 3，再 page 1/2/3 各显示 10/10/5，不带 cursor。验证排序/来源置顶、缺失值、scope、cursor 失效/同批重试，以及回复实时数量变化、重复读页、末页回退、来源数与本地 count 不同。不能要求 page 模式跨页事务快照。
- **竞态：** 快速切换 scope/排序/UP/模式，迟到成功/失败/完成回调，传输忽略取消，同批重复点击，管理重复写入，离开未完成请求后返回；不能串内容、清掉新加载态或永远停留在加载中。
- **阅读：** 现有折叠区域的实际 6 行边界及宽度变化，详情动态全文，独立楼中楼/窄屏预览不折叠；长 URL/emoji/恶意 HTML、计数/时间兜底、图文组合及事件隔离。不恢复编辑信息块。
- **评论/回复：** 排序切换重置，宽屏收起定位与再展开重读首批、历史详情展开页实时重读；窄屏正来源/零/未知、有无作者预览、本地零与入口，独立页直达/翻页/返回及重新挂载首屏；条件化回复目标及来源去重。回复 404 保持普通读取错误，不新增 not-found 契约。
- **导航与恢复：** 全部/单 UP 来源返回、动态详情多批/展开锚点、主动入口及同动态多访问；六路由深链接/刷新/未知地址。楼中楼回详情恢复详情、重新进入楼中楼回首屏分别测试；同 URL 图片预览不重挂载底层详情。
- **图片：** 纯图、单图、多图、4/9/超过 9 图、长图及混合成功/失败/未上传组。数量只是夹具，不恢复旧列数上限；验证完整组可达、owner/索引、长图可读、工具栏、切换、关闭及局部重试。
- **预览历史：** 同 URL 打开、切图、按钮关闭、键盘关闭、后退/前进、重复开关、刷新和遗留元数据、触发元素已消失；没有双预览、二次后退、焦点逃逸、底层滚动或关闭跳位。
- **图片请求：** 冷缓存并使用可区分的缩略/预览 URL，观察实际网络，确认打开单张不要求先下载整组原图；同时验证生产共用 URL 情形，不用缓存命中作未请求证据。不额外要求每次操作恰好只能新增一个请求。
- **管理：** UID/动态 ID 字符串校验、仅 UID 新增与失败，启停、两种互斥模式、默认 N=10 与各 UP 独立配置、指定目标归属正确/不符/未知、删除保留归档、独立草稿与读取反馈、检查/同步/分项失败和窗口状态。
- **响应式与操作：** 360/390/768/1280 四宽度无页面横溢；UP 条只在内部横滚；主要触控区域约 44px，键盘语义与焦点可用。实机长图、工具栏、焦点及滚动须有对应结果。
- **装配与安全：** 默认真实 API、独立 mock/fault 隔离、错误脱敏、安全文本、浏览器不触发上游采集/上传且不接收秘密、业务图原样 OSS URL、不回退来源业务图。
- **交付：** Vue 模板和 TS 类型检查、正常构建与依赖清理，真实 Nginx 下深链接/刷新、API 错误与缺资源不回退 SPA、入口重新验证、哈希资源缓存和旧资源保留、更新后的所有资源可达。
