# 08：用静态产物直接访问页面并正确加载资源

Status: ready-for-agent
Implementation: completed（见 [08 验收记录](../acceptance-08.md)；此 Status 保留分诊标签，不表示实施进度）
Blocked by: [05：在动态中查看多图并打开图片预览](05-preview-dynamic-images.md)

**交付行为：** 维护者能复现构建并按说明静态托管已实现的图文页面；用户可直接访问详情，资源错误和缓存更新符合预期，正常产物不暴露故障模式或依赖真实服务。

## 依据与范围

- [实施规格](../spec.md)：用户故事 40、49、53、55–58 的构建、资源与部署部分。
- [SRS](../../../docs/product/SRS.md)：FR-13、DR-03、NFR-03、NFR-04、NFR-05。

- 验收关联：AC-19，以及 AC-13、AC-17、AC-18 的静态产物子项。

## 实施约束

- 依赖 05，以实际图文素材和图片请求验证交付；不依赖评论、长图或完整历史恢复，因此不添加 06/07 等无关前置。
- 延用 nvm、pnpm、Vite 和既有测试入口；本地或 CI 构建，服务器只提供静态文件，不引入 SSR、常驻 Node.js 应用或模拟 HTTP 服务。
- 提供 Nginx 配置示例及验证步骤；不实际配置阿里云、OSS 或新的 CI 平台，不安装或变更生产基础设施。

## 验收条件

- [x] 固定依赖及工具版本的构建流程可复现，正常产物可提供已完成的图文功能；所需检查、测试、构建和使用说明齐全。
- [x] 正常发布装配使用正常模拟实现，不暴露故障控制面板、公开故障参数、真实内容或服务凭据；专用测试装配不成为唯一被验证的运行路径。
- [x] 配置示例允许直接打开和刷新有效详情，未知页面由前端展示未找到状态；内容不存在与普通读取失败仍由应用分别表达。
- [x] 缺失脚本、样式或演示图片返回资源错误，不错误回退为入口 HTML，也不按成功资源缓存。
- [x] 入口采用重新验证策略，带内容哈希的资源可长期缓存，未版本化图片不一律永久缓存；配置的资源分类与实际构建产物一致。
- [x] 静态资源有明确的路径匹配规则，不仅凭任意页面 URL 是否带扩展名推断资源类型，避免动态标识或未知页面与资源回退混淆。
- [x] 演示素材使用版本化或适当缓存策略；页面图片按给定 URL 请求，不依赖 B站外链，不为未来 OSS 增加应用服务器代理。
- [x] 给出并执行可用环境下的验证步骤：详情深链接、刷新、未知页面、缺失脚本/图片、各类缓存头及一次构建更新后获取新入口和资源。
- [x] 明确静态 SPA 的前端未找到页面不等同于服务器 HTTP 404，不为此增加 SSR；资源错误与应用页面状态分别验证。
- [x] 验证正常构建的图片按需加载和核心导航，运行类型检查、相关测试、构建及已有回归，不只观察开发服务器页面。
- [x] 记录静态服务器/Nginx 验证环境及结果；若环境不可用，交付可执行验证步骤并标明未验证，不能用 Vite 的成功结果冒充 Nginx 验证通过，未验证验收项保持未勾选。
- [x] 交付说明区分本期本地素材和后续 OSS 直连，注明 2 核 2GB 是目标而非容量保证，后端、数据库及爬虫仍需另行评估。

不部署真实 API、爬虫、数据库、鉴权、OSS、CDN 或自动发布平台，也不进行服务器采购和容量压测。本票可针对当前已完成功能验证交付机制；09 必须用最终集成产物复跑相应检查，不以本票较早产物的结果代替最终结果。
