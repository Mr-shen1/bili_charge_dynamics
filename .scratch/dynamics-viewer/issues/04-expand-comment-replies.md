# 04：展开、收起并继续阅读楼中楼

Status: ready-for-agent
Blocked by: [03：阅读一级评论并切换最热/最新](03-read-and-sort-comments.md)

**交付行为：** 用户在一级评论下按时间阅读回复，逐批展开、收起并继续查看；某条回复区失败不会阻断其他讨论。

## 依据与范围

- [实施规格](../spec.md)：用户故事 12–14、20–24、43、45、46、48、50–54 的楼中楼部分。
- [SRS](../../../docs/SRS.md)：FR-01、FR-03、FR-04、FR-06、FR-07、FR-11、FR-12、DR-01、DR-02、NFR-01、NFR-02、NFR-03、NFR-04。
- [HLD](../../../docs/HLD.md)：第 3–5、9、10 节。重点是回复分页、可见范围与缓存区分、读取区域隔离及过期请求保护。
- 验收关联：AC-08；AC-01、AC-03、AC-04、AC-07、AC-14、AC-15、AC-16、AC-18 的回复子项。

## 实施约束

- 在 03 的评论流程中增加回复读取能力，使用同一个已确认的数据读取接缝，不直接导入回复集合或新增模拟 HTTP 服务。
- 按一级评论划分请求代次与错误区域；收起只改变可见范围，不能删除已加载回复及下一批标记。
- 排序切换时，一级评论和相关回复读取一起失效；普通的单条回复加载或重试不能使其他评论请求失效。

## 验收条件

- [ ] 回复按时间正序，时间相同时按稳定 ID 排序；一级评论切换最热/最新不会将楼中楼顺序倒转。
- [ ] 默认预览最早的最多 3 条；存在更多时每次追加最多 10 条。使用 25 条回复验证累计 3、13、23、25，最后不再请求下一批。
- [ ] 以扁平列表展示回复，标识回复目标与 UP 主本人；目标缺失时不拼接错误用户，头像、昵称、时间、计数、空正文按规定兜底。
- [ ] 零回复时无展开入口；不超过预览数量时不显示虚假的“更多”。回复数与动态总评论数来自完整模拟数据，不随已加载范围改变。
- [ ] 展开后可收起至最初最多 3 条；同一访问与排序中再次展开恢复已加载内容，不重复读取，后续追加从保留的下一批标记继续。
- [ ] 回复长文本超过 6 个实际渲染行可展开/收起，换行及 emoji 正常，内容作为安全普通文本展示。
- [ ] 某条回复区首次或追加失败只影响该区域；已有回复、其他评论及上方动态保持可读，并能在原区域重试。
- [ ] 相同批次不重复启动；失败不推进分页，重试无重漏；一次回复重试不会取消无关回复区的有效请求。
- [ ] 切换一级评论排序重置回复展示状态；旧回复成功、错误及完成回调均不能污染目标排序或新的页面访问。
- [ ] 读取契约和页面测试覆盖分页、收起恢复、数据计数一致性、目标缺失、局部失败与排序竞争，浏览器验证实际回复折叠。
- [ ] 楼中楼在约定手机/桌面宽度无横向溢出，长昵称与回复关系可辨识，展开与重试可触控及键盘访问。
- [ ] 本票测试、类型检查、构建及既有测试通过，不以暂时隐藏有问题回复的方式通过验收。

## 本票边界

本票在当前访问内完成楼中楼状态；历史返回到不同详情访问时的完整恢复由 07 完成。图片、手势和预览历史不属于本票。
