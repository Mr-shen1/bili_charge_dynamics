# 02：连续阅读动态并从详情回到原位置

Status: ready-for-agent
Implementation: completed（仅 02 列表范围，验收证据与未验证分支见 [验收记录](../acceptance-02.md)）
Blocked by: [01：打开动态列表并进入文字详情](01-browse-text-dynamics.md)

**交付行为：** 用户逐批阅读动态、展开长正文，进入详情后能返回原列表阅读位置；追加失败不会清空已读内容或破坏进度。

## 依据与范围

- [实施规格](../spec.md)：用户故事 2–5、9、37、39、43、45、46、50、53 的动态列表部分。
- [SRS](../../../docs/product/SRS.md)：FR-03、FR-05、FR-10、FR-11、DR-02、NFR-01、NFR-02、NFR-03、NFR-04。
- [HLD](../../../docs/design/HLD.md)：第 3–6、8、9 节。重点是完整集合排序、不透明分页标记、访问快照和定位点恢复。
- 验收关联：AC-03、AC-05，以及 AC-12、AC-14、AC-16、AC-17 的列表子场景。

## 实施约束

- 沿用 01 的读取接口、会话容器与导航身份；在本票实际流程中实现列表快照，不额外建设与页面无关的状态框架。
- 列表标记由读取 Adapter 解释，UI 只传递；成功才推进分页位置，失败及重试不跳批。
- 文字折叠以渲染行数为准；阅读恢复由应用统一负责，不叠加路由库内建恢复或存储持久化。

## 验收条件

- [x] 准备至少 25 条动态，按时间倒序稳定排列；相同时间按 HLD 的 ID 规则确定顺序，缺失排序值按已确认规则处理。
- [x] 用恰好 25 条的场景验证按 10、10、5 追加，无重复遗漏；加载结束可辨识，不能再请求下一批，不使用无限滚动。
- [x] 追加期间保留原动态及展开状态；重复点击不启动同批重复请求，过期结果或错误不能污染另一访问。
- [x] 追加失败在原位置显示重试，重试仍取失败批次，成功后恢复可继续读取状态，不回到第一页。
- [x] 列表正文超过 6 个渲染行时初始折叠，可展开/收起；未溢出时无多余入口，详情正文仍完整展示。
- [x] 换行、emoji、长 URL、长词和长昵称正常展示；改变视口后折叠判定与布局仍正确，文本保持安全且无自动外链。
- [x] 多批列表中展开正文、滚动后进入详情再返回，恢复同一次列表访问的已加载范围、展开状态和位置；页面返回与浏览器后退均覆盖。
- [x] 保存稳定内容定位点及视口偏移，并保留像素后备；先还原内容和展开状态再定位，找不到锚点时有限回退，不无限等待。（锚点缺失后备已实现，未独立浏览器复现，见验收限制。）
- [x] 主动打开详情仍定位顶部；已开始的恢复任务不在用户主动滚动后把用户拉回，不因读取晚到永久停留在加载中。
- [x] 列表快照只保存在当前会话内存中，按应用访问 ID 隔离，不把可变视图状态共享给另一访问，也不写入浏览器存储。
- [x] 使用读取接口测试排序、分页与失败重试；浏览器测试验证实际 6 行折叠、页面返回及位置恢复，至少覆盖手机与桌面代表视口。
- [x] 本票长内容在 SRS 四种宽度下无横向溢出，操作可用；相关测试、类型检查、构建及既有测试通过，验证限制如实记录。
