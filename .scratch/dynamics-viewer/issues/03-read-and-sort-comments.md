# 03：阅读一级评论并切换最热/最新

Status: ready-for-agent
Implementation: completed（仅 03 一级评论范围，证据与未验证项见 [验收记录](../acceptance-03.md)）
Blocked by: [01：打开动态列表并进入文字详情](01-browse-text-dynamics.md)

**交付行为：** 用户从动态进入评论区，阅读一级评论、切换排序并继续加载；快速操作与读取失败不会让旧结果覆盖当前选择，也不会清空上方动态。

## 依据与范围

- [实施规格](../spec.md)：用户故事 7、13–19、23、43–46、48、50–54、56 的一级评论部分。
- [SRS](../../../docs/SRS.md)：FR-01、FR-02、FR-03、FR-04、FR-06、FR-11、FR-12、DR-01、DR-02、NFR-01、NFR-02、NFR-03、NFR-04。
- [HLD](../../../docs/HLD.md)：第 2–6、9、10 节。重点是评论状态归属、完整集合排序、局部状态和请求代次。
- 验收关联：AC-01、AC-02、AC-03、AC-04 的评论子项，AC-06、AC-07，以及 AC-14、AC-15、AC-16、AC-18 的相应子场景。

## 实施约束

- 只依赖 01 的详情、读取与会话基础，不以 02 的列表分页或文本实现作为隐含前置；可复用已经落地的公开工具，但不跨未完成任务引入依赖。
- 评论视图按当前页面访问保存状态，为 07 的历史恢复保留状态归属；本票不负责完整历史快照恢复。
- 故障与乱序通过注入的读取 Adapter 控制。旧成功、旧错误和旧完成回调都需通过同一有效性规则，不能只依赖取消请求。

## 验收条件

- [x] 详情展示一级评论作者、头像、时间、正文和只读点赞数；用稳定作者 ID 识别 UP 主，不按同名昵称判断。
- [x] 点击列表的评论数进入同一详情并定位评论区；“查看详情”仍定位顶部，不能被旧位置覆盖。
- [x] 默认最热；最热按点赞数降序、时间降序，再按 ID 稳定打破并列；最新按时间降序及 ID 排序，作用于完整集合后分页。
- [x] 至少一条动态具备 45 条一级评论；在该场景中两种排序均按 20、20、5 展示，最终无重复遗漏且显示加载完毕。
- [x] 切换排序回到评论区顶部、目标首批及收起的评论状态，不沿用旧分页进度；上方动态正文和图片区域不被清空或重新初始化。（正文已验证；内容图片尚属 05，未宣称图片区域已验收。）
- [x] 连续切换及旧分页请求晚到时，最后一次选择生效；分别验证旧成功、旧错误、旧完成回调，以及 Adapter 忽略取消的情况。
- [x] 切换失败明确显示目标排序的局部错误，重试读取目标首批，不把旧排序结果冒充为新结果。
- [x] 无评论、首次加载中/失败、追加加载中/失败及加载结束可区分；追加失败保留已有评论，重试同批次且不重复提交。
- [x] 长评论超过 6 个渲染行可展开/收起，普通文字、换行和 emoji 可读，用户提及不跳转，脚本样例不执行。
- [x] 时间、零值及缺失计数、作者信息和空正文遵守 SRS；显示的动态总评论数不能用本页已加载一级评论数量代替。
- [x] 导航到另一动态或离开当前访问后，迟到请求不改写新访问；取消不是用户错误，当前区域不会因旧完成回调提前结束新加载。
- [x] 页面行为测试覆盖排序、分页、重复点击、局部错误及可控乱序；浏览器测试覆盖评论入口定位和实际长评论折叠。
- [x] 评论在约定手机/桌面宽度可读且不横向溢出，操作可触控及键盘访问；本票测试、类型检查、构建及既有测试通过。（Chromium 桌面/手机模拟，不是真机触摸验证。）

## 本票边界

不实现楼中楼；回复展开与排序切换后的回复重置由 04 承担。不同详情访问的完整快照和阅读位置恢复归 07。本票完成一级评论相关需求子项，不宣称 FR-07 或全部 FR-10 已完成。FR-04 的逐条回复数展示由 04 交付，本票未验收，不宣称 FR-04 整体完成。
